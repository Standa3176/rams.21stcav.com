    ```php
    <?php

    namespace App\Console\Commands;

    use App\Services\TimeEntryService;
    use Illuminate\Console\Command;

    /**
     * programme:close-stale-sessions
     *
     * Phase 15 (INST-04e + D-17/D-18): auto-closes time entries whose last
     * heartbeat is older than --minutes (default 120). Delegates to
     * TimeEntryService::closeStaleSessions which handles:
     *   - Row-level locking (DB::transaction + lockForUpdate per entry)
     *   - Fallback when last_heartbeat_at IS NULL (closed_at = clocked_in_at + 1 min)
     *   - Log::warning per closure (user_id, project_id, entry_id, last_heartbeat_at, closed_at)
     *   - closure_reason = 'stale_auto_close' so the dashboard can distinguish auto vs manual
     *
     * Scheduled hourly via routes/console.php (withoutOverlapping).
     */
    class CloseStaleSessionsCommand extends Command
    {
        protected $signature = 'programme:close-stale-sessions
                                {--minutes=120 : Sessions with last_heartbeat_at older than this are closed}';

        protected $description = 'Auto-close time entries whose last heartbeat is older than --minutes (default 2h).';

        public function __construct(
            private readonly TimeEntryService $service,
        ) {
            parent::__construct();
        }

        public function handle(): int
        {
            $minutes = (int) $this->option('minutes');
            if ($minutes <= 0) {
                $this->error('--minutes must be a positive integer.');
                return self::FAILURE;
            }

            $count = $this->service->closeStaleSessions($minutes);

            $this->info("Closed {$count} stale time entries (threshold: {$minutes} min).");

            return self::SUCCESS;
        }
    }
    ```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| cron → php artisan | Command runs as the web user; no HTTP surface. Only reachable from local system. |
| command → DB | Inherits DB::transaction + lockForUpdate from Plan 15-02 service; no new DB risks introduced here |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-03-01 | Tampering | Scheduler fires two overlapping invocations, both try to close the same row | mitigate | `withoutOverlapping(30)` on the Schedule::command chain. Additionally, TimeEntryService::closeStaleSessions (Plan 15-02) uses lockForUpdate inside each DB::transaction per entry — if two invocations somehow proceed, only one acquires the lock; the other sees clocked_out_at already set and skips |
| T-15-03-02 | Denial of service | Command runs amok processing millions of rows | accept | Open entries are bounded by active engineers × active projects (realistic upper bound ≈ 50). Even pathological 10k open entries = ~20s work. `runInBackground()` prevents blocking the scheduler. If load ever justifies, add `take(500)` cap to service layer as a future hardening task |
| T-15-03-03 | Information disclosure | stale-sessions.log file exposes PII | accept | Log file contains entry IDs only + already-scoped project/user IDs; no names, emails, or notes. Stored under storage/logs which is outside webroot. Matches existing `laravel.log` exposure surface |
| T-15-03-04 | Elevation of privilege | Arbitrary user runs command via CLI to close peers' sessions | accept | CLI access already implies full filesystem + DB credentials (config/database.php). No new attack surface. Restricting artisan access is an infra concern, not a Phase 15 concern |
| T-15-03-05 | Repudiation | Engineer disputes auto-closure | mitigate | Every auto-close writes Log::warning (inside Plan 15-02 service) AND sets closure_reason = 'stale_auto_close' on the DB row — the entry itself encodes whether it was auto-closed or manually closed. Dashboard widget (Plan 15-05) can surface this distinction visually if ops requests it later |
</threat_model>
