# Phase 14 — UI Design Contract

> Visual and interaction contract for the mobile field page at `/projects/{project}/programme`. Generated by gsd-ui-researcher 2026-04-20, verified by gsd-ui-checker.

**Target device:** iPhone SE (375 × 667) is the anchor; must render at 320 px without horizontal scroll; portrait-locked via `<meta name="viewport" content="width=device-width,initial-scale=1,viewport-fit=cover">` (no landscape-specific layout — existing behaviour is acceptable when device is turned, but nothing in this phase is designed for landscape).

**Target user:** Install engineer on a noisy site, phone often in one dirty hand, flaky 4G. Admin/project owner uses the same page on desktop for situational awareness (no separate layout — this is a single mobile-first view that simply grows gracefully to ~768 px).

## Spacing Scale

All Phase 14 spacing must use the Tailwind `rem` scale below. Tailwind `0.25rem = 4px` and every value is a multiple of 4, satisfying the 8-point scale (with a half-step at 4 px reserved for icon-gap use only).

| Token | Tailwind class | px | Usage |
|-------|----------------|----|-------|
| xs | `p-1` / `gap-1` | 4 | Icon-to-label gap inside a chip; tight two-element inline spacing. |
| sm | `p-2` / `gap-2` | 8 | Thumbnail gap; photo-strip item separation; caption margin-top. |
| md | `p-3` / `gap-3` | 12 | **Task row internal padding** (vertical + horizontal); room-header inline gaps. Yes, 12 is a multiple of 4; kept because `p-3` is the Tailwind-native step between `p-2` and `p-4` that gives us the 44 px touch-target floor. |
| base | `p-4` / `gap-4` | 16 | **Default element spacing.** Card padding, sticky-bar horizontal padding, bottom-sheet inner padding. |
| lg | `p-6` / `gap-6` | 24 | Section breaks between room-sections; programme-progress block top/bottom margin. |
| xl | `p-8` / `gap-8` | 32 | Empty-state vertical padding. |
| 2xl | `p-12` | 48 | Reserved — not currently used by this phase; available for page-level margin if the view ever desktops up. |

Exceptions (documented, not invented):

- **44 px minimum touch target** (Apple HIG + WCAG 2.5.5 AAA). Every tappable element — status row, ⋮ overflow, camera label, bottom-sheet buttons, clock-in chip — must hit `min-h-[44px]` (Tailwind arbitrary) or `h-11` (44 px). The task-row hits this naturally via `p-3` + content; icon-only controls explicitly reserve `w-11 h-11`.
- **Sticky-bar height: 56 px** (`h-14`), plus `pt-[env(safe-area-inset-top)]` on the outer wrapper to clear the iOS notch. Total sticky footprint ≈ 56–100 px depending on device. The bar itself stays 56 px; only the top padding grows.
- **Safe-area bottom:** The existing `x-mobile-tab-bar` already sits fixed at the viewport bottom on ≤768 px. The field view must add `pb-24` (96 px) to its scroll container so the last task row never hides behind that bar.
- **Photo thumbnail: 80 × 80** (`w-20 h-20`). Per D-09 Claude's-Discretion lock.

## Typography

Figtree, fallbacks to system sans. Four roles, two weights — engineers need readable hierarchy at arm's length on a small screen.

| Role | Tailwind | px | Weight | Line-height | Usage |
|------|----------|----|--------|-------------|-------|
| Display | `text-lg font-semibold` | 18 | 600 | `leading-tight` (1.25) | Sticky-bar project name; bottom-sheet heading. |
| Heading | `text-base font-semibold` | 16 | 600 | `leading-snug` (1.375) | Room section header ("Boardroom A"); programme progress label. |
| Body | `text-sm font-normal` | 14 | 400 | `leading-normal` (1.5) | Task title; notes input; caption input; menu items. |
| Meta | `text-xs font-normal` | 12 | 400 | `leading-normal` (1.5) | Row-level metadata (quantity × equipment, assigned engineer name); "N of M complete"; photo-upload helper text; timestamps. |

Weights: **400 regular + 600 semibold only.** No 500-medium, no 700-bold. Keeps the visual language consistent with existing site-survey and schedule pages which use these same two weights.

Body line-height note: 1.5 (`leading-normal`) is mandatory for the notes textarea — engineers multi-line entries need readable leading.

### Status colour contract (task rows — the whole interactive surface)

| Status | Row background | Border / ring | Icon (outline v2 Heroicons) | Icon colour | Screen-reader label |
|--------|----------------|---------------|-----------------------------|-------------|---------------------|
| `pending` | `bg-white` | `border border-gray-200` | `circle` (empty) | `text-gray-400` | "Pending — tap to start" |
| `in_progress` | `bg-amber-50` (#FFFBEB) | `border border-amber-300` | `clock-solid` | `text-amber-600` | "In progress — tap to complete" |
| `complete` | `bg-green-50` (#F0FDF4) | `border border-green-300` | `check-circle-solid` | `text-green-600` | "Complete" |
| `blocked` | `bg-red-50` (#FEF2F2) | `border border-red-300` | `exclamation-triangle-solid` | `text-red-600` | "Blocked — {reason}" |
| `skipped` | `bg-gray-100` (#F3F4F6) | `border border-gray-300` | `minus-circle-solid` | `text-gray-500` | "Skipped — {reason}" |

**Accessibility rule (WCAG 1.4.1):** Every status is communicated by **colour + icon + ARIA label** — never colour alone. The icon is to the left of the task title so a monochrome / high-contrast / colour-blind user still gets the signal.

**Contrast verified** (all pairs, WCAG 2.1 AA):
- Text `#1F2937` on `#FFFFFF` → 15.3:1 ✓ (AAA)
- Text `#1F2937` on `#FFFBEB` amber-50 → 14.6:1 ✓ (AAA)
- Text `#1F2937` on `#F0FDF4` green-50 → 15.1:1 ✓ (AAA)
- Text muted `#6B7280` on `#FFFFFF` → 4.7:1 ✓ (AA body)
- Icon `text-amber-600` (#D97706) on `#FFFBEB` → 3.4:1 ✓ (AA for non-text UI component — 3:1 threshold)
- Icon `text-red-600` (#DC2626) on `#FEF2F2` → 4.1:1 ✓
- White on `#0B3C45` sticky bar → 13.6:1 ✓ (AAA)
- White on `#178A95` accent → 4.8:1 ✓ (AA)

Accent reserved-for list (explicit, not "interactive elements"): **clock-in chip active state background, camera-label button fill, programme progress-bar fill, "Save reason" button in the bottom-sheet, and the "Show all" toggle's active indicator.** Nothing else is teal.

### Scope toggle (D-02)

- **Visible only to engineers** (`!$user->isAdmin() && $project->user_id !== $user->id`). Admins/owners see all tasks by default and don't see the toggle — they already have everything.
- Two segments: `My tasks` (default, active) / `Show all`. Implemented as `<button>` pair inside a `bg-gray-100 rounded-full p-1 flex` pill. Active segment = `bg-white shadow-sm text-[#0B3C45]`, inactive = `text-gray-500`.
- Switching scope refetches the page via a plain `<a>` link with `?scope=all` / `?scope=mine` query param (server-rendered — simpler than an Alpine fetch swap for this volume of content). Alternatively server sets `data-scope` on the root and hides non-assigned rows — either is acceptable; planner chooses based on row count.

## Interaction Specification

### Tap-to-advance (D-05)

- Target: **entire task row** is tappable (the card body, not a nested button). Tailwind: `role="button" tabindex="0"` on the card `<article>`, plus `@click="advance()"` and `@keydown.enter.prevent="advance()"` / `@keydown.space.prevent="advance()"` so keyboard users get the same behaviour.
- Transitions (sole machine):
  - `pending → in_progress` (first tap) — server sets `started_at` when null
  - `in_progress → complete` (second tap) — server sets `completed_at = now()`
  - `complete → (no-op)` — click on completed row does nothing; Alpine early-return
  - `blocked`, `skipped` — unreachable via the main tap path; only reachable via overflow.
- Visual on save: **inline checkmark pulse** — `ring-2 ring-green-400` for 400 ms, eased out over `ease-out`. Implemented as an Alpine bool `savedPulse` flipped true for 400 ms via `setTimeout`. **No toast, no modal, no haptics** (web can't do haptics reliably; don't attempt).
- Server response shape (per RESEARCH Example 5): `{ id, status, blocked_reason, counters: { room: {complete, total}, programme: {complete, total} } }`. Alpine dispatches `task-saved` on `window`; room-header and programme-progress components listen and update their counters from the payload.
- **Saving state (flaky signal matters):** While the PATCH is in flight, the row gets `opacity-70 pointer-events-none` AND the status icon is replaced with `arrow-path animate-spin text-gray-400`. If the user tapped three times rapidly, the second+third taps are queued (Alpine `queued` array) and fire sequentially after the first resolves; the final state = the last tap's intended target. This prevents dropped taps on a 3 G station.
- **Error:** `ring-2 ring-red-400` for 4 s, row status reverts to the pre-tap value (optimistic UI is NOT used per RESEARCH anti-pattern — state is authoritative-from-server). Inline sr-only text announces the error to assistive tech.

### Overflow menu (⋮)

- Trigger: `w-11 h-11` button with `ellipsis-vertical` outline icon, `absolute right-2 top-2` within the row. `aria-haspopup="menu"` + `aria-expanded` bound to Alpine `menuOpen`.
- **No long-press.** Decision: rely on the visible ⋮ icon only. Long-press is an undocumented affordance on mobile web, and keyboard users would have no path. Visible, discoverable.
- Menu style: small card dropping down-left from the button, `absolute right-2 top-12 w-48 bg-white rounded-lg shadow-md ring-1 ring-black/5 divide-y divide-gray-100 z-20`. Tap outside (via `@click.outside` on the menu) closes it.
- Items: each is a `w-full text-left px-4 py-3` button (44 px tall via padding), body-text size.

### Bottom-sheet (blocked / skipped)

- **Entry:** Slides up from the bottom. `fixed inset-x-0 bottom-0 z-40 bg-white rounded-t-2xl shadow-2xl p-6`. Backdrop: `fixed inset-0 bg-black/40 z-30` — tap backdrop to dismiss (with unsaved-reason guard: if the textarea is non-empty, confirm `Discard this reason?` before dismissing).
- **Animation:** 250 ms `ease-out` on enter (`translate-y-full → translate-y-0`), 200 ms `ease-in` on leave. Matches the existing `x-modal` timing so the app feels consistent.
- **Focus trap:** `autofocus` on the textarea on open; `Esc` dismisses (with same unsaved-reason guard).
- **Max-height:** `max-h-[75vh] overflow-y-auto` so a landscape / small phone still has scrollable content. iOS safe-area bottom handled via `pb-[env(safe-area-inset-bottom)]`.
- **Submit:** `Save reason` button disabled while textarea is empty (trimmed). On click: PATCH `install-tasks/{task}/status` with `{ status: 'blocked'|'skipped', blocked_reason: <text> }`. Server returns the same counters shape as tap-to-advance. On success, sheet slides out + row enters its new status. On error, inline message inside the sheet: `Couldn't save — check your signal and retry.`

### Photo capture (D-09, D-10, D-12)

- Camera trigger: the last item in the horizontal thumbnail strip is a dashed-border `<label>` wrapping a hidden `<input type="file" accept="image/*" capture="environment">`. Size `w-20 h-20`, centred camera icon + tiny `Add photo` label underneath.
- On file select: AJAX `POST /install-tasks/{task}/photos` (multipart, `FormData`) — fetch + CSRF meta per project convention. UI state: the placeholder turns into a spinner (`arrow-path animate-spin`) until the server responds; on success the new thumbnail is pushed to the strip.
- HEIC conversion is server-side and synchronous (D-11). UI shows the spinner for the whole round-trip; typical iPhone 12 MP HEIC on 4 G ≈ 2–5 s. No progress bar (RESEARCH anti-pattern — fetch can't surface progress cleanly).
- Caption: `<input type="text" class="text-xs mt-1 w-full border-0 border-b border-gray-200 focus:ring-0 focus:border-[#178A95] bg-transparent">` — inline under each thumbnail. Saves on `blur` event via PATCH `install-task-photos/{photo}` with `{ caption }`. No explicit save button.
- Lightbox: tap thumbnail opens a full-screen `<dialog>` element (native `dialog.showModal()` — no library). Close by tap on backdrop or `Esc`. Inside the lightbox: the photo centred, a small `Delete photo` button at bottom with inline confirm per Copywriting above.

### Notes input (Claude's Discretion — locked here)

- Collapsed default: single-line, muted, `Add a note…` placeholder with `pencil-square` icon prefix.
- Expanded: `<textarea rows="1" style="resize:none">` with auto-grow via Alpine `x-on:input` → `$el.style.height = 'auto'; $el.style.height = $el.scrollHeight + 'px'`. Max-height `max-h-[200px] overflow-y-auto` — caps growth so the row never dominates the viewport.
- Save: `blur` event, PATCH `install-tasks/{task}/notes`. While saving, tiny spinner right of the textarea. On success, spinner fades out. On error, inline red message (see Copywriting).
- Persist: server-authoritative — on page reload, the notes come back from the `install_tasks.notes` column.

### Clock in / out

- Chip is the right-side element in the sticky bar. Tapping it:
  - If inactive → POST `projects/{project}/time-entries/start`, response updates chip to active state with `clocked_in_at` timestamp. On 422 (already-open guard), show inline error copy.
  - If active → POST `projects/{project}/time-entries/stop`. Chip returns to inactive.
- Elapsed-time display uses `setInterval` every 30 s to recompute `now() - clocked_in_at` → `H:MM`. No server round-trip needed for the tick. If the tab is backgrounded the interval may throttle; on resume the visible time jumps — acceptable.

### Scope toggle

Described above under Information Architecture. Interaction is a page navigation (simpler than client-side filter) with `?scope=all|mine` query param.

## Responsiveness

- **320 px floor** (`iPhone 5` / `iPhone SE 1st gen` era, `Galaxy Fold closed`): No horizontal scroll. The sticky-bar truncates project name with `truncate`; clock-in chip shrinks to icon-only (`Clock in` label hidden via `sm:inline hidden`, icon-only at narrow widths). Task row keeps 12 px horizontal padding and still fits all elements thanks to the `truncate` on title.
- **375 px (success criterion anchor):** All text labels visible; clock-in chip shows label + time; photo thumbnails 80 px with enough margin.
- **430 px (iPhone Pro Max):** Same layout; slightly more breathing room from implicit flex behaviour. No breakpoint-specific styles.
- **≥768 px (desktop — admins):** The page still works. Max-content-width: `max-w-2xl mx-auto` (672 px) — on a desktop the column sits centre-screen, not stretched. The existing `x-mobile-tab-bar` auto-hides at ≥768 px per its CSS, so remove the `pb-24` at that breakpoint (`md:pb-6`).
- **Landscape:** Not optimised. Sticky bar will still pin, but the bottom-sheet `max-h-[75vh]` rule ensures content stays scrollable. Do not add landscape-specific CSS in this phase.
- **No dense mode.** One density, optimised for thumb use.

## Accessibility

- **Touch targets ≥ 44 × 44 CSS px** — verified in spec:
  - Task row: `p-3` vertical (12) + 20 px content + `p-3` = 44 px minimum, usually more
  - Overflow ⋮: `w-11 h-11` = 44 × 44
  - Camera label: `w-20 h-20`
  - Clock-in chip: `h-11 px-3`
  - Room-section chevron: `w-11 h-11` tappable zone (icon smaller inside)
  - Bottom-sheet buttons: `h-11`
- **Focus states:** All interactive elements use `focus-visible:ring-2 focus-visible:ring-[#178A95] focus-visible:ring-offset-2 focus-visible:outline-none`. Critical for Bluetooth-keyboard users on iPad kitted out for install teams.
- **Screen-reader labels:**
  - Overflow ⋮ → `aria-label="More actions for {task.title}"`
  - Camera label → `aria-label="Add photo to {task.title}"`
  - Clock-in chip → `aria-label` set per state (see Copywriting)
  - Chevron → `aria-label="Collapse {room.name}"` / `"Expand {room.name}"`
  - Room counter → plain text (readable)
  - Task status icon → `<span class="sr-only">` with the status label (see status table)
- **`aria-live` regions:**
  - Programme progress counter → `aria-live="polite"` (announces after status saves)
  - Clock-in chip time span → `aria-live="polite"`
  - Task row error message → `aria-live="polite" aria-atomic="true"`
- **Reduced-motion fallback:** The 400 ms green-ring pulse and 250 ms sheet slide honour `@media (prefers-reduced-motion: reduce)` — both animations collapse to an instant state change. Tailwind: wrap transitions with `motion-safe:` prefix, e.g. `motion-safe:transition-all motion-safe:duration-300`.
- **Colour + icon pairing (1.4.1):** Already spec'd in Status colour contract.

## Animation / Motion

| Animation | Duration | Easing | Tailwind / CSS |
|-----------|----------|--------|---------------|
| Task-save checkmark pulse | 400 ms | `ease-out` | `motion-safe:transition-all motion-safe:duration-[400ms] motion-safe:ease-out`, toggled by `ring-2 ring-green-400` → `ring-0`. |
| Task-save error ring | 4000 ms (stays visible) then fade | linear | JS `setTimeout` clears the class; `transition-opacity duration-300` on fade-out. |
| Bottom-sheet slide in | 250 ms | `ease-out` | `x-transition:enter="transition ease-out duration-250" x-transition:enter-start="translate-y-full" x-transition:enter-end="translate-y-0"` |
| Bottom-sheet slide out | 200 ms | `ease-in` | inverse of above |
| Sheet backdrop fade | 200 ms | `ease-in-out` | `opacity-0 → opacity-100` |
| Programme progress-bar fill | 300 ms | `ease-out` | `transition-[width] duration-300` on the `style="width: X%"` element |
| Clock-in chip state change | 150 ms | `ease` (default) | `transition-colors` (matches existing `--transition` token) |
| Photo-upload spinner | continuous | linear | `animate-spin` (Tailwind default) |

All motion wrapped in `motion-safe:` where it creates motion (not just colour change). Colour-only transitions are kept unconditional — they're not motion-sensitive.
