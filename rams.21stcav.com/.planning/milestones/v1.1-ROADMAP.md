## Overview

Transform the platform from a quiet document generator into a real-time AV-operations system. Project Managers see all active projects with health indicators (red/amber/green priority-ordered), overdue stage alerts, install programme progress, and status filtering. The system pushes email notifications when document generation completes, fails, or needs review — no more silent queues, no more dashboard-refreshing.

**Scope reduction:** v1.1 was originally scoped as phases 08–11 in the ROADMAP overview. Phases 10 (Bitrix24/CRM push) and 11 (multi-channel notifications) were not built and were deferred to a future milestone. v1.1 ships as 08 + 09 only.

## Milestone Summary

**Key Decisions:**

- **Idempotency-first dispatch** — every send-once column (`completion_email_sent_at`, `failed_email_sent_at`, `review_needed_email_sent_at`) is set in the same `update()` call as the dispatch, BEFORE the mail leaves the queue. Job retries cannot double-send. ✓ Good
- **`role`-based admin lookup, not `is_admin` boolean** — codebase migrated to `User::where('role', 'admin')` per the actual schema. Eliminates a latent class of "0 admins matched" bugs. ✓ Good
- **`NotificationRecipientResolver` as single source of truth** — every mailable call site resolves recipients through one service. `SurveyService::submitPublic` was refactored to use it (no regression). ✓ Good
- **Postmark over SES** — `rams@21stcav.com` sender; SPF / DKIM (Postmark selector) / DMARC on `21stcav.com`; production cutover gated by `POSTMARK-OPS-CHECKLIST.md`. ⚠ Revisit (operationally pending)
- **No multi-channel notifications in v1.1** — all sends are `Illuminate\Mail\Mailable` subclasses, not the Notification framework. Multi-channel deferred to a future milestone when there is a real second channel. ✓ Good

**Issues Resolved:**

- Latent `is_admin` boolean references removed across `app/` (NOTF-05b)
- Latent `Project::with('user')` (camelCase mismatch with `Project::user()` model relation) removed in `SurveyService` (NOTF-02a)
- Dashboard `/dashboard` route closure replaced with thin controller (DASH-01a) — testable, DI-able

**Issues Deferred:**

- **Phases 10 (Bitrix24 push) and 11 (multi-channel)** — never built; absorbed into roadmap parking lot for a future milestone
- **Production Postmark cutover (NOTF-05g)** — DNS records, API key in production .env, sender signature verification, first-send confirmation. Runbook at `milestones/v1.1-phases/09-email-notifications/POSTMARK-OPS-CHECKLIST.md`
- **Dev log-mailer end-to-end smoke** — manual queue-worker run against `MAIL_MAILER=log` to verify rendered bodies for all 6 mailables

**Technical Debt Incurred:**

- VALIDATION.md `wave_0_complete: false` for both phases — Nyquist contracts authored but not closed (`/gsd-validate-phase 08 09` available post-hoc)
- Phase 09 REVIEW WR-01..WR-04 (4 polish items, non-blocking):
  - WR-01..WR-03: error-message truncation pattern inconsistencies between dispatch sites
  - WR-04: narrow `failed()` try/catch gap in `BuildRamsDocumentJob::failed` and `BuildWorksheetJob::failed` where the DB write that sets `failed_email_sent_at` is outside the catch — could drop a failure alert on transient DB error during the timestamp write
