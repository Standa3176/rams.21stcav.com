# Phase 46.9 — CONTEXT

## Domain

An engineer opens a site survey or worksheet link on a phone, on site, and needs to know what to do
in that room. Today they can get the **sales prose the quote was written in** — QuoteWerks
`CustomMemo01` paragraphs like *"Oregano is now using the Crestron small room system with Jabra
PanaCast 50 video bar, and offers full room control from a single Crestron panel…"*. That is a
sentence written to win work, not to do work.

This phase makes the app derive an **engineer-facing bulleted version** of that scope automatically,
per room, in the background, at import time — so the bullets already exist before anyone creates a
document.

**The user's request, verbatim (2026-10-10):**

> "when creating a doc, can the app keep the imported project scope of works/space descriptions but
> use ai to auto create engineer/install friendly version for site survey, worksheets etc also make
> then clear and some[thing] like bulletpoints to help quick reading and understanding when on site."

## ⚠ Read § Corrections before you plan

The first draft of this CONTEXT named a central design problem ("the bag trap") that **does not
exist**, repeated a **wrong cost model** for the AI calls, and assumed work on the worksheet that is
**already shipped**. `46.9-RESEARCH.md` disproved all three with citations, and the orchestrator
independently re-verified the two most consequential. The decisions below are the corrected set.
**The phase is materially smaller than it looked.**

## Decisions

- **D-01:** The output is **bullets** — short, imperative, written for someone standing in the room
  with a phone. **No prompt change is required to achieve this.**
  `app/Core/AI/Prompts/RoomOverviewSummaryPrompt.php:52-62` already carries `BULLET RULES:`, requires
  each line `prefixed with "- " (dash + space)`, caps a bullet at *"One sentence per bullet, ≤25
  words"*, instructs *"Drop sales fluff"*, and forbids inventing kit; `:67-87` is a worked example
  whose input **is** QuoteWerks sales prose of exactly the complained-about kind. **Therefore D-01
  mints no work and carries zero regression risk to the live sparkle-Generate button.**
- **D-02:** It runs **in the background, right after import**, as a queued job. **This is the user's
  own choice**, made on 2026-10-10 from three options. ⚠ **The cost figure they were given was
  wrong** — see § Corrections C-02. The choice still stands on **latency**: the import request does
  not wait on an AI round trip. **But do not design for a 12-way fan-out**, a per-room retry ledger,
  or per-room partial-failure resumption. There is **one** AI call for the whole package.
- **D-03:** It **never overwrites an office-edited summary.** Hand-authored text always wins; only an
  **empty** `works_summary` is filled. ⚠ **This is the job's responsibility, not the service's.**
  `RoomOverviewSummaryService::summarize()` overwrites `works_summary` on **every** row it is handed
  (`:72-84`), and its no-overview branch at `:51-57` actively sets `works_summary = ''` — so handing
  it a room that already carries an office summary would **wipe** it. The job must filter the rows it
  passes in, and merge the result back by room key.
- **D-04:** If the AI is unavailable, rate-limited or fails, **nothing breaks and the import still
  completes.** Two layers already exist: `RoomOverviewSummaryService` catches
  `AIGenerationException` and falls back to `fallbackSummary()` while setting a `_summary_fallback`
  marker (`:86-99`), and the engineer link independently degrades to machine-split prose via
  `App\Support\SurveyPdfHelpers::textToBullets()` (quick task `261008-gxt`). **A document creation
  must never fail because of this feature.**
- **D-05:** The **imported original is kept.** The AI text is an additional derived value written to
  a sibling key; the raw imported scope (`room_overviews[n].overview`) stays exactly where it is and
  stays readable to the office. Nothing is replaced and nothing is deleted.
- **D-06:** The job is modelled on `app/Jobs/GenerateSurveyQuestionsJob.php` — `implements
  ShouldQueue`, constructor takes an id only, and **`handle()` swallows every `\Throwable` after
  logging it** so the caller is never affected. **Two named deviations from that precedent, both
  justified:**
  (a) the constructor takes **`int $packageId`, not a room id**, because rooms are JSON array
  elements with no primary key — this also settles the "one job per room or per project" question in
  favour of one job per package that loops;
  (b) **`$timeout = 240`, not 60** (precedent: `ReimportQuoteJob:67`), because a 429 is retried
  blind with no backoff and the worst case is 2×180s = 360s.
  ⚠ Note the precedent's `\Throwable` catch makes `$tries` **decorative** — the queue sees success
  and never retries. That is the correct, safer posture here; **do not let a reviewer "fix" it.**
- **D-07:** Reuse `App\Services\RoomOverviewSummaryService::summarize()` and the existing prompt.
  **No new prompt class, no new service, no prompt edit.**
- **D-08:** The job writes to **`extracted_data` only.** ⚠ `project_packages` has **no
  `reviewed_data` column** — see C-01. Both review save paths already write `extracted_data`
  (`ProjectPackageReviewController:374,395,446,466`), and the full first-load round-trip carries
  `works_summary` through (`:290` → `review.blade.php:867,871-874` → `parseReviewPayload():1189`).
  No double-write, no reader change.
- **D-09:** (new, from research) The job must **only update room rows that already exist, never add
  one.** `ProjectPackageReviewController:231-239` freezes the room list in curated mode, so a row
  the job invents would desync the office view from the engineer link.
- **D-10:** (new, from research) The job dispatches **`->afterCommit()`**. Every import creator runs
  inside `DB::transaction` and `config/queue.php:44` sets `'after_commit' => false`, so a worker can
  otherwise pick the job up before the commit and read absent rows. **Do not flip the global flag** —
  it would change semantics for all ten existing jobs. Wrap the dispatch in the try/catch pattern at
  `SurveyService:234-243`.
- **D-11:** (new, from research) For a room whose imported `overview` is **empty**, **generate
  nothing.** On a memo-less QuoteWerks room every per-room source is empty and the only non-empty
  source is the package-wide `scope_narrative`, identical across every room. Feeding quote-wide
  narrative to a prompt that is told to name rooms and not invent kit invites wrong-kit-wrong-room on
  a safety-adjacent document. D-04's derived path already covers these rooms and labels its
  provenance honestly as *"Install actions (from scope notes)"* (`surveys/show.blade.php:600`).
  ⚠ Surfaced at the checkpoint as the user's call to overturn.

## Corrections — what the first draft of this CONTEXT got wrong

Recorded so the planner does not rebuild on it, and so it reads as a correction rather than an
oversight. `46.9-RESEARCH.md` carries the full table with citations.

- **C-01 — "The bag trap" does not exist.** The first draft made
  `reviewed_data['room_overviews'] ?: extracted_data['room_overviews']` (`SurveyController:353-355`)
  the single most consequential call in the phase. **`project_packages` has no `reviewed_data`
  column** — it is absent from the create migration, from `$fillable` and from `$casts`
  (`app/Models/ProjectPackage.php:16-34`), and no later migration adds it; the only `reviewed_data`
  column in the schema is on `rams_documents`. So `$package->reviewed_data` is always `null` and that
  branch is **unreachable by construction**, as are the same reads at `PublicSurveyController:60` and
  `WorksheetGeneratorService:91-96`. **Independently re-verified by the orchestrator against the
  migrations and the model.** Leave the vestigial fallback in place with a note so a future agent does
  not re-derive this; it is dead code, not a bug worth a task.
- **C-02 — the cost model was wrong, and the user was told the wrong number.**
  `RoomOverviewSummaryService:59` makes **one** `AIManager::run()` call with every room in the
  payload, outside any loop. **A 12-room quote is 1 AI call, not 12.** **Independently re-verified by
  the orchestrator.** The real risk is the opposite shape: `maxTokens() = 2000` (`:97`) can trip
  truncation at 12+ rooms (`ClaudeProvider:202-206`), and the service then falls back for **all**
  rooms at once. Prefer chunking inside the job over raising `maxTokens()`, which would touch the
  live prompt's behaviour. ⚠ **Flag to the user**: they chose D-02 partly on "12 rooms = 12 calls".
- **C-03 — "nothing runs at import or at doc creation" was wrong twice.**
  `WorksheetGeneratorService:118-188` **already performs the lazy-at-doc-creation generation** and
  persists the result back (`:180,186`). Part of what was asked for already works.
- **C-04 — the worksheet needs no carry.** `generated_data.rooms[]` is derived at build time from
  `extracted_data['room_overviews'][n]['works_summary']` (`WorksheetGeneratorService:94,108` →
  `:593` → `worksheets/show.blade.php:564`). **Zero tasks.** ⚠ But one undefended cross-surface
  invariant: `:111` and `:174` **discard any `works_summary` line not dash-prefixed**, while the
  survey has no such rule — so a non-dashed bullet renders on the survey and silently vanishes from
  the worksheet. **Assert it.**
- **C-05 — the refusal is not an inversion.** `ProjectPackageReviewController:591`'s *"Please write a
  phrased overview first"* lives in the **HTTP controller**. A job calling the service never reaches
  it. There is nothing to invert.
- **C-06 — `importFromData()` is not the common funnel.** It has **one** production caller
  (`QuoteWerksImportService:72`) and its own docblock says it is *"intended for testing and for
  SQL-based import paths"*. The PDF paths are `import():57`, `reimport():202`,
  `completePendingReimport():294` and `ExtractQuoteJob`. **Whether the two reimport paths should also
  dispatch is a scope question for the checkpoint** — the cost is about three lines.

## Scope fence

**IN:** one queued job that fills empty per-room `works_summary` from the imported overview at import
time, reusing the existing service and prompt; its dispatch wiring; tests proving both sides.

**OUT:**

- **Project-process management of any kind.** The user's own boundary, 2026-10-09: *"App is for doc
  creation and doc mgt - no for mgt of the whole project process."* This phase is document
  production and is in scope; scheduling, resourcing, costing and programme tracking are not.
- Any prompt edit, new prompt class or new service (D-07).
- Any `reviewed_data` work or migration (C-01 — adding the column would start *shadowing*
  `extracted_data` in three readers).
- Any migration at all (D-08, Q8).
- Redesigning the engineer link's layout — 46.6 and 46.8 own that. No Blade edit is expected.
- Changing the live sparkle-Generate button's behaviour.
- Any destructive change to stored scope text. Nothing is deleted.

## Constraints

- **AI output is untrusted text on a page a client may see.** Every echo stays escaped.
  `resources/views/surveys/show.blade.php` has **zero** unescaped echoes and must keep zero.
- **`resources/views/surveys/show.blade.php` is a standalone document** — no layout, no Vite
  directive, no bundler. `SurveyLinkBrandingTest` asserts **rendered** output, bans white on
  `#178A95` and `#C9922A` plus `#0B3C45`/`#0d6e77`, and pins `substr_count($html, 'sv-spine')`.
  ⚠ **There is a SECOND, undocumented `sv-spine` pin at `SurveyRoomCaptureRefinementsTest:283`.**
  Move a pin **by name with a reason**, never by deletion.
- ⚠ **`WorksheetShowViewParityTest:186-190` counts rendered `works_summary_bullets` `<li>` rows
  directly** — the highest-risk pin for this phase.
- ⚠ **`tests/Feature/ProjectAutoAdvanceTest.php:56,96` calls `importFromData()` directly**, and
  `phpunit.xml:40` sets `QUEUE_CONNECTION=sync`, so the new job will run **inline and make real
  network calls** unless faked. **This is the most likely surprise breakage in the phase.**
- ⚠ **The 30-day `AICacheService` will serve a stored response past any fake provider** and produce a
  fake green. Stub it — the seam is `RoomOverviewSummaryFallbackTest:35,44-52`. Note
  `GenerateSurveyQuestionsJobTest`'s `Mockery::mock(AIManager::class)` trick **will not work here**,
  because the service calls `AIManager::run()` **statically**.
- **There is no "AI disabled" config flag** (whole `config/ai.php` read). A 429 is **not**
  distinguishable from a hard error — the status is interpolated into a `RuntimeException` message
  string (`ClaudeProvider:181`), with no `Retry-After` and no backoff.
- **NEVER write a bare Blade directive name as prose in a comment.** On 2026-10-10 a comment
  containing a bare PHP-block directive paired with the next real closing directive 70 lines away and
  **silently deleted a whole card, two includes and most of another**, with no error. That trap has
  fired **five times in a fortnight**, every time on an agent warned about it in the same prompt.
  After editing a Blade file, grep its comments for stray directive tokens **and render the page**.
- Do not touch the `engineer-capture` IndexedDB store — schema-frozen at v1, holding real unsent
  photos on engineers' phones.
- Do not touch `app/Services/RiskTemplateResolverService.php` — it carried a live safety defect fixed
  and deployed 2026-10-10.
- Never render `device_label_photos.captured_by`, `worksheet_signoffs.ip_address`,
  `worksheet_signoffs.user_agent`, or `pre_install_confirmations.room_complete.{room}.completed_by`.
- **LR-04:** a client is never given an engineer's phone or email.
- Preserve `SiteSurvey::$fillable` and `Worksheet::$fillable` omissions. Never mint, rotate,
  mass-assign or render an `access_token`.
- Three files must stay **byte-identical to `4abd2b24`**: `resources/views/layouts/app.blade.php`,
  `resources/css/app.css`, `tailwind.config.js`. Use the gate's `-Hashes`. **A mismatch is a STOP,
  never a hash to refresh.**
- **The gate's real parameters are `-Filter`, `-Path`, `-Baseline`, `-Hashes`. There is no `-File`
  parameter for naming a test** — `-File` is PowerShell's own switch for the `.ps1`. Run it in the
  **foreground**, redirected to a file, never piped, one suite per invocation. PHP is not on the Bash
  PATH, so piping PHP output to `tail` exits 0 while running nothing, and a killed stall also
  reports 0.
- **The D-06 behaviour baseline gate is `>= 159 passed AND 0 failed`** — never equality against 161.
- **NEVER** `php artisan migrate:fresh --env=testing` — there is no `.env.testing`; it falls back to
  `.env`, where `DB_DATABASE` is commented out, and would **drop every table** in
  `database/database.sqlite`, which holds real local dev data.
- **NEVER** `gsd-sdk query state.advance-plan`, `state.update-progress`, or
  `state.add-roadmap-evolution` — all three corrupt `.planning/STATE.md`.
- **NEVER** `git stash`. `git clean` is prohibited.

## Non-vacuity

The house rule, and it has been earned: **render every state you claim, prove the test RED before
the fix, and count what you measure.** A live stoppage shipped on 2026-09-30 because a test asserted
the safe half of a condition. Assert **both** sides:

- a room with an **empty** `works_summary` and a **non-empty** `overview` gets AI bullets;
- a room with an **office-authored** `works_summary` is left **byte-identical** (D-03) — and
  specifically is **not wiped** by the service's empty-overview branch;
- a room with an **empty overview** gets **nothing**, and still renders derived bullets (D-11);
- with the AI **unavailable**, the import still completes and the engineer link still shows bullets
  (D-04);
- the bullets are **visible on the rendered engineer link**, not merely present in the database.

`SurveyPlannedActionsBulletsTest` is the single best seam — its `surveyWithPackage()` helper
(`:26-71`) already builds a package with `extracted_data.room_overviews`, renders the real engineer
link, and already asserts office-bullets-byte-for-byte (`:94-124`). It covers three of the four
non-vacuity bullets including the rendered-page one. **Extend it; do not duplicate it.**

Figures to **re-measure, never inherit** (inherited from the 2026-10-10 measurement at HEAD
`7362e4b1` and not re-run by research): `tests/Feature/Surveys` 83 passed / 682 assertions,
`tests/Feature/Cockpit` 462, `tests/Feature/Worksheets` 265, D-06 baseline 159 passed / 0 failed /
