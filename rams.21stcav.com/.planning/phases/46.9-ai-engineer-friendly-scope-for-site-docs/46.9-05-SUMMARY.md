**Why** — verified in the installed framework, not reasoned from memory:
`Illuminate\Bus\Dispatcher::dispatchSync()` (`:93-102`) does **not** call `dispatchNow()` for a
`ShouldQueue` job. It runs `return $this->dispatchToQueue($command->onConnection('sync'))`. That goes
through the queue manager, and `QueueFake::push()` (`:478-486`) **records** it instead of letting
`SyncQueue` run it. So under `Queue::fake()` the job never executes **and** `assertNothingPushed()`
fails.

Two assertions replaced it, and together they are **stronger** than the one asked for:

- `test_no_job_is_ever_deferred_onto_a_queue_connection` — installs a **real** recording queue
  driver as `queue.default` (Wave 2's `RoomWorksProbeQueue`, kept) and asserts **zero** pushes
  reached it **and** that the bullets were generated anyway. A reversion to `::dispatch()` would hit
  that driver and fail the first half; a deletion of the call outright would fail the second.
- `test_queue_fake_sees_an_explicitly_sync_dispatch_and_nothing_deferred` — under `Queue::fake()`,
  exactly one dispatch, pinned to `$job->connection === 'sync'`. A queued `::dispatch()` leaves
  `connection` as `null`, so this goes RED too.

## The probe, rehomed — what Wave 2 contributed and what changed

Wave 2's non-vacuous idea was a probe that records live DB state **at the moment the work is
handed off**. That idea is kept. What moved is the hook:

| | Wave 2 | Now |
|---|---|---|
| Hook | `RoomWorksProbeQueue::push()` (custom queue driver) | `RoomWorksAiProbeProvider::execute()` (bound `AIProviderContract` double) |
| Records | `DB::transactionLevel()`, `ProjectPackage::find()` non-null | `DB::transactionLevel()`, latest readable `project_packages` id |
| Why there | the real queue push was the handoff | there is no handoff — the AI call **is** the work |

`RoomWorksProbeQueue` was **not deleted**. It changed role: it used to prove *exactly one push
happened*; it now proves *nothing is deferred*.

## The failure test fails at the real AI call — and is guarded against being worthless

`test_a_generation_failure_does_not_fail_the_import` binds a provider double that throws a
`RuntimeException` from inside `execute()` — which is what `ClaudeProvider:181` actually throws on an
HTTP failure or a rate limit, and what `AIManager`'s retry loop catches before converting to
`AIGenerationException`. **Nothing in the dispatch plumbing is failed.** The first assertion is that
the probe recorded a call, so a failure injected anywhere else makes the test fail rather than pass.

It then asserts the full chain the user depends on: the import still returns its `ProjectPackage`,
the row exists, `works_summary` is **not** a persisted empty string (only the `_summary_fallback`
marker is written), and the imported prose survives for the derived-bullet fallback.

## Not asserted, stated plainly rather than faked — the 180s bound

Plan item 3.6 asked, with permission to skip. **Skipped, honestly.**
`AIProviderContract::execute(BasePrompt $prompt)` takes **no `$options` argument**, and the timeout
is applied inside `ClaudeProvider::dispatch()` (`:177`) from `self::DEFAULT_TIMEOUT` (`:20`). There
is **no seam** at which a bound double can observe the timeout without editing the provider, which
this plan forbids. A `DEFAULT_TIMEOUT === 180` constant-equality assertion was considered and
rejected: it would prove nothing about the invocation and would read as a ticked box. The bound is
real, is 180s per attempt with `AIManager::MAX_ATTEMPTS = 2` and no provider-level retry, and is
documented at both call sites and on the job's `$timeout` property. **The timeout was not changed.**

## Deviations from Plan

**Three, all named, none a scope reduction.**

1. **`Queue::fake()` + `assertNothingPushed()` was not shippable** — it fails on a correct
   implementation, for the framework reason quoted above. Written as asked, run, shown failing, and
   replaced by two assertions that are strictly stronger (a real recording driver proving zero
   deferred pushes, plus a `connection === 'sync'` pin under `Queue::fake()`). Both go RED on a
   reversion to a queued `::dispatch()`, which is what the plan wanted the guard for.
2. **The 180s-bound assertion (item 3.6) was skipped**, using the permission the plan granted, for
   the reason given in full above: `execute(BasePrompt)` has no `$options` parameter, so there is no
   observable seam. Nothing was faked to tick the box.
3. **Tasks 1 and 2 share one commit** (`fe6e00bb`). Both are the same mechanical change in the same
   file, and splitting them would have required interactive hunk staging (unavailable) or an
   intermediate commit in which the test file asserted a queue push that the code no longer made.
   Task 3 and Task 4 are their own commits.

Everything else was executed as written. The job class was **not** deleted, `ShouldQueue` was
**not** stripped, its logic was **not** reimplemented inline, the placement did **not** move, the
provider timeout was **not** touched, `config/queue.php` was **not** touched, no migration was
needed, and **nothing was deleted** — including the two Wave 2 tests, which were reworked.
