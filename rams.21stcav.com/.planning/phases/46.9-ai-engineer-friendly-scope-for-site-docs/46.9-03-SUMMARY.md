## Where source contradicted CONTEXT.md / RESEARCH.md / the plan

1. **C-04's wording is wrong, and the correction is now pinned by a discriminating test.** CONTEXT
   C-04, this plan's `<context>` and the plan's threat register all say
   `WorksheetGeneratorService:111,174` *"discard any `works_summary` **line** not dash-prefixed"*.
   They do not. Those lines gate the whole **BLOCK**
   (`str_starts_with($bull, '- ') || str_contains($bull, "\n- ")`); once a block passes, `:573-579`
   keeps **every** non-empty line and merely strips a leading `-`/`•`. The real failure mode is
   coarser and worse than described: **a block with no dashed line anywhere is dropped IN FULL.**
   `test_a_mixed_block_with_one_dashed_line_is_admitted_in_full` is the discriminating case — it
   passes under the block reading and **fails** under the per-line reading. Wave 1's normalise-every-line
   implementation satisfies both readings, so no code changed; the citation is corrected in
   `REQUIREMENTS.md` so it is not inherited a fourth time.

2. **`SurveyController` does NOT strip the leading dash, and the plan implies it does not matter.**
   `:487-491` trims, splits on newlines and drops empties — nothing else. So the rendered
   `planned_actions` for a job-generated room are `['- Mount the …', '- Terminate the …']`, dashes
   **included**, while the worksheet strips them. Asserted as the actual behaviour in state 1 and in
   `test_the_same_non_dashed_block_still_renders_on_the_survey_engineer_link`. This is a cosmetic
   divergence between the two surfaces, not a defect, and it is pinned rather than fixed.

3. **AIB-04's minted wording said the dispatch is `->afterCommit()`. It is not, deliberately.**
   Wave 2 held D-10's intent **by construction** instead (dispatch placed after `DB::transaction()`
   returns, inside a try/catch), because `afterCommit()` only registers a callback whose real push
   runs in an untried `foreach` inside `DatabaseTransactionRecord::executeCallbacks()`, reached from
   a line that sits **outside** `ManagesTransactions`' own try/catch — a queue failure would escape
   **after** the row committed. Verified this session: `grep -rn -- '->afterCommit' app/` returns
   **0**. The `REQUIREMENTS.md` row now carries the correction so nobody "fixes" it back.

4. **CONTEXT.md's Worksheets baseline (265) is stale** — the real figure is **269**, measured three
   times now (pre-phase, Wave 1, and this plan).

5. **⚠ UNRELATED PRE-EXISTING HTTP 500, found while writing Task 2, deliberately NOT fixed.**
