# 46.9-05 — Checkpoint answers: run inline, and cover re-import

## Why this plan exists

The 46.9-04 blocking checkpoint was **put to the user and answered on 2026-10-10**. Two of the
three answers change what was already built. This plan implements the answers; it is not a
re-opening of any decision.

**The answers, verbatim choices:**

1. **"Move it inline at import"** — overturns **D-02**. They were told, at the point of choosing,
   that the cost figure behind their original choice was wrong (one AI call per package, not one per
   room) and that the trade is *"the import screen then blocks on the AI, and a slow or hanging
   provider is felt by whoever clicked import."* They chose inline anyway. **Implement it.**
2. **"Generate nothing (built this way)"** — **confirms D-11.** No code change. AIB-03 becomes
   settled.
3. **"Wire it too"** — `completePendingReimport()` must also generate. About three lines.

## The exposure the user accepted, measured

`app/Core/AI/Providers/ClaudeProvider.php:20` sets `DEFAULT_TIMEOUT = 180` and `:177` applies it via
`->timeout($options['timeout'] ?? self::DEFAULT_TIMEOUT)`. There is **no retry** — `dispatch()` makes
a single `Http::post`. So an inline call is **bounded at 180 seconds**, not unbounded, and on
timeout the existing `AIGenerationException` path puts us on the prose fallback with the import
still succeeding.

⚠ **Do not change that timeout in this plan.** The provider accepts an `$options['timeout']`
override, so tightening it later is a one-line change, but it would make large quotes fail where
they currently succeed. That is a separate decision and it has not been made. **Report the 180s, do
not pre-empt it.**

## Decisions for this plan

- **D-12:** The inline call is `GenerateRoomWorksSummariesJob::dispatchSync($package->id)`. **Keep
  the job class.** It already owns the D-03 filter, the fresh-read re-check before writing, the
  dash normalisation, and a whole-body `\Throwable` envelope that cannot fail its caller. Rewriting
  that logic as a service call would duplicate four guarantees for no benefit. `dispatchSync()` runs
  `handle()` in-process through the bus, so every one of them still applies.
- **D-13:** `$timeout` and `$tries` on the job become **inert** under `dispatchSync()` — they are
  queue-worker concepts. Document that on the properties rather than deleting them: the class must
  stay dispatchable to a queue so a future reversal costs one word. **The real bound is the
  provider's 180s HTTP timeout, and that is what the docblock must say.**
- **D-14:** The call stays **after `DB::transaction()` returns, inside the try/catch**. The reason is
  now simpler than Wave 2's — an inline call inside the transaction would hold the transaction open
  across an HTTP request of up to 180 seconds, which is far worse than the half-reported-import
  problem it was originally placed there to avoid. **Both reasons point the same way. Keep the
  placement and keep the try/catch.**
- **D-15:** `completePendingReimport()` gets the identical call, same placement, same try/catch.
  AIB-01's coverage claim widens to both paths.

What must be true after this task:

   outputs.
4. **A generation failure does not fail the import.** Bind a provider that throws; assert

5. **Re-import generates too** (D-15) — the same positive assertion through

6. **The inline call is bounded** — assert the provider is invoked with the 180s default rather than

Keep the `AICacheService` stub in `setUp()` and the provider-bind seam. `Mockery::mock(AIManager::class)`
