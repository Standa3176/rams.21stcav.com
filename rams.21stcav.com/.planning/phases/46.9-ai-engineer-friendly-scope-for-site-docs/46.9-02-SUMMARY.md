## The seam used, and why

`Queue::fake()` cannot observe push-time state (`QueueFake::push()` only records), so tests 2 and 3
register a real queue driver via `Queue::extend()`:
`RoomWorksProbeQueue extends Illuminate\Queue\NullQueue` with `push()` overridden to record
`job_class`, `packageId`, `DB::transactionLevel()` and whether `ProjectPackage::find()` is non-null
**at push time**, then optionally throw. It never executes the job, so tests 1–3 make no AI call.

## Why there is no `afterCommit()` — implemented as the plan's `<framework_facts>` directs

The production comment (`QuoteImportService.php:393-440`) records the chain: `afterCommit()` only
registers a callback, the real push happens in `DatabaseTransactionRecord::executeCallbacks()`
(`:83-88`), a bare untried `foreach`, reached from `ManagesTransactions`'
`$this->transactionsManager?->commit(...)` (`:66-70`) which sits **outside** that method's own
try/catch (`:51-64`). A queue failure would therefore escape `importFromData()` **after** the
`project_packages` row had committed, and the try/catch would be wrapping only the registration.

**`->afterCommit` appears zero times in the diff** (verified: `git diff HEAD~2 HEAD | grep -c -- "->afterCommit"` → `0`).
The four prose mentions in the production comment and the one in the test docblock are written
`afterCommit()` without the arrow deliberately, so the "no `->afterCommit()` in the diff" criterion
is literally true and no future grep trips on prose. D-10's intent is held **by construction**: the
transaction has already committed by the time the dispatch line is reached.

`config/queue.php` is **not in the diff** — the global `after_commit` flag was not flipped.

## Deviations from Plan

**One, additive, no scope reduction.**

The plan said: if `ProjectAutoAdvanceTest` passes, *"add ONE test"* asserting the reason. I added
**two**. The second (`test_the_same_inline_sync_path_does_reach_the_ai_when_a_room_carries_prose`)
exists because the first on its own is the safe half of a condition: a provider bound
`expects($this->never())` passes both when the early return works *and* when the dispatch never
happened at all. The control proves the inline sync execution is real, which is the only thing that
makes the `never()` meaningful. Adding it is the plan's own non-vacuity rule applied to the plan's
own guard.

Everything else was executed as written. No `->afterCommit()`. No `config/queue.php`. No migration.
No scope reduction, no "v1", nothing "wired later" that the plan asked for now.
