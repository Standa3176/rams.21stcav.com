# Phase 46.1 Plan 05: The Acts, Moved Beneath the Evidence Summary

**One-liner:** Accept, Send back, Add note and Raise a snag now render only at the foot of the
Returned tab, under the photos, room answers, serials and client signature — so pressing Accept
means having scrolled past what came back from site.

## What was built

### The move (D-02, RV-05/06/07)

`visit-row.blade.php` gained one prop, `'controls' => false`, and the entire `.cav-visit__actions`
block — all four acts and all three disclosed forms — is now wrapped in
`@if ($controls && ($canAccept || $canSendBack || $canNote || $canSnag))`.

**The default is FALSE.** A component that offers a write by default is one bad include away from
offering it somewhere nobody looked. `returned-tab.blade.php` is the **only** caller that passes
`:controls="true"`, and it renders the row as the **last block in the card**, after the hand-off,
the room answers, the contact sheet, the serials and the sign-off.

**The eight derived booleans were not touched.** `$isReviewable = ! $isReconstructed &&
! $visit->isClosed()`, `$canAccept`, `$canSendBack`, `$hasContext`, `$canNote`, `$canSnag`,
`$formOpen` and `$snagCount` are byte-identical. `controls` is an AND on top of them, so D-06,
VL-11 and the reconstructed exclusion were never back in play.

`panel.blade.php`'s Overview branch passes **neither** `controls` **nor** `action` /
`action-visit-id`: with no controls there is no form to disclose, and a disclosure prop that can
never disclose is dead wiring. Those two props were re-routed to `returned-tab`, which passes them
straight through.

The three disclosure links (`send-back`, `note`, `snag`) now carry `tab=returned`, so disclosing a
form from the Returned tab does not throw the PM back to Overview. `?action=` membership in
`ProjectCockpitController::ACTIONS` is untouched and `?visit=` is still an int that is compared,
never looked up.

### Overview kept every sentence and lost only the offers

Asserted explicitly by `test_overview_offers_no_control_and_still_says_where_the_visit_stands()`,
on `?tab=overview`, four fixtures, each with `countControls() === 0`:

| Visit | Sentence still on Overview |
|---|---|
| returned | `Scope locked — returned {d M Y}` |
| accepted | `Accepted by {name} on {d M Y}` |
| sent back | `Sent back {d M Y} — awaiting the engineer` |
| sent | `Awaiting the engineer` |

The reconstructed and superseded treatments, the chips and the snag count are all untouched — none
of them lives in the action area. **The offers moved; the record of what happened did not.**

### Per-state control counts, judged where the controls now live

`test_no_visit_state_loses_a_control_it_could_previously_reach()` — 7 factory states × 6 visit
types × 9 drawers, with the expected numbers **copied from the named tests**, not recomputed from
the Blade:

| Factory state | Controls | Derived from |
|---|---|---|
| planned | **0** | `test_a_planned_visit_offers_nothing()` |
| sent | **0** | `test_a_sent_visit_offers_nothing_and_says_it_is_with_the_engineer()` |
| returned | **4** | `test_a_returned_visit_offers_exactly_the_four_pm_acts()` |
| sentBack | **3** | `test_a_sent_back_visit_offers_accept_but_no_second_send_back()` |
| accepted | **1** | `test_an_accepted_visit_offers_only_add_note()` |
| backfilledFromWorksheet (reconstructed) | **0** | `test_a_reconstructed_visit_offers_no_control_even_though_its_state_reads_returned()` |
| default | **0** | a completed visit nobody reviewed is closed |

**The plan's prose and the tests disagreed once, and the tests won.** The plan wrote `sentBack`
as "1 (Accept only — there is no second send-back; Add note and Raise a snag also apply, so 3)".
The named test asserts **3**, and 3 is what the table asserts. Recorded here as the plan asked.

The test also asserts **at least one rendered row per state per type** — a count of zero would
otherwise pass for a visit that had vanished rather than moved.

### The relocation is safe because nothing can be stranded

`test_a_sourceless_visit_could_never_have_offered_a_control()` proves the presence rule (Returned
tab only where a visit has a `source_type`) cannot orphan a control, in three parts:

1. a sourceless visit renders zero controls in every factory state;
2. it cannot **reach** a control-offering state — each of `$canAccept`, `$canSendBack`, `$canNote`
   and `$canSnag` requires `state()` to be RETURNED, SENT_BACK or ACCEPTED, and `returnedAt()`
   reads the **source**;
3. **and the app cannot manufacture the stranded shape**: `POST accept` and `POST send-back` on a
   sourceless sent visit are both **422**, and neither `accepted_at` nor `sent_back_at` is written.

Part 3 is the load-bearing one and is a deliberate strengthening of the plan's wording — see
Deviation 2.

### VL-11 and the fence

The cap loop kept **every** dimension: 7 states × 6 types × 9 drawers × **4 URL states**, ceiling
**4**, `assertStringNotContainsString('disabled', $row)` inside the loop, and the vacuity floor
asserted **unchanged at `> 20`**. Only the helper's default tab moved, so a relocation that had
halved the loop's reach would read red there.

`git diff` on `tests/Feature/Cockpit/CockpitReadOnlyFenceTest.php` is **empty**. `DEFERRED_AFFORDANCES`
stays at 18, `<select` and `<script` stay banned, all nine handler attributes stay, both
`cockpitRegion()` brackets stay, `WRITE_SURFACE_TABLES` stays at 11. No entry was lifted and none
was added — this plan ships no new affordance, only a new location for four that already existed.

## Deviations from Plan

**1. [Rule 3 - Blocking] `CockpitOfficeNoteAndSnagTest` was repointed too**

- **Found during:** Task 2, reading every caller of a `.cav-visit` row before moving the helper.
- **Issue:** that file carries its **own copy** of `visitRows()` and `countControls()` and ten row
  assertions built on them (`..._offers_exactly_the_four_controls_and_no_fifth`,
  `..._offers_add_note_and_nothing_else`, `..._still_offers_nothing_at_all`,
  `..._no_disclosed_form_ever_takes_a_row_past_four_controls`,
  `..._only_one_form_can_be_open...`, `..._a_form_opens_only_on_the_visit_the_url_names`,
  `..._the_row_copy_is_this_phases_wording...`, `..._a_plain_snag_count_that_links_nowhere`). It is
  not in the plan's `files_modified`, and left alone every one of them would have judged a page
  that no longer offers controls.
- **Fix:** the **same** single change — the helper's default query gains `+ ['tab' => 'returned']`,
  with the relocation recorded in its docblock. **Every assertion in that file is byte-identical.**
  No POST assertion was touched.
- **Commit:** `874abd49`

**2. [Rule 2 - Missing critical] The sourceless proof would have been a tautology as written**

- **Found during:** Task 2, writing `test_a_sourceless_visit_could_never_have_offered_a_control()`.
- **Issue:** the plan specifies "a visit forced to `source_type = null` renders 0 controls **on
  Overview**". After this plan, Overview renders zero controls for **every** visit, so that
  assertion passes no matter what the gates say. It would have looked like proof and been none.
- **Fix:** the plan's assertion is kept (it still pins Overview), and two stronger parts were added
  — the derived-state check, and the two 422s that prove production cannot write `accepted_at` or
  `sent_back_at` onto a sourceless visit.
- **Commit:** `874abd49`

**3. [Rule 1 - Bug, in a comment] 46.1-04's claim about the controls was wrong**

- **Found during:** Task 2, checking the RV-08 one-anchor budget against what this plan ships.
- **Issue:** `CockpitReturnedTabTest::test_the_returned_tab_renders_exactly_one_non_photo_anchor()`
  carried the note "The four review controls Plan 46.1-05 adds are BUTTONS inside a form, not
  anchors, so they do not spend this budget." **Three of the four are anchors** — `Send back`,
  `Add note` and `Raise a snag` are disclosure links, because there is no JavaScript on this page
  and a control that only changes the URL has to be a link. Only `Accept` is a button.
- **Why the test is still green and was NOT weakened:** its fixture, `worksheetVisit()`, builds a
  **reconstructed** visit, which offers zero controls (D-06). The budget of exactly one non-photo
  anchor therefore still holds, for a reason the comment got wrong.
- **Fix:** the comment was corrected in place, naming the real reason. **No assertion changed.** A
  reviewable returned visit on this tab renders three anchors and one button, and that is the
  deliberate cost of D-02.
- **Commit:** `874abd49`

**4. [Rule 3 - Blocking] Task 1's commit is not green in isolation**

- **Issue:** shipping the Blade move without the test repoint leaves `CockpitVisitActionsTest` and
  `CockpitOfficeNoteAndSnagTest` red, and repointing first would assert a move that had not
  happened. Task 1's own gate (`-Filter CockpitReturnedTabTest`) **was** green on `a43ce09e`.
- **Fix:** two commits in order, `a43ce09e` then `874abd49`; the tree is green at `874abd49`. Same
  shape as 46.1-04's Deviation 1, and recorded rather than hidden.

### Noted, not fixed (out of scope)

`Cancel` inside a disclosed form still points at `$moduleUrl`, which carries no `tab`, so
cancelling from the Returned tab lands on Overview. The plan names exactly three `route()` calls to
carry `tab=returned` and `$moduleUrl` is not one of them; the four POST routes redirect to the same
tabless module URL and the plan states they are untouched. Cosmetic, no correctness or security
impact — logged here rather than changed.
