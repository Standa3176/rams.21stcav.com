# Phase 46.1 Plan 04: The Hand-off, and the Fence Entry It Pays For Summary

**One-liner:** One `Download all photos (ZIP)` anchor per sourced visit with photos, shipped in the
same commit as the single fence entry it retires — and the fence re-proved capable of failing three
ways, which caught a real hole in the Alpine ban.

## What was built

### The link (RV-04, D-03)

The named slot Plan 46.1-03 left in `returned-tab.blade.php` now holds one anchor per sourced visit:
`Download all photos (ZIP)`, `target="_blank"`, `rel="noopener"`, pointing at
`projects.cockpit.visits.photos-zip`, behind `Route::has()` — the rule `CockpitPanelPresenter`
already follows for every document route, so a rename degrades to no link rather than to a
`RouteNotFoundException` that would blank the page for a PM who only wanted to read it. Beneath it,
one quiet sentence: *Grouped by room, into before / after / label folders.*

**It is NOT rendered for a visit with zero photos.** Offering an archive that would contain only a
README is a worse answer than the sentence "Nothing has come back from site yet." The gate is
`photo_count`, not the empty-state branch — asserted by a visit that returned a client sign-off and
no photo, which still renders its evidence and still carries no link.

**It sits OUTSIDE `.cav-visit`, and that is asserted structurally.**
`CockpitVisitActionsTest::countControls()` counts `<button` and `<a ` INSIDE a visit row and VL-11
caps that at four. A hand-off is not a review control — it is none of D-02's four acts — so putting
it in the row would spend a quarter of that cap on something that does not belong to it.
`test_the_handoff_sits_outside_any_visit_row()` walks the anchor's ancestors and fails if any of
them carries a `cav-visit` class, so a later tidy-up cannot move it in past a comment.

No new colour, no new control style (it reuses `.cav-visit__control--quiet`), no `position` on the
anchor, and the only CSS added is two spacing rules using existing `--cav-*` tokens.

### The second `Download` ban was NARROWED, not deleted

`CockpitPanelTest::test_the_link_copy_is_view_and_never_download()` →
`test_the_files_tab_link_copy_is_view_and_never_download()`. **The two assertions are
byte-identical** and still scoped to `$this->panel($project, 'rams', 'files')`; only the name and
the docblock moved. The ruling still holds on the Files tab — a document row opens a review screen,
it does not stream a file, and copy promising a download would be a lie about what the link does.
Deleting it would have silently stopped covering the tab where the rule still applies.

Four other cockpit tests also ban the word in narrower scopes (`CockpitPageTest:755` and `:802`,
`CockpitPanelTest:359`, `CockpitCreateVisitTest:619`, `CockpitOfficeNoteAndSnagTest:816`). **None
needed changing** — they are scoped to the bare page, to visit rows, to the Quick actions block, or
to `THREE_TABS`, none of which renders the hand-off. All five are green.

## Deviations from Plan

**1. [Rule 3 - Blocking] Tasks 1 and 2 are ONE commit, not two**

- **Found during:** Task 1's gate run.
- **Issue:** a Task-1-only commit cannot be green. Shipping the link turns the fence's `Download`
  ban red and raises the Returned tab's anchor count above the budget 46.1-03 set. Committing the
  fence lift first would be worse: a fence weakened in a commit that ships nothing.
- **Fix:** both tasks landed in `7599f88e`. This is what the plan's own objective asks for — "Ship
  the hand-off link and pay for it at the fence, in one commit" — and what T-46.1-17 requires ("the
  count assertion moves in the same commit").

**2. [Rule 2 - Missing critical] The fence fixture could not see the affordance**

- **Found during:** Task 2, running the fence immediately after the link shipped.
- **Issue:** the fence was **green with the link already rendering**. `populatedProject()` creates
  visits but no photos, so `photo_count` was 0 everywhere and the hand-off never rendered in any
  judged region. The `Download` lift would have been free, the entry could have stayed, and
  breakage 3's "nothing red about Download" would have been trivially true instead of meaningful.
- **Fix:** one `WorksheetPhoto` added to the fence's signed worksheet, with the reasoning recorded
  at the fixture, plus `test_the_returned_tab_is_among_the_regions_this_fence_judges()` which fails
  if no judged region carries the hand-off link.
- **Files modified:** `tests/Feature/Cockpit/CockpitReadOnlyFenceTest.php`
- **Commit:** `7599f88e`

**3. [Rule 1 - Bug] The Alpine/handler ban had stopped covering the fourth tab**

- **Found during:** Task 3, breakage 3.
- **Issue:** described in full above — one red where two were expected.
- **Fix:** `test_rows_are_static_and_nothing_is_wired_to_a_handler()` now walks `everyRegion()`.
- **Files modified:** `tests/Feature/Cockpit/CockpitReadOnlyFenceTest.php`
- **Commit:** `55dbd1fe`
