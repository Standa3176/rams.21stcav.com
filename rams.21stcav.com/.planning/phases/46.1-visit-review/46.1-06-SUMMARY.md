# Phase 46.1 Plan 06: The Walk, the Gates and the Calm Checkpoint Summary

**One-liner:** One HTTP-level walk drives a job from "the PM creates the install visit" to "the PM
accepts it" — and it found two things no unit fixture could: every act bounced the PM off the
Returned tab, and every equipment-label photo was silently missing from the hand-off ZIP on live.

## The coordinator's folded-in fix: an act returns to the tab it came from

Plan 46.1-05 moved D-02's four acts beneath the evidence and logged, correctly out of its own
scope, that `Cancel` went back to Overview. It was worse than that: **all five cockpit writes**
redirected to the module's TABLESS URL, which `ProjectCockpitController::resolveTab()` resolves to
`TABS[0]` — Overview. A PM who read the photos, the serials and the client's signature and pressed
**Accept** was thrown off the very surface this phase exists to create.

- `ProjectCockpitActionController::withTab()` appends a tab to the redirect parameters, resolved by
  **membership against `ProjectCockpitController::TABS`** — the same constant the read controller's
  own `resolveTab()` uses, not a second copy of the list. It **appends** rather than prepends so the
  URL keeps the `?module=…&tab=…` order every other cockpit URL uses.
- The tab travels in a hidden field (`<x-cockpit.tab-field>`), because there is no JavaScript on
  this page and a form is the only carrier available. The component **re-checks the same constant**,
  so a value that is not a real tab is never rendered into the page at all.
- `Cancel` now carries the tab it was opened on (`$moduleUrl`), so changing your mind leaves you
  where you were reading.
- `storeNote`'s hard-coded `tab=notes` is now a FALLBACK: a submitted tab wins.

**Proved by `CockpitTabPreservationTest` — `Tests: 5 passed (54 assertions)`:**

| Test | What it settles |
|---|---|
| `test_the_returned_tab_carries_its_own_tab_into_every_control` | the hidden field is on the closed Accept form and on each of the three disclosed forms, and every `Cancel` href is the Returned tab |
| `test_every_act_initiated_from_the_returned_tab_returns_to_it` | accept · send back · note · snag, each from `?tab=returned`, each redirecting to `?tab=returned`. Each act runs against its OWN visit, because accept closes the visit and send back moves it out of RETURNED — sharing one row would have tested the refusal path |
| `test_an_act_with_no_tab_redirects_exactly_as_it_did_before` | the fallback is not "some tab": it is the exact tabless URL, `storeNote`'s `tab=notes` included |
| `test_a_hostile_tab_value_is_never_reflected` | `"><script>alert(1)</script>` — the act still succeeds, the `Location` header carries no `script`, no `alert(1)` and no `tab=` at all, and the page it lands on carries none of it either |
| `test_every_real_tab_is_carried_and_only_a_real_tab_is` | iterates `TABS` rather than naming four strings, so a fifth tab is covered the day it is added; then six non-tabs (`RETURNED`, `overview/../files`, `''`, `0`, `notes%00`, `returned"`) each fall back |

`'returned '` is deliberately NOT in the hostile list: `TrimStrings` trims it to a real tab before
the controller sees it, so rejecting it would be asserting against the framework rather than
against this rule. Recorded in the test at the point the assertion would have gone.

**On the hostile `original_name`.** `../../../../etc/passwd` cannot arrive through the upload at
all — Symfony's `UploadedFile::getClientOriginalName()` returns the basename, which is the first of
two defences. Asserting only that would have been vacuous, so the walk **plants the hostile value
on the row** after the upload, exactly as an older row on live might carry it, and the ZIP
sanitiser is what has to bite.

## Deviations from Plan

**1. [Rule 1 - Bug] Every equipment-label photo was missing from the hand-off, on live**

- **Found during:** Task 1, step 4 — the walk opened the produced archive and `Board Room/label/`
  was not in it.
- **Issue:** `DeviceLabelPhotoService::capture()` writes `device_label_photos.photo_path` to the
  **public** disk; worksheet and survey photos go to **local**. In Laravel 11+ those roots are
  `storage/app/public` and `storage/app/private` — **siblings, not nested**. `VisitPhotoZipBuilder`
  and `ProjectCockpitEvidenceController` both resolved every path against `local`, so on live every
  label photo was silently **skipped** from the ZIP (the README counted it as skipped) and **404ed**
  on the inline photo route, while the Returned tab still drew a thumbnail pointing at it.
- **Why no test caught it:** every fixture in the phase planted the label file on the faked `local`
  disk. Only a walk that uploaded one through the real public endpoint could see it — which is the
  entire reason this plan exists.
- **Fix:** `VisitEvidence::DISK_FOR_KIND` records the mapping at the definition site and every photo
  entry now carries its own `disk`. `resolveWithinDisk()` takes the disk as a parameter,
  **membership-checked against `ALLOWED_DISKS`** (a disk this app has not declared has a root nobody
  checked), and containment is still measured against exactly one root — the named disk's.
  `CockpitEvidenceDownloadTest` now fakes `public` and plants the label file there, because the
  shape it was testing is one production never produces.
- **Files modified:** `app/Support/Cockpit/VisitEvidence.php`,
  `app/Support/Cockpit/VisitPhotoZipBuilder.php`,
  `app/Http/Controllers/ProjectCockpitEvidenceController.php`,
  `tests/Feature/Cockpit/CockpitEvidenceDownloadTest.php`
- **Commits:** `86144064` (the fix) and `9673a717` (the two invariants it tripped).

**2. [Rule 1 - Bug] Two Unit/Cockpit invariants caught the fix**

- **Found during:** Task 2's `-Path tests/Unit/Cockpit` gate.
- **Issue:** (a) `CockpitEvidencePresenterTest` asserts the photo-entry key list EXACTLY, and it
  gained `disk`; (b) the same file greps `VisitEvidence.php` for the disk facade (T-46.1-05: the
  class reads rows, never files) and the new docblock **quoted** it in prose.
- **Fix:** the key contract was widened deliberately, with the reason recorded in the test rather
  than silently; the docblock was reworded so the class NAMES a disk and opens none. The invariant
  was not relaxed.
- **Commit:** `9673a717`
