  <name>Task 1: VisitEvidence — the project-scoped resolver</name>
  <files>app/Support/Cockpit/VisitEvidence.php</files>
  <behavior>
    - `VisitEvidence::for(Project $project, Visit $visit): ?self` returns **null** when
      `$visit->project_id !== $project->id`. The project is the route-bound one; the visit is never
      trusted to name its own scope.
    - Returns null when `$visit->source_type` is null — a visit with no engineer record behind it
      has nothing to return. Returns a non-null instance with EMPTY collections when the source
      exists but holds nothing yet (an issued link the engineer has not touched); and returns a
      non-null instance whose `sourceMissing()` is true when `source_id` is set but `source()`
      resolves null (force-deleted record — the visit still happened).
    - `photos(): Collection` — one entry per photo, each an array with exactly the keys
      `kind` ('survey'|'worksheet'|'label'), `id` (int), `room` (string, '' when unknown),
      `bucket` ('before'|'after'|'label'), `caption` (string|null), `original_name` (string|null),
      `mime_type` (string|null), `path` (string — the RELATIVE storage path, never absolute).
      Ordered by room name, then bucket, then id, so repeat reads are stable.
    - THE BUCKET MAPPING, decided here and recorded at the definition site. D-03 names three
      buckets; this app's schema has no before/after column, so the buckets are mapped to the three
      kinds of evidence it DOES hold, and the mapping is the meaning:
        `before` = SiteSurveyPhoto  — the survey is the before-state of the room
        `after`  = WorksheetPhoto   — the install evidence
        `label`  = DeviceLabelPhoto — the equipment label
      A survey-sourced visit therefore yields only `before/`; a worksheet-sourced one yields
      `after/` and `label/`. `SiteSurveyPhoto.category` is carried in `caption` only when `caption`
      is null, and never used as a folder name.
    - `rooms(): Collection` — survey-sourced only. One entry per room that returned SOMETHING
      (a photo, a non-empty note, or at least one ANSWERED question). Keys: `name`, `notes`,
      `access_notes`, `completed` (bool), `answered` (int), `total` (int), `answers` (list of
      `['question' => …, 'answer' => …]` where `answer` is the engineer's word, and `other_text`
      when `answer === 'other'`).
      UNANSWERED QUESTIONS ARE OMITTED — an unanswered question is noise on a review page; the
      count of answered-of-total carries that fact in two integers instead of twenty empty rows.
    - `serials(): Collection` — worksheet-sourced only. One entry per `DeviceLabelPhoto` on this
      visit's worksheet, scoped ALSO by `project_id === $project->id`. Keys: `id`, `room`,
      `device` (the device's description/name, or '' — never a raw model dump), `serial`
      (`device->serial_number`, else the `ai_extracted` serial when present, else null),
      `confirmed` (bool), `captured_at`. **`captured_by` IS NOT A KEY OF THIS ARRAY** (RV-03) — add
      a one-line comment naming the backfill migration so nobody restores it.
    - `signoff(): ?array` — worksheet-sourced only, from `Worksheet::latestSignoff()`. Keys:
      `client_name`, `signed_at`, `signed_with_comments`, `comments`, `signature_data_uri`.
      `ip_address` and `user_agent` are NOT keys — the same reasoning as `captured_by`.
    - NOTHING IN THIS CLASS WRITES. No `touch()`, no `firstOrCreate()`, no `save()`, no cache warm
      — the same contract `CockpitPanelPresenter`'s docblock states and its test proves.
    - `photoIds(): array` returns every `[kind, id]` pair this evidence contains. Plan 46.1-02's
      photo route uses it as a MEMBERSHIP check, so a photo id from a query string is never looked
      up globally.
  </behavior>
  <action>
    Create `app/Support/Cockpit/VisitEvidence.php` as a `final class` in `App\Support\Cockpit`,
    constructed privately and built by the static `for()` above. Resolve the source with
    `$visit->source()` — never by a hand-rolled `find()` on a submitted id (per D-03 security and
    the ProjectCockpitController ruling that a query-string id addresses nothing).

    Eager-load in ONE pass per source kind to keep this cheap in Blade:
    survey — `$survey->loadMissing(['rooms.photos', 'rooms.questions'])`;
    worksheet — `$worksheet->loadMissing(['photos', 'signoffs'])` plus a single
    `DeviceLabelPhoto::where('worksheet_id', $worksheet->id)->where('project_id', $project->id)
    ->with('device')->orderBy('room_name')->orderBy('id')->get()`.

    Carry the RELATIVE storage path only: `SiteSurveyPhoto::storagePath()`,
    `WorksheetPhoto::storagePath()`, and `DeviceLabelPhoto->photo_path`. Do NOT call
    `absolutePath()` here and do NOT store an absolute path on the array — absolute paths are
    resolved at the single point of use (the ZIP builder and the photo route in Plan 46.1-02), so
    there is exactly one place where a path meets the filesystem.

    Docblock the class with: (a) the D-04 read-live rule and why a copy is forbidden — a copy goes
    stale and then contradicts its source with no way to tell which is true; (b) the bucket mapping
    above; (c) the `captured_by` / `ip_address` / `user_agent` exclusions with the migration name.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| route-bound `{project}` → visit → source record | The only trusted scope. A visit is accepted only when its `project_id` matches; the source is reached through `Visit::source()`, never through a submitted id |
| engineer-captured free text → this array | `room_name`, `caption`, `question`, `other_text`, `client_name` and `comments` are all untrusted strings from an unauthenticated public token page |
| `device_label_photos.captured_by` → any consumer | An audit field holding a capture IP and an actor hash. It crosses no boundary here because it is never read |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-46.1-01 | Information Disclosure | `serials()` / `signoff()` | mitigate | `captured_by`, `ip_address` and `user_agent` are excluded by construction and asserted absent from the SERIALISED output, so a later key addition trips a red test rather than shipping an IP to a page |
| T-46.1-02 | Information Disclosure | cross-project `DeviceLabelPhoto` rows sharing a `worksheet_id` | mitigate | the label query carries `where('project_id', $project->id)` in addition to `worksheet_id`, and a test creates a real cross-project row to prove the filter is load-bearing |
| T-46.1-03 | Elevation of Privilege | `VisitEvidence::for()` | mitigate | returns null unless `$visit->project_id === $project->id`; the resolver never accepts an id from a request |
| T-46.1-04 | Tampering | engineer free text carried as array values | mitigate | values are carried RAW here and escaped at the single render point (Plan 46.1-03); no `{!! !!}` is permitted in any cockpit view and `CockpitPanelTest::test_no_cockpit_view_uses_unescaped_output()` greps for it |
| T-46.1-05 | Information Disclosure | photo `path` values | mitigate | RELATIVE storage paths only; no `absolutePath()` call exists in this plan's files, so there is exactly one place (Plan 46.1-02) where a path meets the filesystem |

</threat_model>
