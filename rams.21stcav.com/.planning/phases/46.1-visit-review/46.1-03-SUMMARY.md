# Phase 46.1 Plan 03: The Returned Tab Summary

**One-liner:** A fourth panel tab that shows a PM what the engineer actually sent back — room
answers, a contact-sheet gallery, the captured serials and the client sign-off — read live,
read-only, with zero JavaScript and zero non-photo anchors.

## What was built

Phase 46 built the visit workflow but not the review: a PM could accept a visit without having seen
a single thing that came back from site. Plan 46.1-01 derived the evidence and 46.1-02 served the
bytes. This plan renders it.

### The presence rule, as implemented

`ProjectCockpitController::TABS` became `['overview', 'returned', 'files', 'notes']`. The order of
the constant is the tab order and `TABS[0]` is still the fallback, so `resolveTab()` did not change
and everything that **iterates** the constant — the fence's `everyRegion()`, its two GET row-count
tests, `CockpitPageTest::test_every_module_renders_on_every_tab()` — picked the tab up for free.

Membership in `TABS` governs only what the URL may legally say. Whether a given drawer **draws** the
tab is decided in `panel.blade.php`, in one line:

```php
$offersReturned = $visits->contains(fn ($visit) => $visit->source_type !== null);
```

The tab renders **iff the open module's drawer holds at least one visit whose `source_type` is
set**. Not "all nine": `Visit::returnedAt()` reads the SOURCE, so a sourceless visit can never be
RETURNED, SENT BACK or ACCEPTED, and the four document modules hold no visits at all — they would
carry a permanently empty fourth tab. Not "Site survey and First fix only" either: that hardcodes
two module keys, strips the surface from any commissioning / programming / snagging visit that ever
gains a source, and needs a hand-maintained list that drifts. The rule follows the data.

A stale `?tab=returned` is coerced back to `overview` **once**, at the top of the PHP block, so the
strip and the body cannot disagree about which tab is open.

### The tab body

Order mirrors SCC's PMV review panel with this phase's two omissions marked: state line →
**hand-off slot (empty, Plan 46.1-04)** → per-room answers and notes → photo contact sheet →
captured serials → client sign-off → **review-controls slot (empty, Plan 46.1-05)**. Both slots are
named holes, so neither later plan has to restructure the file.

Each sourced visit gets its own `.cav-panel__card` headed by its title and date. A sourceless visit
is not shown here at all — it has nothing to review and Overview already lists it.

## What was deliberately NOT built (RV-08)

"Simple" is an acceptance criterion, not a preference — the user rejected an earlier design with "I
want to make it look simple and less scary". A gallery plus four controls is exactly how a calm page
becomes a control panel, so the tab ships:

- **Nothing per photo.** No lightbox, no pager, no delete, no caption editor, no reorder, no
  per-photo metadata. Each thumbnail is ONE plain `<a target="_blank" rel="noopener">` around an
  `<img loading="lazy" decoding="async">`. (`loading`/`decoding` were checked against the fence's
  nine banned handler attributes before use; they are plain HTML and are not on it.)
- **No thumbnail cap.** Hiding evidence is a worse failure than a long page; the "scary" complaint
  was about controls, not content.
- **Unanswered questions omitted**, carried as "{answered} of {total}" — two integers, not twenty
  empty rows.
- **No new chip and no new colour.** The block reuses `.cav-panel__card`, `.cav-panel__card-head`
  and the `.cav-pnote` shape and introduces no token; every value is an existing `--cav-*`.
- **Zero non-photo anchors.** Asserted by counting every `href` in `.cav-panel__body` and
  subtracting the photo-route ones, with a non-vacuity floor of three photo links. Plan 46.1-04
  raises that budget to exactly one and the test says so.

## Security

`device_label_photos.captured_by`, `worksheet_signoffs.ip_address` and `.user_agent` **render
nowhere**. They are not even keys of what this file receives, because `VisitEvidence` excludes them,
and nothing here reaches past the presenter to a model to get them back. The test asserts all eight
of those strings absent from the raw body **with the real values present in the database** — a
`captured_by` of `ip:203.0.113.9|actor:deadbeef` and a real `ip_address` and `user_agent` — so the
proof cannot pass because there was nothing to leak.

One extra narrowing not asked for: `evidenceFor()` **drops each photo's `path`** on the way to the
view. The view has no use for a storage path, and a page that never receives one cannot print one.

Escaping is proved over five engineer/client fields (room name, caption, question text, client name,
client comments), asserted on the RAW body so an escaped reflection of `?tab=` would also fail, and
non-vacuously (`&lt;script&gt;alert(1)&lt;/script&gt;` must be present).

LR-04 adjacent: the tab reads no `LabourResource` field at all, and a test says so with an active
resource carrying a real email and phone in the database.
`tests/Feature/Security/LabourResourceClientSurfacePrivacyTest.php` was not touched.

## The fence

## Deviations from Plan

**1. [Rule 3 - Blocking] The component file had to exist in Task 1, not Task 2**

- **Found during:** Task 1
- **Issue:** Task 1's `<files>` names only the controller and the panel, but Task 1's own verify
  renders `?tab=returned` — which fatals if `x-cockpit.returned-tab` does not exist.
- **Fix:** Task 1 shipped the component as a SHELL (props, the state branch, the empty-state
  sentence) so every commit in this plan is green on its own; Task 2 grew it into the full evidence
  surface.
- **Files modified:** `resources/views/components/cockpit/returned-tab.blade.php`
- **Commit:** 085f24b1

**2. [Rule 1 - Bug] A directive named in prose inside a Blade comment is still compiled**

- **Found during:** Task 1, first gate run — `Undefined variable $heading` from `panel.blade.php`
- **Issue:** the new docblock explained the coercion by naming the `@php` directive in prose. Blade
  compiles STATEMENTS before it strips COMMENTS, so that mention opened a real PHP block inside the
  comment and swallowed the variable assignments below it. The pre-existing docblock's `@click` was
  harmless only because `@click` is not a registered directive.
- **Fix:** reworded to "the PHP block below", with the trap itself recorded in the comment so the
  next author does not re-introduce it. The literal `<script` was removed from the new component's
  docblock on the same defensive grounds.
- **Files modified:** `resources/views/components/cockpit/panel.blade.php`,
  `resources/views/components/cockpit/returned-tab.blade.php`
- **Commit:** 085f24b1, d5b0ceac

**3. [Rule 1 - Bug] `site_survey_room_questions.answer` is an enum, not free text**

- **Found during:** Task 3
- **Issue:** the first test fixtures stored the engineer's sentence in `answer` and hit
  `CHECK constraint failed: answer` — the column is `enum('yes','no','other')` and the engineer's own
  words live in `other_text`.
- **Fix:** fixtures corrected, AND the tab changed to render `other_text` in place of the enum token
  when the answer reads `other`. Printing "other" beside the words says nothing a PM can use.
- **Files modified:** `tests/Feature/Cockpit/CockpitReturnedTabTest.php`,
  `resources/views/components/cockpit/returned-tab.blade.php`
- **Commit:** a117e05d
