  <files>app/Support/Cockpit/VisitPhotoZipBuilder.php</files>
  <behavior>
    - `build(Project $project, Visit $visit, VisitEvidence $evidence): string` returns the ABSOLUTE
      path of a freshly built temp ZIP. The caller streams it and deletes it after send.
    - THE SHAPE: `{Room}/before/{nnn}-{name}`, `{Room}/after/{nnn}-{name}`,
      `{Room}/label/{nnn}-{name}`. A photo with no resolvable room goes to
      `Unassigned room/{bucket}/`. `{nnn}` is a per-folder sequence so two photos sharing an
      original filename cannot collide.
    - NO PATH IS EVER BUILT FROM USER INPUT. The only source of a file path is the RELATIVE
      `path` value on an entry `VisitEvidence` produced, resolved through
      `Storage::disk('local')->path(...)`. Before any read, the resolved absolute path is checked
      with `realpath()` and asserted to sit INSIDE `Storage::disk('local')->path('')`'s own
      `realpath()` — an entry that resolves outside the disk root is SKIPPED and logged, never read.
      This is the belt to the braces: `VisitEvidence` only ever produced paths from the database,
      but the check makes that a property of this file rather than a property of another file.
    - ZIP-SLIP: every folder segment and every entry name is sanitised before
      `ZipArchive::addFile()`:
        * folder — `preg_replace('/[\/\\\\:*?"<>|]+/', '-', $roomName)`, trimmed; every `.` -only
          result (`.`, `..`, `...`) and every empty result becomes `Unnamed`;
        * filename — `basename()` FIRST (the house rule from `ProjectDrawingController`), then
          `preg_replace('/[^A-Za-z0-9._-]+/', '-', …)`, trimmed of `-`, empty falls back to
          `photo-{id}`, and a leading `.` is stripped so no entry is a dotfile.
      The room name is engineer-entered free text from an unauthenticated token page, so this is
      not theoretical.
    - A photo whose file is missing on disk is SKIPPED, not fatal — the ZIP still streams. The
      count of skipped entries is written into the archive's `README.txt` alongside the included
      count, the visit reference and the generation time, so a short ZIP explains itself instead of
      looking like data loss.
    - `filename(Project $project, Visit $visit): string` — `Str::slug()` of
      `{project ref or name}-{visit date}-photos` with a `.zip` suffix. Never the raw project name
      (it is user data and lands in a `Content-Disposition` header).
    - A visit with ZERO photos still produces a valid ZIP containing only the README. The caller
      decides whether to offer the link at all; the builder never returns a broken archive.
    - NOTHING HERE WRITES TO THE DATABASE, and there is no activity-log call — see the ruling in
      Task 2.
  </behavior>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `{project}`/`{visit}`/`{kind}`/`{photo}` | Four request-supplied values; only `{project}` and `{visit}` are model-bound, and `{visit}` is still checked against `{project}` |
| database `filename` / `photo_path` → filesystem | Written by an UNAUTHENTICATED public token page. Treated as untrusted even though it is not in this request |
| engineer free text (`room_name`, `original_name`) → ZIP entry name | The zip-slip surface |
| ZIP bytes → the operator's machine → Bitrix | The archive leaves this app's control; a malicious entry name would be extracted by whatever unpacks it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-46.1-06 | Tampering / Information Disclosure | path traversal via `worksheet_photos.filename` or `device_label_photos.photo_path` | mitigate | every resolved absolute path is `realpath()`-checked to sit inside the local disk root before it is read; an outside path is skipped and logged. Proven with a real `../../../../.env` row |
| T-46.1-07 | Tampering | zip-slip via engineer-entered room name / original filename | mitigate | `basename()` first, then a strict allow-list `preg_replace` on the filename; a separate separator strip on the folder; `.`/`..`-only results become `Unnamed`. Every entry name in the produced archive is asserted free of `..` and of a leading `/` |
| T-46.1-08 | Elevation of Privilege | photo id enumeration through `{photo}` | mitigate | the id is COMPARED against `VisitEvidence::photoIds()` for the route-bound project+visit, never used in a global `find()`; foreign ids 404 with an indistinguishable body |
| T-46.1-09 | Repudiation | no activity log on download | accept | RULED, not overlooked: `project_activity_logs` is held still by the fence's GET row-count invariance tests, and "a GET writes nothing" is the stronger invariant. Recorded in the controller docblock so a later phase changes it deliberately |
| T-46.1-10 | Information Disclosure | serving user-uploaded bytes same-origin | mitigate | `X-Content-Type-Options: nosniff` and `Content-Security-Policy: sandbox` on the inline photo response; `Content-Disposition: attachment` on the ZIP |
| T-46.1-11 | Denial of Service | a very large visit's ZIP built synchronously to a temp file | accept | `ZipArchive` to a temp file is the house pattern (`ProjectDrawingController`, `OmManualDocxService`) and the only streaming writer available (`maennchen/zipstream-php`) is a TRANSITIVE dependency of `phpoffice/phpspreadsheet`, not a direct require — depending on it directly would be a new composer requirement on a deploy this phase has no mandate to change. Missing files are skipped rather than fatal, and the temp file is deleted after send |
| T-46.1-SC | Tampering | npm/pip/cargo installs | mitigate | NOT APPLICABLE — this plan installs no package. No `composer require`, no `npm install`. If that changes, a blocking human checkpoint and a Package Legitimacy Audit are required first |
