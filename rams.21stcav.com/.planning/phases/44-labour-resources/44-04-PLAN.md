## How the client-facing surface list below was derived (re-derive at plan execution time,
## do not hand-copy without re-checking — routes/web.php may have changed)

Grepped `routes/web.php` for the two public token route groups (both explicitly commented as
client/engineer-facing, unauthenticated, token-gated):

```
grep -n "survey/{token}\|worksheet/{token}" routes/web.php
```

Public **survey** token routes resolve to TWO controllers (not one — `survey.show` and
`survey.download.form` are handled by `SurveyController`, everything else — save/submit/photos/
confirmation — by `PublicSurveyController`):
  - `app/Http/Controllers/SurveyController.php` (renders `resources/views/surveys/show.blade.php`)
  - `app/Http/Controllers/PublicSurveyController.php` (renders `resources/views/public-survey/*.blade.php`)

Public **worksheet** token routes all resolve to one controller:
  - `app/Http/Controllers/PublicWorksheetController.php` (renders
    `resources/views/worksheets/public-show.blade.php`)

Generated **client documents** (per 44-CONTEXT.md canonical_refs: "generated client documents"),
found via `find resources/views/pdf -type f`:
  - `resources/views/pdf/rams.blade.php`, `resources/views/pdf/rams-v2.blade.php` (client RAMS pack)
  - `resources/views/pdf/om-manual.blade.php` + `resources/views/pdf/om-manual/*.blade.php` (client
    O&M manual)
  - `resources/views/pdf/site-survey/*.blade.php` (client-facing survey PDF forms)
  - `resources/views/pdf/commissioning-snagging.blade.php` (client-facing snagging report)
  - `resources/views/pdf/mini-om.blade.php`

Explicitly EXCLUDED as non-client-facing (confirmed by their route's auth requirement, not
assumed): `resources/views/pdf/engineer-report.blade.php` — served by
`worksheets/{worksheet}/engineer-report.pdf`, a `WorksheetController` route living OUTSIDE the
public token group, i.e. requires staff auth (`grep -n "engineer-report" routes/web.php`
confirms it is not inside the `survey/{token}`/`worksheet/{token}` prefix blocks). All
`resources/views/admin/**` views — gated by the real `admin` middleware (see Plan 44-02's
interfaces note) — are staff-only, not client-facing, and are correctly allowed to show email/phone
per D-04's own text ("visible to the PM and admin only").

## Why the source scan and the HTTP render test use different scopes

The static scan below covers BOTH groups (public token controllers/views AND generated PDF views)
because nothing should ever reference `LabourResource` from any of them — that is true today
(nothing consumes the model yet) and should remain true indefinitely per D-05 (the resource
selector is PM-only, never wired into engineer/client-facing forms).

The real HTTP-render test only exercises the public token routes (survey + worksheet), not the PDF
views, because those two are cheap and realistic to fixture (see
`tests/Feature/Worksheets/PublicWorksheetHeaderContactTest.php` and
`tests/Feature/SurveyDownloadFormTest.php`'s `makeSurveyWithRoom()`/`makeWorksheetWithContact()`
patterns, both directly reusable here) and are the two entry points where an unauthenticated third
party (client or the engineer working from a link) actually reaches live data. Rendering the PDF
views end-to-end would additionally require DomPDF/wkhtmltopdf-class fixtures unrelated to what
this phase changes; the static scan already gives a strictly stronger guarantee for those files
today (zero references beats "we rendered one sample and didn't see it").
