| Admin-uploaded logo file -> public storage | Authenticated admin session; the uploaded file is served back to EVERY viewer of any project using this stencil (cross-project propagation, per D-03) — a hostile upload from a compromised admin account is a stored-XSS/malware-serving risk if unsanitised |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-24-13 | Tampering / Elevation of Privilege | SVG logo upload containing `<script>`/`on*`/`javascript:` | mitigate | Mandatory `SvgSanitizerService::sanitize()` before persist — no exceptions, no second sanitiser (D-12) |
| T-24-14 | Information Disclosure | XXE via malicious SVG XML in the upload | mitigate | Already mitigated inside `SvgSanitizerService` via `LIBXML_NONET \| LIBXML_NOENT` on `DOMDocument::loadXML()` — reused, not re-implemented |
| T-24-15 | Denial of Service | Oversized file upload | mitigate | `'max:2048'` (2MB) Laravel validation rule, rejected before any disk write |
| T-24-16 | Tampering | MIME-type spoofing (e.g. `.exe` renamed `.png`) | mitigate | `mimes:svg,png,jpg,jpeg` Laravel rule content-sniffs via PHP fileinfo, not extension-trusted |
