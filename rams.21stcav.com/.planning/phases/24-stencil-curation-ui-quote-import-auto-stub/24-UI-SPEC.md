# Phase 24 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase is **Blade + Alpine.js**, not a component-library ecosystem — there is no shadcn gate to run. Every primitive below is an **existing, already-shipped** class from `resources/views/layouts/app.blade.php` (the "Jetbuilt-clean" 2026-07-09 identity) and its sibling admin screens `admin/device-cable-rules/*` + `admin/devices/*`. This spec's job is to say **which** existing primitive each new element of the curation UI uses, and to define the handful of genuinely new visual signals D-01/D-04/D-05 require (provisional port styling, hard-block vs soft-warn banners).

**Screens in scope:** (1) `/admin/device-stencils` list, (2) `/admin/device-stencils/{id}/edit` — port table + server-rendered preview + logo upload + Promote / Discard-&-regenerate. No create screen (stencils are only ever created by `firstOrCreate` at import time or seed time, per 21 D-03 — never by hand in this UI).

## Spacing Scale

Declared values (must be multiples of 4) — these are the tokens the *existing* codebase already resolves to; new markup in this phase must use them, not invent new gaps:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge dot, inline padding |
| sm | 8px | `.form-control` padding, compact element spacing |
| md | 16px | Default element spacing, filter-row internal gap |
| lg | 24px | Section padding, `.page-header` bottom margin |
| xl | 32px | Layout gaps between major page regions |
| 2xl | 48px | Major section breaks (rare in an admin CRUD screen) |
| 3xl | 64px | Not used in this phase |

Exceptions (existing project precedent, not new deviations — reuse as-is, do not "fix" to a clean 8pt multiple). These non-multiple-of-4 values are a **deliberate reuse-as-is stance**, not an oversight — the planner/executor must not "correct" them to 24px/16px later, because doing so would silently diverge these two screens from their shipped siblings' actual computed layout:
- `.card` / `.section-block` padding is `20px 22px` (established in `app.blade.php:490,816`) — the edit screen's port-table card and preview card both inherit this, do not override.
- `.dv-filter-row` padding is `12px 14px` (established in `admin/devices/index.blade.php:62-72`) — the list view's filter row is a direct sibling of this pattern, reuse the same values under a phase-scoped class (`.stc-filter-row`) per the project's per-screen-scoped-class convention (`.dv-*`, `.gsp-*`).
- Port-table cell padding follows `.dv-table td` precedent: `12px 16px`.

## Typography

Four sizes only, drawn from the project's existing `--fs-*` custom properties (`app.blade.php:157-162`) — this phase deliberately uses a **subset** of the app's full global scale (which also defines `--fs-h2` 22px and `--fs-micro` 11px) rather than the whole thing. `--fs-h2` and `--fs-micro` are **not used anywhere in this phase's new markup**; they remain valid tokens elsewhere in the app on screens this phase does not touch, but neither the list view nor the edit view may introduce a new element styled at 22px or 11px.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Page heading (H1 — `.page-title`) | 28px (`--fs-display`) | 600 | 1.2 |
| Section heading (port-table card header, preview-pane header, any other in-screen `.section-heading`) | 18px (`--fs-h3`) | 600 | 1.2 |
| Body / table cell / form input | 15px (`--fs-body`) | 400 | 1.5 |
| Label / meta / small table text / table-header eyebrow | 13px (`--fs-small`) | 600 (labels, table headers) / 400 (meta) | 1.4 |

Two weights, per the checker's 2-weight rule: **400 (regular body/meta)** and **600 (headings, `.form-label`, `.section-heading`, table header cells, badges)**. The existing `.btn` primitive uses 500 — that is an inherited, unmodified primitive (not new markup this phase authors), so it does not count against the 2-weight budget; do not introduce a *third* new weight anywhere else.

Specific collapses made to hit the 4-size cap:
- **Port-table card header and preview-pane header both use 18px (`--fs-h3`)** via the existing `.section-heading` class (`app.blade.php:771-783`, already 18px/600/1.2) — not the 22px `.section-heading--panel` variant. Do not reach for `--fs-h2` / `.section-heading--panel` on either header.
- **The list table's and port table's header-row eyebrow text (uppercase, tracked) uses 13px (`--fs-small`) at weight 600** — the same size as body labels, not a separate micro size. This phase's `.data-table`/port-table header cells must declare `font-size: var(--fs-small)`, not the 11px `--fs-micro` token and not a hardcoded 10px/11px value (some *other, unmodified* screens — e.g. `admin/devices`' `.dv-table th` — hardcode 10px; that is existing shipped CSS this phase does not edit, and is called out here only so it isn't mistaken for a pattern to copy into new markup).

|------|-------|-------|

| Secondary (30%) | `var(--surface)` `#FFFFFF` | `.card` / `.section-block` fills — the port table's card, the preview pane's card, the filter row's white inputs |

Nothing else gets the accent — do not tint icons, borders, or hover states elsewhere in this phase. |
| Destructive | `var(--danger)` `#EF4444` | "Discard & Regenerate" button (`.btn-danger-outline`), hard-block validation banner border/text, offending port-table row left-border + background tint, duplicate/missing-field inline errors |

Additional semantic tokens already in the system (not new — reused for D-04's two-tier gate):
- `var(--warning)` `#F59E0B` / `var(--warning-light)` `#FEF3C7` — the **soft-warn** banner and per-row warning badges (no logo / unclassified `signal_type` / missing `x_pct`/`y_pct`). Accent reserved for: Promote button, Apply-filter button, focused inputs, `:focus-visible` rings, engineer-curated badge accent text. Never used for the destructive action, never used for provisional-port styling (that is ink-muted, see Component Inventory below), never used as a decorative background tint.

## Component Inventory (new-to-this-phase visual signals)

Everything else in this phase is an existing primitive used as-is (`.page-header`, `.card`, `.btn`/`.btn-outline`/`.btn-primary`/`.btn-danger-outline`/`.btn-sm`, `.data-table`, `.form-control`, `.form-label`, `.form-help`, `.invalid-feedback`, `.alert`/`.alert-error`/`.alert-warning`, `.badge-*`, `<x-edit-action-bar>`). The following are genuinely new and need explicit values because no existing screen has them:

**1. List view filter row** (`.stc-filter-row`, sibling of `admin/devices`' `.dv-filter-row`)
Fields, left to right: Search (`part_number`, text input, `Apply`-on-submit — not live-debounced, matches `admin/devices` convention of a GET form + Apply button, not `x-model.debounce`), Source (`<select>`: All / Auto-generated / Engineer-curated / AI-extracted), Needs review (`<select>`: All / Yes / No), Manufacturer (`<select>`, populated from distinct `device_stencils.manufacturer`). `Apply` = `.btn-teal.btn-sm`, `Clear` = `.btn-outline.btn-sm` (shown only when any filter is active) — byte-identical pattern to `admin/devices/index.blade.php:112-130`. Both labels are single-word CTAs by precedent, not new copy invention — `admin/devices` already ships exactly these two words for exactly this filter-row shape.

**2. List table columns** (`.data-table`, card-flush wrapper, identical chrome to `admin/device-cable-rules`):
Part Number (mono, `--font-mono`) · Manufacturer / Model (bold `--ink-900` + part-number sub-line, `.dv-equipment`/`.dv-partno` pattern) · Source badge · Needs-review badge (only rendered when true — absence *is* the "no" state, do not render a muted "No" pill) · Ports (count, `font-variant-numeric: tabular-nums`) · Logo (28px square thumbnail with 1px `--ink-200` border + `--radius-sm`, or em-dash) · Updated (relative date) · Actions (`Edit` → `.btn-outline.btn-sm`). Header row: 13px (`--fs-small`), weight 600, uppercase, tracked — see Typography above.

Source badge mapping (existing `.badge` classes, `app.blade.php:1009-1029`):
- `auto-generated` → `.badge-grey` "Auto-generated"
- `engineer-curated` → `.badge-green` "Engineer-curated"
- `ai-extracted` → `.badge-blue` "AI-extracted" (reserved value — list filter includes it for forward compatibility with Phase 25, but this phase never writes it)
- `needs_review = true` → separate `.badge-yellow` "Needs review" pill alongside the source badge

**3. Edit screen layout** — two-column, port table left (source of truth, wider, ~60%), preview pane right (read-only, sticky, ~40%), stacking to single-column under 900px. Both panes are `.card`, and each carries a `.section-heading` header ("Ports" / "Live Preview") at 18px/`--fs-h3`/600 — see Typography above; do not use `.section-heading--panel` (22px) for either. Page-level header uses `<x-edit-action-bar>` exactly as `admin/devices/edit.blade.php` and `admin/device-cable-rules/edit.blade.php` do — title = manufacturer + model (or "Stencil #{id}" fallback). Its `Cancel` button is the primitive's own unmodified default (label + `url()->previous()` behaviour, `edit-action-bar.blade.php:24`) — not a new CTA this phase invents. There is no plain "Save" in this bar: edits to the port table autosave-on-blur or submit via an explicit "Save Ports" if the planner chooses batched submission (see Assumption 3) — either way `<x-edit-action-bar>`'s slot carries Cancel + the page title only, and Promote/Discard live in the footer per point 6 below, because they are stage-gated actions, not a plain form-submit.

**4. Port table row** — one row per `device_ports` row + one trailing "+ Add port" row. Columns: Label (text) · Side (select: left/right/top/bottom) · Connector type (select, allowlist from `config/drawings.php` `port_templates` vocabulary) · Signal type (select: audio/video/control/network/usb/power/speaker/dante/unclassified) · Direction (select: in/out/io) · Position (`x_pct` or `y_pct` depending on `side`, small number input, 0–1, step 0.01, placeholder "auto") · Port ID (mono text, stable identifier) · row delete (icon-only `×` button, `.btn-ghost`, `aria-label="Remove port {label}"` — mandatory per the codebase's existing a11y batch-6 convention on icon-only removes). Header row uses the same 13px/`--fs-small`/600 eyebrow treatment as the list table (Typography above) — not `--fs-micro`, not a hardcoded 10px/11px value.

Row state tinting (this is the D-04 hard-block/soft-warn visual language applied per-row):
- **Blocking issue** (missing `label`/`connector_type`/`signal_type`/`direction`, or duplicate `port_id`): row gets `border-left: 3px solid var(--danger)` + `background: var(--danger-light)` at 40% mix, plus an inline `.invalid-feedback`-style caption under the row naming the exact missing field(s).
- **Warning issue** (`signal_type = unclassified`, or both `x_pct`/`y_pct` null): row gets `border-left: 3px solid var(--warning)` + `background: var(--warning-light)` at 40% mix, caption in `--warning`-toned text, non-blocking.
- Clean row: no tint, default `.dv-table td` styling.

**5. Live preview pane** — header "Live Preview" (`.section-heading`, 18px/`--fs-h3`/600, per Typography above) + a small state indicator (three states: idle/clean render, `Rendering…` with the existing `.btn[disabled]`-style opacity-50 treatment on the pane during the in-flight POST, and an inline `.alert-error` if the preview endpoint 500s — never blank the pane on error, keep the last good render visible underneath the error banner). POST to the debounced preview endpoint (`admin.device-stencils.preview`) fires on port-table change, **600ms debounce** — matches the codebase's one existing precedent for autosave-style debounce (`surveys/show.blade.php:1761-1769`, `debouncedAutosave()` at 600ms). Do not use 200ms (that convention is reserved for keystroke-search, e.g. ⌘K) — this is a network round-trip through the real builder (D-02), not a local filter.

Provisional vs. verified port rendering inside the returned SVG (D-05 — this is the server-side renderer's contract, but the UI spec fixes the values so the executor and checker agree on what "dashed/muted" means):
- **Provisional** (template-derived, not yet engineer-touched): rail stroke `stroke-dasharray="4 3"`, stroke colour `var(--ink-400)` `#94A3B8`, `opacity: 0.6`. Connector glyph and label render in the same muted ink, not the signal-type colour.
- **Verified** (engineer has edited this port's row at least once in this session, or the stencil is already `engineer-curated`): solid stroke in the signal-type colour from `config/drawings.php` `signal_colours` (audio `#C0392B`, video `#2980B9`, control `#27AE60`, network `#8E44AD`), full opacity.
- Zero-port stub: unchanged from 21 D-04 — bare placeholder, no rails at all.

**6. Footer actions** (below both panes, full-width row, matches `.dv-footer-actions` gap/alignment convention):
- `Promote to Engineer-Curated` — `.btn-primary` (accent fill). **Disabled** (not hidden) whenever any port-table row carries a blocking issue or the port count is zero; disabled state shows the existing `.btn:disabled { opacity: .5; cursor: not-allowed; }` plus a one-line reason directly above the button ("Blocked: 2 ports missing a signal type" style — enumerate the actual blocking reasons from D-04's list, not a generic "fix errors").
- `Discard & Regenerate` — `.btn-danger-outline`. Always enabled. Confirmed via the project's existing `data-confirm` directive (same mechanism as `admin/device-cable-rules`' rule delete): `data-confirm="Discard all edits and regenerate this stencil from its category template?" data-confirm-label="Discard & Regenerate" data-confirm-danger="1"`.
- `Cancel` — `.btn-outline`, routes to the list view preserving prior filters (`url()->previous()` per `<x-edit-action-bar>`'s existing default — same inherited-unmodified primitive noted in point 3, repeated here because it also appears in the footer row visually).

## Assumptions (not locked by CONTEXT.md — flagged for planner/executor to revisit if wrong)

1. **Preview debounce = 600ms.** CONTEXT.md D-02 specifies server-side render but not a timing; 600ms is derived from the one existing debounced-autosave precedent in the codebase (`surveys/show.blade.php`). If the real builder call proves slow enough that 600ms feels laggy in practice, this is the value to tune first.
2. **"Verified" vs "provisional" port state is session-local** (an engineer has touched the row this session) rather than persisted per-port. CONTEXT.md D-05 only specifies template-derived vs. engineer-curated at the *stencil* level pre-promotion; treating every row as provisional until the stencil is fully promoted is the simpler, safer reading — flag to the planner if per-port provenance tracking turns out to be wanted instead.
3. **Batched port-table save** (edits accumulate client-side, one submit) vs. **per-row autosave** — the design system doesn't dictate this, and D-01 is silent on it. This spec assumes batched submission (an explicit "Save Ports" affordance may be needed inside the port-table card if the planner doesn't fold it into Promote/Discard) because it composes more simply with the hard-gate-on-Promote logic. Flag during planning if per-row autosave is preferred.
4. **No confirm dialog on Promote itself** — D-04 gates on validation, not on a confirmation modal. Given the stakes described in D-04's own rationale ("promotion... starts propagating to every project"), the planner may still want a lightweight confirm; this spec deliberately does not add one so as not to contradict CONTEXT.md by invention, but flags it as worth a second look.
5. **Manufacturer filter is a plain `<select>` of distinct values**, not a typeahead — matches the weight of the existing `admin/devices` project filter (`<select>` of all projects), not a new autocomplete pattern.
