<objective>
Close UAT Gap 1: `stencils:reapply-templates` currently gates eligibility on `source = auto-generated AND whereDoesntHave('audits')`. Empirically, all 91 zero-port stubs in the live-shaped catalogue are `source = engineer-curated` (Phase 21 D-05 seeded them that way) carrying `metadata.needs_phase_24_curation = true`, which the Plan 24-01 migration correctly backfilled into `needs_review = true`. The command's `source` condition makes it unable to see any of them — dry-run and `--commit` both report "No eligible stencils. Nothing to do." against the real catalogue.

Fix: swap the eligibility predicate's `source = auto-generated` clause for `needs_review = true`, keeping `whereDoesntHave('audits')` completely intact — that clause is now the ONLY thing standing between this destructive `--commit` command and overwriting engineer-touched work, since `source` no longer participates in the query at all. This widens what the command can reach (it can now legitimately touch `engineer-curated` stencils, which it could not before) — the plan's tasks make that widening deliberate, tested, and visible in the command's own report output.

Purpose: unblocks Criterion 5 (bounded top-10 Tier 1 fill) and the general "run the tool, review the diff, --commit" workflow D-08 exists for — right now the tool is a no-op against real data.
Output: corrected `StencilsReapplyTemplatesCommand.php`, and a test suite whose fixtures match the REAL catalogue shape (engineer-curated zero-port stubs), not the disproven auto-generated assumption.
</objective>
