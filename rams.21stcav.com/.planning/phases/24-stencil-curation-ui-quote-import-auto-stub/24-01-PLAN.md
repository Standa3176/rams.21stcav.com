The authoritative source for the real grammar is the vendored parser this project ships: `public/vendor/drawio/mxgraph/src/shape/mxStencil.js`. Read directly this session:
- Lines 893-896: the `<dashed>` element's handler reads `node.getAttribute('dashed')` — the attribute name is **`dashed`**, not `value`. `dashed="1"` enables dashing, `dashed="0"` disables it.
- Lines 948-951: the `<strokealpha>` element's handler reads `node.getAttribute('alpha')` and calls `canvas.setAlpha(...)`.
- Lines 90-91 (docblock): `strokealpha` is a **0.0-1.0 fraction** ("1.0 for fully opaque, 0.0 for fully transparent"), never a 0-100 percentage.
- Lines 940-951: the `alpha`, `fillalpha`, and `strokealpha` element handlers are **identical** — all three call the same `canvas.setAlpha(...)`. In this vendored build `strokealpha` is effectively GLOBAL alpha, not a stroke-only channel — it dims every fill/text/line drawn after it until explicitly reset. The reset after the rail batch is therefore MANDATORY, not tidiness (see Task 3).
- `public/vendor/drawio/mxgraph/src/util/mxSvgCanvas2D.js:1137` confirms the alpha value is written straight into SVG `stroke-opacity` with no percentage-to-fraction conversion anywhere in the pipeline.

`resources/data/device-stencils-seed/*.json` contains **zero** `dashed`/`strokealpha` precedent anywhere in the seed pack (grep-confirmed) — the seed pack cannot be used to validate this grammar; the vendored parser is the sole source of truth. Task 3 below specifies the exact emission sequence.
