<objective>
Close UAT Gap 2: the D-17 guard in `DeviceStencilController::update()` fires whenever `$deviceStencil->source === SOURCE_ENGINEER_CURATED`, regardless of whether that stencil actually has any ports. In the real catalogue, 96 of 96 stencils are `engineer-curated`, but only 5 of them (ClickShare Bar Pro, Neat Bar Pro, Netgear GS312TP, Samsung QM65C-T, Sennheiser TCC2) carry genuine hand-built mxGraph artwork — the other 91 are bare zero-port stubs sharing the same `source` value. As shipped, the confirmation warning fires on 91 of 96 saves, directly contradicting D-17's own stated requirement that "the ordinary stub-curation path must stay a single-click save with zero added friction."

Fix: the guard's trigger becomes `source === SOURCE_ENGINEER_CURATED AND $deviceStencil->ports()->exists()` (checked against the stencil's ports as they stand BEFORE this request's Save mutates them) — a stencil with no existing ports has no artwork to protect, so there is nothing for the guard to guard. This is UAT's recommended fix (a), the smallest change that directly matches D-17's intent.

Purpose: restores the phase's main workflow (curating one of the 91 stubs) to zero-friction, while keeping the confirm-to-proceed protection intact for the 5 stencils that genuinely need it.
Output: corrected guard predicate in `DeviceStencilController::update()`, and a test suite whose fixtures include the real bug scenario (engineer-curated + zero ports + no confirm).
</objective>
