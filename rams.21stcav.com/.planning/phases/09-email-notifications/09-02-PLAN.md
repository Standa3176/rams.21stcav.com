```php
<?php

namespace App\Services;

use App\Models\Project;
use App\Models\User;

class NotificationRecipientResolver
{
    /**
     * Resolve the project's primary notification recipient.
     *
     * Order:
     *   1. Project owner (Project.user_id → User) — uses ->owner relation
     *      (NOT ->user — that relation does not exist on the Project model).
     *   2. First admin (User where role='admin') — NOT is_admin = true
     *      (that column does not exist on the users table).
     *   3. null (no recipient — caller logs and skips).
     */
    public function resolveProjectRecipient(?Project $project): ?User
    {
        if ($project) {
            $project->loadMissing('owner');
            if ($project->owner instanceof User && $project->owner->email) {
                return $project->owner;
            }
        }

        return User::where('role', 'admin')
            ->whereNotNull('email')
            ->orderBy('id')
            ->first();
    }

    /**
     * All admin recipients for failure alerts (NOTF-05b).
     * Returns a Collection of User. Empty when no admins with email exist.
     */
    public function resolveAdminRecipients(): \Illuminate\Support\Collection
    {
        return User::where('role', 'admin')
            ->whereNotNull('email')
            ->get();
    }
}
```

| package registry → composer install | New third-party packages enter the codebase; supply-chain risk |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-02 | I (Information disclosure) | `NotificationRecipientResolver::resolveProjectRecipient` | mitigate | Recipient comes only from internal `Project::owner` (auth'd User) or admin-role User; never from external/user input. The 7-test unit suite locks the resolution rule against drift. |
| T-09-06 | E (Elevation of privilege) | `NotificationRecipientResolver::resolveAdminRecipients` | mitigate | Admin lookup is `User::where('role', 'admin')` — same role check used by `User::isAdmin()` and existing admin middleware. No way to spoof admin status without a DB write that already required admin auth. |
| Supply chain | T (Tampering) | `composer require symfony/postmark-mailer symfony/http-client` | accept | Both packages are first-party Symfony components hosted on Packagist with TLS + signature verification by Composer; same provenance as the already-installed `symfony/mailer ^7.4`. No high-risk transitive deps. |
