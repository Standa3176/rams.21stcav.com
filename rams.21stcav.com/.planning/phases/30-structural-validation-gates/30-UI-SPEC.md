# Phase 30 — UI Design Contract

> Visual and interaction contract for the Phase 30 gate-warning surface. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**This is not a greenfield design document.** `rams.21stcav.com` is a shipped Laravel + Blade
application with an established token set, an established alert idiom and an established
advisory-banner component. Everything below is written against what is already in the repo.
Every visual claim carries a `file:line` that was read on 2026-09-13.

---

## The One Real UI Problem

Phase 30 is a backend phase. It has exactly one genuine UI requirement, recorded as
`30-CONTEXT.md` open question 1:

**GATE-04 is specified as two-tier and the codebase has no second tier.**

- `REQUIREMENTS.md:65` and ROADMAP Phase 30 criterion 3: **error** when residual score exceeds
  initial score; **flag for human review** (explicitly "does not silently accept") when residual
  severity is lower than initial severity.
- Every gate in this application is fail-closed: `RamsGenerationException` thrown out of
  `RamsComplianceUpgradeService::upgrade()`, caught at `RamsController.php:603` (Save Review),
  `:701` (DOCX rebuild-on-download), `:857` (`downloadPdf`), each turning into
  `back()->with('error', $e->getMessage())`.
- `resources/views/rams/review.blade.php:393-398` renders **only** `session('success')` and
  `session('error')`. There is no `session('warning')` branch on this screen, and no non-throwing
  advisory surface anywhere in `app/Services/Rams/`.

Phase 30 must invent that second tier. This spec defines it. It also unblocks GATE-05
(warn-only) in Phase 31.

**Accent reserved for:** active tab indicator, primary "Save Changes" button, and links. The
warning surface uses the amber family exclusively and must never borrow accent blue.

**The amber/red split is load-bearing.** Amber = advisory, document still generated. Red = the
document was refused. A reader must be able to tell which happened without reading the copy.
This split already exists in the app and is reused, not invented: the amber
`x-stale-banner` (`components/stale-banner.blade.php`) is advisory; `.alert-error` is refusal.
Precedent for downgrading a red hard-stop to an amber informational note where the meaning is
advisory: Plan 29-11 did exactly this to the "TBC AT SITE INDUCTION" banner.

## The Warning Channel — Data Contract

**Decision (user-confirmed 2026-09-13): warnings ride the data array, not the session.**

`RamsComplianceUpgradeService::upgrade()` is `static function upgrade(array $ramsData): array`
(dispatch body at `:40-100`). The warn channel is therefore a key on that array:

```
$ramsData['compliance_warnings'] = [
    ['gate' => 'GATE-04', 'hazard_index' => 7, 'hazard' => 'Working at Height', 'message' => '...'],
    …
];
```

| Property | Contract | Why |
|----------|----------|-----|
| Persistence | Persisted. `RamsController.php:623` already does `$rams->update([... 'generated_data' => $generatedData])` on the Save-Review path, so the key survives the redirect and is present on the next fresh review load. | A session flash shows once and vanishes; a flag "for human review" that disappears on refresh is a silently-accepted flag. |
| Recomputation | **Overwrite the whole key on every `upgrade()` run.** Never append to a stale array. | A hazard the engineer fixed must clear its own warning with no extra action. |
| Dismissal | **None.** No dismiss control, no `acknowledged_at`, no acknowledgement table or migration. | A dismissed warning that never returns is the exact "silently accept" failure `REQUIREMENTS.md:65` forbids. An ack record is real scope (migration + model) for a gate that ships disarmed. |
| Blocking | **None.** A GATE-04 flag does not block "Save Changes" (`review.blade.php:1178`) and does not block PDF/DOCX download. | Blocking would collapse the flag into a second error tier, duplicating GATE-04's real error branch. |
| Single source | Both render surfaces (panel + inline rail) read `generated_data['compliance_warnings']`. **Never two arrays, never a second computation in the blade.** | Divergent sources produce a panel and a row that disagree — worse than no warning. |

### Boundary — warnings must never reach the generated document

`compliance_warnings` is an **internal review-time signal, not client-facing RAMS content.**

- It must **not** render in `resources/views/pdf/rams.blade.php`.
- It must **not** render in `resources/views/pdf/rams-v2.blade.php`.
- It must **not** be emitted by `app/Services/DocxBuilderService.php` or `DocxBuilderServiceV2`.

This is currently safe by construction and must stay that way: the PDF blade reads only explicit
named keys (`$data['scope_of_works_bullets']` `:853`, `$data['ppe_matrix']` `:1531`,
`$data['permit_and_isolation']['rules']` `:1704`, etc.) — there is no generic
`@foreach($data as …)` dump. The planner should treat "no warning text appears in a regenerated
21CQ30960 PDF or DOCX" as a test assertion, not an assumption.

### Known gap — `review()` does not run the gates

`RamsController::review()` (`:307-326`) calls `patchRamsForDisplay()` and `RamsDiffService::diff()`
and **never calls `upgrade()`**. Consequence, stated plainly:

> A freshly-opened review of a document last saved **before** Phase 30 shipped will show **no
> warnings** until the next Save Review (or regenerate) runs `upgrade()` and persists the key.

**This spec accepts that behaviour and does not require `review()` to change.** Rationale: calling
`upgrade()` from `review()` would make a read-only GET page capable of throwing
`RamsGenerationException` from any of the five new gates plus the four shipped ones — turning a
view into a failure surface, on a path that currently cannot fail. That is a materially larger
change than Phase 30's "keep the migration diff minimal" posture supports, and it is the kind of
bypass-closure work Plan 27-07 handled deliberately and separately.

**Planner action:** record this as a known limitation in the phase SUMMARY, not as a defect. If a
future phase wants live-on-open warnings, the safe shape is a separate non-throwing
`collectWarnings(array $ramsData): array` read-only pass — explicitly out of scope here.

## Surface 1 — Warnings Summary Panel

**Location:** `resources/views/rams/review.blade.php`, immediately after the existing
`session('error')` block at `:396-398` and before the hidden regen form at `:401`. It sits above
the tab wrapper (`:458`) so it is visible regardless of which tab is active — necessary because
the Hazard Register lives behind the 5th tab at `:1184`.

**Markup idiom:** reuse `.alert .alert-warning` (`layouts/app.blade.php:663-673`). Do **not** use
`.alert-banner--warning` (`:704`) — that variant carries `.alert-banner__dismiss` (`:688`), and
this warning is explicitly not dismissible.

**Structure:**

```
<div class="alert alert-warning" role="status">
    <strong>⚠ {N} item{s} flagged for review</strong>
    <ul>  {{-- one <li> per warning, 8px gap --}}
        <li>{gate} — {hazard name}: {message}</li>
    </ul>
</div>
```

- `role="status"` (polite), matching `components/stale-banner.blade.php`'s banner. **Not**
  `role="alert"` — assertive is for blocking errors.
- The `⚠` glyph is the established warning mark in this codebase
  (`components/stale-banner.blade.php`). No icon library to pull from.
- Count badge, if used, is `.badge-warning` (`layouts/app.blade.php:1029`) — same
  `--warning-light` / `#92400E` pair, so it cannot drift from the panel.

### Empty state — the most important state in this phase

Per `30-CONTEXT.md` D-03 all five gates ship disarmed (`env(..., false)`), so **the normal state on
day one is zero warnings.**

> **When `compliance_warnings` is empty or absent, the panel renders NOTHING.** No empty chrome
> box, no "0 warnings", no "All checks passed", no grey placeholder.

There is a direct precedent: `components/stale-banner.blade.php` early-exits
(`if (! $doc->isStale()) return;`) so callers can drop it inline with no outer `@if`. The warnings
panel must have the same property. Phrased as the acceptance test: **with every flag false, the
review screen must be byte-identical to its pre-Phase-30 render.** This mirrors the gate doctrine
already recorded in `RamsComplianceUpgradeService.php:62-66` — flag false means `upgrade()` is
byte-identical to pre-gate behaviour — and extends it to the view layer.

### Partially-armed state

Per D-04 the flags flip in three independent groups — `RAMS_STRUCTURAL_GATES` (01+02+04),
`RAMS_MISSING_RISK_REF_GATE` (14), `RAMS_HOT_WORKS_GATE` (13, flips in Phase 31). A
partially-armed system is **normal, not transitional**, for at least a full phase.

Consequences the copy must respect:

- **Never imply a clean bill of health.** No "All structural checks passed", no green tick, no
  "0 issues found" summary. The panel cannot distinguish "gate ran and found nothing" from "gate
  never ran", so it must never claim the former.
- **Never enumerate or name the gates that did not run.** The panel lists findings, not coverage.
  A user does not need to know `RAMS_HOT_WORKS_GATE` is off; exposing it invites treating the
  absence of a warning as evidence.
- Each rendered warning names its own gate (`GATE-04`, `GATE-14`) so a reader can tell which check
  produced it. That is the only gate identity that appears in the UI.

## Surface 2 — Inline Hazard Row Marker

**Location:** the Hazard Register table in the hazards tab, `review.blade.php:1184-1218` — the
`<tr>` at `:1203` that already carries `{{ $hazardRowChanged ? 'diff-modified' : '' }}`.

**Idiom:** reuse the existing left-rail treatment. `.diff-modified` is defined in the page's own
inline `<style>` at `review.blade.php:420-423`:

```
border-left: 3px solid var(--warning) !important;
background: color-mix(in oklab, var(--warning) 6%, var(--surface)) !important;
```

`--warning` is `--signal-warning` `#F59E0B` (`layouts/app.blade.php:84`, `:140`).

**Contract:**

- Add a sibling class in the same `<style>` block — e.g. `.gate-flagged` — using the **same
  3px left rail + 6% `color-mix` tint** so the two treatments are visually consistent rather than
  competing. Do not invent a different rail width, a different tint percentage, or a border on
  another edge.
- A row can be both diff-modified and gate-flagged. When both apply, the gate flag wins the rail
  (it is the safety signal); a class-order or explicit-precedence decision is the executor's, but
  it must be deliberate and commented — `.diff-modified` uses `!important`, so naive class
  stacking will silently resolve by source order.
- Add `title="{gate} — {message}"` on the flagged row so the reason is reachable without leaving
  the table.
- Matching key: `hazard_index` from the warning entry against `$hIdx` in the `@foreach` at
  `review.blade.php:1196`. If the index cannot be resolved, render the panel entry only and skip
  the rail — **never guess a row.**

**Nothing else in the table changes.** The existing pre/post score badges at `:1206-1214` (the
`#D4EDDA` / `#FFF3CD` / `#FFD0A0` / `#FFDEDE` score bands) are untouched by this phase.

## Surface 3 — Blocking Gate Errors (no change required)

The five new gates' **error** tier needs no new UI. It reuses the existing path end-to-end:

| Step | Location |
|------|----------|
| Throw | `RamsGenerationException` from `upgrade()` |
| Catch | `RamsController.php:603`, `:701`, `:857` |
| Flash | `back()->with('error', $e->getMessage())` |
| Render | `review.blade.php:396-398` → `.alert .alert-error` |

**The only requirement on the executor here is the message string.** It is the entire UI. Per
`30-CONTEXT.md` "Claude's Discretion", every existing gate throws on the first violation with a
message naming the offending item (`:1311`, `:1442`) — follow that shape.

Copy contract for every blocking gate message: **`{what is wrong} — {which item} — {what to do}`.**
Naming the item is not optional; "GATE-02 failed" is an unactionable message on a document with
nine areas.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `💾 Save Changes` — **unchanged**, existing at `review.blade.php:1178`. This phase adds no button. |
| Warning panel heading (1 item) | `⚠ 1 item flagged for review` |
| Warning panel heading (N items) | `⚠ {N} items flagged for review` |
| Warning panel body | `These do not block the document. Check each one before issuing.` |
| GATE-04 warning line | `GATE-04 — {hazard name}: residual severity {s2} is lower than initial severity {s1}. Controls reduce likelihood, not severity — confirm this is intended.` |
| Empty state | **No empty state.** The panel is absent when there are no warnings. See "Empty state" above. |
| Error state (GATE-01) | `Orphan control — "{trigger phrase}" references {document/permit} but the RAMS has no supporting hazard row and no client-responsibility entry. Add the hazard and the client responsibility, or remove the reference.` |
| Error state (GATE-02) | `Area "{area name}" has no method steps. Add at least one method step for this area, or remove the area.` |
| Error state (GATE-04) | `Hazard "{hazard name}" has a residual score of {post} against an initial score of {pre}. Residual risk cannot exceed initial risk — correct the post-control scoring.` |
| Error state (GATE-13) | `Hot-works contradiction — this RAMS states no hot works while also {requiring a hot-works permit / listing {substance} in COSHH}. Resolve the contradiction before issuing.` |
| Error state (GATE-14) | `Method step "{step title}" does not cite {hazard ref} ({hazard name}), which its own text implies. Add the reference to the step's risks line.` |
| Destructive confirmation | **None.** This phase introduces no destructive action. The existing confirm idiom, if one were ever needed, is `window.appConfirm()` / `data-confirm` (`review.blade.php:406`, `components/stale-banner.blade.php`). |

**Tone rules:** state the contradiction, name the item, give the next action. No "Oops", no
"Something went wrong", no exclamation marks beyond the `⚠` glyph. These messages are read by an
engineer about to issue a safety document.
