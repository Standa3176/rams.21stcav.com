<threat_model>
  <threat id="T-03-08" severity="medium">
    <description>The three new text fields accept free-form engineer notes (site_risks, access_constraints, h_and_s_notes). Without length validation, an attacker could submit extremely large payloads through the public survey form, potentially causing database/memory issues.</description>
    <mitigation>All three fields validated with max:3000 in validatePublicSurvey() — matching the existing general_notes pattern. Database columns are TEXT type which handles 3000 characters easily. No additional sanitization required as these fields are display-only and escaped with {{ }} or e() in views.</mitigation>
  </threat>
  <threat id="T-03-09" severity="low">
    <description>The confirmation page is accessible via GET /survey/{token}/confirmation without the survey being in 'completed' status (engineer could bookmark it or navigate to it before submitting). This could display a "Survey Submitted" heading for an unsubmitted survey.</description>
    <mitigation>The confirmation() controller method calls resolveSurvey() which validates the token is valid and not expired. For Phase 3 scope, this is accepted as low risk — the confirmation page is informational only, contains no sensitive data, and the token URL is not guessable. A stricter gate (abort_unless $survey->isSubmitted()) is a Phase 4 polish item if needed.</mitigation>
  </threat>
</threat_model>
