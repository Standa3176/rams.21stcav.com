  <threat id="T-03-04" severity="medium">
    <description>Without the whereNull('superseded_at') filter on the resolve() survey query, a superseded (archived) survey with status='completed' could still be picked up as the active survey after a new survey is created.</description>
    <mitigation>Added ->whereNull('superseded_at') to both the DB query path and the in-memory collection path in resolve(). Test 13 verifies a superseded survey stub is excluded from the result.</mitigation>
  </threat>
  <threat id="T-03-05" severity="low">
    <description>N+1 query risk: if normalizeRooms() is called multiple times per resolve() (once in resolveRooms() via mergeSurveyRooms(), once in resolveSurveyMeta()), the rooms relation would be loaded twice. loadMissing('rooms') is called in mergeSurveyRooms() before the first access — subsequent access to $survey->rooms uses the cached relation.</description>
    <mitigation>Use $survey->loadMissing('rooms') in mergeSurveyRooms() so the relation is loaded once and cached on the model. resolveSurveyMeta() then calls $this->normalizeRooms($survey->rooms) and accesses the already-loaded cached relation (no second query).</mitigation>
  </threat>
