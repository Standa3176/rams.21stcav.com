# Phase 46.4: Engineer Link — Install Capture - Context

**Gathered:** 2026-09-26
**Status:** Ready for planning

<domain>
## Phase Boundary

The worksheet engineer link becomes an **install capture** tool: room **start** and **completion**
photos that can carry labels, **serial capture that feeds an asset list**, and a per-room
**additional-kit list** of separate rows — engineer, qty, part description — so the office receives
a clean list instead of prose in a comments box.

**In scope:** the worksheet engineer link (`/worksheet/{token}`) only; photo buckets and captions;
serial capture surfaced as an asset list; the repeatable additional-kit rows and their offline
queueing; and the office-side view of that list.

**Out of scope:** the **site survey** link — the user's words: *"site survey is a room survey so no
kit"*; splitting the engineer and client into two URLs (D-01 rules it out); the cockpit (no changes);
snags (Phase 47); sending anything to a client (Phase 48).

</domain>

### Decisions

- **D-01:** **The client MAY see the additional-kit list. One page, one URL — do NOT split
  engineer and client views.** SCC splits them (`/pmv/{token}` vs `/client-report/{token}`); RAMS has
  one page serving both roles and the user chose to keep it. This removes the largest piece of work
  that was on the table.

  ⚠️ **But it makes LR-04 BIND HARDER THAN IT EVER HAS.** `LabourResource` carries `name`, `email`
  AND `phone` (`app/Models/LabourResource.php:43-50`). **LR-04 — a client is never given an
  engineer's phone or email, name only** — was previously enforced on office surfaces. The client now
  reads a page that names engineers. **Only `name` may reach this page.** Assert it against the
  rendered output with a realistic email and phone present on the record, so the test cannot pass
  merely because there was nothing to leak. `tests/Feature/Security/LabourResourceClientSurfacePrivacyTest.php`
  is the home for this, and its docblock at `:55-61` forbids adding staff-auth surfaces — **this is a
  genuinely client-facing path, which is the one thing that file says may be added.**

- **D-02:** **The engineer is NOT typed. It is resolved from the visit** — *"engineer will be
  allocated when visit is booked."* `Visit::$labour_resource_ids` (array, `app/Models/Visit.php:180`)
  already holds them, and the visit reaches the worksheet by `source_type`/`source_id` (`:67-68`).
  A kit row records **which of the allocated engineers** did the work. This kills the "same name
  typed thirty times" problem and the free-text spelling drift that would wreck the office's list.

  If a worksheet has no visit, or the visit has no allocated engineers, the row must still be
  recordable — **decide and state the fallback** rather than letting it 500 on a real site.

- **D-03:** **Room photos gain a bucket: START and COMPLETION.** The user: *"Worksheet will need rooms
  start and completion pics."* Today `WorksheetPhoto` has **no bucket column** — `$fillable` is
  `worksheet_id, room_name, filename, original_name, mime_type, caption, sort_order`. SCC's shape is
  the precedent: `PmvVisitPhoto::PURPOSE_ROOM_BEFORE` / `PURPOSE_ROOM_AFTER` / `PURPOSE_KIT_PHOTO`.

  ⚠️ **Existing rows have no bucket.** Choose a default that does not silently relabel history, and
  say what it is. Photos taken before this phase are "completed work" by the old UI's own wording.

- **D-04:** **Photos can carry labels, and this is nearly free.** `WorksheetPhoto.caption` **already
  exists** — on `$fillable` (`:17`) and already validated server-side
  (`PublicWorksheetController.php:95`). **The front end simply never sends it.** It also rides the
  offline queue with **NO schema change**, because `fields` is a free-form bag already spread into
  the upload FormData at drain. ⚠️ **SCC does NOT have this feature** — its photos are bucketed but
  never captioned. This half is designed, not copied.

- **D-05:** **Serial capture feeds an asset list.** *"serial number capture for asset list etc."*
  The mechanism exists: `DeviceLabelPhoto` + OCR writes confirmed values onto a `Device`
  (`part_no, serial_number, mac_address, model, manufacturer`). What does **not** exist is the
  **list** — a per-project asset register the office can read and export. Build the surface; do not
  rebuild the capture.

- **D-06:** **Additional-kit rows are REAL ROWS, and they QUEUE OFFLINE.** *"make queue."*
  Per room, repeatable: **engineer (from D-02) · qty · part description**, "add another" as many
  times as needed, each a separate record.

  ⚠️ **RAMS has no per-room device rows to piggyback on.** SCC reuses its `pmv_visit_checks` table
  with an `engineer_added` flag; RAMS's `$equipment` comes out of
  `worksheet.generated_data['rooms'][*]['equipment']` **JSON**, which is AI-generated output, not a
  row set. **A new table is required.** Room scoping follows the existing convention — a **string**
  `room_name`, as `WorksheetPhoto` and `DeviceLabelPhoto` already do.

  **An engineer may delete their own rows and nothing else** — SCC's asymmetry
  (`PublicPmvController::deleteCheck` refuses to delete contract kit) is the precedent, and the
  server forces the flag rather than trusting the client.

### Claude's Discretion

- ~~Whether an additional-kit row also takes a photo.~~ **ANSWERED 2026-09-26 — NO.** The user:
  *"dont need kit pics , on serial cpature."* Photographic evidence of kit comes from **serial
  capture** (D-05); a kit row is **text and numbers only** — engineer, qty, part description.
  **Do not add a photo input, a thumbnail strip or an upload endpoint to a kit row.**

  This is also what keeps D-06's offline queueing tractable: a kit row has **no blob at all**, so it
  is unambiguously a non-binary record and the `drain()` branch is a clean split rather than an
  "optional blob" that has to work both ways.
- Whether "start" photos gate anything. ⚠️ If they do, the gate is **visual only** — RAMS's existing
  gates deliberately never block the server, with a written rationale that engineers on flaky
  networks must not be locked out (`PublicWorksheetController.php:261-265`). **Copying SCC's hard
  3-photo lock would contradict a documented decision.**
- The asset list's shape and whether it exports.
- Whether the office view of additional kit lives on `worksheets/show.blade.php` or the cockpit.

<code_context>
## Existing Code Insights

- ⚠️ **THE OFFLINE QUEUE CARRIES BINARIES ONLY, AND A KIT ROW HAS NO BLOB.**
  DB `engineer-worksheet`, **version 1**, store `pending_uploads`, keyPath `id` autoIncrement, index
  `capturedAt`. `drain()` unconditionally does `fd.append('photo', row.blob, …)` and routes on a
  **two-value `kind` ternary** (`'label'` → `/label-photo`, else `/photos`). A blobless row hits the
  blob append's catch and is marked **"Local blob unreadable" FOREVER**.

  **The safe route is additive: a third `kind`, branching BEFORE the blob append, and a third URL
  arm.** **DO NOT bump `DB_VERSION`, change `keyPath`, or touch the `capturedAt` index** —
  `onupgradeneeded` only ever creates, never migrates, so an upgrade would strand pending photos.
  This is a standing rule: the queue schema must not change in a way that loses queued work.
  The queue chip/panel UI also assumes every row is a photo (`_icon(kind)`, `renderList`) and must be
  taught the new kind or it renders kit rows wrong.

- **Sign-off already refuses to work offline** by explicit design (`alert('Signing off needs an
  internet connection…')`). Room-complete and survey-reviewed are plain POST+redirect with no offline
  path. Only photos queue today.

- **Rooms are JSON strings, not rows.** `$rooms = $worksheet->generated_data['rooms']`; `room_name`
  is a string join across `WorksheetPhoto`, `DeviceLabelPhoto` and the confirmations JSON, lower-cased
  and trimmed at each use site. **A renamed or regenerated room orphans everything keyed to the old
  string.** SCC has real `PmvVisitRoom` rows with an FK, which is why its rename endpoint is safe and
  a RAMS equivalent would not be. Do not add a rename.

- **TWO PRE-EXISTING BUGS SIT IN THE BLAST RADIUS. Scope them explicitly; do not inherit them
  silently.**
  1. `openPhotoLightbox(...)` is called (`:946`, `:1038`) but **never defined on this page**, and the
     component that defines it is never included. The thumbnail's `onclick` calls
     `event.preventDefault()` first, so **tapping a photo currently does nothing at all** — and this
     phase makes photos more central.
  2. The sign-off form uses Alpine (`x-data`, `x-model`, `x-show`) on a page where **Alpine is never
     loaded**, so the "outstanding items" textarea never hides or shows.

- **`{!! !!}` is pinned at exactly ONE occurrence** by
  `tests/Feature/Worksheets/SurveyCarryForwardOnEngineerLinkTest.php:330-331`. Engineer-typed part
  descriptions are unauthenticated user input rendered on a page the **client signs** — every echo
  must be escaped, including JS-built rows (reuse the `_esc` helper already on the page).

- **The public token is the only credential.** No auth, no session identity. `captured_by` stores
  `ip:…|actor:<sha256 slice>` because a UUID token fragment once leaked into that column
  (`2026_07_08_170000_backfill_device_label_photos_captured_by_leak.php` nulled every legacy value).
  **`device_label_photos.captured_by`, `worksheet_signoffs.ip_address` and `user_agent` must NEVER be
  rendered.** A new "engineer" field must not become a second place the token leaks.

- **`Worksheet` carries DELIBERATE `$fillable` omissions** from a security re-audit (`access_token`,
  `access_token_expires_at`, `submitted_notification_sent_at`). Preserve them; never mass-assign a
  token.

- Per-token throttle keys already exist for the public routes — a new endpoint needs its own.

<specifics>
## Specific Ideas

- **The acceptance test is the office admin's experience**, in the user's words: *"presented to the
  office admin as a clean list rather than free text."* Judge it by whether someone can read the
  additional kit off a screen and reconcile it against the quote without re-keying anything.
- Today the only place extra kit can land is `worksheet_signoffs.comments` — a `max:5000` textarea —
  **or a phone call.** Grep for `additional kit|extra kit|materials used|kit used` across the app
  returns **nothing**. There is no field at all today.
- The engineer link is the one surface in this app used by someone standing in a plant room with bad
  signal. Every decision here should be judged against that, not against a desk.
