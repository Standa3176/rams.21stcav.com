# Phase 46.4 Plan 03: The Two Screens the Office Reads — Summary

The asset register that D-05's capture never had, and the additional-kit table the phase is
judged on — a table in which an **added**, an **amended** and a **marked-for-deletion** row are
each legible as what they are, with the reason and the from-values actually on screen.

## Where the two screens live

| Screen | Route (name) | View | Controller |
|---|---|---|---|
| Asset list | `GET projects/{project}/asset-list` (`projects.asset-list`) | `resources/views/projects/asset-list.blade.php` | `ProjectAssetListController@index` |
| Asset CSV | `GET projects/{project}/asset-list/export.csv` (`projects.asset-list.export`) | — | `ProjectAssetListController@export` |
| Office kit table | rendered on `GET worksheets/{worksheet}` (`worksheets.show`) | `resources/views/worksheets/show.blade.php` | `WorksheetController@show` |
| Reconcile | `POST worksheets/{worksheet}/additional-kit/{row}/reconcile` (`worksheets.additional-kit.reconcile`) | — | `WorksheetController@reconcileAdditionalKit` |

All four routes are inside the existing `Route::middleware('auth')` group, with the same
`abort_unless(auth()->check(), 403)` shared-workspace guard the sibling project and worksheet
screens use. No new gate was invented and none was weakened.

**`resources/views/worksheets/public-show.blade.php` and
`app/Http/Controllers/PublicWorksheetController.php` were NOT touched** — plan 46.4-02 owns
both, and neither file appears in any of this plan's three commits (`git show --stat` on
`fea6158d`, `a475cbca`, `49271457` verified).

## 1. The asset list (D-05)

The capture existed since Phase 4 — a label is photographed, OCR'd, confirmed, and written onto a
`Device`. There was nowhere to READ it. This is the list.

A device is on the register when it carries a non-empty `serial_number`, `mac_address` or
`asset_tag`, **or** has a confirmed `DeviceLabelPhoto`. A device with none of those has not been
visited; listing it would make the register a second copy of the quote.

`assetRows()` is private and **both** actions go through it — the screen and the spreadsheet
cannot drift. The projection is explicit (`select([...])`) for the same reason `AllocatedEngineers`
selects two columns: an unfetched column cannot be rendered by accident. The label-photo relation
is touched only via `whereHas` and a `withCount`, so **no photo row is ever hydrated and
`captured_by` is never in memory, let alone on the page.**

### How rippable is it, if the user says "not that"

**Very.** It is one controller, one Blade, two route lines, and one anchor on the worksheet
toolbar. Nothing else in the app refers to it: no model change, no service, no migration, no new
CSS file, no package, no job, no cockpit entry. `git revert fea6158d` plus deleting five lines
from `show.blade.php` removes the feature entirely and leaves the kit table — the part the user
actually asked for — untouched. It shares no code with the kit table beyond Blade conventions.
This is deliberate: the shape had no D-number and the user has not seen it (planning Flag 5).

It is also deliberately **not** merged with `OmManualController::downloadAssetTemplate`, which
exports every device with blank fill-in columns as a round-trip import template. Different
question, different audience.

## 2. The office kit table (the acceptance test)

One table, `data-kit-table`, columns **Room · Engineer · Qty · Part description · Captured ·
Status · Office**, grouped by room inside the single table using plan 01's stable order
(`room_name, sort_order, id`). Row status branches on `isMarked()` / `isAmended()` — never
re-derived from `marked_for_deletion_at` or `count($amendments)`, so plan 05's server-side
enforcement and this screen cannot drift.

### The marked row is PRESENT — the assertions that prove it

Every marked-row test asserts the row before it asserts the marking:

```php
// ⚠️ PRESENCE FIRST. …catches a screen which filtered marked rows
// out and then still printed the word "Marked" somewhere.
$response->assertSee('Trunking, 50x50 white', false);
// THEN the marking.
$response->assertSee('Marked for deletion', false);
// AND the reason, verbatim.
$response->assertSee('Ordered twice — only one length fitted.', false);
```

and it is not moved into a second table:

```php
$this->assertStringContainsString('Open row — HDMI 2.1 lead, 3m', $content);
$this->assertStringContainsString('Marked row — Backbox, 35mm', $content);
$this->assertSame(
    1,
    substr_count($content, 'data-kit-table'),
    'The marked row was split into a second table — the office reconciles ONE list.',
);
```

A marked row with a NULL reason renders `No reason recorded`, not a blank cell.

### The amended row's FROM-values render — the assertions that prove it

```php
// The CURRENT values.
$response->assertSee('Trunking, 75x75 white', false);
// The chip.
$response->assertSee('Amended', false);
// ⚠️ THE FROM-VALUES. Without these the screen is silently showing the
// latest values, which is the exact failure D-08 exists to prevent.
// 'Trunking, 50x50 white' exists NOWHERE on this row's current state —
// if it renders, it came from the trail.
$response->assertSee('Trunking, 50x50 white', false);
$response->assertSee('qty: 3 → 5', false);
```

The trail is a `<details>` collapsed by default (asserted: the page contains `<details` and does
not contain `<details open`) and renders oldest-first (asserted by comparing `strpos` of
`qty: 1 → 4` against `qty: 4 → 9`). A row that is **both** amended and marked shows both.

### Reconcile works on a marked row — confirmed

`test_a_marked_row_CAN_be_reconciled` posts reconcile at a marked row and asserts
`reconciled_at` is set, `isMarked()` is still true (reconciling does not silently unmark), and
the row still shows its marking and its reason afterwards. Refusing would have left every marked
row outstanding on the office's list forever.

It is idempotent (a second post does not move the timestamp — asserted with `travel(2)->minutes()`),
ownership-checked (`abort_unless($row->worksheet_id === $worksheet->id, 404)`), authenticated-only,
and assigns `reconciled_at` **explicitly** because the column is off `$fillable` by design.

The control says what it costs, on screen and asserted:
`test_the_reconcile_control_says_out_loud_what_it_costs_the_engineer` pins
*"the engineer can no longer amend or mark it"*.

### `deletion_reason` is treated as engineer free text, not metadata

It is in the escaping assertions — `test_a_hostile_deletion_reason_is_escaped` seeds
`<script>alert(2)</script>`, asserts the row is present (non-vacuity), asserts the raw form is
absent and asserts the escaped form `&lt;script&gt;alert(2)&lt;/script&gt;` IS present — and it is
in the leak test's non-vacuity set (`$response->assertSee('Not needed.', false)` before the actor
assertions fire).

### Actor stamps and contact details

`test_no_actor_stamp_reaches_the_office_table` seeds `created_by_actor`, `marked_by_actor` **and**
`amendments[0].actor` with realistic values (`ip:198.51.100.9|actor:c0ffee1234567890`,
`ip:198.51.100.10|actor:abad1dea98765432`), asserts the row, the reason and the trail all rendered
first, then asserts every stamp, every hex slice and every IP absent.

On the asset list, `captured_by` is seeded as `ip:10.0.0.1|actor:deadbeefcafe` on a confirmed
label photo whose device IS on the page, and asserted absent from both the HTML and the CSV.

`worksheet_signoffs.ip_address` / `user_agent` are not read by anything this plan added — neither
column is selected, referenced or rendered on either new surface.

LR-04: the engineer fixture carries `rachel.okafor@example.test` and `07700 900123`; the name
renders and both are asserted absent. The mechanism is the constrained
`additionalKit.labourResource:id,name` eager load in `WorksheetController::show()`, commented as
load-bearing. **The projection was not widened** — the office screen needs no contact detail, and
if it ever does, that is a decision to put to the user, not a column to add here.

## Deviations from Plan

**1. [Rule 1 — test bug] The CSV header assertion was written as it reads in a spec, not as PHP
writes it.** `fputcsv` quotes any field containing a space, so the real header line is
`Room,Description,Manufacturer,Model,"Part No",Qty,"Serial Number","MAC Address","Asset Tag"`.
The assertion was corrected to the actual bytes rather than the column names being renamed to
avoid quoting — the office reads the header, and `Part No` is the right label.

**2. [Rule 2 — missing critical] The "Reconciled" column header was renamed "Office".** With a
column literally headed `Reconciled`, `assertSee('Reconciled')` after reconciling would have
passed on a page where nothing was reconciled. The header is now `Office`, and the cell shows
`✓ Reconciled` + the timestamp or the `Mark reconciled` button, so the assertion is real.

**3. [Rule 2] Defensive parsing in the trail.** `amendments[].at` and the `from`/`to` values come
from a JSON column that a raw insert can reach. The timestamp parses through `rescue(..., null,
false)` (report suppressed) and falls back to `Date not recorded`; a non-scalar `from`/`to`
renders `—`. One bad legacy row must not 500 an office screen.

**4. [Rule 2] One extra escaping test beyond the plan's list.** Device serials reach `devices`
from OCR of a photo taken on an unauthenticated link, so `test_an_ocr_derived_value_is_escaped_on_
the_page` treats them as untrusted too.

## Is the acceptance test met?

**Yes, for the office half — with one honest caveat.**

Someone can read the kit off `worksheets/{worksheet}` and reconcile it against the quote without
re-keying anything: every line carries its room, a named engineer (or a named gap), a quantity, a
part description, when it was captured, whether the engineer has since amended it (and from what),
whether they have asked for it to come off (and why), and a one-click tick recording that the
office has dealt with it. That is the replacement for "a `max:5000` comments textarea, or a phone
call".

**The caveat: nothing writes these rows yet.** Plan 46.4-05 builds the engineer-link endpoints
that add, amend and mark. Until it lands, this table is correct and empty on every real worksheet.
The office experience is therefore *demonstrated by tests, not yet by data* — worth saying plainly
at the 46.4-07 checkpoint rather than presenting a screen the user cannot exercise.

**`npm run build` was NOT made necessary.** No CSS file was created or edited; the kit table and
the asset list use classes already defined in `layouts/app.blade.php` plus the inline-style idiom
those views already use.

## Things noticed and deliberately left alone

- **`openPhotoLightbox` on the office page.** `worksheets/show.blade.php` calls it from the
  completed-work and label-photo thumbnails. Plan 46.4-02 has been fixing the lightbox on the
  ENGINEER link; whether the office page's copy is now also fine is 02's territory to report, not
  mine to touch mid-flight. Not in scope; not modified.
- **There is still no `unmark`.** Carried from plan 01's known gaps. If an engineer marks a row by
  mistake, the office cannot undo it from this screen either — reconcile is the only control here,
  because what to do with a marked row is a conversation, not a button the user asked for.
- **`amendments` cannot be queried across rows.** Plan 01 named the promote-to-
  `worksheet_additional_kit_events` trigger; this screen reads one row's trail at a time and does
  nothing to bring that moment closer.
- **~110 untracked PNG screenshots and a stray `nul` in the repo root.** Pre-existing; not mine,
  and `git clean` is prohibited.
- **The asset list has no pagination.** A project with thousands of captured devices would render
  one long page. Real projects are tens of devices; adding pagination to a screen the user may
  reject would be building on sand.
