# Phase 46.4 Plan 05: Additional Kit — Add, Correct, Mark Summary

The thing the phase is named for. An engineer standing in a room can now record extra kit as
**rows** — tapping Add as many times as the job needs, without the page reloading — **correct** a row
in a way that leaves a trail instead of an overwrite, and **mark** a row for deletion with a reason
that the office reads. **Nothing is ever hard deleted, and `DELETE` on a kit row is 405.**

Before this plan the only place extra kit could land was the sign-off comments textarea or a phone
call. It now lands in the table plan 03 already built a screen for.

## The three endpoints

| Verb | URI | Name | Success |
|---|---|---|---|
| POST | `worksheet/{token}/additional-kit` | `public-worksheet.additional-kit.add` | 201 + the row |
| POST | `worksheet/{token}/additional-kit/{row}` | `public-worksheet.additional-kit.modify` | 200 + `amended: true` |
| POST | `worksheet/{token}/additional-kit/{row}/mark-deleted` | `public-worksheet.additional-kit.mark-deleted` | 200 + `marked: true` |

All three on `throttle:worksheet-kit-write` — **30/min, keyed per-token** with the load-bearing
`?: $request->ip()` fallback. 30 because a kit row is a *text* write with no AI cost and no file I/O,
so it belongs with `worksheet-photo-write` and not the 15/min label route — and because an engineer
adding fifteen items in a burst must not be 429'd half way down the list.

**No `DELETE` route. No `unmark`. No `restore`. No soft-delete trait.**

## Nothing is hard deleted — the 405, quoted

The URI exists (modify lives there), so the router knows it and has **no DELETE verb** for it. That
is a stronger statement than a 404 would be:

```php
$this->delete($this->modifyUrl($worksheet, $row->id))->assertStatus(405);

$this->assertDatabaseHas('worksheet_additional_kit', ['id' => $row->id]);

// And no route anywhere in the app hard-deletes a kit row.
foreach (Route::getRoutes() as $route) {
    if (str_contains($route->uri(), 'additional-kit')) {
        $this->assertNotContains(
            'DELETE',
            $route->methods(),
            "A DELETE route was registered on an additional-kit URI ({$route->uri()}) — D-08 forbids it.",
        );
    }
}
```

And the row survives its own marking — the assertion that catches a future "optimisation":

```php
$kit = $worksheet->fresh()->additionalKit;

$this->assertCount(1, $kit);
$this->assertSame('Trunking, 50x50 white', $kit->first()->part_description);
$this->assertTrue($kit->first()->isMarked());
$this->assertDatabaseHas('worksheet_additional_kit', ['id' => $row->id]);
```

## Append-only, proven byte-for-byte

The trail is built by diffing the validated payload against the row **before** saving, so only fields
that actually moved are recorded. The first entry is then compared **byte-for-byte** after a second
modify:

```php
$firstEntry     = $row->fresh()->amendments[0];
$firstEntryJson = json_encode($firstEntry);

$this->travel(2)->minutes();

$this->postJson($this->modifyUrl($worksheet, $row->id), ['qty' => 9])->assertOk();

$row->refresh();

$this->assertCount(2, $row->amendments);
// BYTE-FOR-BYTE. An office that cannot see what a row USED to say cannot reconcile it.
$this->assertSame($firstEntryJson, json_encode($row->amendments[0]));
$this->assertSame($firstEntry, $row->amendments[0]);
// Oldest first, and the second entry starts where the first ended.
$this->assertSame(['from' => 5, 'to' => 9], $row->amendments[1]['changes']['qty']);
```

**An unchanged field is ABSENT, and the absence is the assertion** — a pre-filled drawer posts the
description back unchanged, and the trail must not record it:

```php
$this->assertArrayHasKey('qty', $changes);
// ⚠️ THE ABSENCE IS THE ASSERTION. A trail of {from: x, to: x} entries is noise
// the office stops reading, and a trail nobody reads is not an audit trail.
$this->assertArrayNotHasKey('part_description', $changes);
$this->assertSame(['qty'], array_keys($changes));
```

**The no-op is refused, so the trail can never gain an empty entry:**

```php
$response->assertStatus(422);
$this->assertStringContainsString('Nothing changed.', $response->getContent());

$row->refresh();
// An EMPTY amendment is worse than no amendment.
$this->assertSame([], $row->amendments);
$this->assertNull($row->amended_at);
$this->assertFalse($row->isAmended());
```

Changing description **and** engineer in one request appends **ONE** entry carrying both — one entry
per request, not one per field.

## A second mark cannot rewrite the first explanation

`assertRowIsOpen()` refuses an already-marked row, and **that refusal is the mechanism** — there is
no "update the reason" path to guard:

```php
$this->travel(5)->minutes();

$this->postJson($this->markUrl($worksheet, $row->id), [
    'deletion_reason' => 'Actually it was the wrong colour.',
])->assertStatus(422);

$row->refresh();

// A SECOND MARK MUST NOT OVERWRITE THE FIRST EXPLANATION.
$this->assertSame($firstReason, $row->deletion_reason);
$this->assertSame($firstStamp, $row->marked_for_deletion_at->toIso8601String());
$this->assertSame($firstActor, $row->marked_by_actor);
$this->assertStringNotContainsString('wrong colour', (string) $row->deletion_reason);
```

Reason floors: missing → 422, whitespace-only → 422 (trimmed before validation so a JSON caller gets
the same rule as a form post), under 3 characters → 422, over 500 → 422. Marking a **reconciled** row
→ 422.

body carries the lock sentence and **not** a field name.

## The verbatim 422 texts — plan 46.4-06 must surface these

Captured from real HTTP responses, not transcribed from the source:

| Case | HTTP | `message`, verbatim |
|---|---|---|
| signed (all three endpoints) | 422 | `This worksheet has been signed off — it can no longer be changed.` |
| nothing changed | 422 | `Nothing changed.` |
| already marked | 422 | `This row is already marked for deletion — the office will action it. Its original reason stays on the record.` |
| already reconciled | 422 | `The office has already reconciled this row — it can no longer be changed here.` |
| blank / whitespace reason | 422 | `The deletion reason field is required.` |
| reason under 3 chars | 422 | `The deletion reason field must be at least 3 characters.` |
| reason over 500 chars | 422 | `The deletion reason field must not be greater than 500 characters.` |
| forged room name | 422 | `Unknown room name.` |
| worksheet with no rooms | 422 | `Worksheet has no rooms — cannot record additional kit.` |
| engineer not on the visit | 422 | `That engineer is not allocated to this visit.` |
| row on another worksheet | 404 | `Kit row not found on this worksheet.` |

The two state refusals are deliberately **distinct sentences**: an engineer who cannot tell *why*
a row refused rings the office, which is the cost this feature exists to remove.

## The page: vanilla, one drawer, no framework

Alpine is never loaded here, so RAMS's own repeaters would have silently no-opped. The drawer is
copied in **shape** from SCC's PMV add-device drawer and imports nothing.

- **One query** for the whole worksheet, partitioned by trimmed lower-cased `room_name` — the
  `WorksheetPhoto` / `DeviceLabelPhoto` convention, not one query per room.
- **Per-room list:** `Qty × Part description — Engineer name`, an `Amended` chip and a
  `Marked for deletion — <reason>` chip, worded exactly as plan 03 words them for the office, so an
  engineer on the phone and an admin at a desk describe the same row the same way. Both chips are
  independent checks — a row that is both shows both. A marked or reconciled row shows state and
  **no controls**.
- **ONE page-level drawer** after the room loop, `data-mode` switching between *Add* and
  *Save correction*, with a backdrop, `role="dialog" aria-modal="true"`, a 44px close target, and
  44–48px inputs throughout.
- **Add does not reload:** the returned row is grafted in, qty resets to 1, the description clears,
  **the engineer is kept and the drawer stays open**.
- **A failure does not clear the form.** The server's own sentence goes in the status line — which is
  how the lock's message reaches an engineer whose worksheet was signed while the drawer was open.
- **The mark prompt is a dialog, not `confirm()`** — a confirm box cannot collect a reason, and here
  the text *is* the payload. Submit stays disabled under 3 non-whitespace characters, the same floor
  the server enforces, so the button never promises a 422.
- Every new control carries **`data-capture-control`** and reads **`$captureLocked`** — no second
  flag was invented.

### The offline ruling, surfaced rather than hidden

`ADD` works offline (plan 06 queues it). **`CORRECT` and `MARK` do not** — they diff against the
row's current server-side state, and a queued correction could drain onto a row the office had
already reconciled. So both render **visibly disabled reading `Needs a connection`**, bound to the
`online` / `offline` events rather than page-load time, and **say so on tap**. What was not
acceptable was a control that looks like it worked and silently loses the change.

## Deviations from Plan

**1. [Rule 1 — test-side] Four lock assertions had to read the DECODED json.**
`WorksheetCaptureLock::MESSAGE` contains an em dash, which `json_encode` escapes to `—`, so
`assertStringContainsString` on the raw body failed on the *encoding*, not the behaviour. Swapped to
`$response->assertJson(['message' => WorksheetCaptureLock::MESSAGE])`, which decodes first. Not a
loosening — it is a stricter comparison of the same string.

**2. [Rule 1 — test-side] The signed-rendering assertion keys off Blade-ONLY copy.**
`data-kit-trigger` and `Mark for deletion</button>` both appear inside the drawer's **script**, which
renders unconditionally, so an attribute-name assertion failed on the JS. The test now asserts
`+ Add additional kit` and `Tap to open — add one or several before closing.` are absent — strings
that exist nowhere else on the page. Recorded in the test as a comment so the next reader does not
"fix" it back.

**3. [Rule 1 — my assertion was wrong, not the code] The NULL-engineer check is scoped to the ROW.**
The allocated engineer's name legitimately appears elsewhere on the page — as an `<option>` in the
picker, which is D-02 working exactly as specified. The test now extracts the `<li data-kit-row=…>`
element and asserts the unassigned sentence is inside it and the name is not, with the row's presence
asserted first so it cannot pass vacuously. Contact details are still asserted absent from the whole
page.

**4. [Stated, not taken silently] `_esc` is a local copy, not the page's existing one.**
The plan said reuse it. The existing `_esc` lives inside the queue panel's own IIFE and is **not
exported**; reaching into that closure or promoting it to a global would edit plan 46.4-06's
territory. A five-replace copy with a comment naming the original was the smaller change. The two are
character-identical and escape the same five characters.

**5. Plan 04's forward-reference comment was rewritten, not deleted.**
Task 2(h) said delete it. It was the comment telling this plan to use `$captureLocked`; deleting it
would have removed the "do not invent a second flag" rule along with the stale pointer. It is now
present tense — the rule kept, the pointer gone.

**6. Offline controls use `aria-disabled`, not the `disabled` attribute.**
A natively disabled button fires no click, and the plan also requires a **toast on tap**. The two
requirements are incompatible, so the controls carry `aria-disabled="true"`, reduced opacity and the
words `Needs a connection`, and remain tappable purely to explain themselves.

**7. The empty-allocation `<option>` is `selected disabled`, and submittability is preserved.**
The plan required both. A selected-but-disabled option would be a problem for a native form submit;
this drawer builds its own payload in JS from `select.value` (which is `''`), so the form stays
submittable exactly as D-02's fallback requires.

**8. The `<ul data-kit-list>` renders even when empty.**
A grafted row needs a home that exists before the first row does. Empty, the list displays nothing
and its title is `display:none`, so "a room with none shows nothing" holds as written.

**9. `UNASSIGNED_ENGINEER` lives on the controller and the view reads it.**
A view referencing a controller constant is unusual. The alternative — putting it on
`AllocatedEngineers` — meant editing a file outside this plan's `files_modified`. One definition
shared by the JSON response and the server-rendered fallback was worth the oddity; the two must be
the same sentence.

### Harness observation — the stall, reproduced a fourth and fifth time

`tests/Feature/Cockpit tests/Unit/Cockpit` run) and `-Baseline` (a single `artisan test` with twelve
paths). Both were **direct file redirects, not pipes**, and nothing else was running. In each case
three `php` processes accrued **~0.02 s of CPU across 40–45 s of wall clock** and sat flat for over
ten minutes.

is the kill. No figure was taken from either.** The cockpit gate was re-run as its **two halves,
one suite per invocation** (295 in 146.88s, 92 in 11.71s); `-Baseline` completed normally in 32.75s
on a straight retry. The pattern from waves 1, 2 and 4 holds: **batching several paths into one
invocation is itself enough to trigger it.**
