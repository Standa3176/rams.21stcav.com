    Add a `bucket` string column to `worksheet_photos`, NOT NULL, default `'completion'`, indexed
    together with `room_name` (`['worksheet_id', 'room_name', 'bucket']`) because every read in
    plans 02 and 03 is "this room's photos in this bucket".

    **The D-03 ruling, and it goes in the migration's own docblock, not only here:** existing rows
    are **explicitly** backfilled to `completion` by a statement in `up()` — not left to the column
    default. The relabel is deliberate and correct: the tray these photos were captured through is
    titled, verbatim, `📷 Photos of completed work` (`public-show.blade.php:938`). Calling them
    `completion` restates the label the engineer was already reading; calling them `start` or
    leaving them NULL would invent a distinction nobody made. Write that sentence into the
    migration. The counter-argument — that a legacy row is really "unbucketed" — is recorded and
    rejected, because a third `unknown` bucket would have to be rendered somewhere forever and the
    office would have to learn what it means.

    `down()` drops the column and the index; it does NOT try to restore a distinction that never
    existed.

    Add `bucket` to `WorksheetPhoto::$fillable` and add `BUCKET_START = 'start'`,
    `BUCKET_COMPLETION = 'completion'` and `BUCKETS` constants. Do not add a cast; it is a string.
  </action>
