<objective>
Teach the offline queue a **third kind** so a kit row survives a plant room with no signal (D-06,
*"make queue"*) — **additively**, without touching the schema that every pending photo depends on.

Purpose: this is the single most dangerous change in the phase and it gets its own plan and its own
green gate for that reason. `drain()` today **unconditionally** does
`fd.append('photo', row.blob, …)` and routes on a **two-value `kind` ternary**. A kit row has no
blob, so as things stand it would hit that append's catch and be marked **"Local blob unreadable"
FOREVER** — an engineer's work, lost silently, on the one surface used by someone standing in a
plant room.

Output: a `kit` kind that branches BEFORE the blob append, a third URL arm, a queue panel that names
it, and guards that pin the schema.
</objective>

**The schema — DO NOT CHANGE ANY OF IT:**
  DB_NAME 'engineer-worksheet' · **DB_VERSION 1** · STORE 'pending_uploads'
  `createObjectStore(STORE, { keyPath: 'id', autoIncrement: true })`
  `store.createIndex('capturedAt', 'capturedAt', { unique: false })`
⚠ `onupgradeneeded` only ever **creates** the store — it has no migration branch. Bumping
DB_VERSION would fire an upgrade against an existing store and the handler would do nothing, but any
future reader assuming a migrated shape would be wrong, and a keyPath or index change **strands
every photo already queued on every engineer's phone**. The queue's own record is the engineer's
only copy. Treat this schema as immutable.

**`OfflineQueue.enqueue(row)`** — `row = {token, kind, room, blob, mime, fields}`; stores
`{token, kind: row.kind || 'completed', room, blob, mime, fields: row.fields || {},
attemptCount: 0, lastError: null, capturedAt: Date.now()}`. `fields` is a **free-form bag**;
nothing in the store's shape needs to change for a kit row.

**`OfflineQueue.drain(opts)`** — the three places that must change, in order:

  1. THE BLOB APPEND (this is the bug):
        const fd = new FormData();
        try {
            fd.append('photo', row.blob, (row.kind === 'label' ? 'label.jpg' : 'photo.jpg'));
        } catch (e) {
            row.attemptCount = (row.attemptCount || 0) + 1;
            row.lastError = 'Local blob unreadable';
            …
        }
  2. `fd.append('room_name', row.room || '')` then the fields spread — **both already correct for a
     kit row**; a kit row needs `room_name` and its fields and nothing else.
  3. THE URL:
        const path = row.kind === 'label' ? '/label-photo' : '/photos';

**The panel UI** (a separate IIFE, ~:2631+): `_esc(s)`, `_relTime(ts)`,
`_icon(kind) { return kind === 'label' ? '📷' : '🖼'; }`, `_statusFor(row)`, `renderList(items)` —
which prints `row.kind === 'label' ? 'Box serial label' : 'Completed-work photo'` as every row's
subtitle. **Both assume every row is a photo.**

`OfflineQueue.list()` projects `{id, token, kind, room, mime, fields, attemptCount, lastError,
capturedAt}` — note it does NOT project the blob, so the panel already works for a blobless row.

Auto-drain: `_autoDrain(reason)` fires on the `online` event and a 60s tick, guarded by
`_draining`; it calls `drain({ onSuccess: window.__lcHandleLabelUploadSuccess })`. Drain sleeps
200ms between rows for throttle compliance.

From plan 04: `POST /worksheet/{token}/additional-kit` accepts `room_name`, `labour_resource_id`
(nullable), `qty`, `part_description` and returns 201. Its throttle is `worksheet-kit-write`,
30/min per token — comfortably above drain's 5/sec-capped serial loop.
