# Phase 46.4 Plan 01: Install-Capture Foundations Summary

Three contracts the rest of the phase writes against — the photo **bucket**, the
**additional-kit table**, and the **allocated-engineer resolver** — with four rulings answered in
writing before any UI exists to make them expensive to change. **No Blade file was touched.**

## What shipped

### 1. `worksheet_photos.bucket` (D-03)

`start` / `completion`, NOT NULL, default `completion`, on a `['worksheet_id','room_name','bucket']`
index — the shape of every read in plans 02 and 03.

**The backfill is explicit, and it is load-bearing.** A column added `NOT NULL DEFAULT 'completion'`
fills existing rows with the default on both MySQL and SQLite, which would have made any backfill
underneath it a no-op that *reads* like a decision. So:

1. the column arrives **NULLABLE**,
2. `DB::table('worksheet_photos')->whereNull('bucket')->update([...])` stamps every pre-existing row,
3. only then is it tightened to NOT NULL + default,
4. and the index is created **after** the `->change()`, because on SQLite a column change rebuilds
   the table.

The ruling, and the **rejected** `unknown` third bucket, are in the migration docblock, quoting the
tray title the decision rests on: `📷 Photos of completed work` (`public-show.blade.php:938`).

⚠️ **That tray title is now load-bearing. A later plan in this phase must not change it.**

### 2. `worksheet_additional_kit` (D-06 / D-08 / D-10)

The first structured field for extra kit in RAMS — a grep for
`additional kit|extra kit|materials used|kit used` across the app returned **nothing**.

**Six columns fillable, eight deliberately not.** `room_name` is a **string**, per the existing
`WorksheetPhoto` / `DeviceLabelPhoto` convention — rooms are JSON, there is nothing to point an FK
at, and **no rename was added**. `labour_resource_id` is nullable `nullOnDelete`.

**Nothing is ever hard deleted.** No delete path, no soft-delete trait, no `deleted_at`.
`Worksheet::additionalKit()` returns marked rows **on purpose**, and its docblock says why.

`amendments` reads as a list unconditionally, via an `Attribute` accessor rather than an `'array'`
cast — an `'array'` cast returns NULL for a NULL column, and every reader would then need its own
`?? []`.

### 3. `App\Support\Worksheets\AllocatedEngineers` (D-02, LR-04)

`forWorksheet()` returns **a plain array of `['id' => int, 'name' => string]`** — never a model,
never a collection. Two mechanisms, both load-bearing and both commented as such: an explicit
`->select(['id', 'name'])` so the hydrated models never *hold* an email or a phone, and
`LabourResource::toClientSafeArray()`, which only ever builds those two keys.

All three D-02 fallbacks are asserted, plus two more: no visit, empty allocation, deleted resource,
NULL allocation, all-gone allocation. `scopeActive()` is deliberately **not** applied (LR-02).

## Deviations from Plan

**1. [Rule 3 — blocking] The migration design had to change to make the backfill real.**
The plan said "NOT NULL default `completion`, and every pre-existing row explicitly backfilled in
`up()`". Those two clauses are in tension: with a default, the backfill can never do anything. The
nullable-add → backfill → tighten sequence delivers the plan's *intent* — a decision somebody has to
read — rather than its literal shape. Documented in the migration docblock and pinned by
`test_the_backfill_is_an_explicit_statement_and_not_the_column_default()`.

**2. [Rule 2 — missing critical] `created_via` got a default.** The plan specified `string 32` with
no default, but the column is off `$fillable`, so any `create()` would have violated NOT NULL. It
defaults to `CREATED_VIA_ENGINEER_LINK` — the only writer this phase introduces — and the
mass-assignment test asserts a caller-supplied `'office'` value does **not** stick.

**3. [Rule 2] Two fallbacks added beyond the three the plan named.** A NULL `labour_resource_ids`
(reachable — it is an array cast on a nullable column) and an allocation where *every* named
resource is gone. Both return `[]` rather than throwing.

**4. ROADMAP criterion 2 annotated, not rewritten.** Criterion 2 still says an engineer "may delete
their own rows". D-08 replaced that with mark-with-a-reason and D-09 recorded that "own" is not
per-person. The line is left as written with a superseded note, following the DL-04 precedent.

## Known gaps, carried rather than solved

- **There is no `unmark` and no `restore`.** D-08 gives the engineer add, modify and mark, and does
  not give them a way back. If an engineer marks a row by mistake, today the office fixes it.
  **Worth putting to the user at the 46.4-07 checkpoint.**
- **The `amendments` promote-to-rows trigger, named:** if Phase 47 or 49 needs a **cross-row**
  amendment query — "everything amended this week", or any filter not scoped to one kit row —
  promote the column to a `worksheet_additional_kit_events` table. Do not write a JSON search.
- **IC-07's enforcement is not built.** The sign-off lock (D-07) is plan 46.4-04's; this plan
  delivered only the shape.
