<objective>
Build the two screens the office reads: the **asset list** (D-05) and the **additional-kit list**
(the acceptance test, in the user's words — *"presented to the office admin as a clean list rather
than free text"*).

Purpose: D-05's capture mechanism already exists — `DeviceLabelPhoto` + OCR already writes serials
onto `Device`. What has never existed is a place to READ it. And additional kit has never existed at
all; today it lands in a `max:5000` comments textarea or a phone call. **This plan is where the
phase is judged.**

Output: a per-project asset list with a CSV export, and a per-worksheet additional-kit table in
which an added row, an **amended** row and a row **marked for deletion** are each legible as what
they are.

**REVISED 2026-09-26 after D-08.** The original plan's table had one row state. It now has three,
and the reconcile tick has to cope with all of them.

**This plan runs in parallel with 46.4-02.** It shares not one file with it: 02 owns
`public-show.blade.php` and `PublicWorksheetController.php`; this plan owns the office side.
</objective>

      idempotent.
    - **A marked row CAN be reconciled** — reconciling means *the office has actioned this row*,

      outstanding on the office's list, which is exactly the "can't action it" failure D-08 exists
      to prevent.
    - Only an authenticated staff user can reconcile.

    - `part_description` AND `deletion_reason` containing `<script>alert(1)</script>` each render
