<objective>
Ship GATE-09 as a new step inside `RamsComplianceUpgradeService::upgrade()` that
independently re-validates every display item's stated team size against
`DisplayLiftPolicy::violatesPolicy()` and throws when it disagrees, reusing the
codebase's existing blocking-error mechanism (`BuildRamsDocumentJob::handle()`'s
`catch (\Throwable $e)` -> `RamsDocument.status = FAILED` -> `error_message` rendered
on `rams/index.blade.php`) rather than inventing a validation framework. Gate the
throwing behaviour behind a new `RAMS_DISPLAY_LIFT_GATE` env flag, mirroring
`RAMS_HAZARD_LIBRARY_TIERING` exactly, since this milestone requires every
live-validated safety change to be one `.env` edit from off.

Purpose: GATE-09 is this phase's fourth requirement and, per CONTEXT.md, establishes
the enforcement mechanism the remaining six gates (06/07/11/12/13/14) will reuse —
treat the exception type and the catch/surface path as a real architectural decision,
not a one-off.

Output: `RamsComplianceUpgradeService::enforceDisplayLiftGate()` (new private
static method, wired into `upgrade()`'s pipeline after `deriveMaterialHandling()`);
`config/rams_tier1.php`'s new `display_lift_gate_enabled` key; a unit test proving
throw/no-throw boundaries; a feature test proving both generation entry points agree;
a structural guard test proving no file computes a divergent copy of the bands.
</objective>
