<objective>
Close GATE-09's production coverage hole: extend `enforceDisplayLiftGate()` to also
validate the **engineer-typed** `material_handling.large_items[]` rows, not only the
policy-derived `material_handling_derived.items`.

**Why this plan exists.** Plan 27-03 shipped GATE-09 exactly as planned, and the plan
explicitly instructed *"`material_handling.large_items` … is explicitly OUT of this
gate's scope … Do not scan it."* That instruction, followed correctly, produced a gate
that **cannot fire in production**: the derived items it does check are generated by
`deriveMaterialHandling()` → `suggestHandlingMethod()` → `DisplayLiftPolicy::forSize()`
one line earlier in the same pipeline, so they are conformant by construction. Proving
the gate fires at all required a Mockery `alias:` mock of `DisplayLiftPolicy` — the
signature of a check that no real data can trip.

Meanwhile `material_handling.large_items` is a free-text form field on the RAMS review
screen (`resources/views/rams/review.blade.php:701-749`, persisted by
`RamsController.php:496-497`) that renders straight into the **live** DOCX
(`DocxBuilderService.php:1751`) and the live PDF (`resources/views/pdf/rams.blade.php:419`).
An engineer can type "Team lift — minimum 4 persons" and it reaches a client-facing pack
unchecked. That is precisely the defect class the 21CQ30960 professional review raised and
that GATE-09 was written to catch — REQUIREMENTS.md's GATE-09 and ROADMAP criterion 3 both
say *"any **reviewed** or generated RAMS"*, and "reviewed" means engineer-entered data.

**User decision, 2026-08-26.** Shown that the gate was a no-op and offered four options
(extend to engineer rows / warn-only / ship-as-is with a follow-up / pause for Ali), the
user chose **extend the gate to engineer-typed rows**. This deliberately makes an
exception to the codebase's "engineer values always win, never re-validated" convention
(HAZ-04's `score_reviewed` precedent), on the grounds that a stated lift team size is a
safety claim rather than a preference. Record that exception in the SUMMARY — it is a
convention break made on purpose, not an oversight.

Output: `enforceDisplayLiftGate()` extended with an engineer-row pass; a conservative
free-text team-size parser; a unit test proving both the enforce cases and the
must-not-block-on-ambiguity cases; and an extension to `DisplayLiftDualPathTest` proving
the gate now fires on both real generation entry points **without** mocking
`DisplayLiftPolicy`.
</objective>
