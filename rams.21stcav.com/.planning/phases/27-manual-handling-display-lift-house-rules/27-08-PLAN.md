<objective>
Close Blocker 1 from `27-VERIFICATION.md`: the hazard library's control text never reaches a
RAMS regenerated from existing reviewed data, which is most real jobs.

**The evidence.** Live regeneration of 21CQ30960 (RAMS 100, 2026-08-26) rendered the Manual
Handling hazard as *"Use mechanical aids … for items **over 20 kg**"* and *"Team lift
required for **screens and equipment over 40"** — minimum two persons"*. Neither is the
pre-Phase-27 seeded text nor the corrected text verified in the live `hazard_templates`
table the same day — it is stale `reviewed_data` passed straight through. The surviving text
violates RULE-13 (banned kg threshold) and contradicts RULE-02 (a 40″ display is a
single-operative lift under the agreed bands).

**The cause.** `reviewedToRisk()` maps reviewed hazards 1:1 and calls `resolveFromSeeds()`
only to fill *missing* controls. Plan 26-08 made it replace controls on a **genuine rename**;
`Manual handling` already matches the canonical library name, so no rename fires and the
legacy controls survive.

**Why this matters beyond Phase 27.** Phases 28 and 31 correct house-rule text in the same
library, reached by the same path. Unless this is fixed first, their corrections will be
defeated the same way, on the same jobs, and the same green test suite will hide it.

**The policy (user decision, 2026-08-26), a two-tier union:**
1. **Replace where the reviewed text violates a known house rule** — always, engineer-edited
   or not. A house rule is a settled safety position, not a preference.
2. **Replace whenever the engineer never edited the controls** — the library has moved on and
   there is no human intent to protect.
3. Otherwise the engineer's text stands.

**The provenance mechanism — mirror `score_reviewed`, do not invent one.** The codebase has
already solved this exact question for scores: `RamsBuilderService::reviewedToRisk()` gates
score precedence on a `score_reviewed` marker, and its own comment states the rule —
*"No human ever touched this score through the numeric UI (score_reviewed false or absent) —
the library's typical value wins outright."* Controls get the symmetric `controls_reviewed`
marker, set the same way, read the same way. This also handles legacy documents correctly:
RAMS 99/100 carry no marker, so the library wins and the stale text is replaced.

Output: a `ControlTextRuleViolations` registry; `controls_reviewed` threaded through the
review form, the four builder/DTO services and `reviewedToRisk()`; tests proving all three
policy branches; and a regeneration of 21CQ30960 that no longer carries the banned text.
</objective>
