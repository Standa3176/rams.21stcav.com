## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `SurveyService::update()` would null historical comms-room data on the next office edit**
- **Found during:** Task 3 (D-08, office edit screen comms-room removal)
- **Issue:** `SurveyService::update()` wrote `'comms_room_access_status' => $data['comms_room_access_status'] ?? null` (and the `_notes` sibling) unconditionally on every `site-surveys.update` POST. Once `edit.blade.php` stopped submitting those fields (D-08), `$data` would never contain the keys, and every subsequent office edit of ANY survey — including surveys with a real historical comms-room value — would silently null that value on save. This directly violates D-03's explicit "stored values on past surveys must survive on disk," which both D-03 and D-08's own text restate.
- **Fix:** Changed both lines to `$data['comms_room_access_status'] ?? $survey->comms_room_access_status` / `$data['comms_room_access_notes'] ?? $survey->comms_room_access_notes` — preserves the existing value when the key is absent, matching the method's own existing pattern for `project_id`/`project_name`/`survey_type` three lines above.
- **Files modified:** `app/Core/Modules/Survey/SurveyService.php` — **outside this plan's `files_modified` list.**
- **Verification:** `php -l` clean; full baseline gate (`>= 159 passed AND 0 failed`) green; `tests/Feature/Documents`, `tests/Unit/Visits`, `tests/Feature/Worksheets`, `tests/Feature/Rams/CommsRoomRemovedFromRamsFeedTest` all green (these exercise the downstream readers of the columns this fix protects). No test in the repo currently exercises `SiteSurveyController::update()` posting a comms-room-carrying survey through the edit form and re-reading it, so this specific preserve-on-absent behaviour is verified by code inspection + the general suite staying green, not by a new feature test (none was added, per the plan's "no test-file edits" scope fence).
- **Committed in:** `2083f6b4` (Task 3 commit, with explicit rationale in the commit body)
