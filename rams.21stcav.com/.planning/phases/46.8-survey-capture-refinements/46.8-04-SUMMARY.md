## Accomplishments

### Task 0 — The regression (found before any plan task, fixed first)

`SurveyLinkSiteContactProminenceTest` had 3 of 5 methods failing. 46.8-03-SUMMARY recorded this as
"pre-existing, unrelated, out of scope" — that claim was wrong. Root cause: 46.8-03's commit
`8186fb3d` added a Blade `{{-- --}}` comment to `resources/views/surveys/show.blade.php` whose prose
contained the literal text `@php` ("computed once in the masthead's own @php block above"). Blade's
`@php`/`@endphp` compiler matches this stray token as a real directive opener and pairs it with the
**next real `@endphp` in the file** — the RAMS-required label block, over 70 lines later — silently
swallowing everything in between (the entire Site Address + Site Contact card, the office send-back
banner include, the engineer-reference-drawer include, and the Site Logistics card's heading/parking/
site-access/other-notes fields) from rendered output, with no error, no warning, no failed assertion
anywhere else. Fix: reworded the comment to say "PHP block" instead of "@php block" — one word, zero
behavioural change. `SurveyLinkSiteContactProminenceTest` is now 5/5; `tests/Feature/Surveys` is back
to 69 passed / 0 failed / 614 assertions, exactly matching the user's own pre-regression measurement
from 2026-10-08. Committed separately (`6c58628b`), before any plan task, since it blocked nothing
else but needed to be true before building on top of that file further.

- `CockpitWizardPresenterTest::test_the_comms_room_group_is_returned_by_no_step_at_all` →
  `..._is_gone_from_the_map_entirely`: the test's own non-vacuity premise ("the group really is on
  the map") was the thing that had to become false — `assertContains` → `assertNotContains`;
  `STEPLESS_LEGENDS` narrowed from two entries to one (`Comms room` removed), with both that

### Task 2 — VisitLifecycleEndToEndTest reconciled + new non-vacuity test for D-01/D-07

`VisitLifecycleEndToEndTest`'s engineer-submission walk posts through `/survey/{token}/submit`,
which is `PublicSurveyController::submit()` — **not** the `SurveyController` capture surface 46.8
D-01 narrowed (that's the live Alpine wizard's `stepSave`, rendered by `surveys/show.blade.php`).
Reading `PublicSurveyController::validatePublicSurvey()`/`extractSiteEngineerFeedback()` directly
confirmed comms-room is validated/extracted nowhere there (46.8 D-02, removed everywhere) while both
`distance_from_base_*` rules/extraction are unchanged. Removed only the two comms-room keys from the
field map (renamed `tenSurveyFields()` → `surveyCaptureFields()` to match the new count), removed the
now-dead `'Permission required'`/`'E2E-COMMS-KEY-WITH-FACILITIES'` assertions, and added explicit
`assertDontSee` calls for both as a non-vacuity check that the removal is real, not a sentinel-shape
coincidence.

Created `tests/Feature/Surveys/SurveyEngineerLinkSiteInfoTest.php` — the dedicated proof
46.8-RESEARCH flagged as a Wave 0 gap:
- Four separate `assertStringNotContainsString` calls (not one combined string) for
  `engineerFeedbackSite.{comms_room_access_status,comms_room_access_notes,distance_from_base_miles,
  distance_from_base_notes}` on the real rendered `GET /survey/{token}` response.
- `engineerFeedbackSite.general_notes` present, `"Site delivery info"` label text present, old
  `"Delivery Routes"` label text (not the `x-model` attribute) absent.
- A REAL round trip: POST `survey.step.save` step 0 with a sentinel `general_notes` value, then a
  FRESH `GET survey.show` for the same token, asserting the sentinel is in the re-rendered seed — not
  a same-request Alpine assumption.
- All three `ProjectDeliverable::STATE_*` values rendering three distinct, non-blank RAMS-required
  strings (never the same string twice).
- The no-row case (no `ProjectDeliverable` row for `rams` at all) rendering the
  `STATE_NOT_YET_DECIDED` default, proving the `project.deliverables` eager-load in
  `SurveyController::show()` is both present and load-bearing (its absence would make
  `deliverableState()` return `null` unconditionally, per `Project::deliverableState()`'s own
  `relationLoaded()` guard).

### Added — D-08 non-vacuity proof (not in the plan's own task list; named by the orchestrating task)

46.8-03-SUMMARY explicitly flagged this gap: "no test in the repo currently exercises
`SiteSurveyController::update()` posting a comms-room-carrying survey through the edit form and
re-reading it." Created `tests/Feature/SiteSurvey/CommsRoomOfficeEditPreservedTest.php`:
- The real rendered office edit screen has neither comms-room field.
- A POST that still carries the old field keys (simulating a stale cached form / hand-crafted
  request) is silently dropped by validation (the rule was removed in 46.8-03) and does **not**

  survive the save untouched, proving `SurveyService::update()`'s preserve-on-absent fix (46.8-03's
  own flagged out-of-scope deviation) actually works on a real save through the real controller.
- The same preservation holds for an ordinary save that posts neither comms-room field at all (what
  the real form always sends now), proving the preservation is the absent-key default behaviour, not
  an artefact of this test's own payload shape.
