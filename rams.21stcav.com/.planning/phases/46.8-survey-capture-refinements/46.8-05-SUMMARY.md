## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - missing critical functionality] The new section-2 Working Height reveal would silently lose its own edits**
- **Found during:** Task 2, while tracing how each section's `@focusout="autosave(N)"` maps to which step payload.
- **Issue:** `risks` (and therefore `risks[0].working_height`) is sent only in the step-6 payload (`buildStepPayload()` case 6), autosaved only by section 6's own `@focusout="autosave(6)"`. The new Working Height reveal in section 2 sits inside section 2's DOM subtree, which only triggers `autosave(2)` on focusout — a payload that does not include `risks` at all. Without an explicit fix, an engineer who changes the Working Height value via the NEW section-2 reveal and never scrolls down to section 6 would have that edit silently discarded on reload — a real data-loss path, not merely a cosmetic gap.
- **Fix:** Added `@focusout="autosave(6)"` directly on the new reveal's wrapping `<div>`. Focusout events bubble, so clicking a Working Height button inside this div now fires both the section's own `autosave(2)` (bubbled, harmless — it simply resends the unrelated step-2 fields again) and this div's local `autosave(6)` (which actually persists the change). Verified via `test_working_height_control_renders_twice_bound_to_the_same_canonical_field` and `test_working_height_selection_made_via_section_6_also_shows_selected_in_the_new_section_2_reveal` in the new test file, both of which read the value back from a fresh render after being set only via the direct-payload seeding helper (not exercised through the actual autosave click path, since PHPUnit cannot click a button — the fix is proven by code inspection of the two autosave payload shapes plus the passing round-trip tests for the OTHER direction of this binding).
- **Files modified:** `resources/views/surveys/show.blade.php` (one attribute, inside this plan's own new markup — not outside the plan's file list).
- **Verification:** `gate-46.ps1 -Filter SurveyRoomCaptureRefinementsTest` green; `gate-46.ps1 -Path tests/Feature/Surveys` green (83 passed, 0 failed).
- **Committed in:** `704f571d` (Task 2 commit).

## Issues Encountered

- `SurveyRoomCaptureRefinementsTest.php`'s first draft used `strpos($html, 'field="access_issues"')` to locate the toggle for ordering assertions. The `toggle-field` Blade component never echoes its `$field` prop as a literal HTML attribute — it only appears inside Alpine `@click`/`:class` attribute strings as `['access_issues']`. Fixed by searching for that substring instead; documented as a code comment in the test itself.
- The first draft also asserted `substr_count($html, '>Under 2m<')` and `'>4m+<'` to prove the Working Height value list was copied verbatim in both locations. The compiled `@foreach` places the button label text on its own line, separated from the tag's closing `>` by whitespace/newline, so no `>Label<` substring ever exists in real output. Fixed by matching the label text alone (`'Under 2m'`, `'4m+'`) instead.
- Both fixes were caught by the RED-first run and the first post-edit GREEN attempt respectively — neither represents a change in the plan's underlying behaviour, only a correction to how the test observes it.
