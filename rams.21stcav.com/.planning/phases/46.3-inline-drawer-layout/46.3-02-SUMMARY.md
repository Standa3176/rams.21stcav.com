# Phase 46.3 Plan 02: The inline drawer, collapse-away, and the way back — Summary

The module panel stopped being a right-hand column and became a drawer inside the module list,
directly beneath the row that was clicked; the other rows are no longer rendered while it is open;
and because that leaves the close control as the only route back, the drawer now carries a named
anchor reading **Back to all modules** above its tab strip. The read-only fence was then re-taken
against the page that produces: both region brackets judged and written down, the three-way
breakage ritual run and recorded with its raw reds, and the **new** vacuity that collapse-away
introduces — which neither bracket watches — closed with an exact row-count guard that was proven
to bite.

## Task 1 — the drawer, the collapse, and the way back

**The markup.** The `@if ($openModule !== null) <x-cockpit.panel .../>` block moved from being a
sibling of `.cav-modules` into the `@foreach`, immediately after the row whose key matches. All
twelve attributes moved **unchanged** — not one prop added, removed or re-derived, which the moved
comment now says in place. The collapse is a loop skip on every non-matching row, so the file still
**states no number and names no module**: a fifth module needs no edit here.

**Proven RED before implementation** (`gate-46.ps1 -Filter CockpitPageTest`, before any markup
moved): `Tests: 3 failed, 36 passed (330 assertions)`. The collapse test's diff read

```
 Array &0 [
     0 => 'Site survey',
+    1 => 'Worksheet',
+    2 => 'RAMS',
+    3 => 'O&M manual',
 ]
```

The three new tests, and why each is shaped the way it is:

1. `test_the_open_panel_renders_inside_the_module_list_immediately_after_its_own_row()` — a **DOM
   position** assertion, never a `strpos` order: same `parentNode` as the row, that parent's class
   contains `cav-modules`, and the panel is the row's **immediate next element sibling**. A substring
   race would have been satisfied by a panel that merely appears later in the markup while still
   living in a second column.
2. `test_opening_a_module_collapses_every_other_row_away()` — compares the **whole set** of rendered
   row titles against `[$definition['title']]`, so the wrong row surviving is a red, not just the
   wrong count. It then re-renders the closed page and asserts the full list is still there, so it
   is measuring a *collapse* and not a *missing module list*.
3. `test_the_open_drawer_carries_a_named_visible_way_back_above_its_tab_strip()` — see below.

**The way back.** `resources/views/components/cockpit/panel.blade.php`, above `.cav-panel__head`:

```blade
<a class="cav-panel__back" href="{{ route('projects.cockpit', $project) }}">
    <x-cockpit.icon name="arrow" class="cav-icon cav-icon--sm cav-panel__back-icon" />
    <span class="cav-panel__back-text">Back to all modules</span>
</a>
```

**How "getting back is obvious" is asserted rather than styled** — four measurable properties, each
a separate assertion, on every module:

- it exists, **exactly once**, and it is an `<a>` — no JavaScript;
- its `href` is **exactly** the bare cockpit URL (`assertSame`, not "contains"), so it drops
  `?module=` entirely;
- `trim($back->textContent) !== ''` — it has **visible text**, which is the executable form of "not
  a glyph". This is the assertion that would have caught shipping a second small `×`;
- it precedes `.cav-panel__tabs` in **document order**, compared by index in an ordered node list —
  so it is reachable without reading past the panel body.

And the header close is asserted to **still exist** and to point at the same URL, so one control was
not swapped for the other. Task 3 then walks all sixteen open regions with the same four checks, and
asserts the **closed** page carries neither — otherwise "on every open region" could be satisfied by
an anchor that renders unconditionally.

The copy names the destination in the user's words, not the app's: **"Back to all modules"**, never
"Close". There is no left-pointing glyph in the icon map, so the existing `arrow` is turned round
with `transform: scaleX(-1)` on a `cav-`-prefixed class — adding a glyph to `icon.blade.php` was not
this plan's business.

**The fence check on the copy, made BEFORE it was used**, as the plan required: `Back to all modules`
was checked as a **substring** against all 21 `DEFERRED_AFFORDANCES` keys (`Book another survey`,
`Prepare a visit`, `Add a snag`, `Book a visit`, `Issue to client`, `Send a RAMS to the client`,
`Upload a drawing`, `Add document`, `Add anyway`, `Edit details`, `Re-import from QuoteWerks`,
`Close this project`, `Open register`, `Export CSV`, `Upload files`, `Assign parts`, `Close snag`,
`Mark as sent`, plus the three "Unsurfaced by 46.2 D-02" entries) and against both
`FORBIDDEN_MARKUP` entries. **No collision. Nothing was lifted** — and nothing would have been.

### The `cav-module--active` ruling: KEPT, with its meaning restated

With the other rows gone, the surviving row still carries the 4px spine and tint that marked it as
"the open one" — while being the only row on screen. **Ruling: keep it.** It now means *"this row
owns the drawer beneath it"*, not *"this is the open one of four"*. Three reasons, in order of
weight:

1. The drawer is full-width and sits directly under the row; the spine and tint are **the only thing
   joining them visually**. Without them the pair reads as two unrelated cards — the opposite of the
   calm the user asked for.
2. The row is now effectively the drawer's **heading**, and a tinted heading is the honest signal
   that it is not one item of a list.
3. Removing it would have meant editing the `.cav-module--active` rules that `CockpitVisualTest`'s
   containing-block scan covers — real risk, no gain.

Written into `cockpit.blade.php`'s docblock at the `:active` flag, which now also records that the
flag is always true while a drawer is open.

used in the subtree.

**The Alpine ban, re-taken on the phase that had the best reason to duck it** — said out loud in the
docblock because a reader needs to know it was faced: the whole subject of this plan is a disclosure
widget. A drawer that opens beneath a row while its siblings collapse away is, in any other
codebase, three lines of `x-data` / `x-show` / `x-collapse`, and Alpine is loaded globally by the
layout. It was **considered and refused**: opening, collapsing and closing are `?module=` query
state, which costs a page load and buys a bookmarkable URL, a working back button and a page that
works with JavaScript off. Retiring the ban still means deciding the cockpit ships JavaScript, and
that decision still belongs to whoever writes its first line.

## Task 3 — the vacuity collapse-away introduces, and the guard that closes it

Before D-02 an open-module region held **four** `cav-module` rows; after it, **one**. Sixteen of
`everyRegion()`'s seventeen regions are open-module renders, so **every fence assertion shaped "no
row contains X", iterated over rows, now judges a quarter of what it used to — and would have gone
quiet without going red.** Neither bracket watches that route: the extraction is correct, the page
is simply smaller.

Closed with **exact** counts, derived from `CockpitModulePresenter::moduleMap()` and never a literal:

1. **Inside `everyRegion()`** — the first region must hold `count(moduleMap())` rows. This is "the
   bare closed page is still the first entry", **asserted rather than assumed**, so the whole-list
   judgement cannot be lost as a later phase appends regions.
2. **`test_the_region_holds_every_module_row_closed_and_exactly_one_open()`** — the full list closed;
   exactly one on every module × every tab **and** every `?action=generate` render; and the full list
   again behind an unknown `?module=` key, which opens no drawer and so must collapse nothing. It
   also refuses to be vacuous on a one-module map.
3. **`CockpitPanelTest::test_the_way_back_and_the_close_are_on_every_open_region()`** — the same
   sixteen regions, each carrying both controls with the right href and visible text; and the closed
   page carrying **neither**.

**THE GUARD WAS PROVEN TO BITE.** The loop skip that performs the collapse was temporarily removed
and the fence run:

```
   FAILED  Tests\Feature\Cockpit\CockpitReadOnlyFenceTest > the region holds every module row closed and exactly one…
  Opening 'site_survey' on the 'overview' tab must leave EXACTLY ONE module row (46.3 D-02). More
  than one means the collapse stopped happening; none means the row list went with the others.
Failed asserting that 4 is identical to 1.

  Tests:    1 failed, 12 passed (1448 assertions)
```

Restored from a file copy and verified identical.

**The spine's iff property** was **narrowed by name to the closed page** (`..._on_the_closed_page()`)
— it always rendered one, but "the closed page" is now the only place the whole list exists, so an
agent who later pointed it at an open render would have found three rows missing and been tempted to
relax it. Neither direction was dropped and no `>= 1` was introduced. The open page gets its **own**
assertion of the **same** property in `test_the_surviving_open_row_obeys_the_same_count_iff_property()`
— and it is the **iff property, never "exactly one count"**, because a zero-visit module legitimately
renders none. Two exact assertions, never one vague one.

**The grep the plan asked for, and its result.** Every test-file hit for a bare `cav-module` class —
`CockpitPageTest:365` / `:396` / `:559`, `CockpitSpineTest:136` / `:183` / `:247` / `:274` / `:654` /
`:802`, `CockpitVisualTest:526` — was opened and judged individually. Every one renders the closed
page or an unknown-key page. **Not one iterated rows on an open-module render.** `CockpitPageTest`'s
panel counts (`:651-652`, `:660`, `:841`) and `CockpitSpineTest`'s (`:273`, `:281`, `:629`) judge the
panel's **count**, not its position, so the move could not reach them — all survived unchanged, which
the plan allowed for but did not predict.

### Judgement calls inside the plan's discretion

- **The way back sits in `panel.blade.php`**, not in `cockpit.blade.php`. Both were permitted; the
  panel was chosen because the anchor then exists on **every** open region — all tabs and the
  `?action=generate` disclosure — by construction rather than by a second `@if` that could drift.

  destination and the act; "Close" was excluded by the plan and is what the `×` already means.
- **The 1024px block was removed rather than narrowed.** A breakpoint that changes nothing is worse
  than no breakpoint — the next reader takes it as evidence a second column exists somewhere. It is
  retired **by name**, with its two declarations quoted and instructions for restoring it.
