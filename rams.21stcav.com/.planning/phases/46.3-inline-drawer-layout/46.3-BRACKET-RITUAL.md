# Phase 46.3 — the bracket verdicts and the three-way breakage ritual

Run by **Plan 46.3-02 (wave 2)** on **2026-09-26**, against the page the inline drawer produced
(D-01 / D-02). Every command below ran in the **FOREGROUND** through
`.planning/phases/46-visit-lifecycle/gate-46.ps1`.

`CockpitReadOnlyFenceTest::cockpitRegion()` extracts the cockpit subtree by XPath on the first
element carrying the `cav-cockpit` class, then brackets the result at both ends. The brackets exist
so that a truncated or empty extraction cannot pass **vacuously** — every "contains no X" assertion
in this file would go green while proving nothing, which is worse than a fence that fails.

---

## Part 1 — the two brackets, judged

**The rule this file follows:** a bracket **retargeted for no reason is churn**; a bracket **left
unjudged is the vacuity**. Both verdicts are legitimate. An unstated one is not. So both verdicts
are written down, including — and especially — the verdict "this bracket did not have to move", and
the ritual was run **regardless** of the verdicts.

### TOP bracket — `self::PROJECT_NAME` (`'Fence Test Job'`), the masthead

> **VERDICT: THIS BRACKET DID NOT HAVE TO MOVE.**

The restructure moved the **panel** (out of a second grid column, into the module list, immediately
after its own row) and stopped rendering the other rows. Both changes happen **inside
`.cav-layout`**, which is the fourth child of `.cav-page`.

The masthead is still the **first child of `.cav-page`**, and `.cav-page` is still the first child
of `.cav-cockpit`. `cockpit.blade.php`'s first three elements are byte-for-byte what they were.

The deeper reason the restructure could not reach it: the bracket string is **content, not
structure** — it is the project's own name, rendered by `x-cockpit.masthead`. A layout change does
not rename a project.

**Retargeting it would have been churn**, and the churn would have cost something real: the next
reader would have had to work out whether the masthead had moved, and the answer would have been no.

### BOTTOM bracket — the literal `Open full project`, the last element in the page shell

> **VERDICT: THIS BRACKET DID NOT HAVE TO MOVE EITHER — and the open-render half was checked
> separately, because collapse-away shortens the page.**

Two questions were asked, as the plan required, not one.

1. **Is it still the last element in the page shell?** Yes. The `<p class="cav-note">` that holds
   the link is a **sibling of `.cav-layout`** and still the final child of `.cav-page`. The
   restructure happened one level in, so the end of the shell never moved.

2. **Is it still present on an OPEN-module render, as well as a closed one?** Yes — and this is the
   half a restructure breaks quietly. D-02 removes three of the four rows, so an open page is much
   **shorter** than it was; a link that had drifted inside the module list would have vanished with
   them and the bracket would have started failing (or, worse, a later agent would have "fixed" it
   by loosening the bracket).

   **This is not taken on trust.** `everyRegion()` runs `cockpitRegion()` over the bare page, all
   four modules × all three tabs, **and** the four `?action=generate` renders — seventeen regions —
   so the bottom-bracket assertion executes on every one of them, and a missing link on any single
   one is a red. The suite is green, so the link is present on all seventeen.

Both verdicts are now written **in the helper's own docblock, at the bracket each concerns**, so the
next agent to restructure this page finds the reasoning at the assertion rather than in a phase
folder.

**Neither bracket was loosened. Neither was removed.** That is the standing rule and it held.

arrival and green after the change tells you nothing; these are the runs that prove the fence can

Reverts were made from **file copies taken before each edit**. **`git stash` was not used anywhere**
— it is prohibited in this repo's worktree rules.

### The Alpine ban, re-taken on the phase that had the best reason to duck it

Said out loud in the docblock, as the plan required, because a reader needs to know it was **faced**
rather than skipped:

**The whole subject of this phase is a disclosure widget.** A drawer that opens beneath a row while
its siblings collapse away is, in every other codebase, three lines of `x-data` / `x-show` /
`x-collapse`. Alpine is loaded globally by this application's layout, so it was there for the
taking — this is not a ban that survives because nobody wanted the alternative.

It was **considered and refused**. Opening, collapsing and closing are all `?module=` query-string
state. The cost is a full page load per open, stated plainly and accepted. What it buys: a
bookmarkable and shareable URL, a working browser back button, a drawer that survives JavaScript
being off, and a page a PM can read in a plant room. Retiring the ban still means deciding that the
cockpit ships JavaScript, and that decision still belongs to whoever writes its first line.

Five phases in a row now — 46-04, 46.1-04, 46.2-03, 46.2-05 and this one — have re-taken it, and
**this is the one that had the strongest argument against**.
