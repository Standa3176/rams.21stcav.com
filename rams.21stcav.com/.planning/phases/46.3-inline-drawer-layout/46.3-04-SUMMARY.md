# Phase 46.3 Plan 04: The Walk, the Reconciliation and the Close — Summary

The new cockpit layout walked end to end through real HTTP with JavaScript off, the phase's ledger
reconciled against the code rather than against its own summaries, the deploy step that will
otherwise break this release written down, and the two questions the phase is actually judged on
handed back to the user unanswered.

## The walk's results

**The way back, as a round trip.** The anchor is found by class, its text asserted to be
`Back to all modules`, its **own href parsed out of the response** and then issued as a fresh GET.
The response is the bare page: `count(moduleMap())` rows, zero panels, all four titles present.
Done for every one of the four modules. Building `route('projects.cockpit', $project)` in the test
would have proven the route and left the control — the only way back there is — unwalked.

**D-04, both ways, on one fixture.** The project is seeded with a `backfilledFromWorksheet()` visit,
so the Worksheet module HAS visits and one of them is reconstructed, while Site survey has none.
On the closed page: `0 visits` appears nowhere in the body, the Site survey row renders **no**
`cav-module__count` element at all, and the Worksheet row renders exactly one reading
**`1 visit · reconstructed`**. The reverse direction is the half a full strip would have deleted,
and it is now walked rather than assumed.

**The drawer's position, proven to bite.** A `<div class="cav-bite-probe">` was inserted between the
row and the panel in `cockpit.blade.php`. The walk went red in two places
(`Tests: 2 failed, 9 passed (296 assertions)`). The Blade was restored **from a file copy taken
before the edit**, md5 compared identical, `git status` clean. **`git stash` was not used.**

**And the walk caught a mistake in itself, which is worth more than the assertion it fixed.** The
first version asserted the collapsed rows' absence over the WHOLE response body and failed on
`>RAMS<` — because the app's own navigation carries a RAMS link on every page. The collapse-away was
working perfectly; the assertion was reading the chrome. Scoped to `.cav-modules`, where the question
lives. **An absence assertion over a whole page is an assertion about the layout, not the feature.**

## ⚠️ DEPLOY — the one thing that will break this release

`resources/css/cockpit.css` is a **Vite entry** (`vite.config.js:32`) and **this phase's layout is
entirely in that file**.

> **Deploying without `npm run build` ships the new markup against the old stylesheet — the rows will
> not collapse, the drawer will not sit beneath its row, and the page will look BROKEN rather than
> merely unchanged.**

Blade components were **added** this phase, not deleted, so the usual delete-a-component trap does
not apply — but `php artisan view:clear` is still the safe habit. **No migration, no queue restart,
no config change, no dependency change.** Deploy as `stcav`, not `root`. Full note:
`.planning/phases/46.3-inline-drawer-layout/46.3-DEPLOY-NOTE.md`.

## Deviations from plan

**None that changed the plan's intent.** Two adjustments made during execution, both recorded:

1. **[Rule 1 — Bug in the new test]** The collapsed-row absence assertion read the whole response
   body and failed on the app navigation's `RAMS` link. Scoped to the `.cav-modules` subtree.
2. **[Rule 3 — Blocking]** Title assertions had to be entity-decoded: `O&M manual` reaches the wire
   as `O&amp;M manual`, so a raw-body assertion would have been false for one module and true for
   three. The subtree helper decodes on the way out.

Neither touched application code.
