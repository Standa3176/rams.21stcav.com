# Phase 46.3: Inline Drawer Layout - Context

**Gathered:** 2026-09-26
**Status:** Ready for planning

<domain>
## Phase Boundary

The cockpit's module panel stops being a side panel and becomes an **inline drawer beneath the row
you clicked**, with the other rows collapsing away. Recent activity moves out of the module panel
into its own right-hand panel. The vestigial visit phrase comes off the rows.

**In scope:** the drawer's position and the collapse behaviour; a project-level Recent activity
panel; removing the "N visits" phrase from the module rows; and relabelling the generate control so
it reads as opening a form rather than producing a file.

**Out of scope:** what the form CONTAINS (Phase 46.2 settled that, and it is not being reopened);
the documents themselves; re-surfacing the visit workflow (that is the open Phase 47 question);
sending documents to a client (Phase 48).

</domain>

<decisions>
## Implementation Decisions

Taken with the user on 2026-09-26, after they opened the live cockpit for the DC-08 check — the
first time anyone had used this page. Their words, verbatim:

> "can click site survey etc open as a drawer underneath not to the side. CAN RECENT ACTIVITY BE A
> SEPARATE PANEL TO THE RIGHT. Can output be word and pdf."

and, on the follow-up question:

> "collapse away so you see only the one you're working in . strip 0 visits"

### The layout

- **D-01:** **The panel opens as an inline drawer directly beneath the clicked module row**, not as
  a right-hand side panel. This returns to the user's ORIGINAL framing for this page — "a drawer per
  required deliverable" — which sketch 002 had and sketch 004 replaced with a side panel. Record that
  this narrows sketch 004's panel mechanics; the tokens, row design and query-string state survive.

- **D-02:** **While a drawer is open, the other module rows COLLAPSE AWAY.** You see only the module
  you are working in. The user chose this over keeping all four visible and pushing them down,
  explicitly for calm: "collapse away so you see only the one you're working in."

  ⚠️ **Consequence that must be designed, not discovered:** with the other rows gone, the ONLY way
  back to the module list is the panel's close control. That control is currently a small `×` in the
  panel header. If it stays that small it becomes a trap — a user who wants a different document has
  no visible route. **Getting back must be obvious**, and it must work with no JavaScript (the close
  is a link that drops `?module=`). Judge it by whether someone who opened the wrong module can get
  out without thinking.

- **D-03:** **Recent activity becomes its own panel on the right**, outside any module. It is
  project-level data and never belonged inside a module's panel — it shows the same three entries
  whichever module is open. Moving it also fills the column the drawer vacates.

- **D-04:** **Strip the "N visits" phrase from the module rows.** This settles Phase 46.2's open
  ruling (a) — the user chose to remove it. The rows become: icon, title, description, status chip,
  document count, chevron. Phase 46.2's D-06 kept the phrase to avoid redesigning the row; the user
  has now looked at it and wants it gone.

- **D-05:** **Relabel the generate control.** Word and PDF radios ALREADY EXIST and render per
  document (`CockpitDocumentFormPresenter` `formats`, rendered by `doc-form.blade.php:270-276`), but
  they sit behind the `Generate document` button and the user could not tell they were there — they
  asked "can output be word and pdf" while looking at a page that already does both. The button
  reads like it produces a file; it opens a form. **Nothing about the formats changes; only the
  affordance that reveals them.**

### Claude's Discretion

- Whether the collapsed state hides the other rows entirely or leaves a compact strip.
- Whether Recent activity is sticky, and how many entries it shows.
- Whether the drawer animates. There is no JavaScript on this page, so any transition is CSS only.
- Where the "back to modules" control sits and what it says.

</decisions>

<code_context>
## Existing Code Insights

- ⚠️ **THIS PHASE MOVES THE FENCE'S REGION BRACKETS, WHICH IS THE RISKY PART.**
  `CockpitReadOnlyFenceTest::cockpitRegion()` extracts the cockpit subtree using **two brackets** —
  a top one at the masthead and a bottom one at the page shell. Both exist so a truncated extraction
  cannot pass vacuously, and the breakage ritual has proven the bottom bracket fires independently
  of the top. **Restructuring the page will move both.** Move them deliberately, re-run the
  three-way ritual, and prove the empty-region and truncated-region guards still go red. Do NOT
  loosen a bracket to make an extraction work.

- **The stretched-link trap, and it is live here.** `.cav-module` has `position: relative` and
  `.cav-module__open::after` has `inset: 0`. Giving the anchor its own `position`, or removing the
  row's, silently collapses the click target onto the chevron with **nothing else failing**. This
  phase changes row layout, so this is the single most likely way to ship a broken page that passes
  every test. `.planning/quick/260920-rwc-whole-module-row-opens-the-side-panel/` is the task that
  established it.

- **No JavaScript and no Alpine**, by ruling not by absence — the layout loads Alpine globally.
  The drawer, the collapse and the close are all query-string state (`?module=…&tab=…`), which also
  gives a working back button and a bookmarkable URL. The fence bans `<script` and nine handler
  attributes; keep them banned.

- **Fence counts stand at 2 / 21 / 9 / 13** (`FORBIDDEN_MARKUP` / `DEFERRED_AFFORDANCES` /
  `BANNED_HANDLER_ATTRIBUTES` / `WRITE_SURFACE_TABLES`). Move any count **by name with a reason**,
  never by deletion. `<select` is still banned and did not need lifting in 46.2.

- **`resources/views/layouts/app.blade.php`, `resources/css/app.css` and `tailwind.config.js` must
  stay BYTE-IDENTICAL to `4abd2b24`** — sha256-asserted with working-tree `Get-FileHash`; a
  `git hash-object` will NOT match on this CRLF checkout. **A mismatch is a STOP, never a hash to
  refresh.**

- All colour is a `--cav-*` token on `.cav-brand` in `resources/css/cav-tokens.css`. **No hex literal
  may reach a Blade file** — there is a test. Every class is `cav-`-prefixed. `resources/css/cockpit.css`
  is a Vite entry (`vite.config.js:32`), so **any change here needs `npm run build` on deploy.**

- **Known defect on this page's layout file, NOT this phase's to fix:** `D-46.2-06-01` —
  `layouts/app.blade.php:858` has `<x-edit-action-bar/>` inside a CSS block comment, and Blade's tag
  compiler does not respect CSS comments, so that component renders inside the `<style>` element of
  every page in the app. Confirmed in the compiled view. It sits on a sha256-pinned file and
  predates v4.0.

  Their three asks all point the same way: less side-by-side, more one-thing-at-a-time. Judge the
  result against "simple to use" and "less scary", their words on every version of this page.

  missing. The user asked for a feature the page already had. Prefer revealing what is built over
  building more.
