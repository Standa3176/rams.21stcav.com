## Component Specification

### 1. Pre-Install Checks Panel (`.checks-block`)

**Placement:** Immediately after the kit drawer block (`.kit-block`) in the room card body, before Section 1 (Space Information). If no kit items exist, the panel is the first element in the room body.

**Render condition:** Only rendered when `$room->questions->isNotEmpty()`. No placeholder, no loading spinner while the background job runs. Section appears silently once questions exist.

**Applies to:** Both `resources/views/public-survey/show.blade.php` and `resources/views/site-survey/_room-form.blade.php`.

```
[PRE-INSTALL]  Pre-Install Checks — N question(s)             [chevron]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  Q1. Is there a power outlet within 1m of the display position?
      [Yes]  [No]  [Other]

  Q2. Has the wall been confirmed as solid for bracket fixings?
      [Yes]  [No]  [Other]
      ┌─────────────────────────────────────────────────────┐
      │ Please explain...                                   │  ← revealed on Other
      └─────────────────────────────────────────────────────┘

  2 of 3 answered
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

**Toggle behaviour:** Collapsed by default (max-height: 0, chevron pointing down). Click toggle to expand (max-height: 800px, chevron rotates 180deg, 350ms ease transition). Identical mechanic to `toggleKit()` JS function.

**Toggle label:** `Pre-Install Checks — N question(s)` where N is the count of question records. Pluralisation: `question` when N=1, `questions` when N>1.

**Answered progress label:** Shown at the bottom of the open drawer:
- Text: `{answered} of {total} answered`
- Style: 13px, weight 400, color #6B7280
- Updated immediately on each AJAX answer save (JS DOM update)
- Omitted when all questions are answered

### 2. Answer Buttons

Three inline buttons per question row: Yes, No, Other. Rendered as `<button type="button">` elements (not form inputs), AJAX-driven.

**Layout:** Horizontal flex row, gap 8px (0.5rem), flex-wrap: wrap for small screens.

**Sizing:** min-height 44px, padding 0.45rem 1rem, border-radius 6px, font-size 0.82rem, font-weight 700.

**States:**
- Unselected: white background, #D1D5DB border, #374151 text
- Yes selected: #D1FAE5 background, #059669 border, #065F46 text
- No selected: #FEE2E2 background, #FCA5A5 border, #991B1B text
- Other selected: #FEF3C7 background, #FCD34D border, #92400E text
- Loading (while AJAX in flight): opacity 0.6, cursor not-allowed on all three buttons in the group

**Selection is exclusive:** Selecting Yes deselects No and Other. Applied via JS class toggle (`.is-selected`). Selected state is also persisted server-side and reflected on page load from `$question->answer`.

### 3. Other Text Reveal

When "Other" is selected, a `<textarea>` appears beneath the answer buttons via `style="display:none"` toggled to `display:block` by JS. No CSS transition — instant reveal matches the existing `infra-panel.open` pattern.

**Textarea spec:**
- rows: 2 (resizable vertically)
- placeholder: `Please explain…`
- max characters: 2000 (server-side validation; no client-side counter)
- font-size: 14px (0.875rem), color #1F2937
- border: 1.5px solid #D1D5DB, border-radius 7px, padding 0.72rem 0.8rem
- focus: border-color #178A95, box-shadow 0 0 0 3px rgba(23,138,149,.15)

**Save timing:** `other_text` is saved on `blur` of the textarea, via the same AJAX answer endpoint. A separate `blur`-triggered AJAX call (not on keystroke) prevents hammering the server.

**`other_text` required:** Optional — engineer may select "Other" without entering text. Server does not reject blank `other_text` when `answer = 'other'`. This allows the answer state (other = not a clean yes/no) to be captured even if explanation is not yet written.

### 4. Completion Block Message

When the engineer taps "Mark Complete" and questions are unanswered, the server returns a 422 JSON response. The JS `completeRoom()` handler must display an amber inline message inside the room card.

**Message placement:** Inserted above the Mark Complete button (inside `#complete-area-{roomId}`), replacing any previous blocked message.

**Message copy:** `Please answer all {N} pre-install check question(s) before marking this room complete.`

**Message style:** Matches `.alert-warning` — background #FEF3C7, border 1.5px solid #FCD34D, color #92400E, border-radius 8px, padding 0.9rem 1.1rem, font-size 0.9rem.

**Dismissal:** Message is cleared automatically when the next attempt is made (button re-enabled after first failure, message replaced on next response).

**Button re-enable:** The Mark Complete button must be re-enabled after a 422 response so the engineer can try again after answering.

### 5. Internal Admin Form (`_room-form.blade.php`)

The panel uses Alpine.js `x-show` / `x-data` (consistent with the rest of the internal form), not the vanilla JS `toggleKit` pattern used in the public view.

**Toggle data model:** `x-data="{ checksOpen: false }"` on the `.checks-block` wrapper.

**Toggle button:** `@click="checksOpen = !checksOpen"` on the toggle button; `x-show="checksOpen"` with `x-transition` on the drawer div.

**Answer persistence on internal form:** The authenticated engineer uses the same AJAX answer endpoint (`POST /survey/{token}/rooms/{room}/questions/{question}`). Token is not applicable for internal form — use a separate authenticated route: `POST /site-surveys/{siteSurvey}/rooms/{room}/questions/{question}` returning JSON. This keeps the internal form consistent with the public form's AJAX answer model.

## Interaction Contract

### AJAX Answer Flow (Public Form)

1. Engineer taps Yes / No / Other button.
2. All three buttons in the group are immediately set to opacity 0.6 / cursor not-allowed (loading state).
3. AJAX POST to `survey/{token}/rooms/{room}/questions/{question}` with `{ answer: 'yes'|'no'|'other' }`.
4. On success (200): apply selected visual state to chosen button; remove loading state from all three.
5. If "Other" was chosen: reveal the `other_text` textarea.
6. Update progress label (`{answered} of {total} answered`).
7. On error (network/5xx): restore pre-click state; display `.alert-error` inline below the question row: `Could not save your answer. Please check your connection and try again.`

### AJAX Other-Text Save Flow

1. Engineer types in `other_text` textarea and tabs/clicks away (blur event).
2. AJAX PATCH/POST to same answer endpoint with `{ other_text: '...' }`.
3. No visible loading indicator (silent save — matches existing photo-upload silent pattern).
4. On error: no UI change (silent failure acceptable — question answer is already saved).

### Completion Gate Flow

1. Engineer taps "Mark Complete" button.
2. Existing `completeRoom()` JS gathers form data and POSTs to `survey/{token}/rooms/{room}/complete`.
3. Server checks unanswered questions before saving. If any unanswered:
   - Returns 422 JSON: `{ completed: false, blocked: true, message: '...' }`
   - JS displays amber blocked message above Mark Complete button
   - Mark Complete button re-enabled immediately
4. If all questions answered: existing success flow proceeds unchanged.

### Drawer Toggle — Public Form

```js
function toggleChecks(btn) {
    const drawer  = btn.nextElementSibling;
    const chevron = btn.querySelector('.checks-chevron');
    const isOpen  = drawer.style.maxHeight && drawer.style.maxHeight !== '0px';
    drawer.style.maxHeight  = isOpen ? '0' : '800px';
    chevron.style.transform = isOpen ? 'rotate(0deg)' : 'rotate(180deg)';
}
```

Default state: `drawer.style.maxHeight = '0'` (collapsed on load). Consistent with `toggleKit()`.

## Accessibility Contract

- All answer buttons must have accessible labels. Since button text ("Yes", "No", "Other") may be ambiguous without context, add `aria-label` including the question number: `aria-label="Answer Yes to question {N}"`.
- The `other_text` textarea must be associated with a `<label>` (visually hidden if needed): `<label for="other-{questionId}" class="sr-only">Explanation for "Other"</label>`.
- The completion block message must use `role="alert"` so screen readers announce it immediately on injection.
- Toggle button must declare `aria-expanded="true/false"` matching drawer open/closed state.
- Minimum touch target: 44px height on answer buttons (verified against existing `.infra-toggle` at 44px).
