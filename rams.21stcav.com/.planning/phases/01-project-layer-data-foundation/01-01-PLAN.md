    use Illuminate\Support\Facades\DB;
    use Illuminate\Support\Facades\Log;

    $matched    = 0;
    $created    = 0;

    // Step 1: Ensure every project_package has a project_id.
    // Per D-03: orphaned packages get an auto-created Project — never left as NULL.
    DB::table('project_packages')
        ->whereNull('project_id')
        ->orderBy('id')
        ->each(function ($pkg) use (&$matched, &$created, &$skipped) {
            // Attempt to match an existing project by user_id + ref
            $project = DB::table('projects')
                ->where('user_id', $pkg->user_id)
                ->where('ref', $pkg->ref)
                ->first();

            if ($project) {
                // Match found — link to existing project
                DB::table('project_packages')
                    ->where('id', $pkg->id)
                    ->update(['project_id' => $project->id]);
                $matched++;
            } else {
                // No match — auto-create a Project from the package's own data (D-03)
                // Use ref as the project name if client_name is unavailable on the package.
                $clientName = $pkg->client_name ?? null;
                if ($clientName === null) {
                    // Attempt to find client_name from extracted_data JSON column
                    $extracted = json_decode($pkg->extracted_data ?? '{}', true);
                    $clientName = $extracted['client_name'] ?? $extracted['client'] ?? ($pkg->ref ?? 'Unknown Client');
                }

                $newProjectId = DB::table('projects')->insertGetId([
                    'user_id'      => $pkg->user_id,
                    'ref'          => $pkg->ref,
                    'client_name'  => $clientName,
                    'site_address' => $pkg->site_address ?? '',
                    'name'         => ($pkg->ref ?? 'Project') . ' — ' . $clientName,
                    'status'       => 'quote_imported',
                    'created_at'   => now(),

                    ->where('id', $pkg->id)
                    ->update(['project_id' => $newProjectId]);

                $created++;

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → ProjectController | Authenticated user submits project create/update/transition forms |
| ProjectController → ProjectService | Validated input passed to service layer |
| Database query output → Blade view | Project data rendered in templates |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Spoofing | ProjectController::store() | mitigate | Laravel auth middleware (`auth`) required on all project routes; CSRF token required on all POST forms (Laravel default) |
| T-01-02 | Tampering | quote_reference field | mitigate | Server-side validation in ProjectRequest: `max:50`, string-only; HTML-escaped in Blade via `{{ }}` double-brace syntax |
| T-01-03 | Elevation of Privilege | ProjectController::transition() / destroy() | mitigate | `auth()->check()` required; D-19 allows any authenticated user to transition — this is intentional by design decision; destructive actions (forceDestroy) retain admin-only guard (`abort_unless(auth()->user()?->isAdmin(), 403)`) |
| T-01-04 | Information Disclosure | ProjectController::index() — shared visibility | accept | D-15 explicitly requires all authenticated users to see all projects. This is an internal tool; all users are company employees. No PII beyond business project data. |
| T-01-05 | Denial of Service | Backfill migration | accept | One-time data migration; runs during deployment; no user-facing risk |
| T-01-06 | Injection | Similar-project warning query | mitigate | Uses `whereRaw()` with bound parameter `[strtolower(...)]` (parameterized query, not string interpolation) — prevents SQL injection |
| T-01-07 | Tampering | Auto-created Projects from orphaned packages | accept | Migration runs during deployment under DB admin credentials; auto-created Project fields derive from existing package data only; no external user input involved |
</threat_model>
