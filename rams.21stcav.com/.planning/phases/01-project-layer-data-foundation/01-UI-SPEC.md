## Design System

| Property | Value |
|----------|-------|
| Tool | none — CSS custom properties defined in `resources/views/layouts/app.blade.php` `<style>` block |
| Preset | not applicable |

## Spacing Scale

All spacing uses the 8-point base scale. Existing layout uses CSS shorthand values mapped as follows:

| Token | Value | Usage in this codebase |
|-------|-------|------------------------|
| xs | 4px | Icon-to-label gaps (`.35rem`), dot indicators |
| sm | 8px | Button gaps, badge inner padding, inline element spacing |
| md | 16px | Default form group bottom margin (`1.1rem` ≈ 17.6px, acceptable), card inner padding |
| lg | 24px | Section vertical rhythm, card padding (`1.5rem`) |
| xl | 32px | Page-wrap padding (`2rem`), between major card blocks (`1.75rem` ≈ 28px, acceptable) |
| 2xl | 48px | Empty-state internal padding (`4rem` = 64px — see exception) |
| 3xl | 64px | Reserved for page-level top spacing |

Exceptions:
- Empty state: `padding: 4rem 1.5rem` (64px/24px) — established pattern, preserve as-is.
- Touch targets: all interactive elements (buttons, filter tabs, table rows) achieve minimum 36px height through existing padding declarations. No new touch target exceptions needed.
- Lifecycle step badges in the progress bar use `padding: .3rem .75rem` — preserve this compact size for the 8-step horizontal stepper to avoid overflow.

Brownfield exception note: spacing values `1.1rem` and `.3rem` exist only in pre-existing CSS inherited from the brownfield codebase. These values must never appear in new style blocks written for Phase 1 or later phases. New code uses the token scale above.

New Phase 1 templates must not introduce spacing values outside these tokens. Use existing CSS classes where possible rather than inline style values.

## Typography

Source: body declaration in `layouts/app.blade.php`.

| Role | Size | Weight | Line Height | Notes |
|------|------|--------|-------------|-------|
| Body | 15px (0.9375rem) | 400 | 1.5 | Base body; used for all paragraph and td text |
| Label / small body | 14px (0.875rem) | 400 / 600 | 1.5 | Form labels at 600, helper text at 400, table cells at 400 |
| Caption / muted | 12–13px (0.75–0.8125rem) | 400 / 600 | 1.4 | Timestamps, badge text, stat labels |
| Heading / page title | 22px (1.375rem) | 700 | 1.2 | `.page-title` — one per page only |
| Section heading | 15px (0.9375rem) | 700 | 1.2 | `.section-heading` with teal bottom border |
| Card title | 15px (0.9375rem) | 600 | 1.3 | `.card-title` |

Font stack: `Figtree, -apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, 'Inter', 'Helvetica Neue', Arial, sans-serif`

Rules:
- Use exactly these 4 size tiers: 12–13px caption, 14px label, 15px body/heading, 22px page title.
- Weight is either 400 (regular) or 600/700 (emphasis). Weight 500 is not permitted. Do not introduce any other weights.
- Never use `font-size` values outside the 4 tiers above in Phase 1 templates.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F3F6F7` (`--bg`) | Page background behind all content |
| Secondary (30%) | `#FFFFFF` (`--surface`) | All cards, panels, inputs, sidebar content area |
| Accent (10%) | `#178A95` (`--teal`) | Strictly reserved — see list below |
| Destructive | `#DC2626` (`--danger`) | Destructive actions and error states only |

Accent (`--teal`) is reserved exclusively for:
- Primary action buttons (`.btn-teal`)
- Active filter tab state (`.proj-filter-tab.active`)
- Project name links in the listing table
- Input focus ring (`box-shadow: 0 0 0 3px rgba(23,138,149,.15)`)
- Section heading underline border (`border-bottom: 2px solid var(--teal)`)
- Table header background (`.data-table th`)
- Lifecycle step "active" state highlight
- Lifecycle step "advance" button (primary CTA on project show page)
- Stat card value text (`.stat-value`)
- Logo mark background

Accent is NOT used for: secondary links, muted labels, card backgrounds, helper text, timestamps, or any decorative purposes.

## Surface Specifications

### Surface 1: Project Creation Form

**Route:** `GET /projects/create` → `resources/views/projects/create.blade.php`

**Current state:** This view already exists and implements the correct pattern. Phase 1 extends it with quote reference versioning support (PROJ-05).

**Extension required:** Add a `quote_reference` field with a `version_number` suffix input (e.g., `ABC123` + `-01` selector or combined text field). Use `.form-grid-2` grid layout, place quote reference spanning one column. Add `.form-help` hint: "Version suffix (e.g. -01) is added automatically if a quote is uploaded later."

**Interaction:** Standard form POST. On validation error, show `.invalid-feedback` inline under each field. No Alpine.js interaction needed for Phase 1 creation form.

**Layout:** `.card` at `max-width: 720px` — match existing create.blade.php.

---

### Surface 2: Project Listing Page

**Route:** `GET /projects` → `resources/views/projects/index.blade.php`

**Current state:** Fully implemented. Phase 1 should not change the listing layout. Any new lifecycle statuses added by Phase 1 (none expected — statuses are already defined in the model) will automatically appear in the filter tabs via the existing `STATUS_LABELS` loop.

**Verify only:** Confirm that all 8 lifecycle states (`quote_imported`, `survey_pending`, `engineering`, `installing`, `commissioning`, `handover`, `completed`, `archived`) are present in `Project::STATUS_LABELS`. No UI changes required if they are.

---

### Surface 3: Project Dashboard (Show Page)

**Route:** `GET /projects/{project}` → `resources/views/projects/show.blade.php`

**Current state:** Partially implemented — lifecycle progress bar and Quote History section exist. Phase 1 extends this with a unified linked records panel.

**Primary focal point:** The lifecycle progress bar at the top of the left column. It is the dominant visual element on this page and must remain the first thing the eye lands on. All new content sections sit below it.

**Layout:** Two-column grid `grid-template-columns: 1fr 320px` (pre-existing). Left column contains main content sections stacked as `.card.card-sm` blocks. Right column (sidebar) shows project metadata summary.

**New section required — "Linked Records":** Add a `.card.card-sm` with flush padding, placed below Quote History in the left column. It displays a table of all record types linked to this project:

| Column | Content |
|--------|---------|
| Type | Badge using `.badge` with record type label (RAMS, Survey, Worksheet, O&M, Cable Schedule) |
| Reference / Name | Linked name or filename, truncated at 50 chars |
| Status | `<x-dashboard.status-badge>` using the record's status |
| Date | `updated_at->diffForHumans()` in `--text-faint` color |
| Actions | `.btn.btn-outline.btn-sm` "View" link |

Empty state for Linked Records section: use inline paragraph style matching existing Quote History empty state — `color: #888; font-size: .875rem; padding: 1rem 1.25rem` — not the full `<x-dashboard.empty-state>` component (which is for full-page zero states only).

**Lifecycle progress bar:** Pre-existing implementation is correct and must not be changed. It renders all 8 states as horizontally scrollable chips with `overflow-x: auto`. Active state uses full `$stepColour` background. Past states use `$stepColour.'22'` (10% opacity) background. Future states use `#f4f6f8` background.

**Lifecycle action panel:** Pre-existing implementation. The "Advance" button uses `.btn.btn-teal` with `onclick="return confirm(...)"`. This pattern is already established and must not be changed to a modal for Phase 1 (deferred complexity).

## Interaction Contracts

### Lifecycle Transitions

- Advance action: `<form method="POST">` with `onclick="return confirm(...)"` — no JavaScript modal. Pre-existing pattern.
- Archive action: Same form POST pattern with browser confirm.
- Reopen action: Inline form with required text input for reason. No modal. Pre-existing pattern.
- All transitions: Server-side validation via controller. On failure, redirect back with `session('error')` flash, rendered as `.alert.alert-error`.

### Filter Tabs (Project Listing)

- Tab click performs full page GET with `?status={key}` query param.
- Active tab: `.proj-filter-tab.active` class — white text on teal background.
- Count badge appears inside each tab — hide tab entirely if count is 0 (pre-existing behaviour).
- Search input submits on button click (no live filtering — Alpine.js not required here).

### Form Validation (Project Creation)

- Server-side validation only. On failure: redirect back with `old()` values populated and `@error()` inline messages.
- Error display: `.invalid-feedback` below the relevant `.form-control.is-invalid`.
- No client-side validation in Phase 1.

### Keyboard / Accessibility

- All buttons: `focus-visible` ring via `.btn:focus-visible` rule (2px teal outline, 2px offset) — pre-existing.
- Table rows: not keyboard-navigable individually (not required for internal tool at this phase).
- SVG icons: all decorative icons must carry `aria-hidden="true"`.
- Form labels: all `<label>` elements must have matching `for`/`id` pairs — enforce this in all Phase 1 templates.
- Confirm dialogs: browser native `confirm()` is accessible and sufficient for Phase 1.
