<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| QuoteImportService::import() → ProjectService::create() | Auto-create hook — system-initiated from parsed quote data; client_name and site_address are sourced from quote, not raw user input |
| QuoteImportService → ProjectService::transition() | Auto-advance hook — system-initiated, not user-controlled |
| SurveyService → ProjectService::transition() | Auto-advance hook — system-initiated, not user-controlled |
| ProjectDataService output → show.blade.php | Canonical dataset rendered in Blade — must be HTML-escaped |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | Auto-create project from quote data (D-02) | mitigate | client_name and site_address are normalised via strtolower() for matching; the new Project is created by ProjectService::create() which enforces fillable and validation rules; no raw user-supplied strings bypass the service layer |
| T-04-02 | Tampering | Auto-advance hook triggers | accept | Hooks triggered by internal service calls (import, confirm, survey submit) — not exposed as external endpoints; no external user can directly invoke transition() |
| T-04-03 | Denial of Service | Auto-advance hook exception | mitigate | Both hooks wrap transition() in try/catch \InvalidArgumentException — failure is logged and swallowed; primary action is never blocked |
| T-04-04 | Information Disclosure | Canonical dataset in Project Data tab | accept | Tab is only visible to authenticated users; internal tool; no PII beyond business data; data_source labels are informational only |
| T-04-05 | Injection | canonicalData rendered in Blade | mitigate | All values output via `{{ }}` double-brace (Blade auto-escapes HTML); no `{!! !!}` raw output used in this view |
| T-04-06 | Repudiation | Auto-advance transitions not logged | mitigate | ProjectService::transition() logs to ProjectActivityLog internally — auto-advance transitions carry the same audit trail as manual transitions |
| T-04-07 | Spoofing | Duplicate project detection in auto-create | accept | Matching uses LOWER() normalised comparison on client_name + site_address — same logic as the similar-project warning in Plan 01-01; D-14 allows creation of same client+site projects (warn but allow), auto-create avoids creating a second one |
</threat_model>
