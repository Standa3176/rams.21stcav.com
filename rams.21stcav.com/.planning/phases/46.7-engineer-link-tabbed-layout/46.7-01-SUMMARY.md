# Phase 46.7 Plan 01: The Offline Ruling for Autosave Summary

An engineer typing in a plant room with no signal keeps typing. The words are held on the device in
`localStorage` under a per-worksheet key, last-write-wins per field, and the page can tell them in
words that the note has not reached the office. The photo queue — schema-frozen and holding real
unsent work on real phones — **is not opened at all.** The store is built and pinned; it is **wired
to nothing**, because the autosave endpoint does not exist until wave 3.

## The ruling, and the four headings, at the code

`resources/views/worksheets/public-show.blade.php`, a new final script IIFE (~line 4240 onward),
headed by a block comment titled exactly `46.7-01 — WHAT AUTOSAVE DOES WHEN THERE IS NO SIGNAL`:

| Heading | Ruling |
|---|---|
| `AUTOSAVE USES localStorage, NEVER THE PHOTO QUEUE` | An autosave payload is the WHOLE value of one field, so a single overwritten key is already a complete record. Adding a kind to the frozen store to get that would risk every pending photo for nothing. |
| `A DRAFT HELD ON THE DEVICE IS A DRAFT THE ENGINEER CAN SEE` | Not-yet-sent is shown in words, and shown again after a reload. No field appears saved when it is not. |
| `LAST WRITE WINS, AND THAT IS SAFE HERE BECAUSE THE PAYLOAD IS WHOLE` | A notes field is replaced, not merged. No merge to get wrong, no queued-add-with-no-server-id problem. |
| `A DRAFT THE SERVER REFUSES IS NEVER DISCARDED` | The sign-off lock refuses correctly; the draft stays, the engineer is shown the server's own sentence, the text stays selectable. |

and it closes on **`THE COST, STATED AND NOT HIDDEN`** — an undrained draft lives only on that phone
in that browser profile; a wiped handset, cleared site data, or a different phone loses it; a draft
refused by the sign-off lock will never reach the office by itself.

### Why this EXTENDS 46.4-06 rather than contradicting it — written at the code, verbatim

```
             * A notes field is REPLACED, not merged. There is no two-writers
             * merge to get wrong and no queued-add-with-no-server-id problem.
             * That last point is why this EXTENDS the shipped offline ruling of
             * plan 46.4-06 rather than contradicting it: 46.4-06 refused an
             * offline correction to a row already on the server because a queued
             * row has no identity to modify — an identity problem, not a
             * principle. A room's notes are keyed by the room name, always have
             * an identity, and carry the whole field, so an overwrite is
             * deterministic. 46.4-06's other three reasons carry over unchanged.
             * The one place order still matters is an acknowledgement arriving
             * after a newer keystroke, which markSent below refuses to apply.
```

It is at the code, not a pointer to a plan file, because the plan file will not be open when
somebody next wonders.

## What happens when `localStorage` throws

Private browsing, cleared site data and a full quota all throw. There are exactly **four** device
storage calls in `DraftStore` (the draft read, the draft write, and the two halves of the probe) and
**every one sits inside an open `try` block** — asserted by source position, not by eye. A throw is
**surfaced, not swallowed**: `_fail()` sets `storageWorks = false`, records `lastError` against the
operation that failed, and calls `warnIfUnusable()`, which inserts a `role="alert"` banner built with
`textContent` (never markup — this is a page a client signs) reading:

> This phone cannot keep notes on the device. Stay on a signal while you type — anything typed with
> no signal will NOT be kept.

`probe()` runs at page load, so a device that cannot hold anything is known **before** the engineer
types two hundred words into it rather than after. A read that throws degrades to "nothing held" and
never blows up. The assertion that pins the sentence:

```php
$this->assertSame(
    'This phone cannot keep notes on the device. Stay on a signal while you type — '
    . 'anything typed with no signal will NOT be kept.',
    $result['throwing']['bannerText'],
    'A device that cannot hold a draft says nothing. The engineer types two hundred '
    . 'words into a field that keeps none of them — the exact silent loss this ruling '
    . 'exists to prevent.',
);
```

## Five states rendered, not one

A source scan alone would have proved nothing about behaviour, so the test file lifts the
`DraftStore` body out of the view between two extract markers and **executes it in node** against a
stubbed device store and a stubbed DOM. **Seven scenarios covering all five states** were rendered
and asserted:

| # | State | What was rendered and checked |
|---|---|---|
| 1 | **empty** | `count() === 0`, `get()` returns null for a field nobody typed in |
| 2 | **holding** | `put()` returns true, the value is the text typed, `sent === false`, `queuedAt` is a number, `count() === 1`; a second `put()` **replaces** rather than accumulating (last-write-wins) |
| 2b | **holding, after a reload** | The store is loaded a SECOND time against the same backing storage — the draft is still there, still `sent === false` |
| 3 | **synced** | `markSent()` with the exact held value returns true, `count() === 0`, `get()` null |
| 3b | **stale acknowledgement** | Two edits, then an acknowledgement for the FIRST: returns **false**, the NEWER text is still held, `count()` still 1 |
| 4 | **refused by the server** | `markRefused()` keeps the draft, `refused === true`, `refusedMessage` is the server's own sentence verbatim, `sent === false`, and it **survives a reload** |
| 5 | **quota-exceeded / throwing storage** | Write throws: `probe()` false, `storageWorks` false, `put()` false, **nothing escaped** (`threw === false`), `lastError` starts `write:`, the banner text is exactly the sentence above. Read throws: nothing escaped, `get()` null, `count() === 0` |

Plus the change event: `worksheet-draft-change` fired at least four times, so wave 3's indicator can
subscribe rather than poll.

⚠️ **What this does NOT prove, stated here and at the top of the test file:** it is node with stubs,
not a phone. A real Safari private-mode `QuotaExceededError`, a real full-page reload, and a real
one-handed plant-room walk are **not** proven. This repo has no browser-driving harness — `puppeteer`
is reached only through Browsershot inside `PdfRenderService`, which renders HTML to PDF and does not
drive a live application. **The real proof is step 2 of plan 46.7-04's blocking human checkpoint.**

built.

## Deviations from Plan

### Auto-fixed / additive

**1. [Rule 2 — missing critical verification] Added a node logic harness inside the planned test file**

- **Found during:** Task 2
- **Issue:** The plan specified source-scan assertions only. A source scan proves the ruling is
  *written* and the frozen store is *untouched*, but proves **nothing** about whether the store
  behaves — and the store's whole purpose is not losing an engineer's words. Every assertion would
  have rendered a single state: "the file says X".
- **Fix:** Two extract markers in the view delimit the pure-JS `DraftStore` body; the test lifts that
  slice, wraps it in a `new Function`, and runs it in node against a stubbed device store and DOM.
  Five states, seven scenarios, all asserted. No new file — it lives in the planned test file, so
  `files_modified` is unchanged.
- **Files modified:** both files in `files_modified`
- **Commits:** `2145646b` (the markers), `ef07a73f` (the harness)
- **Honesty guard:** if node is not reachable from PHP the harness test **skips with a message
  saying the source pins still ran**; the source pins are never conditional. On this machine node
  v24.14.1 is reachable from PHP and the harness ran (0.41s, PASS, not skipped).

**2. [Rule 1 — test defect] The harness crashed instead of reporting, on the first bite**

- **Found during:** Task 2 bite proof 3

  the failure surfaced as a node stack trace and `Failed asserting that 1 is identical to 0` instead

- **Fix:** read the entry defensively and pass `null` through to PHP, so the crafted assertion is
  what reports. Re-bitten and confirmed.
