# Phase 46.7 Plan 03: The Per-Room Notes Box and Its Autosave Endpoint Summary

An engineer types what they found in a room and never taps save. The words go to the device first,
synchronously, and to the office 1200ms later. With no signal they stay on the phone, the field says
so in a sentence, and it still says so after a reload. Once the client has signed, the server refuses
the note, the engineer reads the server's own sentence, and **the words are kept**.

`DraftStore` was wired to nothing after wave 1. It now has exactly one caller.

## The endpoint's guard order — and the lock precedes validation

`app/Http/Controllers/PublicWorksheetController.php`, `saveRoomNotes`, placed next to
`markRoomComplete` so the three room-scoped writes read together. Verbatim, in order:

```php
$worksheet = $this->resolveWorksheet($token);

// D-07 — BEFORE VALIDATION, on purpose. A note is the captured record,
// not a status confirmation, so it freezes when the record freezes; and
// a locked caller must not learn which field was malformed. ...
if (WorksheetCaptureLock::isLocked($worksheet)) {
    return response()->json(['message' => WorksheetCaptureLock::MESSAGE], 422);
}

// Forged-room-name guard — mirrors markRoomComplete / markSurveyReviewed.
$validRoomNames = collect((array) ($worksheet->generated_data['rooms'] ?? []))
    ->pluck('name')->filter()->values()->all();

abort_if(empty($validRoomNames), 422,
    'Worksheet has no rooms — cannot save notes for a room.');

if (! in_array($roomName, $validRoomNames, true)) {
    abort(422, 'Unknown room name.');
}

$validated = $request->validate([
    'notes' => ['nullable', 'string', 'max:5000'],
]);
```

**Confirmed: the lock is the first statement after `resolveWorksheet` and it precedes both the
room-name guard and `validate`.** It is not asserted by eye. `max:5000` was posted to a **signed**
worksheet and the refusal carried the lock's sentence with **no validation error bag** — the one
assertion that proves ordering rather than restating it (T-46.4-04-05 / T-46.7-03-06):

```php
$this->assertSame(
    WorksheetCaptureLock::MESSAGE,
    $response->json('message'),
    'A signed worksheet answered a malformed body with a VALIDATION error, which means '
    . 'the lock runs after validation. A locked caller must learn nothing about the '
    . 'payload shape.',
);
$this->assertNull($response->json('errors'), 'The refusal carried a validation error bag. The guard is in the wrong place.');
```

422 and not 423, for `WorksheetCaptureLock`'s own written reason: the page's hand-rolled fetch
handlers have never seen a 423, and 422 is already this controller's refusal idiom.

## The seven states — what the engineer sees in each

Rendered and asserted, not reasoned about. The harness lifts **both** `DraftStore` and the notes
wiring out of the view between extract markers and runs them in node against a stubbed
`localStorage`, a stubbed DOM, a controllable `fetch` and manually pumped timers.

| # | State | What the engineer sees | Asserted |
|---|---|---|---|
| 1 | **empty** | nothing — the indicator is blank until there is something to say, and **no request fires** | `status === ''`, `requests === 0` |
| 2 | **typed** | `Held on this phone — not sent yet`, immediately, before the debounce; the draft is already on the device | held sentence, draft value, `requests === 0` |
| 3 | **saving** | still `Held on this phone — not sent yet`. **There is deliberately no "Saving…" state** — until the office has it, it is held, and a fourth state is one an engineer has to interpret | `requests === 1`, status is the held sentence |
| 4 | **saved** | `Saved 12:04` — the office has it, with the time; the draft is gone from the device | `assertStringStartsWith('Saved ')`, `draftCount === 0` |
| 5 | **offline-held** | the held sentence, **no request attempted at all**, and after a **reload** the text is back in the box and it **still says held** | `requests === 0`, plus three after-reload assertions (draft, status, field value) |
| 6 | **the signal returns** | the note sends itself on the `online` event and flips to `Saved 12:04` | `requests === 1`, status, `draftCount === 0` |
| 7 | **signed and locked** | *"This worksheet has been signed off — it can no longer be changed."* verbatim, the words **still in the box and selectable**, retrying **stopped**, and the refusal **survives a reload** | status === `MESSAGE`, draft intact, `requestsAfterRetry === 1`, after-reload status |

Plus the **roomless** case (zero textareas, no PHP notice) and the **per-room** case (exactly one box
and one indicator per room on a four-room fixture, counted by xpath, each room checked by name).

And the state that is not a state but a race: **a late acknowledgement cannot retire newer text.**
The engineer types, types again while the first save is in flight, and the server echoes the *older*
value:

```php
$this->assertSame(
    'second thoughts — it is the NEXT backbox',
    $result['lateAck']['draft'],
    'AN ACKNOWLEDGEMENT FOR THE OLD TEXT RETIRED THE NEWER DRAFT. The engineer\'s latest '
    . 'keystrokes would be dropped while the field showed as saved.',
);
$this->assertSame(
    'Held on this phone — not sent yet',
    $result['lateAck']['status'],
    'A stale acknowledgement was reported to the engineer as "Saved" while newer words '
    . 'sat unsent on the device.',
);
```

`markSent` refuses it (wave 1), the return value is **read** rather than ignored, and the field
honestly reports held. **Confirmed: a late acknowledgement cannot retire newer text.**

A request that **neither resolves nor rejects** — a captive-portal wifi answering the handshake and
nothing else — times out into the held state after 8 seconds, reusing the same `Promise.race` idiom
the sign-off drain already uses rather than inventing a second timeout.

Stated here, at the top of the test file, and in the plan's own words.

It is **node with stubs, not a phone.** It does **not** prove a real `localStorage` in Safari private

one-handed in a plant room. The timers are pumped manually, the DOM is four stub objects, and `fetch`
is a function I wrote. What it proves is that **the shipped lines**, given those inputs, produce those
outputs — which is strictly more than a source scan and strictly less than a walk.

**The real proof is step 2 of plan 46.7-04's blocking human checkpoint:** airplane mode, type a note,
reload, see it still marked not-sent, restore signal, watch it arrive.

One thing the harness proved that no source scan could: see the tight loop below.

## The debounce and the limiter, with their reasons

**Debounce 1200ms.** Long enough that a whole sentence is one request instead of forty; short enough
that putting the phone back in a pocket mid-thought has already saved. The **device copy is not
debounced at all** — only the network call is.

**`worksheet-notes-write`, 60/min, per token, its own key.** The number is a data-loss argument, not a
security one: a debounced field cannot legitimately emit more than a few saves a minute per room, but
an engineer working fast across seven rooms plus the offline drain retrying can burst well past a
handful, and **being 429'd mid-note is exactly the silent loss D-04 forbids** — no visible failure,
the engineer walks away, the words never arrive. So it sits with the status-write band (60), not the
tighter photo band (30). There is nothing expensive behind the route — no AI call, no file I/O, one
JSON column write — so a leaked token has no costly worst case to bound.

**Deliberately not a reuse of `worksheet-status-write`:** that budget is shaped for deliberate button
taps, this one for a field that saves itself, and one change must not silently re-tune the other.

The `?: $request->ip()` fallback is present and load-bearing — without it a request reaching the route
with no token resolves to an empty-string key, i.e. one shared unlimited bucket.

## The field on a signed worksheet — gone as a control, readable as a record

Wrapped in the **same** `$captureLocked` flag every other capture control uses; there is one flag on
this page and no second was introduced. On a signed worksheet the notes **still render**, read-only,
as escaped static text — matching how the trays keep thumbnails and captions and lose only the
buttons. **Not a disabled textarea:** a disabled control reads as *broken*, and a signed record should
look like a record. A signed room with no note reads `— nothing recorded for this room —` rather than
a blank gap, so a reader can tell "nothing was found" from "the page is broken".

The signed assertion runs **after an unsigned mirror in the same test**, so a broken selector cannot
fake the lock by finding nothing anywhere.

## Deviations from Plan

### Auto-fixed

**1. [Rule 1 — bug the harness found] A tight re-send loop in the wiring**

- **Found during:** Task 3, running the node harness
- **Issue:** On a save whose acknowledgement did not match the held value, `_notesSend` set
  `room.pending` and then **re-entered `_notesSend` directly**. Given a server that keeps echoing a
  value we do not hold, that is an unbounded recursion of fetches. The harness did not report it — it
  **exhausted node's heap** (`FATAL ERROR: Ineffective mark-compacts near heap limit`). A real server
  converges because we always send the current held value, so a source scan would never have found
  this, and neither would any endpoint test.
- **Why it matters beyond the harness:** the first thing that loop does is exhaust the rate limiter,
  which is the silent 429 D-04 forbids.
- **Fix:** a follow-up save goes back through the **debounce** (`setTimeout(NOTES_DEBOUNCE_MS)`)
  instead of re-entering the sender, with the reason written at the code including *"The harness found
  this by hanging; it is not theoretical."*
- **Commit:** `40306b2d`

**2. [Rule 1 — test defect, mine] The stub was lying**

- The stale-acknowledgement stub echoed a mismatched value on **every** request forever. That is not a
