<objective>
Rooms stop being a long scroll of `<details>` accordions and become tabs with a **sticky bar that
shows which rooms are done** — and the tab an engineer is on survives the full-page reloads that
photo upload and sign-off still perform.

just long — the win is the bar showing status, not tabs for their own sake. If a room's status is
not visible in the bar, the phase has missed its point.**

Output: a tabbed page with a bottom-fixed status bar, a site tab, and tab-state restore folded into
the restore code that already exists.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| engineer's browser → `/worksheet/{token}` | The token is the only credential. No login, no identity. |
| `generated_data['rooms'][*]['name']` → the DOM | Room names originate in an imported QuoteWerks package, not from the engineer, but they are still data flowing into markup and into JS-built strings. |
| `location.hash` → the tab activator | Fully attacker-controlled: anyone can hand an engineer a URL with any fragment. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-46.7-02-01 | Tampering | `location.hash` → tab activation | mitigate | The hash is only ever used as a **lookup key** against panels that already exist in the DOM — matched by `data-tab` then by `id`, with a silent give-up. It is never interpolated into a selector string, never into markup, and never into `innerHTML`. |
| T-46.7-02-02 | Tampering | room name → bar button label and `data-room-name` | mitigate | Server-rendered with `{{ }}` escaping. Any JS that reads a room name for display assigns via `textContent`. The page's one unescaped echo stays `$skipRestoreAttr` and its count stays pinned at 1. |
| T-46.7-02-03 | Elevation of Privilege | a signed worksheet's bar | mitigate | The bar is navigation only — it emits no write. The D-07 capture-control assertions are re-asserted in the signed state so a markup rewrite cannot resurrect a control the lock removed. |
| T-46.7-02-04 | Information Disclosure | the site tab | mitigate | Renders client, ref, address, site contact — all already rendered today on the same page to the same token-holder. **No new field is surfaced.** `device_label_photos.captured_by`, `worksheet_signoffs.ip_address` and `user_agent` are not rendered and must not become "useful header context". |
| T-46.7-02-05 | Denial of Service | `<main>` bottom padding vs the fixed bar | mitigate | A bar overlaying the sign-off button makes the page unusable on the exact device it is for. Padding is required in task 1 and judged at plan 04's checkpoint on a real phone, one-handed. |
| T-46.7-02-SC | Tampering | npm/pip/cargo installs | mitigate | **No package is installed.** The page has no bundler and loads no framework. A plan that needs a package here has drifted. |
</threat_model>
