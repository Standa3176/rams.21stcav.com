# Phase 46.7 Plan 04: The Whole Visit, In Order Summary

Nine steps of one visit on one worksheet, every one through the route table with a real HTTP call:
open the link, read the site tab, type a note, mark the survey reviewed, upload a photo, mark the
room complete, add a kit row, sign, and be refused. **The note typed at step 3 is asserted still
present after steps 4, 5, 6 and 8** — four redirects, at each, not only at the end.

Plans 02 and 03 proved every state renders. This proves they compose. **Neither proves the one
thing that matters most**, which is why task 3 below is blocking and unanswered.

### Why one long method, and it is written into the class docblock

The plan allowed either. One method was chosen and the reason is structural: moving step 6 above
step 4 moves the statements that *produce* the state step 6 asserts, so the file goes red
immediately rather than quietly asserting a different page. Nine `@depends` methods would have to
hand a `Worksheet` between methods — and a worksheet handed between methods is one whose
`RefreshDatabase` transaction has already rolled back. The step-3 note also has to be re-read at
four later steps: one variable in one scope, not four methods re-deriving it.

## Three things the code said that the summaries did not

### 1. `captured_by` is in the shipped response, in a JS comment — the sweep is narrowed, not dropped

T-46.7-04-01 asks that `ip_address`, `user_agent` and `captured_by` appear **nowhere** in the
signed render. **As written for the bare column names that is unachievable**, and it failed:

```
Not to contain: captured_by
  at tests\Feature\Worksheets\EngineerLinkTabbedWalkthroughTest.php:825
```

`public-show.blade.php:2666` is a **`//` comment inside a `<script>` block** reading *"…and never
`captured_by` (T-46.4-02-04)"*. Blade `{{-- --}}` comments are stripped from the response; a JS
comment is **not** — it ships to every browser. The sweep for the bare string fails on the comment
that exists to prevent the very leak it is sweeping for.

The narrowing, with the reason written at the code: **the VALUES are swept over the whole body**
(that is where a real leak is, script tags included) and **the column NAMES over the body with
every `<script>` element removed** (that is everywhere a column name could arrive as data). The
script-stripped body is asserted to still exceed 20,000 characters, so the narrowed sweep is not
sweeping nothing, and `captured_by` is pinned at **exactly 1** occurrence so a second cannot hide
behind the narrowing.

### 3. A `assertStatus(422)` reports a mechanism, not a consequence

Bite 2's first run reported PHPUnit's own sentence — *"Expected response status code [422] but
received 200"* — which says nothing about what a 200 would mean. Laravel's `assertStatus` takes no
message. Waves 1 and 3 each recorded the same lesson in a different shape ("an assertion that
crashes instead of reporting is an assertion nobody can read at 8pm"); this is the third
recurrence. All three forged-name checks now route through
`assertForgedNameRefused(TestResponse, string $endpoint)`, which asserts on `->status()` with a
crafted sentence naming the endpoint and the consequence.

## What was built

Rooms are now **tabs**, and there is a **bar fixed to the bottom of the screen with one button per
room showing whether that room is done**. That bar is the point of the phase, not the tabs. A
**site tab** carries the client, the reference, the address and the site contact. Each room has a
**notes field that saves itself** — no button to tap. With no signal the words are **held on the
phone**, the field says so, and it still says so after a reload; they send themselves when signal
returns. If the client has already signed, the server refuses the note, you read why in a sentence,
**and the words stay on screen**. The tab you are on **survives** the reload that a photo upload
and a sign-off still perform.

Nothing about photo stages, tray labels, kit rows, serial capture or sign-off was changed. No
pending photo already queued on any phone was put at risk — autosave uses a separate store on the
device, on purpose.

**⚠️ The tabs and the sticky bar are ALREADY LIVE** (wave 2 went out early, and it carried wave 1's
dormant draft store with it — verified, see the deploy note). **What has not been deployed is the
notes box and its endpoint.**

### 1. ⚠️ THE BAD-CONNECTION WALK — the single most important thing, and the one nothing in this repo can prove

- **Close the tab. Reopen the link.** Are **the words still in the box**, and does it **still say
