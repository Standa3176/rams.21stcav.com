# Phase 46.5 Plan 03: The `during` Photo Bucket Summary

An install now records **three photo stages — start · during · end**. `WorksheetPhoto::BUCKETS`
holds three values in capture order, the engineer link renders three trays per room, and **nothing
about the existing two changed**: no rename, no relabel, no data migration, no DDL.

## The two rulings this plan was most at risk of breaking

1. **`completion` was NOT renamed to `end`.** `2026_09_26_100000` backfilled every pre-46.4 photo to
   `completion` by explicit UPDATE and justified that ruling by quoting the tray's own title,
   `📷 Photos of completed work`. A rename would have falsified a written decision and cost a data
   migration for zero gain. `test_completion_is_still_spelled_completion` now asserts the string as
   a **literal**, so a later rename is a red test rather than a quiet migration.

2. **No label was relabelled.** "End" was considered and **not** adopted: the completion tray's
   title is the string the migration quotes, so changing it would have broken ruling 1 by the back
   door. The trays already read as start / during / end in plain English —
   `📸 Before you start`, `🛠️ While the work is underway`, `📷 Photos of completed work`.

## What shipped

- `WorksheetPhoto::BUCKET_DURING = 'during'`, placed between START and COMPLETION, and `BUCKETS` in
  **capture order** — order is a decision, not formatting.
- **The class comment was rewritten, not left.** It previously said, verbatim, *"There are TWO
  buckets and there will not be a third."* The replacement records the real history in order: 46.4
  D-03's rejection of an `unknown` bucket, why that rejection **still stands**, why `during` does not
  contradict it, and why `completion` is not renamed.
- A third tray on the engineer link between Start and Completion, fed by `$duringPhotos` off the
  **same** `groupBy` (no new query, no N+1). The `groupBy` default `?: BUCKET_COMPLETION` is
  untouched, so a NULL-bucket row still reads as completion.
- The add-photo label became a `$trayAddLabels` **map** instead of a two-arm ternary that would have
  had to nest. Start and completion labels are byte-identical.
- `PublicWorksheetController` was **not edited** — its `Rule::in(WorksheetPhoto::BUCKETS)` picked the
  third value up for free, and `bucket=rubbish` is still a 422 that stores nothing.

## NO MIGRATION

`git diff --stat -- database/migrations/` is **empty**. `worksheet_photos.bucket` is a plain
`string(20)` with a default — no enum, no check constraint — so a third VALUE is not a schema
change. Because none was written, the sqlite-vs-MySQL 64-char identifier trap does not apply to this
plan and no index was named or created.

`git diff` on `public-show.blade.php` contains `Photos of completed work` **only as an unchanged
context line** (the new During entry sits immediately above it); there is no `+` or `-` line
carrying the load-bearing title.
