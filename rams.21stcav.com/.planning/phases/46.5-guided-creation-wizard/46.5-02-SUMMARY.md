# Phase 46.5 Plan 02: Client Company Name on the Masthead Summary

The cockpit masthead now names **who the job is for** — one presenter key, one rendered line,
six tests. `client_name` goes through the same `put()` helper every other masthead fact uses, so a
project whose client is blank carries **no key at all** and renders **no line**.

## What shipped

- `CockpitHeaderPresenter::masthead()` puts `client_name` first, before `ref`.
- `masthead.blade.php` renders `<p class="cav-mast__site" data-mast-client>` under the `<h1>` and
  above the site address, with the existing `person` icon.
- The class docblock gained one paragraph saying where the value comes from and why it is **not**
  the survey's contact. It was **not** added to the "three values that have no source" list — this
  value has a source.

## Tests

`tests/Unit/Cockpit/CockpitHeaderPresenterTest.php` (3 new):
- `test_the_masthead_carries_the_projects_client_company_name`
- `test_a_blank_or_whitespace_client_name_leaves_no_key_at_all` — asserts `array_key_exists` is
  **false** for both `''` and `'   '`, never a falsy value
- `test_the_client_name_is_the_projects_own_never_the_surveys_contact` — the fixture's survey
  carries `client_name = 'A Different Client Plc'`, `site_contact_name = 'Dana Holt'` and
  `pm_email`, so a wire-up to the survey goes red

`tests/Feature/Cockpit/CockpitPageTest.php` (3 new, all rendered through a real GET):
- `test_the_masthead_renders_the_client_company_name_and_keeps_its_h1` — asserted inside the
  `.cav-mast` subtree, plus the `<h1>` is still the project's ref-or-name
- `test_a_project_with_no_client_name_renders_no_client_line` — **two states rendered**: blank
  (0 occurrences of the hook) and populated (1), so a renamed hook cannot fake the zero
- `test_a_client_name_containing_script_renders_escaped` — asserted on the RAW html

## CSS

`resources/css/cockpit.css` was **NOT touched**. No new selector was added; the line reuses
`.cav-mast__site` and the test hook is a data attribute. **`npm run build` is NOT needed for this
plan.** No `position` and no `transform` were introduced, so the stretched-link pairing is
untouched — `CockpitVisualTest` ran green inside the feature suite.
