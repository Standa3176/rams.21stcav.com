## THE PERSISTENCE RULE, AND HOW IT IS HELD

`ProjectCockpitDocumentController::advance()` reads the document's step list, adds or subtracts one,
and returns `redirect()->to($this->wizardUrl(...))->withInput()`. It creates no model, updates no
column, dispatches no job, writes no file and logs no activity — and the branch that reaches it is
the **first** thing `store()` does, before `ensureSurvey()`, before `persist()` and before
`delegate()`, so a half-finished wizard cannot have written anything by the time it is recognised.

**The assertion that holds it** (`CockpitWizardTest::test_a_step_advance_writes_no_row_in_any_of_the_six_tables`):

```php
foreach (self::UNTOUCHED_TABLES as $table) {
    $this->assertSame(
        $before[$table],
        $after[$table],
        "A step advance wrote to `{$table}`. Nothing is persisted until the final step."
    );
}
```

**The six tables, named individually** — `site_surveys`, `visits`, `worksheets`, `rams_documents`,
`project_activity_logs`, `project_packages`. A count of one table would have passed while a visit or
an activity row was written behind it, so the constant names all six and the test asserts
`assertCount(6, $before)` so a later edit cannot quietly shrink the list.

**The abandoned-wizard test**, verbatim:

```php
public function test_no_engineer_link_exists_for_a_project_whose_wizard_was_abandoned(): void
{
    // ... two `intent=next` posts, then walkAway() ...
    $this->assertSame(
        0,
        SiteSurvey::where('project_id', $project->id)->whereNotNull('access_token')->count(),
        'An engineer link exists for a survey whose spaces were never confirmed.'
    );

    $this->assertSame(0, SiteSurvey::where('project_id', $project->id)->count(), 'There is no survey at all — that is the point.');
    $this->assertSame(0, Visit::where('project_id', $project->id)->count());
    // ... then the MIRROR: finish the wizard and the survey and its link DO appear ...
}
```

Every `SiteSurvey` is given an `access_token` on creation and that token **is** the engineer link
(`SiteSurvey::publicUrl()`), so "no survey" is the only guarantee that means "no link". The mirror at
the end finishes the wizard and asserts the survey **does** appear, so the absence above is the rule
rather than a broken form.

`test_a_wizard_abandoned_after_step_one_persists_nothing` and
`test_a_wizard_abandoned_after_step_two_persists_nothing` each snapshot the same six tables, walk to
the step, walk away twice (the bare module URL — the form's own Cancel target — and then the cockpit
page) and assert every count identical plus `Visit::where('project_id', …)` empty.

**The cost, stated:** close the tab on step 2 and the answers are gone. That was accepted: losing two
short steps of typing is a smaller harm than an engineer arriving on site against a survey nobody
finished. A resumable draft was rejected because a draft **is** a half-finished record — the exact
thing D-02 forbids — and it would need a table, a cleanup job and a staleness rule.

## The carry-forward is re-validated, never trusted

`CockpitDocumentRequest::groupsToValidate()` returns **every** group when `intent === 'create'` and
only the current step's groups on an advance. So a hand-crafted POST claiming `step=1` cannot skip
step 2's rules, and a forged `readonly` field still trips `prohibited`. Both are asserted:

- `test_the_final_submit_revalidates_every_steps_rules_even_on_a_forged_step` — `intent=create`,
  `step=1`, a 5001-character `general_notes` (a **step 2** field) → `assertSessionHasErrors('general_notes')`.
- `test_a_carried_display_only_field_is_still_prohibited_on_the_final_submit` — a submitted
  `project_name` → `assertSessionHasErrors('project_name')`, and no survey created.

A `readonly` field is **never carried**: it holds `rules => ['prohibited']`, and a hidden input for it
would turn an ordinary submission into a validation failure the PM could not fix. A `step => null`
group is never carried either — a hidden empty value would have overwritten what the engineer
captures on site.
