## 5. ⚠ THE SPACES SOURCE IS AN ASSUMPTION, NOT AN INSTRUCTION

**This leads the checkpoint, and it is the first thing to read.**

The user was asked **twice** where step 3's confirmable list of spaces should come from, and did not
answer. It was therefore **INFERRED**, and the inference is written at two code sites in those words
— `CockpitDocumentFormPresenter::PREFILL_PROJECT_SPACES` and
`ProjectCockpitController::spaceNames()`.

What it does today:

- **No live survey on the project** (the normal creation case) → `ProjectContextResolver::resolve($project)['rooms']`
  — the SAME source `SurveyService::createFromProject()` seeds a new survey's rooms from.
- **A live survey exists and will be ADOPTED** → that survey's own rooms, because those are the
  spaces that actually exist on the record the engineer opens.
- **Every space is offered TICKED.** That is a **RENDER** decision and never a stored one; a stored
  default would persist something before the final step, which GCW-03 forbids.
- **Ticking none is an answer**, stored as an empty scope, never a validation failure.

**Changing the inference is one method.** If the answer is "the rooms on the quote", "the rooms the
PM types here", or "whatever the last survey had", say which and it is a single edit to
`spaceNames()`.
