## THE TICK: READ THROUGH THE GUARDED READER, AND IT GATES NOTHING

`CockpitModulePresenter::deliverablePrompt()` is one lookup against a one-row const:

```php
if ($project->deliverableState($prompt['requires']) !== ProjectDeliverable::STATE_REQUIRED) {
    return null;
}
```

`Project::deliverableState()` returns **null when the `deliverables` relation is not loaded** — that
guard is honoured rather than worked around, and the honouring is asserted with
`Project::preventLazyLoading()` armed, so a lazy query would be an exception rather than a silent
N+1. `ProjectCockpitController` eager-loads `deliverables` at `:146`, which is why the real page
always has a real answer.

**What the tick changes is a ROUTE, not a GATE.** The worksheet panel gains one escaped sentence and
one link to `?module=rams&amp;action=generate&amp;step=1` — the SAME RAMS document, reached from the
install, never a second creation path. Every deliverable state still renders the RAMS wizard and
still creates a RAMS. The machine token never reaches a PM: `not_yet_decided` and `not_required` are
asserted absent from every response in every state.

## Deviations from Plan

Six, all mechanical or count-moving. None is a scope change, and **not one relaxes an assertion to
make a red test fit** — every number moved because a document joined the wizard.

1. **[Rule 3 — blocking] The e2e assertion in Task 1 needed a Feature test file.** The plan lists
   `CockpitRamsWizardTest.php` under Task 2, but Task 1's `<behavior>` requires the job summary
   "asserted end-to-end against the created document row", which needs a database. The file was
   therefore created in Task 1 and extended in Task 2.

2. **[Rule 3 — blocking] `resources/views/components/cockpit/panel.blade.php` had to render the
   prompt.** The plan named the two presenters only, but a value derived and never rendered is a
   value a PM never sees. It is four lines above the doc-form, reusing `.cav-hint` and a bare `<a>`:
   **no CSS was written**, so `resources/css/cockpit.css` — a Vite entry — is untouched and
   `npm run build` is NOT needed. The markup is written out rather than passed to `x-cockpit.hint`,
   whose slot is `{{ $slot }}` and would escape an anchor into text.

3. **[Rule 1 — six inherited assertions were step-blind or count-pinned]**
   `CockpitWizardTest` (4 → 7 states, 2 → 3 documents, and the RAMS half of
   `test_a_document_with_no_wizard_is_unchanged_by_this_plan` moved to `CockpitRamsWizardTest`),
   `CockpitDocumentFormTest` (6 → 8 form states twice, 13 → 14 groups, the display-only trailer and
   the LR-04 test made step-aware), `CockpitDocCreationEndToEndTest` (the RAMS walk now opens the
   **last** step, where the Format radios have lived since 46.5-04, with the step number read off the
   presenter rather than typed), and `CockpitWizardPresenterTest` (2 → 3 stepped documents). Every
   moved number carries the reason in a comment beside it.

4. **[Rule 1 — a genuine gap the new document exposed] `CockpitWizardTest`'s blanket hidden-carry
   assertion was wrong for multi-selects.** An `array`-ruled field is carried as one hidden input
   **per selected value** (`doc-form.blade.php:361-364`), so an EMPTY one carries nothing — an empty
   `name[]` would submit a phantom blank engineer. The site survey and the worksheet have no array
   field off-step, which is why this only surfaced when RAMS joined. The assertion is now array-aware
   **and the real behaviour is PROVEN rather than dropped**: a new test selects `additional_engineers`
   and `programmers` on step 2, asserts both are carried as hidden inputs on step 3 and neither is
   re-asked, and then asserts the selection reaches `reviewed_data['programme']['additional_engineers']`
   on the document.

5. **[Rule 1 — two fixtures rendered nothing]** `CockpitWizardTest::resources()` and the new file's
   created only an engineer, so RAMS's `programmers` resource-list rendered **no control at all** and
   the step-membership assertion would have passed vacuously on an absence it exists to catch. A
   programmer (`Ana Ruiz`) was added to both.

6. **[Rule 1 — my own assertion was wrong] `STATE_REQUIRED` is spelt `required`,** and an English
   sentence about a requirement contains that word. The T-46.5-05-02 assertion was re-aimed at what
   actually matters — the **machine tokens** `not_yet_decided` and `not_required` never reach a PM —
   and is now asserted against the sentence *and* against every rendered response in all four states.
