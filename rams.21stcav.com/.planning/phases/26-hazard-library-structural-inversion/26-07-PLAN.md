<objective>
Close the HAZ-02 gap found by live verification (`26-VERIFICATION.md`): `RamsBuilderService::runFromReview()` — the path every already-reviewed project takes — never wires the tiered `HazardIncludeWhenResolver` that Plan 26-04 wired into `runPipeline()`. A genuinely fresh regeneration of a reviewed project (21CQ30960 / RAMS 96) produced 11 old-vocabulary hazards with all 4 always-tier and all 5 confirm-tier hazards absent.

Investigation for this plan (see `<investigation>` below) also traced the unexplained 7→11 delta the verification report could not explain: `RamsComplianceUpgradeService::addProjectSpecificRisks()` — a SIXTH, previously-undocumented hazard-injection path, called from `RamsComplianceUpgradeService::upgrade()` on **both** `runFromReview()` and `runPipeline()` — unconditionally appends 3 old-vocabulary hazard rows on every single generation (plus up to 4 more when scope/equipment keywords match), regardless of tiering. This plan closes that path too.

Purpose: A RAMS generated from previously-reviewed data must carry the same tiered, job-scope-matched hazard register as one generated fresh through the manual form — never a vocabulary the new 18-hazard library was supposed to have retired.

Output:
- `RiskTemplateResolverService` gains a public, reusable tier-1/3 fetch-and-dedup entry point usable by a caller that already holds a fully-formed register (not just a list of names to look up).
- `RamsBuilderService::reviewedToRisk()` merges tier-1 (always) and tier-3 (confirm) hazards onto the reviewed engineer's picks, idempotently, honouring `RAMS_HAZARD_LIBRARY_TIERING`, and forwards a REAL derived drilling signal (`EquipmentClassifierService::textIndicatesDrilling()` against the scope narrative) instead of a hardcoded `false`, so drilling-gated tier-2 hazards can auto-populate on this path too.
- `RamsComplianceUpgradeService::addProjectSpecificRisks()` — the sixth injection path — is gated off (no-op) when tiering governs the register, since every one of its 7 legacy candidates now has a direct declarative equivalent in the 18-hazard library.
- A feature test that generates through `runFromReview()` with a pre-populated reviewed hazard list — the coverage hole 2265 passing tests never touched.
- A structural regression guard against a future fourth/fifth path bypassing the tiered resolver.

## The 7→11 delta — traced and resolved (do not defer)

`RamsComplianceUpgradeService::addProjectSpecificRisks()` (`app/Services/Rams/RamsComplianceUpgradeService.php:611-825`) runs inside `upgrade()` (`:24-48`, step 5 of 14), which both `RamsBuilderService::runFromReview()` (`:267`) and `RamsBuilderService::runPipeline()` (`:779`) call on every single generation — **before** this plan's fix, unconditionally, with no tiering-flag gate anywhere.

It holds 7 hardcoded candidate hazards, each with an `applies` closure gating on scope/equipment keyword text:

| Candidate (old name) | `applies` condition | New 18-hazard-library equivalent (same content, correct wording) |
|---|---|---|
| `Cable Pulling & Termination` | always `true` | `Cable pulling and termination` (`signal:first_fix_cabling`) |
| `Low Voltage AV Connections` | always `true` | `Low voltage AV connections` (`always`) |
| `Fixings into Walls & Ceilings` | always `true` | `Fixings into walls, ceilings and pillars` (`signal:any_penetration`) |
| `Rack Installation` | rack/cabinet keywords | folded into `Manual handling` (`signal:display_mount_or_rack`) + `Fixings into walls, ceilings and pillars` per D-02 |
| `Working in Ceiling Voids` | ceiling/tray/riser keywords | `Restricted access and ceiling voids` (`signal:ceiling_void_access`) |
| `Dust from Drilling & Cutting` | drill/fix/mount keywords | `Dust from drilling and cutting` (`signal:any_drilling`) |
| `Working Near Existing Services` | ceiling/riser/comms-room keywords | folded into `Fixings into walls, ceilings and pillars` per D-02 (hidden-services check) |

Three of the seven fire unconditionally on **every** generation, regardless of scope match, engineer review, or the tiering flag: `7 reviewed + 3 unconditional = 10`. The live register held 11, meaning exactly one of the four keyword-gated candidates also matched 21CQ30960's scope/equipment text — consistent with a real AV install job. This fully accounts for the 7→11 delta without needing production DB access (the local environment is `sqlite`, disconnected from the live `zoomhardware_21backend_live` MySQL replica per `CLAUDE.md`'s deployment note — this plan's Task 3 test proves the mechanism deterministically instead).

**Why this was missed by the phase's five-path removal map:** `RESEARCH.md`'s Pitfall 5 (line 276) flagged `fillMissingHazardControls()` (the sibling method that only fills *empty controls arrays on existing rows* — never adds new rows) as worth a no-op check. It never named `addProjectSpecificRisks()`, which does something categorically different: it **appends new hazard rows**, unconditionally for 3 of them, using pre-Phase-26 vocabulary that duplicates (under a different name) hazards the tiered resolver already adds declaratively. Every one of its 7 candidates now has a direct or D-02-mapped equivalent already in `hazard_templates` — meaning the fix removes zero real safety coverage, only a duplicate legacy mechanism.

**Scope consequence:** the five-path removal map in `26-CONTEXT.md` is confirmed incomplete, exactly as `26-VERIFICATION.md` outstanding item 2 anticipated. This plan's scope grows to include gating this sixth path (Task 3) — the removal follows the SAME flag-gate precedent (`RAMS_HAZARD_LIBRARY_TIERING`, `config('rams_tier1.hazard_tiering_enabled')`) `26-CONTEXT.md`'s Claude's Discretion section already established for all five original paths, keeping the diff minimal (an early-return guard, not a rewrite).

A secondary, unrelated hazard-adding mechanism exists — `RamsDataBuilderService::mergeRiskData()` (`:131-174`), gated on `$projectContext['rooms']` being non-empty (i.e. only fires when a `SiteSurvey` is attached to the project). It is deterministic, per-room, job-condition-driven (`working_height`, `cable_installation`, `manual_handling_risk`, etc. — real captured survey answers, not padding), already satisfies HAZ-02's "included only when the job meets it" principle, and is out of scope for this plan. It was not part of the phase's original five-path list and is not part of this gap.

```
class RiskTemplateResolverService
{
    public function __construct(
        private readonly HazardLibraryService $hazardLibrary,
        private readonly HazardIncludeWhenResolver $includeWhenResolver,
    ) {}

    public function resolve(array $activities, bool $drillingRequired = false, ?int $userId = null,
        array $hazardNames = [], array $personsAtRisk = [], string $scopeNarrative = ''): array

    private function resolveHazards(int $userId, array $names, array $activities,
        bool $drillingRequired, string $scopeNarrative): Collection
    {
        $explicit = $this->hazardLibrary->resolveFromSeeds($userId, $names);
        if (! config('rams_tier1.hazard_tiering_enabled', true)) { return $explicit; }
        $library = HazardTemplate::visibleTo($userId)->get();
        $tiered = $this->includeWhenResolver->resolve($library, [
            'activities' => $activities, 'drilling_required' => $drillingRequired,
            'scope_narrative' => $scopeNarrative,
        ]);
        foreach ($tiered as $match) {
            $alreadyPresent = $match->id !== null
                ? $explicit->contains('id', $match->id)
                : $explicit->contains(fn ($e) => strtolower((string) ($e->name ?? '')) === strtolower((string) $match->name));
            if (! $alreadyPresent) { $explicit->push($match); }
        }
        return $explicit;
    }
}
```
