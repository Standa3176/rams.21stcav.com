<objective>
Implement D-11: a not-required Site Survey causes the project to skip `STATUS_SURVEY_PENDING` entirely (quote_imported -> engineering directly), not pass through it. This is the highest-risk item in the phase — `Project::TRANSITIONS`/`TRANSITIONS_BACKWARD` are pure static-array constants consumed by a currently-stateless `canTransitionTo()`, and there are 3 live auto-advance call sites that must not silently legalise the skip for every project.

**Design decision (per RESEARCH.md Open Question 3 — narrow special case, not a full relation-aware refactor):** `TRANSITIONS`/`TRANSITIONS_BACKWARD` stay exactly as they are today (the "structurally possible" superset, unaffected for the other 6 lifecycle stages). `canTransitionTo()` gets ONE new explicit branch for the `quote_imported -> engineering` case, gated on `$this->relationLoaded('deliverables')` — it NEVER triggers its own relation query. This is deliberate: `tests/Unit/ProjectTransitionTest.php` extends bare `PHPUnit\Framework\TestCase` (no DB, no Laravel container) and constructs `new Project(['status' => ...])` directly — if `canTransitionTo()` forced a `$this->deliverables` lazy-load, every existing test in that file would break, not just the one being rewritten. The `relationLoaded()` guard keeps the method's existing "pure function, callable with no DB" character intact, while still letting the two real call sites (which explicitly load the relation first) drive the skip.

**Hook 2 requires NO code change.** Once Hook 1 sends a not-required-Survey project straight to `engineering`, `SurveyService::complete()` (~line 452) and `SurveyService::submitPublic()` (~line 556) both already guard with `if ($project->canTransitionTo(Project::STATUS_ENGINEERING))` — for a project already IN `engineering`, that check is false via the EXISTING unmodified `TRANSITIONS['engineering']` array (which does not include `engineering` itself), so both call sites become no-ops automatically. This plan proves that with a test rather than assuming it.

Purpose: This is the direct fix for the false-progress problem D-11 names — a hardware-only project should never be forced through a survey stage that never happened.
Output: `Project::canTransitionTo()` extended; `QuoteImportService::confirm()`'s Hook 1 extended; both existing test files updated to prove the conditional behaviour in both directions.
</objective>

public function canTransitionTo(string $status): bool
{
    if ($status === self::STATUS_ARCHIVED) { return $this->status !== self::STATUS_ARCHIVED; }
    if ($this->status === self::STATUS_ARCHIVED) { return false; }
    if (in_array($status, self::TRANSITIONS[$this->status] ?? [])) { return true; }
    return in_array($status, self::TRANSITIONS_BACKWARD[$this->status] ?? []);
}
