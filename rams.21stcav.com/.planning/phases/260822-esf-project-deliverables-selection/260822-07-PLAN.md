**⚠ Standing-hazard clarification (verified this session, matches PATTERNS.md's own flag):** the Project Data tab is a **read-only canonical-data viewer today** (`show.blade.php:1815-1888` — equipment/rooms tables, no form anywhere). CONTEXT.md's phrasing ("the tab that already exists for project-level settings") does NOT mean there is an existing edit form to extend — this plan is building the FIRST write form that has ever lived in that tabpanel. The closest real precedent for "a single-purpose POST action off a project that validates, calls a service, flashes, and redirects back to show" is `ProjectController::transition()` (`:294-320`) + its matching route (`routes/web.php:231`) — that is the template this plan's new `updateDeliverables()` follows, not anything already inside the Project Data tabpanel.

**D-14's mechanism mirrors an existing precedent in this codebase** (`DeviceStencilController::update()`'s `confirm_regenerate` guard, `app/Http/Controllers/Admin/DeviceStencilController.php:169-174`): the first POST to `transition()` with `to_status=completed` and outstanding required deliverables returns a `warning`-flashed redirect back to `projects.show` listing what's outstanding, WITHOUT performing the transition. Resubmitting the same form with an added `confirm_incomplete=1` field proceeds. This is the established shape for "warn once, let the user explicitly proceed" in this codebase — reused verbatim in spirit, not invented fresh.

Purpose: gives the phase's soft-gate philosophy (D-02) its natural counterpart on the OTHER end of a project's life — you can always create something you said you wouldn't, and you can always finish something that's missing what you said you would produce, but never silently.
Output: new `projects.deliverables.update` route + controller action + Project Data tab edit form; `transition()` extended with the D-14 warn branch.

public function transition(Request $request, Project $project): RedirectResponse
{
    $validated = $request->validate(['to_status' => ['required', 'string'], 'note' => ['nullable', 'string', 'max:500']]);
    try {
        $this->service->transition($project, $validated['to_status'], auth()->user(), $validated['note'] ?? null);
    } catch (\InvalidArgumentException $e) {
        return back()->with('error', $e->getMessage());
    }
    $label = Project::STATUS_LABELS[$validated['to_status']] ?? $validated['to_status'];
    return redirect()->route('projects.show', $project)->with('success', "Project advanced to: {$label}.");
}
