## Accomplishments

- `project_deliverables` (unique `project_id`+`deliverable_key`, indexed `state`) and `project_deliverable_audits` (adds the `reason` column the `device_stencil_audits` precedent is missing) both migrate cleanly against SQLite and were exercised end-to-end by 6 passing tests.
- `ProjectDeliverable::ALL_KEYS` is now the single canonical 9-item deliverable vocabulary (D-04), verified at runtime to exclude `quotes`/`assets`/`data`/`project_data` (D-06).
- `Project::snaggingSignoffs()` closes the standing-hazard gap flagged in the plan: there is genuinely no `Snagging` model in this codebase — Snagging data lives on `CommissioningSignoff`, one row per `InstallProgramme`, reached via a two-hop `HasManyThrough`.
- `Project::deliverableState()` is provably safe to call with zero DB bootstrap — verified with a bare `vendor/autoload.php` script (no `.env`, no container, no DB connection configured) returning `null` without erroring.
- `ProjectDeliverablesService` (TDD RED→GREEN) is the sole write path; every state change — including a no-op re-write of the same state — writes one audit row inside the same transaction as the model update.
