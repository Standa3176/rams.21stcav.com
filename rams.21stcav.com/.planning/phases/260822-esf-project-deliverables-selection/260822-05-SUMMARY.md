## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `OmManualController::cleanupTmp()` could crash an otherwise-successful `store()` request**
- **Found during:** Task 3, while building the site-7 (`om-manuals.store`) HTTP test
- **Issue:** `cleanupTmp()`'s `rmdir()`/`unlink()` calls were unguarded. Any filesystem failure (observed deterministically on this Windows dev machine: `UploadedFile::fake()->create($name, $kilobytes)` produces a sparse file whose logical size did not survive `move()`, separately tripping `extractFromPdf()`'s own "Could not read the uploaded PDF file" guard — see Issues Encountered) converted into an uncaught `ErrorException` via Laravel's error-to-exception handler, 500ing the whole request even on the path where cleanup runs *after* a fully successful OmManual creation.
- **Fix:** Wrapped every delete in `@` + an explicit success check, logging a `Log::warning()` on failure instead of throwing. `cleanupTmp()` is a best-effort tidy-up of a scratch directory — a leftover empty (or non-empty, in genuine failure cases) tmp dir is disk hygiene, not a correctness issue, and must never crash a request whose primary work already succeeded.
- **Files modified:** `app/Http/Controllers/OmManualController.php`
- **Verification:** `test_site7_om_store_with_project_id_auto_flips` and `test_site7_om_store_without_project_id_does_not_flip` both pass; targeted regression run `--filter="OmManual|OmDraftMode|OmDocxRoomNarrative|OmRoomNarrative"` — 63/63 passed, no regressions.
- **Committed in:** `8eab539` (Task 3 commit)

---

**Total deviations:** 1 auto-fixed (1 bug)
**Impact on plan:** Necessary to make site 7's real-HTTP verification possible at all. No scope creep — no new features, no architectural changes, and the fix is confined to a private helper method already inside `OmManualController.php` (already in the plan's `files_modified` list from Task 2).

## Issues Encountered

- **`UploadedFile::fake()->create($name, $kilobytes, $mimeType)` produced a genuinely 0-byte file after `move()` on this Windows dev machine.** Laravel's `FileFactory::create()` builds the fake file as a sparse file (`fseek` to the target size, write one byte at the end) rather than writing real content throughout. This is separate from (and was masked by) the `cleanupTmp()` bug above — even after that fix, `extractFromPdf()`'s own `file_exists($pdfPath) && filesize($pdfPath) !== 0` guard correctly rejected the 0-byte file and returned the controller's generic "unexpected error" message. Root-caused via a temporary debug log (`file_exists`/`filesize`/`scandir` dump), confirmed, then reverted — not left in the diff. **Fix (test-only):** switched the two `om-manuals.store` test cases to `UploadedFile::fake()->createWithContent('quote.pdf', str_repeat('%PDF-1.4 fake', 200))`, which writes real bytes and sidesteps the sparse-file behaviour entirely. No production code change was needed for this half of the investigation — it only affected the test's own fixture.
