<objective>
Implement D-17: back-fill every existing project with an inferred deliverables record, so the amber-after-grace-period behaviour (D-13, Plan 03) does not turn the entire pre-existing project list amber on day one, and so pre-existing hardware-only projects immediately stop showing false red (D-12, Plan 03) as soon as this migration runs — they do not have to wait for someone to open the project and manually set the flags.

**Explicitly rejected (per CONTEXT.md D-17):** defaulting the whole back-catalogue to `not_yet_decided` uniformly. The rule is per-deliverable: has evidence of the work (a document/relation row exists) → `required`; no evidence → `not_yet_decided`. `programming` has no data type at all in this codebase, so it ALWAYS lands on `not_yet_decided` for every existing project — this is not a violation of the "don't default everything" rule, it is the correct application of it (there is no signal to check).

**⚠ Known open risk, carried forward from RESEARCH.md and VALIDATION.md (do not treat as resolved by this plan):** local SQLite has exactly 1 project with 0 related documents, so the REAL per-deliverable distribution this migration will produce in production (MySQL/MariaDB) cannot be validated in this environment. This plan's test suite proves the INFERENCE LOGIC is correct against synthetic fixtures; it cannot prove the real-world row counts are sane. Idempotency (this migration must be safely re-runnable) is the concrete mitigation this plan implements for that uncertainty.

Purpose: without this, D-13's amber-after-7-days and D-12's health filter only work for NEW projects created after this phase ships — every pre-existing project would sit with zero deliverables rows, which `Project::deliverableState()` (Plan 01) correctly treats as `not_yet_decided` by default, meaning the entire back-catalogue would start aging toward amber from THIS migration's run date rather than reflecting real project history.
Output: one idempotent backfill migration + a Feature test proving the inference logic against seeded fixtures.
</objective>
