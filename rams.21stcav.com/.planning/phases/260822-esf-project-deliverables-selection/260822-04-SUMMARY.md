## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Used a raw URL instead of `route()` for the not-yet-registered `projects.deliverables.update` route**
- **Found during:** Task 2 (tab strip render loop)
- **Issue:** The plan's action text said to POST to "Plan 07's forthcoming `projects.deliverables.update` route" without specifying how to reference an unregistered route name. Calling Laravel's `route()` helper with a name that has no registered route throws `RouteNotFoundException` at render time — this would have made every `GET /projects/{project}` request 500 the instant any project had a muted tab, which is a correctness-blocking regression, not a cosmetic gap.
- **Fix:** Used `url('/projects/'.$project->id.'/deliverables')` — the literal path PATTERNS.md Pattern 7 already specifies for Plan 07's new route — instead of `route()`. Verified live via `php artisan route:list` that no route currently claims this path, so there is no collision, and the Blade compile check plus all 3 new feature tests (which exercise a real HTTP GET against a project with a muted tab) confirm the page renders without error.
- **Files modified:** `resources/views/projects/show.blade.php`
- **Verification:** `ProjectTabStripTest::test_not_required_empty_deliverable_renders_muted_and_grouped` performs a real `GET` against a project with a muted RAMS tab and asserts `200 OK` plus the form's presence — this would have failed with a 500 had the `route()` helper been used instead.
- **Committed in:** `9812c48` (Task 2 commit)

**2. [Rule 1 - Bug] Guarded the stepper's inter-step connector line against the newly-added skipped state**
- **Found during:** Task 2 (stepper skip-state fix)
- **Issue:** The plan's action text only specified the pill markup for the skipped state, not the connector line immediately after it. Without a guard, a skipped Survey Pending step (which is technically "past" by index, `$isPast === true`) would still render an accent-600 "done" connector line leading out of a grey "skipped" pill — visually implying completion right next to a marker explicitly saying the opposite, directly contradicting the plan's own stated goal ("never a false done tick").
- **Fix:** Changed the connector-line colour condition from `$isPast ? accent : grey` to `($isPast && ! $isSkipped) ? accent : grey`.
- **Files modified:** `resources/views/projects/show.blade.php`
- **Verification:** Visual only (no test asserts inline `style` attribute colour values) — consistent with the plan's own Manual-Only Verifications table, which defers the muted grouping's legibility to human judgement. The pill-level assertions (`ws-step--skipped` class, "(skipped" text) are automated and pass.
- **Committed in:** `9812c48` (Task 2 commit)

## Issues Encountered

- Two of the first-draft feature-test assertions (`assertSee('ws-tab--muted')` / `assertDontSee('ws-tab--muted')` and the equivalent for `ws-tabs__divider`) were false positives/negatives because the bare CSS class name is always present in the page's own `<style>` block regardless of whether any tab is actually muted. Fixed by asserting the rendered class *attribute* (`class="ws-tab ws-tab--muted"`) or tag (`<span class="ws-tabs__divider"`) instead of the bare string. Caught immediately by the first test run (2 failures), not left in the suite.
- First-draft `RamsDocument::create()` calls in the new tests omitted the NOT NULL `form_data` column, caught by the first test run and fixed with `'form_data' => ['source' => 'test']` (matches the existing `RamsEditAdapterTest` fixture shape).
- First-draft `ProjectNextStepTest`'s "no next step" case asserted `assertDontSee('Generate Worksheet')`, which collided with the tab strip's own always-rendered (Alpine `x-show`-hidden, not DOM-absent) "+ Generate Worksheet" action button — unrelated to the Next Step card. Narrowed the assertion to `assertDontSee('Next Step')` (the aria-label/eyebrow text that only exists inside the `@if($nextStep)` block) plus `assertDontSee('Create Site Survey')` (unique to the Next Step card title).
