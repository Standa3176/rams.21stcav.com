      No `legacy` type — D-02 forbids an enum value meaning "we do not know".
    - `Visit::STATUSES` — `STATUS_PLANNED`, `STATUS_COMPLETED`. Only the two states a read-only
      phase can evidence. The full prepare/send/return/accept lifecycle is Phase 46's and must not

      backfilled survey visit routinely predates any install programme existing.
    - `install_record_id` is present and **nullable**, with no `constrained()` in this migration —
      Plan 45-04 creates `install_records` and adds the FK constraint. A visit never requires one.
    - `source_type` + `source_id` identify the wrapped record. `source_type` accepts exactly
      `Visit::SOURCE_SITE_SURVEY = 'site_survey'` and `Visit::SOURCE_WORKSHEET = 'worksheet'`.
      There is a **unique composite index on (source_type, source_id)**, so the same record can
      never mint two visits even under a concurrent re-run of the backfill.
    - `source()` resolves the wrapped model **with `withTrashed()`** and returns null if the row has
      been force-deleted. `Visit::factory()->create()` then soft-deleting the source must still let
      `source()` return the model — this is D-04 as an executable fact.
    - `is_backfilled` is a boolean defaulting to false; `isBackfilled(): bool` reads it. This is
      D-02's "explicit and queryable" marker.
    - `isSuperseded(): bool` is DERIVED, never stored: true when the resolved source has a non-null
      `superseded_at` (SiteSurvey only) or a non-null `deleted_at`. Storing a copy would go stale
      the moment someone supersedes a survey.
    - `labour_resource_ids` round-trips as a PHP array of ints (json cast). Empty array by default.
    - `visits` does NOT use `SoftDeletes`. There is no delete path in this phase, and the trait
      would add a global scope the backfill's idempotency guard would then have to reason about.
  </behavior>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| backfill command → `visits` table | The only writer in this phase. No HTTP surface writes to `visits`, so no untrusted input reaches it. |
| `visits.source_id` → wrapped model lookup | An int used in a `find()`; parameter-bound by Eloquent, never string-interpolated. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-45-02-01 | Tampering | `visits.source_type` accepting an arbitrary class string | mitigate | `source()` branches on two hardcoded `SOURCE_*` constants with a `default => null`. It never resolves a class name from the column, so a poisoned value cannot instantiate an arbitrary model. |
| T-45-02-02 | Elevation of Privilege | `labour_resource_ids` json | accept | Descriptive display data only; it gates nothing. `LabourResource::toClientSafeArray()` (Plan 44-01) is the sanctioned shape when a client surface ever needs it — none exists in this phase. |
| T-45-02-03 | Information Disclosure | Denormalised `title` / `summary` on a visit | accept | Both are project/document titles already visible to any authenticated user on the eleven-tab page. The cockpit is staff-auth only; no client-facing surface exists in Phase 45. |
| T-45-02-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs in this plan. |
