<objective>
The spine. Nine section drawers, closed at rest, each one also its deliverable, with the visit rows
inside them — including the two qualifier treatments that make the record honest: **reconstructed**
(an inference, dashed) and **superseded** (a recorded fact about the paperwork, solid).

Purpose: this is where D-02 and D-04 become visible, and where the read-only fence is enforced as a
test rather than a promise. The sketch draws thirteen write affordances; Phase 45 renders none of
them, and a PM must not be shown a row that looks clickable and is not.
Output: a presenter, four components, the filled-in page, and two feature tests.
</objective>

    `<summary>` gets `list-style: none` and `::-webkit-details-marker { display: none }` but
    **never** `tabindex="-1"` or `pointer-events` tricks, and you must **not** hand-write
    `aria-expanded` — `<details>` announces its own state. `:focus-visible` outline always present.
    Minimum interactive target 44px (16px padding + 15px line-height computes to 48px).
    **Every drawer body contains the mandatory `<x-cockpit.hint>` sentence** — with actions
    stripped, an open drawer must never be empty.

    `visit-row.blade.php` — `[52px date column] [title] [sub-line] [chips] [status]`. Rows are
    **static**: no `cursor: pointer`, no hover colour change, no `tabindex`, no `onclick`. A row
    that looks clickable and is not is worse than one that looks inert. **No pip on a visit row** —
    pips live on summaries only.

    **Reconstructed treatment (D-02) — all four, none optional:**
    1. `<x-cockpit.chip type="reconstructed">` first in the chip strip, before any `RAMS issued` /
       `Worksheet signed` tag.
    2. A 2px **dashed** left border in `--cav-inferred`, inset by `--cav-s1`. Dashed appears nowhere
       else on the page, so it reads as a qualifier rather than decoration, and it survives
       greyscale because it is a line style, not a hue.
    3. Sub-line copy **verbatim** — worksheet-derived: "Type inferred from a signed worksheet — the
       work actually done was not recorded." Survey-derived: "Built from the existing survey record,
       not captured as a visit."
    4. Worksheet-derived only: the inferred type word renders with
       `text-decoration: underline dotted currentColor; text-underline-offset: 2px` and an
       `aria-describedby` pointing at the sub-line. A survey-derived visit's type is not in doubt,
       only its provenance.
    **No colour is used for reconstruction.** Not gold (it is not actionable), not teal (it is not
    confirmed). Neutral tier.

    **Superseded treatment (D-04):**
    1. **Position unchanged** — the row stays in date order in its own type's drawer. Never hidden,
       never moved to a history group, never behind a "show superseded" toggle.
    2. `<x-cockpit.chip type="superseded">` — same geometry as reconstructed but a **solid** 1px
       `--cav-border`. A row may carry both chips, Reconstructed first.
    3. `line-through` on the **wrapped record's title only** — never the whole row. Striking the
       engineer's name and the date would make the surviving fact (someone went) harder to read,
       which is the opposite of D-04's intent.
    4. **No opacity on this row.** `#767676` at 0.7 is 3.03:1 and fails AA for the very meta text
       the row exists to preserve. The `line-through` and the chip are the recession.
    5. Sub-line verbatim: "Superseded {d M Y} — the visit still happened."
    6. Never gold, never counted as attention.

    Source unreadable (force-deleted): chip "Record unavailable" + sub-line "The visit is recorded;

    `lifecycle-row.blade.php` — the uploaded → sent → issued disc rows; discs reuse the Done and

    **Blade traps:** no `@php(...)` short-form, especially with `?->` or `??`; always
