  <behavior>
    - `files(Project, string $moduleKey): Collection` returns one array per document:
      `['name', 'produced_at', 'status', 'route' => ?string]`. `route` is a resolved URL when a
      verified GET route exists for that document type, and **null** otherwise. Null means the row
      renders without a link — it does not mean the row is omitted. A document that exists and is
      not listed is a worse failure than one listed without a link.
    - A module with no document relation (`install_programme`, `snagging`, `programming`) returns
      an empty collection, and the Files tab says so in one plain sentence naming the module.
    - Soft-deleted documents are excluded. A document whose source row is force-deleted cannot
      appear at all — nothing to exclude, but assert the presenter does not fatal on the gap.
    - `notes(Project, string $moduleKey): Collection` returns the module's recorded notes. Sources,
      in this order, and NO others: the module's own note field where one exists on its document
      model, and `ProjectActivityLog` entries with `action === ACTION_NOTE_ADDED`. If a module has
      neither, the tab says the module has no notes — it must not fall back to `Project::notes`,
      which is a project-level field and would show the same text under all eight modules.
    - `activity(Project, int $limit = 6): Collection` returns
      `['initials', 'actor', 'phrase', 'at']` per entry, newest first, from `Project::activityLog`.
      `actor` uses the existing `actor_name` accessor, so a deleted user reads "System" rather than
      blank. `initials` is derived from `actor` (first letters of the first two words, uppercased),
      because there is no avatar column on `User` — initials are what the design draws anyway.
    - `phrase` renders the log's `description` when present, and otherwise a humanised `action`
      ("added a note", "imported a package"). It must NOT invent a phrase for an unknown action —
      an unrecognised action falls back to the raw action value humanised, never to "updated".
    - The feed is project-wide, not module-filtered. `ProjectActivityLog` has no module column, and
      filtering by guessing at `metadata` keys would silently drop entries. A test asserts the same
      feed renders for every module, so this is a recorded decision rather than a bug.
    - Calling any of the three methods writes nothing.
  </behavior>

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-45-12-01 | Information disclosure | file and activity rows | mitigate | Every value renders through `{{ }}`. `{!! !!}` must appear in no cockpit view — a test asserts its absence across `resources/views/components/cockpit/*`. |
