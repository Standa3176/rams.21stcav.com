<objective>
`visits:backfill` — the idempotent console command that wraps the history the app already holds.
A separate, re-runnable decision, not a migration (D-05), because the user validates on the live
VPS against real project data: deploy and backfill must be separable, and a bad backfill must be
re-runnable rather than unpickable.

Purpose: this is where ROADMAP criterion 2 is delivered, narrowed by D-01 — a `SiteSurvey` is an
attendance by nature; a `Worksheet` is a generation-pipeline record whose own docblock calls it
"one worksheet generation run per project", so it evidences a trip to site only when a client
signed on site. D-01 is authoritative over the criterion's wording.
Output: one command, its tests, and an HTTP proof that the public token links are untouched.
</objective>

  <files>app/Console/Commands/BackfillVisitsCommand.php</files>
  <behavior>
    - Signature `visits:backfill {project? : Project ID to scope the backfill (default: all
      projects)} {--apply : Actually create visits (default: dry-run reports only)}`.
      **Dry-run by default.**
    - **Surveys:** every `SiteSurvey` row, including soft-deleted and superseded ones, is wrapped.
      The query uses `withTrashed()` and does **NOT** filter `superseded_at` — D-04 says the trip to
      site happened, and the cockpit shows it marked, not hidden. Type is hardcoded
      `Visit::TYPE_SITE_SURVEY` (D-03); `SiteSurvey.survey_type` is never read.
    - **Worksheets:** `Worksheet::withTrashed()->whereHas('signoffs')->orderBy('id')` — **one visit
      per worksheet, never per signoff.** `worksheet_signoffs` has no unique constraint on
      `worksheet_id`, so iterating signoffs would mint duplicate visits for a re-signed worksheet.
      Type is `Visit::TYPE_INSTALL` (D-02, an inference), and `is_backfilled` is true.
    - **Unsigned worksheets produce no visit** and are counted in their own
      `worksheet-unsigned-skipped` category so the report shows they were seen and deliberately
      passed over.
    - Every created visit has `is_backfilled = true` (D-02's explicit, queryable marker — no
      `legacy` type).
    - `scheduled_date` comes from the source's own best available date (a survey's `submitted_at`
      or `created_at`; a worksheet's latest `signed_at` or `created_at`), and `title` is
      denormalised from the source so the row still renders if the source is later force-deleted.
    - **Idempotency guard runs FIRST, before any other per-row work:**
      `Visit::where('source_type', ...)->where('source_id', ...)->exists()` → count
      `already-wrapped` and `continue`. The DB unique index is the backstop against a concurrent
      re-run; the `exists()` check is what keeps the report honest.
    - Running twice with `--apply` yields identical `visits` counts and zero second-run writes.
    - **The command writes ONLY to `visits`.** It never calls `save()` or `update()` on a
      `SiteSurvey` or `Worksheet` — both have `boot::creating()` hooks and observers that fire on
      save, and both carry deliberate `$fillable` omissions from a security re-audit.
    - A project id argument scopes both queries to that project.
  </behavior>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| console arg → SQL | `visits:backfill {project?}` takes an operator-supplied id; `(int)` cast and parameter-bound per the `BackfillCablePortFksCommand:53-58` precedent. |
| backfill → `site_surveys` / `worksheets` | Read-only across this boundary. Any write would fire `boot::creating()` hooks and observers on models holding live public access tokens. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-45-05-01 | Tampering | Rotation of a live `access_token` on a survey or worksheet | mitigate | The command never calls `save()`/`update()` on either model, and Task 2 asserts every source row's `updated_at` is unchanged plus the tokens are byte-identical across the run. |
| T-45-05-02 | Denial of Service | Duplicate visits from a re-run or a concurrent run | mitigate | `already-wrapped` guard runs first, and the `(source_type, source_id)` unique index (Plan 45-02) makes a double insert impossible even under concurrency. |
| T-45-05-03 | Information Disclosure | Over-filtering hides real history | mitigate | The query deliberately omits `whereNull('superseded_at')` and uses `withTrashed()`; a test asserts superseded and soft-deleted surveys are wrapped, so a future "tidy-up" that adds the filter fails CI. |
| T-45-05-04 | Repudiation | An unexplained production data change | mitigate | Dry-run by default, per-row outcome lines, a counter summary and one structured `Log::info` — the operator can show exactly what a run did before applying it. |
| T-45-05-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs in this plan. |
</threat_model>
