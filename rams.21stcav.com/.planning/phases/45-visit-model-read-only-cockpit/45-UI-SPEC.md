## Verified Constraints

The three hard constraints this contract is designed around. All three were re-verified from
source on 2026-09-19 by this agent, not taken on trust from `45-RESEARCH.md`.

### Constraint 1 — `--teal-*` already means BLUE in this app · VERIFIED

`resources/views/layouts/app.blade.php:65-71`:

```css
--teal-900:       var(--nav-900);     /* #0A1F3D navy */
--teal-800:       var(--nav-800);
--teal-700:       var(--accent-700);  /* #1E5FE0 electric blue */
--teal-600:       var(--accent-600);  /* #2E7BFF */
--teal-500:       var(--accent-600);
--teal-100:       var(--accent-100);
--teal-50:        var(--accent-50);
```

`--accent-700: #1E5FE0` is declared at `:56`. The inline comment at `:64-66` states the aliases
exist so `.btn-teal` and every `--teal-*` reference "inherit the Jetbuilt look without renaming".
`resources/views/surveys/show.blade.php` contains **72** occurrences of `teal` (verified by
`grep -c`), confirming the dependency is load-bearing.

**Contract consequence:** every new token uses the `--cav-` prefix. `grep -- "--cav-\|\.cav-"`
across `layouts/app.blade.php`, `resources/css/app.css` and `tailwind.config.js` returns **zero
hits** — the prefix is free. Do not use `--teal-*`, `--brand-*`, `--accent-*`, `--nav-*`, `--ink-*`
or `--paper*`; all are taken and all mean the blue palette.

Also forbidden: Tailwind colour utilities for brand colour. `tailwind.config.js` maps
`brand.teal` to `#2E7BFF` (a blue). `text-brand-teal` in a cockpit view would render blue.

### Constraint 2 — There is no token file; tokens are inline in the layout · VERIFIED

`resources/views/layouts/app.blade.php` is **2,154 lines** (`wc -l`). Its `:root` block opens at
**line 33** and is followed by hundreds of lines of global component CSS in the same inline
`<style>`. Adding 21CAV tokens to that `:root` would retone every page in the app, violating
ROADMAP criterion 4 (`:373-374`, "with the flag off the application behaves exactly as it does
today") and D-07 ("Existing pages are NOT retoned in this phase").

The seam is confirmed: `@stack('styles')` is at **line 1322**, and `</head>` is at **line 1323**
— i.e. the stack is the last thing in `<head>`, after the app's `:root`, so anything pushed there
wins on source order at equal specificity.

**Contract consequence — the scoping mechanism:**

1. All cockpit CSS lives in **one new file, `resources/css/cockpit.css`**, registered as a new
   Vite input alongside the existing per-page bundles (`resources/js/rack-editor.js`,
   `resources/js/spike/main.jsx` — per-page bundles are already an established pattern here).
2. Every token is declared on the class **`.cav-brand`**, never on `:root`:

   ```css
   .cav-brand { --cav-teal: #01889F; /* …full set in § Token Set… */ }
   ```

3. The cockpit page root element carries **two** classes: `class="cav-brand cav-cockpit"`.
   `.cav-brand` is the token scope (inherited by phases 46-51 on any page); `.cav-cockpit` is the
   layout scope for this page's structural CSS. Separating them is deliberate: Phase 49's import
   review is a brand page but is not the cockpit.
4. The page loads it with, in the cockpit view only:

   ```blade
   @push('styles')
       @vite('resources/css/cockpit.css')
   @endpush
   ```

5. **Nothing is added to, removed from or edited in `layouts/app.blade.php`.** A flag-off
   behaviour test can assert this by diffing the file, and no other page can inherit a `--cav-`
   token because no other page carries `.cav-brand`.

### Constraint 3 — These tokens are inherited by phases 46-51 · BINDING

D-07 makes this page the origin of the v4.0 brand refresh. The set in § Token Set is therefore
specified as a **reusable palette**, not page-local styles, and is split into **structural** and
**accent** tiers so a later phase knows which tokens it may spend freely and which are rationed.
Phases 46-51 import the same `resources/css/cockpit.css` (or a `@import` of a `_tokens.css`
extracted from it at that time) and nest their own classes under `.cav-brand`. One file to change;
no duplication; zero reach into existing pages.

### Class-name collision — additional verified hazard

The sketch uses single-letter and generic class names (`.t`, `.c`, `.s`, `.body`, `.bar`, `.note`,
`.close`, `.btn`, `.step`, `.tag`) inside a document that, in production, inherits a 2,154-line
global stylesheet. `grep` confirms `.btn` has **4** existing rules and `.card` **3** in
`layouts/app.blade.php`. `.btn:focus-visible` at `:617` and `.btn` styling would fight the
sketch's `.btn`.

**Contract consequence:** every cockpit class is renamed with a `cav-` prefix — `.cav-drawer`,
`.cav-pip`, `.cav-visit`, `.cav-title`, `.cav-count`, `.cav-status`, `.cav-hint`, `.cav-tag`,
`.cav-sec`, `.cav-mast`. No single-letter class names. No bare `.btn`, `.card`, `.body`, `.close`.

## Spacing Scale

Declared values (all multiples of 4). The sketch's odd values (22, 17, 13, 11, 7) are normalised to
the nearest 4-step — a change of at most 2px, no layout consequence.

| Token | Value | Usage | Sketch original |
|-------|-------|-------|-----------------|
| `--cav-s1` | 4px | Inline glyph gaps, title/sub-line gap | 4 |
| `--cav-s2` | 8px | Drawer-to-drawer gap, chip gaps | 7 |
| `--cav-s3` | 12px | Summary row gap, visit-row vertical padding | 11 / 13 |
| `--cav-s4` | 16px | Drawer inner padding, drawer body padding | 15 / 17 |
| `--cav-s5` | 24px | Page gutter, masthead vertical padding | 22 |
| `--cav-s6` | 32px | Section-group break, attention-block bottom margin | 34 / 36 |
| `--cav-s7` | 48px | Page bottom padding above the fold-out | — |

Exceptions (non-spacing dimensions, stated so the executor does not round them):

- Pip: **8px** diameter (circle and diamond alike)
- Tick box: **16px** square, 1.5px border
- Date column in a visit row: **52px** fixed (sketch 50)
- Hairline rules: **1px**; section rule and attention underline: **2px**
- Content max-width: **680px** (sketch, locked — the spine is a single reading column)
- Masthead `clip-path` bevel: **24px** desktop, **12px** below 480px
- **Minimum interactive target: 44px.** A drawer summary at 16px padding + 15px line-height
  computes to 48px, which satisfies it. Any affordance that does not reach 44px must be padded
  until it does

## Typography

Four sizes, **two weights** (400 regular, 600 semibold). `@fontsource/poppins` must import exactly
those two weights. Verdana ships only 400/700, so a heading at 600 resolves to Verdana Bold — that
is intended and consistent; do not add a third declared weight to compensate.

| Role | Size | Weight | Line Height | Font | Used for |
|------|------|--------|-------------|------|----------|
| Display | 26px | 600 | 1.2 | head | Masthead project name (`<h1>`). 22px below 480px |
| Heading | 16px | 600 | 1.3 | head | Attention-line heading (`<h2>`), section-group headings (`<h2>`) |
| Body | 15px | 400 | 1.65 | body | Prose, drawer titles (drawer titles at 600), visit-row titles |
| Meta | 13px | 400 | 1.45 | body | Counts, statuses, sub-lines, dates, chips (chips at 600, uppercase, `letter-spacing: .04em`) |

**13px is a floor, not a preference.** The sketch's `.78rem` (12.5px) and `.7rem` (11.2px) meta text
rounds **up** to 13px. Nothing on this page renders below 13px. The `.68rem` snag-group eyebrow
(`cockpit-sections.html:140`) becomes 13px Meta at 600 uppercase.

Section eyebrows keep the sketch's treatment (head font, 600, uppercase-ish `letter-spacing: .04em`,
`--cav-mid` on the canvas) but are marked up as real `<h2>` elements so the page is navigable by
heading. Heading order is `h1` (project name) → `h2` (attention) → `h2` per section group. Drawer
summaries are **not** headings — `<summary>` carries its own role.

## State Vocabulary

The single most important part of this contract. Four states, each carrying meaning on **three**
independent channels — shape, text, and accessible name — so no state depends on colour, and all
four survive greyscale.

### Where state appears

| Level | Channel | Rationale |
|-------|---------|-----------|
| Drawer summary (section level) | **pip** + count text + status text | The sketch's `.pip` lives on `<summary>` only |
| Visit row (inside a drawer) | **status text + chip**, no pip | Matches the sketch: `.vz` rows carry `.vs` text, never a pip. Do not add pips to rows |

### The three lights and the tick

| State | Shape | Fill / border | Text (always present) | Accessible name | Greyscale test |
|-------|-------|---------------|------------------------|-----------------|----------------|
| **Done** | Circle, 8px, solid | fill `--cav-teal` | e.g. "Accepted", "All issued" | `aria-label="Complete"` | Solid dark circle |
| **Attention** | **Diamond** (8px square, `transform: rotate(45deg)`), solid | fill `--cav-gold`, 1.5px outline `--cav-gold-ink` | e.g. "1 needs accepting", weight 600 | `aria-label="Needs attention"` | Solid outlined diamond — shape differs from both circles |
| **Waiting** | Circle, 8px, **hollow** | `#FFFFFF` fill, 1.5px `--cav-wait` border | e.g. "Not started", "No link sent" | `aria-label="Not started"` | Hollow circle |
| **Ticked by hand** | **Rounded square**, 16px | ticked: `--cav-teal` fill + white `✓`; unticked: white fill + 1.5px `--cav-wait` border | "Marked done" / "Not marked" + who and when | `aria-label="Marked done by hand"` / `aria-label="Not marked"` | Square — categorically not a light |

**The tick is not a light, and that distinction is load-bearing.** Per the sketch's own design rule
and corroborated in code (`app/Services/ProjectHealthService.php:105-107`: *"Programming
(KEY_PROGRAMMING) is skipped entirely: no model, table, or relation exists for it anywhere in this
codebase"*), nothing in the system can evidence programming. A circle says *the system knows*; a
square box says *a human asserted this*. Using a light there would claim a certainty that does not
exist. The shape difference is the whole point — do not unify them.

**Not-required deliverable** (sketch `.dw--na`): unticked box + chip reading "Not required" + body
hint "Marked not required at import." Opacity **0.6** (sketch used 0.45, which drops
`#767676` meta text below the contrast floor).

### Where per-drawer state comes from

`ProjectHealthService::assess()` returns **one** status for the whole project
(`app/DTO/ProjectHealth.php:17-24` — `status`, `reason`, `overdue`). **It must not be extended**:
it is the dashboard's derivation (`DashboardController.php:28,:59`), and changing it changes what
the dashboard renders with the cockpit flag *off*, violating criterion 4.

So: the service is reused **unchanged** for the masthead/attention line only. Per-drawer pips come
from existing model helpers, no new service and no new derivation source:

| Drawer | Pip derived from |
|--------|------------------|
| Site survey | `SiteSurvey::isDraft()` / `isCompleted()` (`SiteSurvey.php:112-120`), `submitted_at`, `superseded_at` |
| First fix / Install | `Worksheet::isSigned()` (`:177`), `isStale()` (`:287`), `hasEngineerActivity()` (`:375`), `isReadyForSignoff()` (`:420`) |
| Programme | `InstallProgramme::isDraft()` / `isActive()` / `statusLabel()` (`:106-145`) |
| Commissioning | `$programme->commissioningSignoff()->exists()` (`InstallProgramme.php:96-99`) |
| Deliverable sections (RAMS, drawings, O&M, cable schedule) | `Project::deliverableState($key)` (`Project.php:447+`) |
| Programming | **no derivation** — tick state only |

The mapping helper belongs in a Blade component or a thin view presenter, **not** in
`ProjectHealthService`.

## Reconstructed (backfilled) Visits — D-02

**The problem:** a backfilled visit is an inference. A signed worksheet proves someone attended;
it does not prove what they did. D-02 types it `install` anyway and requires an explicit marker. A
PM must never read that row as a recorded fact.

**The grammar: dashed means inferred.** Solid borders and solid rules mean recorded. A dashed
border appears nowhere else in the cockpit, so it reads as a qualifier rather than as decoration,
and it survives greyscale and colour-blindness because it is a line style, not a hue.

**Contract — a reconstructed visit row renders all four of these. None is optional.**

1. **Chip** `Reconstructed` — 13px head font, 600, uppercase, `--cav-light` on `--cav-chip-bg`,
   **1px dashed `--cav-inferred`** border, `--cav-radius-sm`. Sits first in the row's chip strip,
   before any `RAMS issued` / `Worksheet signed` tag.
2. **Left edge** — the row carries a 2px **dashed** left border in `--cav-inferred`, inset by
   `--cav-s1`. Visually detaches the row from the solid-ruled recorded rows around it.
3. **Sub-line copy, verbatim** — replaces the sketch's free descriptive sub-line:
   - Worksheet-derived (typed `install` by inference, D-02):
     **"Type inferred from a signed worksheet — the work actually done was not recorded."**
   - Survey-derived (typed `site survey` from the record's nature, D-03):
     **"Built from the existing survey record, not captured as a visit."**
4. **Dotted-underlined type word** — where the inferred type is named, it renders with
   `text-decoration: underline dotted currentColor; text-underline-offset: 2px` and an
   `aria-describedby` pointing at the sub-line. Only worksheet-derived visits get this; a
   survey-derived visit's type is not in doubt, only its provenance.

**Colour is not used.** No gold (it is not actionable), no teal (it is not confirmed).
Reconstructed rows sit in the neutral tier.

**Disclosure at rest — the consequence of closed drawers.** Drawers are closed at rest, so if
reconstruction is only visible when a drawer is open, a PM reading the spine is misled by
omission. Therefore the **summary count slot must disclose it**:

- `3 visits · 2 reconstructed`
- `1 visit · reconstructed` (singular form drops the numeral)

and the summary status text is unaffected — reconstruction never makes a drawer go gold.

## Superseded Visits — D-04

**The rule from D-04:** the trip to site happened; superseding the paperwork does not un-happen it.
The visit stays on the spine, visibly marked.

**Contract:**

1. **Position is unchanged.** The row stays in date order in its own type's drawer. It is never
   hidden, never moved to a "history" group, never collapsed behind a "show superseded" toggle.
   The query must not filter `superseded_at` and must read the wrapped record with
   `withTrashed()` — the row survives even a soft-deleted source.
2. **Chip** `Superseded` — same chip geometry as `Reconstructed` but with a **solid** 1px
   `--cav-border`. Solid vs dashed is the distinction: superseded is a recorded fact about the
   paperwork; reconstructed is an inference about the visit. A row may legitimately carry both
   chips, `Reconstructed` first.
3. **Strikethrough is scoped to the deliverable name only** — `line-through` on the wrapped
   record's title, never on the whole row. Striking the engineer's name and the date would make
   the surviving fact (someone went) harder to read, which is the opposite of D-04's intent.
4. **Opacity floor 0.7.** Enough to recede, not enough to break the contrast ledger. (The sketch's
   `.sg--done{opacity:.55}` and `.dw--na{opacity:.45}` both fail at 13px meta text.)
5. **Sub-line copy, verbatim:** **"Superseded {d M Y} — the visit still happened."**
6. **Never gold, never counted as attention.** A superseded visit cannot be actioned on a
   read-only page, so it must not drive a drawer's pip to the attention state, and must not appear
   in the attention line's count. It *is* disclosed in the summary count slot:
   `2 visits · 1 superseded`.

**"Open the full project page"**, rendered as a `--cav-teal-dark` text link at the foot of the
page. The eleven-tab page remains the default (criterion 4); the cockpit must offer a way back.

## Layout Contract

Locked from `cockpit-sections.html`. Restated for the executor; not reopened.

1. **Masthead** — `--cav-teal-dark` fill, white text, `clip-path: polygon(0 0, 100% 0, 100% calc(100% - 24px), 0 100%)`.
   `<h1>` project name at Display; sub-line at Meta in white (not the sketch's `#C5E6EE` — see
   Contrast Ledger) reading `{quote code} · {stage} · {site}`.
2. **Attention line** — immediately below, `<h2>` + one paragraph, bottom-ruled 1px `--cav-rule`,
   `--cav-s6` bottom margin. The waiting item is named inline inside `<em>` with a 2px
   `--cav-gold` bottom border. **Not a panel, not a list, not a card.** It never duplicates the
   spine below it.
3. **The spine is the hero** — a single 680px column of section drawers, 8px apart, grouped under
   three `<h2>` eyebrows: "Visits — someone goes to site", "Documents — produced in the office",
   "Reference". No card grid, no stat row, no KPI tiles.
4. **Drawers closed at rest.** `<details>` with **no** `open` attribute — including the Install
   drawer, which the sketch shows open purely to demonstrate its contents. Simplicity at rest is
   the brief: *"there is a lot in data/sections and I want to make it look simple and less
   scary."* No drawer may ship `open`, and open state is not persisted (no JS).
5. **A summary is one line at rest:** `[pip] [title] [count] [status] [›]`. The arrow rotates 90°
   on open.
6. **Each section drawer IS its deliverable.** No second list anywhere on the page restating what
   a drawer contains.
7. All nine deliverable sections always render, including not-required ones — a missing drawer
   would read as an app fault.

## Responsive Contract

| Width | Behaviour |
|-------|-----------|
| ≥ 1024px | Unchanged. Column stays 680px, centred. **No multi-column layout** — the spine is a reading column and widening it would break the hierarchy |
| 681-1023px | Column fluid to 680px max, gutter `--cav-s5` (24px) |
| 481-680px | Single column, gutter 24px, masthead Display stays 26px |
| **≤ 480px (phone)** | Gutter 16px. Masthead Display 22px, bevel 12px. **Summary becomes a two-row flex:** row 1 = pip + title + arrow; row 2 = count + status at Meta, indented to the title's left edge |
| 320px | Minimum supported width. No horizontal scroll at 320px. The 52px date column and the pip are the only fixed widths; everything else flexes |

**Deviation from the sketch, flagged.** `cockpit-sections.html:167` reads
`@media(max-width:480px){ .dw>summary{gap:10px;padding:14px 13px} .s,.c{display:none} }` — it
**hides the status and count text on phones**. That cannot ship: it leaves the pip as the only
state channel on the one device engineers and PMs actually use on site, which is exactly
colour-only encoding. Sketch open question 3 already flags that phone width was checked at 560px
but never on a handset. The two-row summary above preserves every state channel at 320px; it
changes reflow only, not hierarchy or visual direction.

## Accessibility Contract

1. **No meaning in colour alone.** Every pip is accompanied by visible status text and carries
   `role="img"` with an `aria-label` from § State Vocabulary. Every state is additionally
   distinguished by shape (filled circle / outlined diamond / hollow circle / square box).
2. **Greyscale survivability is a test, not an aspiration.** A greyscale screenshot of the spine
   must still distinguish all four states. The shape system guarantees it; the palette alone does
   not.
3. **Keyboard.** Native `<details>`/`<summary>` is focusable and operable with Enter/Space with no
   JS. `<summary>` gets `list-style: none` and `::-webkit-details-marker { display: none }` but
   **must not** get `tabindex="-1"` or `pointer-events` tricks. Open/closed state is announced
   natively — do not hand-write `aria-expanded`.
4. **Visible focus, always.** `:focus-visible { outline: 2px solid var(--cav-focus); outline-offset: 2px }`
   on `<summary>` and on every link. This mirrors the app's existing precedent
   (`layouts/app.blade.php:617`, `.btn:focus-visible { outline: 2px solid var(--accent-600); outline-offset: 2px }`)
   in brand colour. `#016E82` on white is 5.9:1, comfortably over the 3:1 non-text floor. Never
   `outline: none` without a replacement.
5. **Reduced motion.** The arrow's `transform .18s` transition is disabled under
   `@media (prefers-reduced-motion: reduce)`, following the existing block at
   `resources/css/app.css:41`.
6. **Headings.** One `h1` (project name); `h2` for the attention line and each of the three
   section groups. The page is navigable by heading alone.
7. **Glyphs.** `›`, `✓`, `▣` are decorative: `aria-hidden="true"`, with the meaning carried by
   adjacent text. No glyph is the sole carrier of information.
8. **Targets.** Every interactive element ≥ 44px in its smallest dimension.
9. **Chips are text, not badges-as-icons** — "Reconstructed" and "Superseded" are readable words,
   not symbols requiring a legend.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **None exists.** Phase 45 is read-only and has no call to action. The single navigation affordance is the text link **"Open the full project page"** |
| Attention line — something waiting (plural) | Heading: **"{n} things need you"**. Body names each item in a sentence, the waiting item inside `<em>` |
| Attention line — something waiting (singular) | Heading: **"One thing needs you"** (word, not numeral) |
| Attention line — nothing waiting | Heading: **"Nothing needs you on this job"**. Body: **"Every section below is either complete or not yet due."** No gold rule is rendered |
| Page empty state — heading | **"Nothing has been recorded on this job yet"** |
| Page empty state — body | **"This cockpit reads records the app already holds. When a site survey is submitted or a worksheet is signed on site, the visit appears here."** Drawers still render, all in the waiting state |
| Drawer empty state | Count slot: **"none yet"**. Status: **"Not started"**. Pip: waiting. Body: the section's mandatory hint sentence |
| Not-required deliverable | Chip: **"Not required"**. Body: **"Marked not required at import."** |
| Reconstructed visit (worksheet-derived) | Chip **"Reconstructed"** + sub-line **"Type inferred from a signed worksheet — the work actually done was not recorded."** |
| Reconstructed visit (survey-derived) | Chip **"Reconstructed"** + sub-line **"Built from the existing survey record, not captured as a visit."** |
| Superseded visit | Chip **"Superseded"** + sub-line **"Superseded {d M Y} — the visit still happened."** |
| Hand-ticked section (programming) | Status **"Marked done"** + body **"Nothing in the system can evidence this one, so it is a box someone ticks by hand. Ticked by {name} on {d M Y}."** Unticked: status **"Not marked"**, body drops the final sentence |
| Count disclosure | **"{n} visits · {m} reconstructed"** · **"{n} visits · {m} superseded"** · singular drops the numeral: **"1 visit · reconstructed"** |
| Error state — health unavailable | **"This job's summary could not be read just now. The sections below are still accurate."** The spine renders; only the attention line degrades. Never blank the page |
| Error state — a section's source record is unreadable | Row renders with the chip **"Record unavailable"** and sub-line **"The visit is recorded; the document behind it could not be read."** A broken source must not remove a visit from the spine (D-04) |
| Footer note (from the sketch, keep) | **"Visits group by type, so a three-day install is one line until you open it. Each section is also the deliverable — there is no second list saying the same thing twice."** The sketch's third sentence about the hidden task planner is dropped: the planner is Phase 51's concern |
| Destructive confirmation | **None.** No destructive action exists in Phase 45 |

Tone rules: plain English, no jargon, no exclamation marks, British spelling ("Superseded",
"organised"), dates as `02 Sep` in rows and `2 September 2026` in prose. Never the word "Error" in
user-facing copy — say what happened and what is still true.
