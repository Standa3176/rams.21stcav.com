## Decisions Made

- **SC #6 method-scoped token_get_all() check** — tightened from a broad literal-substring file scan. The previous heuristic would have rejected a legitimate future `systemMessage()` instructing the AI "do not invent hazards" (constraint text, not an output field). The new heuristic walks tokens to capture only `build()` / `*schema*` / `*response_format*` method bodies. BasePrompt is skipped (it is the contract, not an implementation).
- **Heuristic-robustness probe ran both ways:** a temp file `app/Core/AI/Prompts/__test_fixture_robustness.php` was created with the literal `"hazards"` (with quotes) inside `systemMessage()` body — SC#6 PASSED (40 assertions). The probe was then flipped to put `"hazards"` inside `build()` body — SC#6 correctly FAILED. The positive probe was restored, SC#6 passed again, and the file was deleted. The heuristic correctly distinguishes constraint-instruction text from AI-output schema fields in both directions.
- **DeadPathRemovalGuard whitelist extension** — Phase22_1InvariantGuardTest legitimately cites the same deleted class names as SC#3 deletion targets. Extending the whitelist (which already covered the DeadPathRemovalGuardTest file itself) to recognise the downstream guard file is the cleanest fix.
