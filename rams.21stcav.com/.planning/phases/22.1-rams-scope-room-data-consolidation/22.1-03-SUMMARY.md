# Phase 22.1 Plan 03: rams-scope-room-data-consolidation Summary

**One-liner:** Trimmed the per-room narrative schema to exactly 4 canonical keys (room / overview / works_summary / solution_type_id) and shipped `rams:backfill-room-overview-summary` — a dry-run-default artisan that copies the legacy `summary` field into `works_summary` with 4-category reporting and idempotent re-runs.

## What Shipped

- **Pure-function resolver service** `App\Services\Rams\RoomOverviewSummaryBackfillService` (single `resolveRow(array): array` method, no DB writes — mirrors Phase 22 `CablePortFkResolverService` pattern).
- **Artisan command** `rams:backfill-room-overview-summary {rams?} {--apply}` — dry-run by default, atomic write inside `DB::transaction` on `--apply`, 4-category report + apply-time `rows-written` counter, idempotent.
- **Schema trim** — `RamsReviewDataService::normaliseRoomOverviews()` outputs exactly 4 keys (`room`, `overview`, `works_summary`, `solution_type_id`). Legacy `summary` / `description` / `scope` keys removed from the canonical normaliser output. Load-time backfill block (for legacy summary + description fields) removed.
- **MethodStatementService input swap (D-01)** — `buildRoomDescriptions()` reads `room_overviews[*].overview` (PM-typed prose) instead of legacy AI-generated `description`. Fallback when overview empty: joins `works_summary` bullets into a prose paragraph (strips leading `- ` / `• ` markers, joins with `. `).
- **Legacy `summary` fallback drop (D-07)** — `MethodStatementService::buildRoomOverviewSummary()` AND `MethodStatementGeneratorService::buildRoomOverviewSummary()` (cache-key builder) no longer fall back to `$row['summary']`. `works_summary` is the single canonical source. `buildRoomList()` also updated to read `works_summary`.
- **AI prompt schema change (D-01)** — `RoomOverviewSummaryPrompt::systemMessage()` no longer instructs the model to produce a `description` field. The example JSON schema in `build()` contains only the `summary` key. The single surviving AI output is the bullet list.
- **Service wrapper update** — `RoomOverviewSummaryService::summarize()` no longer persists `description` into reviewed_data. The output array carries only `summary`.
- **Controller compatibility shim** — `ProjectPackageReviewController::generateRoomSummary` returns the engineer-typed `overview` verbatim as the `description` JSON response key so any existing front-end consumer stays renderable while the legacy AI prose is gone.
- **9 test files** (3 new test classes + 6 updated existing tests).

## Idempotency Proof

The `test_idempotency_second_apply_run_writes_zero_rows` feature test (49 GREEN assertions across the test class) seeds a single legacy-only fixture, runs `--apply` twice, and asserts:

- **First run:** `backfilled: 1` + `rows-written: 1` (works_summary now matches legacy summary verbatim).
- **Second run:** `backfilled: 0` + `both-set-no-action: 1` + `rows-written: 0` (because the legacy summary field is intentionally preserved verbatim — the row now has both works_summary AND summary populated → falls into both-set-no-action category, NOT already-set).

This is the correct semantics: the legacy `summary` field is preserved on disk by this command so the Plan 06 schema-trim has a clean before/after to test against. Plan 06 owns the on-disk JSON cleanup.

## Production Deploy Runbook (REQUIRED)

> **Deploy runbook:** Production deploy MUST run `php artisan rams:backfill-room-overview-summary --apply` immediately after this wave's code ships. Legacy `reviewed_data` records with the old `summary` field set but `works_summary` empty will render with empty bullets until the backfill runs.
>
> The byte-equivalence regression test in Plan 02 does NOT cover this edge case (its fixtures populate both fields). Run the dry-run first to inspect the 4-category report, then `--apply` to persist.
>
> Suggested order on a live deploy:
>
> ```bash
> # 1. Dry-run inspection
> php artisan rams:backfill-room-overview-summary

> php artisan rams:backfill-room-overview-summary --apply
> # 3. Confirm idempotency
> php artisan rams:backfill-room-overview-summary --apply  # must report backfilled:0 rows-written:0
> ```
>
> If the second `--apply` invocation reports `backfilled > 0` something is wrong — investigate before continuing the deploy.
