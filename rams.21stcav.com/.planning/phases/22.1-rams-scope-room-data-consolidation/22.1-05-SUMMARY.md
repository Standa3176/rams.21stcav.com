### Decisions captured (NOT deviations)

**1. Test strategy — pragmatic static guards over feature tests**

The plan's `<behavior>` section called for `ExtractRamsDraftJobTest::test_does_not_auto_write_project_works_description_from_quote_overview` and a feature-test pair `ProjectPackageReviewControllerScopeBulletsTest`. Both would require substantial fixture setup (faked DB + PDF + AIManager stub for the extraction job; faked authenticated user + ProjectPackage factory + route exercise for the controller). The fundamental invariant being asserted is "this LINE of code does not exist" — which is exactly what a static source scan captures with zero runtime deps.

I shipped:
- `ScopeConsolidationGuardTest` — 8 static invariants covering all 6 plan changes
- `RamsComplianceUpgradeServiceCacheTest` — 6 reflection-driven unit tests for the cache hit + cache miss + D-01 invariants
- 2 D-09 additions to the existing `RamsReviewDataServiceTest`

The combined suite asserts the same logical invariants as the originally-proposed feature tests, runs in <5 seconds, and has zero runtime dependencies (so it fires on every CI run regardless of binary availability).

**2. D-09 acceptance criterion deliberately not interpreted literally**

The plan's grep `grep -c "'overview'\\s*=>" app/Services/RamsReviewDataService.php returns 0` would also drop the room-level `overview` key on line 196 of `normaliseRoomOverviews` — which is explicitly canonical per Plan 22.1-03's 4-key schema. The plan's PROSE intent is dropping ONLY the project-level overview. I dropped the project-level emission and added 2 explicit unit assertions (canonical-11-keys + no-overview-key in project) that lock the correct invariant.

**3. Plan-cited line numbers reconciled — ExtractQuoteJob is the target**

The plan equivocated: `<read_first>` cites `ExtractRamsDraftJob:124,133` but `<action>` Step 1 says "the audit cites ExtractQuoteJob:124,133". The actual location is **ExtractQuoteJob** lines 124 (project create) + 133 (package update) — confirmed by grep. ExtractRamsDraftJob does NOT touch works_description. Both files are guard-tested for the dead pattern so a future drift in either is caught.
