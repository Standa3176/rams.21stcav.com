# Phase 46.6 Plan 05: Tab Persistence + Offline-Safe Autosave Summary

**The flattened survey link's active tab now survives a reload (`location.hash` + `sessionStorage`, keyed `svTab_{survey_id}`), and a failed autosave queues its whole payload to a `localStorage`-only draft map (`svDraft_{survey_id}`) instead of silently losing it — status text reads "Needs a connection" exactly, drained back through the existing `step-save` endpoint on reconnect.**

## Performance

- **Duration:** ~75 min
- **Tasks:** 3 (Task 1+2 combined implementation — they share the same two files and were committed together; Task 3 full-suite verification, no code change)
- **Files modified:** 1 modified (`resources/views/surveys/show.blade.php`), 1 created (`tests/Feature/Surveys/SurveyLinkOfflineAutosaveTest.php`)

## Accomplishments

- `SURVEY_ID` is injected once, as a bare `var` before the `surveyWizard()` Alpine component function — the same shape `WORKSHEET_ID` uses on the worksheet link (`public-show.blade.php:4829`).
- **Tab persistence (D-09):** `init()` now calls `_seedActiveTabFromPersistence()` before registering any watchers — it reads `location.hash` first (if it names a real tab: `'site'` or `'room-N'` for an existing room), falls back to `sessionStorage.getItem('svTab_' + SURVEY_ID)`, falls back to the existing default `'site'`. A restored room tab also re-syncs `currentRoomIdx`, matching what `selectRoom()` already does on a click. A `$watch('activeTab', ...)` then calls `_persistActiveTab(value)` on every change, which writes `history.replaceState` (hash) and mirrors into `sessionStorage`. The page's pre-existing `x-cloak` on `<body>` (unchanged) is what prevents a flash of the wrong tab while this seeding runs.
- **Offline-safe autosave (D-09):** `autosave(step)` now captures `roomIndex`/`payload` before the fetch. On success, `_draftClear(roomIndex, step)` removes any stale queued entry for that step. On failure, `_draftPut(roomIndex, step, payload.data)` queues the whole payload and `this.saveError` is set to the exact string `'Needs a connection'` — rendered by the page's pre-existing red status banner (`x-show="saveError"`, `x-text="saveError"`), no new UI markup needed.
- The draft queue (`_draftProbe`/`_draftReadAll`/`_draftWriteAll`/`_draftPut`/`_draftClear`/`_draftDrain`) is `localStorage` only, keyed `'svDraft_' + SURVEY_ID`, write-probe guarded by `'svDraftProbe_' + SURVEY_ID` (set-then-remove before any real write/read, so a private-browsing/quota-full environment degrades to the pre-existing `saveError` text rather than throwing).
- `window.addEventListener('online', () => this._draftDrain())` registered in `init()` — on reconnect, every queued entry is replayed through the same `/survey/{token}/step-save` endpoint and payload shape as a normal autosave; a failure mid-drain stops the loop (still offline), leaving the remainder queued for the next `'online'` event.
- The shared engineer offline-photo `IndexedDB` store (frozen at v1, `@include`d via `partials._engineer-offline-capture`) was not touched in any way — confirmed by grepping this plan's own diff and by a test reading the raw `show.blade.php` source directly for `indexedDB`/`engineer-capture` (zero occurrences in this plan's file; the pre-existing `@include` line is untouched and still appears exactly once).

## Deviations from Plan

**None requiring Rule 4 (architectural) escalation.** One Rule 3 (blocking-issue) auto-fix, caught and corrected before any test ran against it:

1. **[Rule 3] A comment written as `(@include'd below, schema-frozen...)` was parsed by Blade as the actual `@include` directive**, because Blade's lexer does not distinguish prose inside a `/* */` JS comment from real template syntax — it matched `@include` followed by `'d below...'` as if that were an attempt at the directive's argument list, and compiled to a broken `$__env->make(...)` call injected mid-sentence, breaking the whole script block with a `ParseError: syntax error, unexpected token ","`. Found immediately on the first test run (a `ParseError`, not a passing-for-the-wrong-reason false green). Fixed by rewording to "included below via the shared partial" — same meaning, no `@`-prefixed token. Files: `resources/views/surveys/show.blade.php`. Folded into commit `fd383603` (the breaking text was never committed on its own).
