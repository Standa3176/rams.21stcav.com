# Phase 46.6 Plan 03: Room-Tab Flatten (D-06) Summary

**Each survey room's 8-step sequential Alpine wizard is flattened into one scrolling tab panel — the 8 former steps become always-visible labelled `<section>` blocks, no Next/Back, no "Step N of 8", `autosave(step)` now takes an explicit step argument instead of a shared `currentStep`.**

## Performance

- **Duration:** ~90 min
- **Tasks:** 3 (Task 1 test + field inventory, Task 2 flatten implementation, Task 3 regression verification)
- **Files modified:** 1 modified (`resources/views/surveys/show.blade.php`), 1 created (`tests/Feature/Surveys/SurveyRoomTabFlattenTest.php`)

## Accomplishments

- All 8 former `<x-survey.step-container :step="N">`-gated blocks (Room Context, Quick Capture, Photos, Infrastructure, Equipment, Access & H&S, Constraints, Sign-off) are now plain `<section id="sv-step-N">` elements with a literal heading, rendered simultaneously — no `x-show="currentStep === N"` gating remains anywhere in the file.
- The header's "Step N of 8" progress bar, the wizard heading row's back-chevron button, and both bottom Next/Back nav bars (editable + read-only) were deleted. The sv-tab-bar (46.6-01) is now the only navigation in or out of a room.
- `currentStep`, `stepTitle` (getter), `validateCurrentStep()`, `nextStep()`, `prevStep()` — all retired from the Alpine component, not left dead.
- `autosave(step)` and `buildStepPayload(step)` now take an explicit `step` argument. Every call site was repointed: the existing debounced `$watch` triggers for `work_type` (step 1), the quick-capture toggles (step 2), and `engineer_feedback` (step 4) each now name their own step explicitly, and each got its OWN debounce timer (`_autosaveTimers: {}` keyed by step) — the old single shared timer would have let a rapid edit in one section cancel a pending save for a different section, now that all sections are editable at once.
- Each of the 8 `<section>` wrappers carries `@focusout="autosave(N)"`, giving every section a save trigger (not just the previously-watched toggle fields) — "once per section on blur/explicit-save", exactly the granularity the plan specified, same `stepSave` endpoint and payload shape as before.
- `markRoomComplete()` now (a) blocks completion with a `validationError` message if room name/type are blank — restoring the requirement the deleted Next-gate used to enforce structurally — and (b) saves all 8 steps in sequence before calling the `/complete` endpoint, instead of saving only whichever step happened to be `currentStep`.
- `work_type`-conditional `x-show` (Infrastructure section) and all other content-relevance `x-show`s were left completely untouched — only the step-container wrapper tags changed, confirmed by diff review.

## Decisions Made

See `key-decisions` in frontmatter. In short: re-add the name/type completion guard inline (Rule 1/2, not scope creep — the deleted Next-gate is what enforced it before); save all 8 steps before completion since there's no longer a forced per-step save on transition; leave the now-unused `step-container.blade.php` component file in place (D-05 forbids deletion, and nothing else references it); leave `work_type` content-relevance gating untouched per D-06.

## Deviations from Plan

**None requiring Rule 4 (architectural) escalation.** Two Rule 1/2 additions, both scoped to correctness regressions the flatten itself would otherwise introduce:

1. **[Rule 1/2] Independent per-step debounce timers.** The plan didn't call this out explicitly, but tracing the existing `debouncedAutosave()` mechanism showed it relied on ONE shared timer plus an implicit assumption (fields watched always belonged to whichever step was `currentStep`) that the flatten breaks — all fields are now simultaneously editable. A shared timer would have let a step-2 edit silently cancel a pending step-1 save. Fixed with `_autosaveTimers: {}` keyed by step number. Files: `resources/views/surveys/show.blade.php`. Commit: `49c2ee8a`.
2. **[Rule 1/2] Room name/type re-guard in `markRoomComplete()`.** The old `validateCurrentStep()` made it structurally impossible to reach Step 8 (sign-off) without a filled name+type, because `nextStep()` refused to advance. Deleting `nextStep()` removes that chain. Re-added the same requirement as an explicit check at the one remaining gate (room completion) so the flatten does not silently permit completing an unnamed/untyped room — something the pre-flatten page could never do. Files: `resources/views/surveys/show.blade.php`. Commit: `49c2ee8a`.
