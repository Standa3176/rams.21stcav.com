## 1. Migration — MUST run

One new migration this whole phase added:

```
database/migrations/2026_10_01_000000_create_survey_report_sections_table.php
```

Creates `survey_report_sections` (`id`, `site_survey_id` FK cascade, `section` ENUM of the four
named sections, `body` text, `user_id` FK nullOnDelete, `created_at` only — append-only, no
`updated_at` column at all). Run `php artisan migrate` on deploy.

⚠️ **The live-vs-sqlite hazard, named explicitly, per the non-negotiable rules:** tests run sqlite
`:memory:`; live is MySQL/MariaDB. This migration's identifiers were counted explicitly because a
prior migration in this repo passed every sqlite gate and was impossible on live (the 64-char
identifier cap). This migration's own identifiers:

| Identifier | Chars | Under 64? |
|---|---|---|
| `survey_report_sections_survey_idx` (explicitly named index) | 33 | yes |
| `survey_report_sections_site_survey_id_foreign` (Laravel auto FK name) | 45 | yes |
| `survey_report_sections_user_id_foreign` (Laravel auto FK name) | 38 | yes |

All three are comfortably under 64 characters — re-counted here, not assumed safe from the
46.6-02-SUMMARY.md figure alone.

## 2. `php artisan view:clear` — REQUIRED

Several Blade views changed across this phase (`surveys/show.blade.php`,
`site-survey/edit.blade.php`, `pdf/site-survey/summary.blade.php`) and two are new indirectly
(the `$completed`-gated block inside the existing unified `summary.blade.php`, and this plan's own
new links block on `edit.blade.php`). Laravel's compiled-view cache on the VPS will serve stale
markup otherwise. Run `php artisan view:clear` immediately after deploying the file changes.
