## Phase Boundary

The **survey engineer link** (`/survey/{token}` → `SurveyController::show` →
`resources/views/surveys/show.blade.php`) becomes a **tabbed page in the shape of SCC's PMV engineer
link** — site/contract details first, one tab per room along the bottom — and the survey it collects
gains a **review process** and **document output (PDF and XLS)**.

**In scope:** the tabbed layout and its sticky bar for the SURVEY link; a site/contract-details first
tab; the review process for a returned survey; PDF and XLS output of the completed survey.

**Out of scope:** the **worksheet** engineer link, which already received this treatment in Phase 46.7
and must not be re-cut; the cockpit (Phase 47 owns it); the RAMS pipeline (*"RAMs will use existing
RAM process"*, 46.5 D-04); the snag lifecycle (Phase 47.1).

⚠️ **THIS IS THE SECOND TIME THIS GAP HAS BEEN REPORTED, AND IT IS A DELIVERY GAP, NOT A CHANGE OF
MIND.** Phase 46.4 was asked to make the engineer link *"follow the same design as the scc pmv
engineer links"* and delivered the capture FIELDS without the LAYOUT. Phase 46.7 then fixed the
layout — **but only for the worksheet link** — and listed the survey link under its own Deferred
Ideas as *"The same treatment for the site-survey link"*. Quick task `260930-sv2` branded the survey
link but deliberately changed no structure. So the user has now asked for the same thing twice and

- **D-01:** **Rooms become TABS along the bottom, and the FIRST tab is site/contract details.**
  Measured 2026-10-01: `resources/views/surveys/show.blade.php` is 2,464 lines with **six `<details>`
  blocks and ZERO tab markup** (`data-tab` count: 0), while
  `resources/views/worksheets/public-show.blade.php` carries **12** `data-tab` hits. The survey link
  genuinely never got the treatment. The user names the ordering explicitly — site/contract details
  is tab one, rooms follow.

- **D-02:** **Re-review SCC's PMV engineer link — design AND function — rather than working from the
  earlier description of it.** The user asked for this directly (*"review the SCC pmv engineer links
  design and function again"*), and there is a reason to comply rather than reuse notes: the research

  **READ ONLY — IMPORT NOTHING:**
  `…/service contractor creator/service-contractor-creator/resources/views/pmv/show.blade.php`.
  ⚠️ Do not edit anything in that repository. It is a separate live application.

- **D-03:** **The review process is in scope, and `46.5-CONTEXT.md` already fixed its shape.**

- **D-04:** **Output is PDF *and* XLS.** The user names both. ⚠️ **A PDF route already exists and is
  reachable from nothing** — `site-surveys.client-report`, flagged in `47-CONTEXT.md`'s Deferred

  delete it."* **Check what it already produces before writing a second renderer.** XLS has no
  precedent in this repo — establish whether a library is already present before adding one.

- **D-05:** **The earlier structure of the completed-survey report still stands.** From the user on

  *"rooms summary, points raised/poss issues, items agreed with client and client lsts of items
  required plus any additional comments"*. That is five sections, not a free-form dump.

### Four decisions taken 2026-10-01, AFTER research surfaced them

- **D-06 (THE USER'S CHOICE — EACH ROOM FLATTENS TO ONE TAB):** ⚠️ **The survey link is NOT an
  accordion.** Research measured it as a **sequential Alpine step-wizard** —
  `screen: 'rooms' | 'step'`, **eight steps per room with Next/Back**
  (`surveys/show.blade.php:264`, `:312`). That is a materially harder starting point than the
  worksheet's `<details>` blocks were, and it created a real fork, so it was **put to the user rather
  than decided here**.

  **They chose: flatten each room into ONE scrolling tab, keeping the eight former steps as labelled
  sections so nothing is lost.** This is SCC's actual shape. It is the **larger** diff — roughly 900
  lines of Blade/Alpine on a page engineers use live — and that cost was stated to them before they
  chose. The rejected alternative was nesting the existing wizard inside each tab: a much smaller,
  safer diff, but not SCC's layout, and therefore likely to draw the same complaint a third time.

- **D-07:** **"XLS" means a real `.xlsx`.** ⚠️ **D-04's claim that XLS has no precedent was WRONG.**
  `phpoffice/phpspreadsheet ^5.8` is already a dependency (`composer.json:19`) and already used by
  `app/Services/CableScheduleXlsxService.php` — **follow that service's pattern.** A CSV precedent
  also exists in the very controller a new report method belongs in
  (`SiteSurveyController::variationsCsv`), but a real workbook is what an office needs, and the
  library is already paid for.

- **D-08:** **Do NOT write a second PDF renderer, and do not invent a new field for the report's
  office content.** `site-surveys.client-report` is real and works end to end: route →
  `SiteSurveyController::clientReport` → `SurveyPdfService::buildClientReport` → Browsershot →
  `pdf.site-survey.summary`, which already serves both the client and internal variants via an
  `$internal` flag. **Surface and extend it.** For the five sections' office content, follow the
  shipped doctrine in `app/Support/Visits/VisitReworkState.php`: **the office annotates a returned
  visit via `visit_notes` WITHOUT CHANGING WHAT THE ENGINEER SAID**, and
  `ProjectCockpitActionController.php:318` states outright that it never writes
  `SiteSurvey::office_review_notes`. The user's phrase was *"the engineer raised points on site and
  the office edited them"* — annotate-not-overwrite honours that while keeping the engineer's own
  record intact, which is the safer reading of "edited".

- **D-09:** **Follow the WORKSHEET's mechanics, not SCC's, where the worksheet is better.** D-02 asked
  to re-derive from SCC, and that was done — but research found **SCC's active tab does NOT survive a
  reload** (no hash or sessionStorage tie). RAMS's own worksheet link already persists tab state via
  `location.hash` + `sessionStorage`, and its autosave is `localStorage`-only and never touches the
  binary IndexedDB queue. Copying SCC faithfully here would be a **regression against the worksheet**,
  so the worksheet wins on both points. ⚠️ **Also corrected:** the `engineer-worksheet` IndexedDB
  warning does NOT bear on this page. The survey link `@include`s
  `partials._engineer-offline-capture.blade.php` (`:2461`), whose store is the **separate** — and also
  schema-frozen-at-v1 — **`engineer-capture`** database. That is the one not to disturb.

⚠️ **One more research finding, to prevent a wasted day:** `resources/views/public-survey/show.blade.php`
is a **dead 127KB file** backed by `PublicSurveyController::show()` with **NO GET ROUTE**. It compiles
and is easy to mistake for the live view. The live view is `resources/views/surveys/show.blade.php`
via `SurveyController::show` (`routes/web.php:87`). **Do not edit the dead one, and do not delete it
in this phase** (D-05 of SCOPE.md — nothing is deleted).

### Claude's Discretion

- Whether the survey link reuses the worksheet link's tab CSS and JS or carries its own, **given that

- Whether XLS means a real `.xlsx` or a CSV that opens in Excel — decide by what the office actually
  needs to do with it, and say which you chose.

## Existing Code Insights

- ⚠️ **THE OFFLINE QUEUE IS SCHEMA-FROZEN AT VERSION 1 AND HOLDS REAL UNSENT WORK** on engineers'
  phones: IndexedDB `engineer-worksheet`, store `pending_uploads`, keyPath `id`, index `capturedAt`,
  kinds `completed` / `label` / `kit`. `onupgradeneeded` only ever CREATES — it never migrates — so
  **bumping `DB_VERSION`, changing `keyPath` or touching the index STRANDS EVERY PENDING PHOTO on
  every engineer's phone.** If this page needs storage it must be **additive**, the way `kind:'kit'`
  was. Note the DB name is the *worksheet's*; decide deliberately whether the survey link shares it
  or uses its own, and state the reasoning.
- **46.7's offline ruling, which applies here too (D-06):** autosave keeps working offline using
  **`localStorage`** and never touches the IndexedDB store. **No affordance may appear to work
  offline and silently lose the change** — the controls say `Needs a connection` instead.
- ⚠️ **Guard tests on these pages match COMMENTS, and the counts are pinned.** On the worksheet link
  `{!!` is pinned at exactly **ONE** occurrence and the dead-but-pinned Alpine directives are
  ` x-data` 1, ` x-show` 1, ` x-model` 2, ` x-cloak` 1. **Writing any of those literals in prose or a
  comment breaks the guard** — it has nearly happened seven times and did happen twice.
  ⚠️ **`@php` inside a Blade `{{-- --}}` comment STILL COMPILES** and once swallowed the entire nav
  below Projects.
- **The survey link was branded on 2026-09-30** (`260930-sv2`): tokens `TEAL 01889F`,
  `TEAL_DARK 016E82`, `GOLD D4AF37`, `TEXT 1A1A1A`. ⚠️ Three AA contrast failures were fixed then —
  white on `#178A95` (4.11) and `#C9922A` (2.75) are **banned and asserted against** by
  `SurveyLinkBrandingTest`, which checks RENDERED output. `#01889F` and `#D4AF37` carry no text
  anywhere because both fail as text. **No webfont is fetched** — system stacks only. Do not
  reintroduce the old palette, including in a comment.
- **Engineer-typed text is unauthenticated input on a page a CLIENT may see** — every echo stays
  escaped, including anything built in JavaScript.
- **Banned columns that must NEVER render:** `device_label_photos.captured_by`,
  `worksheet_signoffs.ip_address`, `worksheet_signoffs.user_agent`, and
  `pre_install_confirmations.room_complete.{room}.completed_by` — the fourth was found rendering an
  engineer's IP to clients and was fixed on 2026-10-01 by plan 47-02. **Do not reintroduce any.**
- **LR-04:** a client is never given an engineer's phone or email — **name only**. Do not touch
  `tests/Feature/Security/LabourResourceClientSurfacePrivacyTest.php` except to add a genuinely
  client-facing path.
- **The three protected files stay BYTE-IDENTICAL to `4abd2b24`** (`resources/views/layouts/app.blade.php`,
  `resources/css/app.css`, `tailwind.config.js`), verified with working-tree `Get-FileHash` —
  `git hash-object` will NOT match on this CRLF checkout, and raw `git show` output is LF so a naive
  comparison falsely reports a mismatch. **A real mismatch is a STOP, never a hash to refresh.**
- ⚠️ **Tests run sqlite `:memory:`; live is MySQL/MariaDB.** A migration can pass every gate and be
  impossible on live — the 64-char identifier cap did exactly that, and because MySQL DDL is not
  transactional the retry then lied with "table already exists". **Name every composite index
  explicitly.**
- ⚠️ **PHP is not on the Bash tool PATH** — `php … | tail` exits 0 while running nothing, faking a
  green gate. Use `gate-46.ps1 -File`, **foreground, redirected not piped, one suite per
  invocation**; a killed stall also reports exit 0.
