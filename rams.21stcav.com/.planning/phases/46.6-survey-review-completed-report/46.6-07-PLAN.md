<task type="checkpoint:human-verify" gate="blocking">
  <name>Task 1: The user judges it — on a real phone, one-handed, in a plant room with bad signal</name>
  <what-built>
    The survey engineer link (`/survey/{token}`) now opens with a sticky bottom tab bar: a
    site/contract-details tab first, then one tab per room. Each room's former 8-step wizard is now
    one scrolling tab with the 8 steps kept as labelled sections — no Next/Back. Tab state survives a
    reload; typed text is never silently lost offline ("Needs a connection" + a local draft instead).
    The office can now write four report sections against a returned survey — points raised, items
    agreed with client, client's list of items required, additional comments — without ever touching
    the engineer's own captured record. A completed-survey report is downloadable as both a PDF
    (five sections: rooms summary, then the four office-authored ones) and a real `.xlsx` workbook.
  </what-built>
  <how-to-verify>
    1. **The acceptance test.** Open a real survey link on your phone. Do you see tabs along the
       bottom, with site/contract details as the first tab, exactly like the SCC PMV link? If not,
       say precisely what is missing or different.

    2. **The flatten.** Open a room's tab. Is everything from the old 8-step wizard still there, now
       all visible on one scrolling page instead of behind Next/Back? Is anything missing that used
       to be captured?

    3. **Reload survival.** While on room 3's tab, reload the page. Does it reopen on room 3, or does
       it reset to the site tab?

    4. **Offline honesty.** Turn on airplane mode, type something in a room section. Does the page
       say "Needs a connection" rather than appearing to save? Turn airplane mode off — does the text
       then actually save?

    5. **The office review.** Open a returned survey's internal edit page. Can you write and save the
       four new report sections? Does editing them leave the engineer's own original notes/variations
       untouched and still visible?

    6. **SRV-04's open discretion call.** The report sections are stored in a NEW table
       (`survey_report_sections`), separate from the visit-lifecycle's own `visit_notes` table,
       because a survey report needs to exist even for surveys no `Visit` wraps. Read the ledger's
       entry on this. Is that the right call, or would you rather these lived on `visit_notes`
       instead (accepting that pre-visit surveys then could not have a report)?

    7. **The report output.** Download both the PDF and the `.xlsx`. Do both show the five sections,
       in the right order, with real content? Would you be comfortable sending either to a client or
       using it internally today?

    8. **Simple to use.** Judging the whole link by your own standing criterion this milestone — is
       it simple, or does any part of it feel "scary" the way an earlier design in this project did?
       If so, name the part.

    Read the ledger's "For the checkpoint" column and answer each open question there too.
  </how-to-verify>
