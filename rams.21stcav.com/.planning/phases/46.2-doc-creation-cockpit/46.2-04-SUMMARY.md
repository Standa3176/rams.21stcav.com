# Phase 46.2 Plan 04: CockpitDocumentFormPresenter::DOCUMENT_FIELD_MAP Summary

The per-document field set is now one const map with four rows, and every field in it names a file
and a symbol that `grep` finds in a real generator — proven by an iterating test, not asserted in a
comment.

## THE DEFECTS — read these first

### D-46.2-04-01 (carried from planning, CONFIRMED, deliberately NOT fixed)

`programme.planned_end_time` is READ at `app/Services/Rams/RamsDisplayPatchService.php:153`
(`foreach (['planned_start_date', 'planned_end_date', 'planned_start_time', 'planned_end_time'] as $f)`)
but is **never emitted** by `RamsReviewDataService::normaliseProgramme()`
(`app/Services/RamsReviewDataService.php:270-296` returns a fresh array and that key is absent), so
the value is **always `''`**. A panel field for it would let a PM type a value `normalise()` silently
discards on the next pass. **Excluded from the map, asserted excluded by name**
(`test_planned_end_time_is_not_a_field()`), and the underlying defect left unfixed — logged, not this
plan's call.

### D-46.2-04-02 (NEW, found while deriving the survey field set, NOT fixed)

`resources/views/pdf/site-survey/_header-meta.blade.php:66-69` renders the comms-room access
checkboxes by comparing `comms_room_access_status` against `'permission'` / `'outsourced'` /
`'free'`. The **stored** vocabulary is `yes,no,outsourced,unknown` —
`SiteSurveyController.php:681` validates `in:yes,no,outsourced,unknown`, and
`DocxBuilderService.php:695` / `pdf/rams-v2.blade.php:866` map exactly those four to labels. So on
the field-form and blank-form PDFs, "Permission required" and "Free" **can never tick**; only
`outsourced` ever matches. The map offers the STORED vocabulary (offering the Blade's would store a
value the validator rejects). Not fixed here — out of this plan's `files_modified`.

### D-46.2-04-03 (NEW, the `working_hours` disagreement — grep overruled the plan)

The plan's `<interfaces>` specified `programme.working_hours` as two radios over the
`in_hours|out_of_hours` enum. **No generator reads that enum**: 0 hits for `$prog['working_hours']`
or `$programme['working_hours']` across the whole generator set, and its only consumer is the review
form that writes it (`ProjectPackageReviewController.php:1132`). What the RAMS cover and Section 4
actually render is a human-readable **string** from `form_data.working_hours`
(`CoverComposer.php:56`, `pdf/rams-v2.blade.php:420`, `DocxBuilderService.php:663`), validated at
`RamsFormRequest.php:64`. There is no `reviewed_data` home for it that survives normalisation —
`normaliseProject()` is exactly 11 keys and `working_hours` is not one. **Mapped as a text field at
`form_data.working_hours`**, the single documented exception to the normalised-key rule.

in the map is an access expression, not a bare key.

## How a fifth document type is added, without new branching

1. One row in `CockpitModulePresenter::MODULE_MAP` (title, icon, hue, count mode).
2. One row in `CockpitDocumentFormPresenter::DOCUMENT_FIELD_MAP` — `generate_route`, `formats`,
   `intro`, `readiness` (`null`, or an existing readiness kind), and `groups`.

No code changes anywhere: `fieldsFor()` is a map lookup, `readiness()` is a lookup plus a `match` on
a readiness **key**, and Plan 46.2-05's Blade iterates `groups` and switches on `type` — a closed set
of seven. `test_the_document_keys_match_the_module_keys_exactly()` makes forgetting either row a red
test rather than a panel with no fields. The only case needing new code is a fifth document with a
**genuinely new readiness source**, which adds one delegate method and one `READINESS_*` constant —
and that is a new data source, not a new branch in the rendering path.

**1. [Rule 1 - Bug] `working_hours` remapped from `programme.*` to `form_data.working_hours`**

- **Found during:** Task 1
- **Issue:** The plan listed `access_type`, `access_notes`, `parking`, `parking_notes`,
  `install_floor`, `delivery_area`, `restrictions` as RAMS fields. No generator reads any of them.

  documented in the class docblock so the next author does not re-add them.

**3. [Rule 1 - Bug] `programme.ongoing` dropped**
- **Issue:** the plan listed it as a checkbox; nothing in the application reads it.
- **Commit:** `c78ff05e`

**4. [Rule 2 - Missing critical functionality] `rules` for display-only fields is `['prohibited']`**
- **Issue:** the plan requires non-empty `rules` on every field so 46.2-05 cannot ship an
  unvalidated input. A read-only pre-filled field with permissive rules would let a submitted value
  silently overwrite what the project already knows.
- **Fix:** `prohibited` — submitting one is a validation failure, not a silent overwrite.
- **Commit:** `c78ff05e`
