## ⛔ The spend boundary, stated first because it changes what this plan proved

The plan's headline verification is *"generate each of the four documents on a real local project and
confirm the artifact opens."* **Three of the four could not be done, and were not done.**

`BuildRamsDocumentJob`, `BuildOmManualJob` and `BuildWorksheetJob` **step 1**
(`WorksheetGeneratorService::generateContent()` — per-room AI) all call the model. Running them costs
real money on the user's Anthropic account and **that spend was not authorised for this plan.**

| Document | Word artifact | PDF artifact | How far this plan got |
|---|---|---|---|
| **Worksheet** | ✅ **PRODUCED AND OPENED** | n/a (DC-07) | The whole walk: form → POST → delegation → `.docx` → download → zip opened → `word/document.xml` present → the project's own data inside it |
| **RAMS** | ❌ **NOT VERIFIED** | ❌ **NOT VERIFIED** | POST validated · values persisted where the generator reads them · `BuildRamsDocumentJob` dispatch asserted · both format routes resolve · **and the typed values followed all the way into the document's own data** (see below) |
| **O&M manual** | ❌ **NOT VERIFIED** | ❌ **NOT VERIFIED** | POST validated · `handover_date` persisted on the project · delegation reached · both format routes resolve |
| **Site survey** | ❌ **NOT VERIFIED** | ❌ **NOT VERIFIED** | POST validated · all the columns the PDF reads written on the active survey · both format routes resolve |

**Reason, in one line: unauthorised AI spend.** Nobody reading a green phase should conclude that
somebody opened these files. Three of them nobody has opened.

### Two things that make the boundary an assertion instead of a promise

1. **`QUEUE_CONNECTION` is `sync` in `phpunit.xml`.** An un-faked `dispatch()` RUNS the job inline.
   So the plan's literal instruction — *"`Queue::fake()` is NOT enough here … run the job inline"* —
   is precisely the instruction that would have spent the money, and it was **deviated from in the
   opposite direction**: `Bus::fake()` first in every test that reaches a generator, with
   `Bus::assertDispatched()` standing in for the run. The dispatch IS the delegation, and the
   delegation is what this phase owns.
2. **`Http::fake()` in `setUp()`** is the second belt — nothing may leave the machine even if a
   future generator stops going through the bus.

### And the site-survey premise turns out to be wrong — for free, and worth knowing

The brief that carried the prohibition said all three of RAMS, O&M **and site survey** "run through
the AI pipeline". **The site-survey Word path does not.** `site-surveys.docx` →
`SiteSurveyController::downloadDocx` → `SiteSurveyDocxService::build()` is pure PhpWord with no model
call anywhere in it, exactly like `WorksheetDocxService`. It is **already exercised for real** by
`DocumentFormatInventoryTest::test_site_survey_word_downloads_a_docx` (200, `.docx` attachment) — and
the four real `.docx` files sitting in `storage/app/site-surveys/` are its output from earlier gate
runs.

**It was still not produced or opened here**, because the instruction named the site survey
explicitly and a prohibition on the user's money is not mine to reinterpret on a premise. Recorded
so the user can lift it in one sentence: **the site-survey Word cell can be closed for zero spend by
adding a zip-open assertion to a test that already downloads the file.**

## The Worksheet, which really does open

`test_the_worksheet_walks_from_the_form_to_a_word_file_that_opens()`, in eight steps:

1. `GET` the cockpit with the Worksheet row closed — one control reading `Generate document`, and
   `<form` count **0** inside `cav-qa`.
2. `GET ?action=generate` — the form discloses, and the DC-07 sentence is on the page verbatim:
   `PDF is not available for this document (DC-07).` No `value="pdf"` anywhere.
3. `POST projects/{project}/cockpit/documents` through the real kernel → redirect to
   `?module=worksheet&tab=files`, the `Worksheet` row created at `status=generating`.
4. `Bus::assertDispatched(BuildWorksheetJob::class)` — **the delegation reached, and stopped there,
   unspent.**
5. The AI-authored content **seeded as a named fixture** — this is the seam, and it is named at the
   seam rather than in a footnote.
6. `WorksheetDocxService::build()` run for real. `filename` written on the row.
7. `GET worksheets.download` → 200, a real file on disk, **non-zero bytes**.
8. **It opens.** `ZipArchive::open()` returns true, `word/document.xml` is in the entry list, and the
   XML contains `Northbank Fitout` and `Boardroom` — the project's own data, not a cover-only shell.

Byte count is necessary and not sufficient (T-46.2-20), which is why steps 7 and 8 are both there.

## D-46.2-04-02 — assessed as IN SCOPE, and fixed

**It was fixed.** `resources/views/pdf/site-survey/_header-meta.blade.php` compared
`comms_room_access_status` against `permission|outsourced|free`, while the stored vocabulary is
`yes,no,outsourced,unknown` — validated in three controllers (`PublicSurveyController:759`,
`SiteSurveyController:681`, `SurveyController:1096`) and mapped correctly by every other renderer
(`WorksheetDocxService:156`, `DocxBuilderService:711`, both `yes => 'Permission required'`,
`no => 'Free access'`). So **"Permission required" and "Free" could never tick**, whatever the
surveyor answered.

**Why in scope:** 46.2-05 put the field on the cockpit's own document form, which turned a defect
nobody could trigger into a defect a PM triggers in one click. That is the change that moved it, and
logging it a third time would have been a decision to ship a known-wrong document off a brand-new
surface.

**Measured RED first.** `Tests: 5 failed, 1 passed` before the fix; `Tests: 11 passed` across
`tests/Feature/Documents` after it (was 5).

### The second defect in the same three lines, which is why the fix is two tokens wider than "the comparison"

The glyphs were `{{ $status === '…' ? '&#9745;' : '&#9744;' }}`. Blade's `{{ }}` runs `e()` with
`$doubleEncode = true`, so the numeric entity left the renderer as `&amp;#9744;` and **the PDF printed
the literal text `&#9744;`** where a ballot box belonged. Measured, not reasoned about:

```
$ php artisan tinker --execute="... view('pdf.site-survey._header-meta', ['survey' => new SiteSurvey(['comms_room_access_status' => 'yes'])])->render() ..."
            <span class="checkbox">&amp;#9744;</span> Permission required &nbsp;
            <span class="checkbox">&amp;#9744;</span> Outsourced &nbsp;
            <span class="checkbox">&amp;#9744;</span> Free &nbsp;
```

Fixing only the comparison would have produced a tick **no reader could see**, so the two are one
fix. The glyphs are now the ballot **characters** (U+2611 / U+2610), which need no entity and survive
`e()` untouched. **No `{!! !!}` was added** — that would have put a fresh unescaped echo on a PDF
Blade, which is the exact thing T-46.2-16 exists to keep out.

**What changed, and nothing else:** three comparison lines, their three glyph pairs, and the stale
`// permission|outsourced|free|null` comment above them. No generator. `unknown` and `null` tick
nothing, which is correct — there is no fourth box, and adding one is a content decision.
