# Phase 46.2 Plan 03: Unsurface the visit workflow Summary

The visit workflow and the returned-evidence review came off the cockpit without one line of the
code behind them being deleted — proven by driving all five POSTs and both evidence GETs for real
while asserting that no anchor on the page reaches any of them.

## What shipped

### The surfacing that went

| Removed | What it was |
|---|---|
| `resources/views/components/cockpit/quick-actions.blade.php` | the Create-visit form and control, plus the per-row "Generate document" control |
| `resources/views/components/cockpit/returned-tab.blade.php` | the returned-evidence tab and the four review acts beneath it |
| `panel.blade.php` — `$offersReturned`, the `?tab=returned` coercion, `$returnedVisits`, five props | the presence rule and the Returned tab's wiring |
| `ProjectCockpitController` — `evidenceFor()`, `resolveAction()`, `resolveActionVisitId()`, `roomNames()`, `activePeople()` | the five wirings those controls needed |
| `projects/cockpit.blade.php` — five `<x-cockpit.panel>` attributes | `evidence`, `action`, `action-visit-id`, `rooms`, `people` |

Deleting the two Blade components is this repo's own established rule, cited in the replacement
comment: `CockpitPageTest`'s ruling on the superseded accordion — *"a dead drawer component left on
disk is an invitation for a later agent to render one beside the new design."* Neither file is on
D-02's protected list; neither is a model, a service, a controller or a route.

`$tabs` is now the literal three. `ProjectCockpitController::TABS` drops `returned`, which moves the
stale-bookmark fallback into ONE place — `resolveTab()` — so the strip and the body can no longer
disagree about which tab is open. `ACTIONS` is `[]`, documented dormant on the same reasoning that
kept `COUNT_NONE` dormant in 46.2-01: Plan 46.2-05's `?action=generate` needs exactly this mechanism.

`panel.blade.php`'s docblock now names all seven routes the capability still lives at, so the next
reader finds the kept code rather than concluding it was deleted.

### Zero-caller services, deliberately

`App\Support\Cockpit\CockpitEvidencePresenter` and `App\Support\Cockpit\VisitEvidence` now have no
caller from the cockpit's side. **This is deliberate and it is stated in three places** — the
controller, `panel.blade.php`'s docblock and `CockpitReturnedTabTest`'s class docblock. It matches
the precedent `SiteSurveyDocxService` set: a written, tested service waiting for a surface, which
Plan 46.2-02 wired up rather than deleting. Both keep their own green tests
(`CockpitEvidencePresenterTest`, 16 passed, unedited).

### The proof that unsurfaced ≠ deleted

`CockpitReadOnlyFenceTest::test_the_unsurfaced_write_routes_all_still_work_with_no_link_on_the_page()`
replaces the retired `test_the_returned_tab_is_among_the_regions_this_fence_judges()` with its exact
inverse. Against a genuinely RETURNED visit with real bytes on a faked disk it:

1. POSTs `visits.store`, `.notes`, `.snags`, `.send-back`, `.accept` — all five redirect;
2. GETs `visits.photos-zip` and `visits.photo` — both 200;
3. asserts **no judged region contains any of those seven URLs, and none contains the substring
   `/cockpit/visits/` at all**;
4. asserts `returned ∉ TABS` and `ACTIONS === []`.

That is the executable form of threat-register entries **T-46.2-06** and **T-46.2-07**, both
`accept`: these routes were never protected by the absence of a link, and their real guards — `auth`,
`@csrf`, per-route validation, route-bound `{project}` scoping — are untouched. Removing a link is
not a security change in either direction.

## Deviations from Plan

### Applied under the plan's own instruction

**1. [Rule 3 — Blocking] Four test files not in `files_modified` had to be edited**
- **Found during:** Task 2
- **Issue:** the plan's Task 2 named six classes, but 46.2-01 routed seven findings to this plan
  (F-1…F-7) landing in `CockpitPageTest`, `CockpitPanelTest` and `tests/Unit/Cockpit/CockpitHeaderPresenterTest.php`,
  none of them in `files_modified`. The cockpit suite could not go green without them.
- **Fix:** repointed or retired by name, each with its reason — see the F-table above.
- **Commit:** `48b054ba`

**2. [Rule 3 — Blocking] `projects/cockpit.blade.php` edited though absent from `files_modified`**
- The plan's Task 1 action explicitly instructs it ("drop the five now-unused attributes"); only the
  frontmatter list omits it. Also corrected its stale "Nine rows … (D-16)" comment.
- **Commit:** `0a02b6dc`

**3. [Rule 1 — Bug] `returned` removed from `ProjectCockpitController::TABS`**
- **Issue:** the plan named the Blade-side coercion for removal but not the constant. With `returned`
  still a legal tab and the `@elseif ($tab === 'returned')` branch gone, `?tab=returned` would have
  fallen through to the `@else` and rendered the **Notes body with no tab marked active** — a real
  defect, not a stale bookmark.
- **Fix:** `TABS = ['overview','files','notes']`, so the fallback is `resolveTab()`'s and there is
  exactly one of it. `CockpitTabPreservationTest` now asserts plain `'returned'` is rejected at the
  POST boundary too.
- **Commit:** `0a02b6dc`

**4. Three unused imports and one unused constructor injection removed** from
`ProjectCockpitController` (`LabourResource`, `SiteSurvey`, `CockpitEvidencePresenter`). The
injection went with its only caller, `evidenceFor()`. **The classes themselves are untouched** —
see the zero-line diff above.

**5. Five green-but-now-vacuous tests retired or repointed rather than left green.** The plan says
"do not retire a test that is still green", and that rule was honoured for its purpose — nothing was
retired to make a change fit. These five passed by asserting an EMPTY `.cav-qa` subtree or by
rendering `?tab=returned` (which silently became an Overview render): green while covering nothing,
and carrying names that lied. Each is named in the ledger with which of the two it was. The stronger
replacement is asserted in every case.

**6. Names corrected where they had become false:** three stale "nine" references in
`CockpitPageTest`, and seven test names that said "offers accept" / "shows its evidence" / "renders
per room answers" while asserting the opposite.
