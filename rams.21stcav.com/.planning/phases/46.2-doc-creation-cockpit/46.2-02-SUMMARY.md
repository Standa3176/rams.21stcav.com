# Phase 46.2 Plan 02: Document Format Inventory + Site Survey Word Summary

Measured the Word x PDF matrix for all four cockpit documents, wired the never-called
`SiteSurveyDocxService` to a guarded `site-surveys.docx` route, and recorded the one gap that cannot
be closed without writing a new renderer.

## THE FINDING: the Worksheet has no PDF, and cannot get one in this phase

**DC-07 is recorded NOT DELIVERED.** Three measured facts, any one of them sufficient:

1. `worksheets.engineer-report-pdf` (`routes/web.php:704`) renders `pdf.engineer-report` — the
   engineer's **activity** report from `EngineerActivityService::buildReportContext()`. A different
   document for a different purpose.
2. It carries `abort_if(! $worksheet->hasEngineerActivity(), 404)` (`WorksheetController.php:110`),
   so it **404s for exactly the user this phase serves** — a PM generating a worksheet up front.
3. `ls resources/views/pdf | grep -i work` returns nothing (exit 1). There is no worksheet PDF
   Blade, so producing one means **authoring a new render target**, which D-04 forbids here.

The Worksheet's PDF control must therefore say PDF is unavailable rather than offer a button that
fails. **Three options with their costs are written up in the inventory file and NONE is chosen on
the user's behalf**: (a) accept Word-only in 46.2; (b) authorise `pdf/worksheet.blade.php` as its own
phase — a content decision before a code one; (c) offer the engineer-activity report, honest only if
**relabelled** and gated on `hasEngineerActivity()`.

## What shipped

- **`GET site-surveys/{siteSurvey}/docx`**, named `site-surveys.docx`, registered immediately beside
  `site-surveys.pdf` inside the same `auth` group, so its ordering against the
  `Route::resource('site-surveys', ...)` wildcard is identical to the PDF route that already works.
- **`SiteSurveyController::downloadDocx()`** — `authorizeSurvey($siteSurvey)` as the FIRST statement
  (the same guard as `downloadPdf`, not a looser one, T-46.2-03), then
  `$this->docxService->build($siteSurvey)` and `response()->download($path, 'site-survey-{id}.docx')`.
  `SiteSurveyDocxService` is injected via the constructor, matching the file's own convention rather
  than an `app()` call mid-method.
- **Attachment filename is the survey id only** — never the raw project or client name, which is user
  data in a response header.
- **`DocumentFormatInventoryTest`** — five tests; the inventory as code.

## The inventory is executable, not prose

The eight cells live as a `FORMAT_ROUTES` const map in `tests/Feature/Documents/DocumentFormatInventoryTest.php`:

- `test_every_named_format_route_exists()` — `Route::has()` for all seven non-null cells, so a
  renamed or deleted route fails in CI rather than as a dead control on a PM's screen.
- `test_the_only_missing_format_is_the_worksheet_pdf()` — asserts the null set is **exactly**
  `['worksheet.pdf']`. Kept exact, never a floor: a new null means a format was silently dropped, a
  missing null means DC-07 was closed without recording it. `worksheet.pdf => null` carries an inline
  comment naming DC-07 and the reason, including an explicit "do not fix by pointing this at the
  engineer report".

The markdown file is the prose explanation of that assertion, not the record itself.

## D-46-05-01 not reproduced

`test_site_survey_word_survives_a_survey_with_no_rooms()` GETs `site-surveys.docx` for a survey with
genuinely zero rooms (asserted `rooms()->count() === 0`) and gets **200, not 500**. Proven by test,
not by reasoning: `SiteSurveyDocxService` iterates `$survey->rooms->sortBy('sort_order')`
(`:75`), which is empty-safe, and the template branch does not read a variable assigned inside a
populated-rooms branch. The live `/worksheet/{token}` roomless 500 (`$signOffBlocked`) is carried
forward untouched, as instructed.

## Named for 46.2-05: a write during a GET

`SiteSurveyDocxService::build()` executes `$survey->update(['filename' => ...])` (`:89`) — a WRITE on
a GET request. **Deliberately not changed** (minimal-diff rule; T-46.2-05 accepted). This is stated
rather than implied because **Plan 46.2-05 will link to this route from inside the cockpit**: the
cockpit fence's write-surface / GET row-count invariance is about the cockpit's OWN GETs, not about
what a link's target does once the browser leaves the page. If 46.2-05 ever fetches this route
in-page rather than linking out, that boundary changes and must be re-argued.
