# Phase 46.2 Plan 01: MODULE_MAP nine to four Summary

Nine cockpit module rows reduced to the four documents the cockpit now creates, with Phase 45's
"every visit type reaches exactly one module row" invariant retired by name and replaced by the two
halves of it that 46.2 D-01 did not license.

## What shipped

### The four rows (46.2 D-01), in render order

| # | Key | Title | Count mode |
|---|-----|-------|------------|
| 1 | `site_survey` | Site survey | `visits` |
| 2 | `worksheet` | **Worksheet** (D-07) | `visits` |
| 3 | `rams` | RAMS | `documents` |
| 4 | `om` | O&M manual | `documents` |

Removed entirely from `MODULE_MAP`: `install_programme` (Programme and commissioning), `drawings`
(Drawings), `cable_schedule` (Cable schedule), `programming` (Programming), `snagging` (Snagging).
All five remain in `ProjectDeliverable::ALL_KEYS`, which stays **nine** — that is the deliverables
screen's vocabulary and this phase does not touch it.

`site_survey` and `worksheet` keep their `visit_types` arrays (D-06): the row stops *offering* visit
actions in 46.2-03, it does not stop *reporting* them.

`COUNT_NONE` (Programming was its only user) and `COUNT_TASKS` (Programme and commissioning was its
only user) are now unreachable. Both are **kept** and documented as dormant at the class docblock —
`ProjectDeliverable.php:14-26` still forbids inventing a Programming store, and a future row with no
store must stay representable.

### The retirement (the delicate part)

`CockpitModulePresenterTest::test_every_visit_type_maps_to_exactly_one_module()` is gone as a name,
with a retirement block at its former position citing **46.2 D-01** and stating it was retired, not
deleted to make a red test pass. Its two surviving halves:

- `test_no_visit_type_reaches_two_module_rows()` — iterates `Visit::TYPES`, counts owners in
  `moduleMap()`, asserts `<= 1`, and still asserts that any owning row is actually rendered.
- `test_the_visit_types_with_no_module_row_are_exactly_three_and_named()` — the zero-owner set must
  equal exactly `[commissioning, programming, snag]`. A seventh visit type added later, or a fourth
  type losing its row, still fails loudly. That was D-16's real argument and it is kept even though
  its conclusion was reversed.

The class docblock of `CockpitModulePresenter` now records: four rows per 46.2 D-01, D-16 as the
decision reversed (with the reversal already recorded at D-16 itself in
`.planning/sketches/004-delivery-cockpit/README.md`), the invariant as now false, and both
replacement test names.

Two further retirements named in the plan:

- `test_the_nine_module_keys_are_the_canonical_deliverable_vocabulary()` →
  `test_the_four_module_keys_are_a_named_subset_of_the_canonical_deliverable_vocabulary()`. Keeps the
  membership half: every rendered key must still be in `ProjectDeliverable::ALL_KEYS`, and
  `ALL_KEYS` is still asserted to be nine.
- `test_a_snag_visit_reaches_the_snagging_row()` → `test_a_snag_visit_reaches_no_module_row_by_design()`
  — inverted rather than dropped, and it also asserts the snag visit changes no surviving row's count.

### Threat model

still rendered. T-46.2-02 and T-46.2-SC remain `accept` — `progress()` returns null for any unknown
key (asserted), and this plan installed no package.
