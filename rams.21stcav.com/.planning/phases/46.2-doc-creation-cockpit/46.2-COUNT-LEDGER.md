## RETRACTED — the "one gap this reconciliation found" was not a gap

**The first version of this ledger claimed `DEFERRED_AFFORDANCES` was the only fence list whose
length is not asserted. THAT CLAIM WAS WRONG.** It is asserted, it always has been, and it bites.

```php
// tests/Feature/Cockpit/CockpitReadOnlyFenceTest.php:853-857
$this->assertCount(
    21,
    self::DEFERRED_AFFORDANCES,
    'Every affordance drawn in either sketch is enumerated; nothing is dropped silently.'
);
```

It is the FIRST assertion in `test_the_fence_enumerates_the_whole_deferred_set()` — the test whose
name says exactly that — and the other three lists are pinned 110 lines further down the SAME
method, at `:964-966`.

### How the false finding was made, because the method is the lesson

The reconciliation was done with a single-line regex:

```
$ grep -n "assertCount([0-9]\|assertSame([0-9]" tests/Feature/Cockpit/CockpitReadOnlyFenceTest.php
964:        $this->assertCount(2, self::FORBIDDEN_MARKUP);
965:        $this->assertCount(13, self::WRITE_SURFACE_TABLES);
966:        $this->assertCount(9, self::BANNED_HANDLER_ATTRIBUTES);
```

Three hits, so three pinned lists, so the fourth must be unpinned. **The three that matched are
single-line calls. The one that did not is a multi-line call with its `21` on its own line**, which
the pattern `assertCount([0-9]` cannot match. An absence in a grep was read as an absence in the
code, and a paragraph was written asserting a negative that had never been checked by any other
means.

The claim then propagated into `46.2-RETIREMENT-LEDGER.md`, into `REQUIREMENTS.md` under DC-11, into
`46.2-06-SUMMARY.md` as defect **`D-46.2-06-04`**, and into a report that led the coordinator to
authorise a commit adding the "missing" assertion. All of it is corrected here and in those files.

### It was caught by the instruction to prove the fix bites

Removing `'Add document' => 'Phase 48'` from the list was supposed to demonstrate a newly added
pin. Instead it went red on line **853** — an assertion that predates this phase entirely:

```
FAILED  CockpitReadOnlyFenceTest > the fence enumerates the whole deferred set
Failed asserting that actual size 20 matches expected size 21.
  ➜ 853▕         $this->assertCount(

Tests:    1 failed, 11 passed (1368 assertions)
```

So the entry CANNOT leave the list silently, has never been able to, and the duplicate assertion
that had been added at `:967` was removed. `CockpitReadOnlyFenceTest.php` is **byte-identical to
the commit that entered this plan** — `git status --short` clean for that path.

**Every one of the four fence lists is pinned. The house rule held. There is no gap.**

The two genuine disagreements with the plan's planning-time table — `cav-kpi` being an exact
literal rather than a derived count, and `cav-module__count` being genuinely derived — stand as
written above. They were each verified by reading the assertion, not by failing to grep it.
