<objective>
Wire `PdfTextExtractorService` to detect priced "ram"-template QuoteWerks PDFs (short-tag variant) and re-extract them with `pdftotext -layout` instead of the default `-raw`. The 260603-q7t translator (`translateShortTagsToLong()`) was tuned to the `-raw` column-flattened output and works partially via Quirk 1/2 column-split repairs; switching to `-layout` gives the translator clean column-positioned text and unlocks full extraction (site name, ship contact/phone/email, three room overviews, all priced line items).

Purpose: Project 78 (Cicor Hartlepool / pkg 142) currently loses ship_contact, ship_phone, room overviews, and most equipment areas. Live diagnostic on the production PDF showed `pdftotext -layout` produces the clean shape the translator can parse end-to-end. The translator stays as-is; only the extractor changes WHAT TEXT it feeds the parser.

Output:
- Extractor branches on short-tag detection and prefers `-layout` output over `-raw` when the priced template is detected.
- Graceful fallback preserves today's behaviour when `-layout` re-extract fails (binary lookup miss, shell_exec disabled on CWP, Process error, empty output).
- Test fixture replaced with the real `pdftotext -layout` output of the Cicor PDF; existing translator end-to-end tests stay green against the new shape (with assertions unchanged — they were always the right goals).
- New routing tests prove the detection + re-extract + fallback paths.
- Post-deploy: project 78 gets a THIRD `reimportPending` re-extract using the same recipe from 260603-q7t SUMMARY (with `$prev` captured first).
</objective>

<context_correction priority="critical">
**The planning context describes the OLD extractor architecture. The current extractor (post-260603 work) is materially different:**

1. **Stage 0 already runs pdftotext** (`extractWithPdfToText` at L168-250) with `-raw -enc UTF-8` flags via `shell_exec`. It is the PRIMARY extractor, ahead of smalot. The planning brief's "smalot extracts → detect → re-extract via pdftotext" framing is inverted.
2. **The current "wrong" fixture** at `tests/Fixtures/quotewerks/priced-cicor-21CQ30167.txt` is actually **`pdftotext -raw` output**, not smalot output — confirmed by the layout: line 1 is the total `15,089.50` (a footer position artefact of `-raw`'s reading-order flattening), and lines 11/24/43/68 carry the column-split `H1 ... H1E 1E` and `D1S F D1E irst Floor` shapes that the q7t translator's Quirk 1 (H-tag column-split repair) and Quirk 2 (D-tag prefix-split repair) regexes are tuned to handle. The translator already partially works on this `-raw` form (the unit tests pass via reflection); what fails is the live end-to-end pipeline where the column-split repairs miss because real-PDF spacing differs slightly from the synthetic fixture.
3. **The real fix:** when the short-tag variant is detected, re-extract the PDF with `pdftotext -layout` (column-positioned output). `-layout` preserves spatial positioning, eliminates the column-split garbage entirely, and gives the translator clean `H1 ... H1E` patterns the SHORT_TO_LONG_TAGS map can rewrite directly.
4. **`spatie/pdf-to-text` package: not the right vehicle.** The current Stage-0 implementation invokes pdftotext via raw `shell_exec` with cross-platform binary detection (Windows Git/Poppler + Linux `/usr/bin/pdftotext` + PATH lookup via `where`/`which`). Introducing spatie/pdf-to-text would fork that detection logic in two places. The Layout re-extract reuses the SAME binary detection (extracted to a helper) and just swaps `-raw` for `-layout`. The spatie/pdf-to-text package is left in composer as documented fallback, not added to the runtime path here.

This plan implements (a) and (b)–(d) of the requested output deliverables accordingly.
