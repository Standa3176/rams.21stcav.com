# Quick Task 260925-d51: Roomless worksheet public link 500 (D-46-05-01) Summary

`GET /worksheet/{token}` returned a 500 for any worksheet with zero rooms because the survey-review sign-off gate was computed inside the populated-rooms branch of `public-show.blade.php` but read after it; both `$signOffBlocked` and `$unreviewedRooms` are now declared unconditionally above the branch, defaulting to not-blocked.

## The defect

`resources/views/worksheets/public-show.blade.php` wraps all room rendering in
`@if(empty($rooms)) … @else … @endif` (`:671` / `:676` / `:1338` pre-fix). Two
variables were assigned only in the `@else` arm yet read after the `@endif`:

| Variable | Assigned | Read outside the branch |
|---|---|---|
| `$signOffBlocked` | `:773` | `:1359`, `:1441` |
| `$unreviewedRooms` | `:765` | `:1362` |

With `$rooms === []` the `@else` arm never runs → `Undefined variable
$signOffBlocked` → 500 on an unauthenticated engineer link.

`$unreviewedRooms` was masked in production only because `@if($signOffBlocked)`
is evaluated first and throws. Defaulting `$signOffBlocked` on its own would
have surfaced a second, identical 500 at `:1362` — which is why both are fixed
in this one commit.

## Neighbourhood scan

All 70+ variables assigned inside the branch were enumerated and intersected
against every variable used after the `@endif`. The full set used after the
`@endif` is `$latestSignoff`, `$signOffBlocked`, `$token`, `$unreviewedRooms`,
`$worksheet`. Of those, `$latestSignoff`, `$token` and `$worksheet` are passed in
by `PublicWorksheetController::show`. **`$signOffBlocked` and `$unreviewedRooms`
are the only two with the assigned-inside / read-outside shape, and both are
fixed here.** No third instance exists, so nothing was logged for later.

## Reachability — this is a real state, not a theoretical one

`resolveWorksheet()` gates on token existence and token expiry only. It never
checks `status`, and never checks whether content exists. Three routes in:

1. **Generation window.** `WorksheetController::generateFromProject` inserts the
   row with `generated_data` NULL, and `Worksheet::boot::creating` mints the
   `access_token` in the same instant. The public link is live and 500ing for the
   whole time `BuildWorksheetJob` is queued/running.
2. **Failed generation — permanent.** `BuildWorksheetJob` *throws* when
   `roomsCount === 0`, or when no room has equipment / install steps /
   pre-install answers. `generated_data` stays NULL forever → permanent 500.
3. **Edited to empty — permanent.** `WorksheetEditAdapter::applyRemoveRoom` has
   no last-room guard; removing the final room writes `rooms: []` → permanent 500.

## What changed

**`resources/views/worksheets/public-show.blade.php`** — in the existing
unconditional `@php` block, immediately after `$rooms = …`:

```php
$signOffBlocked  = false;
$unreviewedRooms = [];
```

plus a comment block recording the three reachable states, the decision and its
reasoning, and a "keep these ABOVE the branch" warning. No markup, no styling,
no JavaScript, no Alpine, no refactor. The `@else` arm's own assignments are
untouched and still overwrite these whenever rooms exist.

**`tests/Feature/Worksheets/RoomlessWorksheetPublicLinkTest.php`** (new, 4 tests):

1. `generated_data` NULL → 200 + "No room data is available yet"
2. `['rooms' => []]` → 200 + same
3. roomless → `data-signoff-blocked="0"`, no warning banner, Client Sign-Off card present
4. **canary** — a room whose linked `SiteSurveyRoom` carries `mounting_heights`
   and is unreviewed is STILL blocked (`data-signoff-blocked="1"` + banner), so
   the defaults cannot be shown to have disarmed the live gate

The fixture uses `Worksheet::create()` so `boot::creating` assigns
`access_token` by direct property assignment — `access_token` is deliberately
absent from `$fillable` (re-audit S-03) and is never mass-assigned in the test.

## Deferred / logged, NOT fixed

1. **`WorksheetEditAdapter::applyRemoveRoom` has no last-room guard.** It will
   happily write `rooms: []`. After this fix that renders a valid 200 page, so it
   is no longer a 500 — but whether emptying a worksheet via an edit op should be
   permitted at all is a product question, out of scope here.
2. **A roomless worksheet is still client-signable.** The Client Sign-Off form
   renders below the "No room data is available yet" card, and
   `PublicWorksheetController::sign()` has no precondition on content. If an
   empty worksheet must not be signable, that is a server-side gate in `sign()`,
   not a display flag — see D-01.
3. **`BuildWorksheetJob`'s zero-content throw leaves the row permanently NULL**
   with a live public token. A status-aware branch on the public page (e.g.
   "generation failed, contact your project manager") would read better than the
   generic "no room data is available yet", but that is new behaviour, not a
   null-variable fix.
