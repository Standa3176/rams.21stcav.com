<objective>
Build a single-click, auto-generated client-facing Mini O&M PDF for projects that don't warrant the full AI-assisted O&M Manual pipeline. The PDF bundles existing data -- confirmed device labels, worksheet completion photos, sign-offs, quoted equipment -- into a Tier 1 visual presentation matching the existing `feat(om-tier1)` document family.

Purpose: Give every project (not just heavyweight ones) a polished handover artifact at install close-out. No new data capture, no AI, no migrations. One button, one render, one PDF -- driven entirely by data that already lives in `project_packages`, `worksheet_photos`, `site_survey_photos`, and `device_label_photos`.

Output: New `MiniOmBuilderService` (pure aggregation), new `pdf/mini-om.blade.php` (Tier 1 visual chrome), new `config/rams.php` `mini_om_support` block (editable boilerplate), new `MiniOmController` + named route `projects.mini-om.pdf`, and a Generate Mini O&M button + status pill on the project page.
</objective>

Implementation rules -- NON-NEGOTIABLE:

1. **Pure aggregation.** No DB writes. No file writes. No HTTP. No AI calls. `$project` only.
2. **Eager-load** to avoid N+1: `$project->load(['owner', 'latestPackage', 'worksheets.photos', 'worksheets.signoffs', 'siteSurveys.rooms.photos'])`. For DeviceLabelPhotos, query `DeviceLabelPhoto::where('project_id', $project->id)->where('confirmed', true)->get()` once at the top of `build()` and reuse the collection.
3. **All rooms (D-LOCK-3).** The room list = the rooms in the latest `project_packages.extracted_data['rooms']` array (each entry typically has a `name` key) OR `array_keys(extracted_data['room_overviews'])` when `'rooms'` is missing. Iterate these -- DO NOT skip any. Even rooms with zero photos yield a `rooms[]` entry; the Blade renders the placeholder.
4. **Cover hero (D-LOCK-1).** Iterate `$project->worksheets` (oldest first by `created_at`), then `$worksheet->photos` (already ordered by sort_order, id). Return `WorksheetPhoto::absolutePath()` for the FIRST photo found. If none exist anywhere, set `cover.hero_photo_abs_path = null`.
5. **Photo room match.** WorksheetPhoto.room_name and SiteSurveyRoom.name use raw labels -- match via `strtolower(trim($x))`. Same as `Worksheet::photoCountsByRoom()` precedent (Worksheet.php line 132).
6. **Confirmed labels (D-LOCK-2).** Use `DeviceLabelPhoto` rows where `project_id = $project->id` AND `confirmed = true` AND `room_name` matches. Pull manufacturer/model/serial/mac/part_number from `ai_extracted` array using `data_get($photo->ai_extracted, 'manufacturer')` etc. Empty string when absent.
7. **Quoted overlay (D-LOCK-2).** From `$package->equipment_list`, filter to rows where `room` matches the current room (case-insensitive, trimmed). For the per-room `assets.quoted` array, OMIT any line already represented in `assets.confirmed` (match by `part_number` exact OR `manufacturer+model` lower-trimmed).
8. **Asset register summary** uses the same dedup logic but project-wide rather than per-room.
9. **Survey photos before/after (D-LOCK-6).** From the latest non-superseded `SiteSurvey` for the project (`whereNull('superseded_at')->latest()->first()`), iterate `$survey->rooms`, match by name, return `SiteSurveyPhoto::absolutePath()`. The Blade renders the pair only when BOTH `photos.before` AND `photos.after` are non-empty -- the service still populates both arrays unconditionally (graceful degrade is a Blade concern, not a service concern).
10. **DeviceLabelPhoto** absolute file path (when needed): `Storage::disk('public')->path($photo->photo_path)`. We do NOT include this path in the returned data structure -- we only return the extracted text fields. (Photos themselves are not embedded in the asset register; they are inferred via "confirmed" status.)
11. **No throws** for missing data. Empty strings, empty arrays, null Carbons are valid values. The Blade is responsible for rendering empty-state UX. Log a `Log::warning('MiniOmBuilderService: project has no latest package', ['project_id'=>$project->id])` once when `latestPackage` is null and continue with an empty `rooms` array -- the Mini O&M still renders (cover + asset register empty + support copy).
12. PHPDoc the class + `build()` method with the exact return-shape contract documented above so future maintainers don't have to reverse-engineer the Blade.
13. Follow conventions from CLAUDE.md: PSR-12, 4-space indent, ASCII art comment dividers between major helper sections (`// ====== Section ======` or `// -- Label --`), camelCase methods, `Log::info/warning` lines prefixed with `'MiniOmBuilderService: ...'`.

Decompose internally into private helpers -- none should exceed ~40 lines:
`buildProjectMeta`, `pickCoverHeroPath`, `buildRooms`, `buildOneRoom`, `confirmedLabelsForRoom`, `quotedAssetsForRoom`, `dedupeQuoted`, `worksheetPhotosForRoom`, `surveyPhotosForRoom`, `signoffForRoom`, `buildAssetRegister`, `buildSupportBlock`, `buildCompanyBlock`.

```php
<?php
namespace App\Http\Controllers;

use App\Models\Project;
use App\Services\DocumentArtifactStorage;
use App\Services\MiniOmBuilderService;
use App\Services\PdfRenderService;
use Illuminate\Support\Facades\Log;
use Illuminate\Support\Str;
use Symfony\Component\HttpFoundation\BinaryFileResponse;

class MiniOmController extends Controller
{
    public function __construct(
        private readonly MiniOmBuilderService    $builder,
        private readonly PdfRenderService        $renderer,
        private readonly DocumentArtifactStorage $artifacts,
    ) {}

    public function generate(Project $project): BinaryFileResponse
    {
        $this->authorize('view', $project);  // ProjectPolicy::view -- owner OR admin

        $data = $this->builder->build($project);

        // H-07 storage convention -- Mini O&M is on-demand render but we still
        // persist via DocumentArtifactStorage::TYPE_OM so it is discoverable
        // alongside full O&M artifacts. Filename prefix `mini-om-` differentiates
        // from the heavyweight pipeline (which prefixes with `om-manuals_`).
        $filename = sprintf(
            'mini-om-%d-%s-%s.pdf',
            $project->id,
            Str::slug($project->client_name ?: 'unknown'),
            now()->format('Ymd-His'),
        );
        $absPath = $this->artifacts->writePath(DocumentArtifactStorage::TYPE_OM, $filename);

        // Use the existing OM brand teal #01889F (same as full O&M PdfService::buildOmManual).
        $this->renderer->fromBlade('pdf.mini-om', $data, $absPath, [
            'marginTop'    => 12,
            'marginBottom' => 12,
            'marginLeft'   => 0,
            'marginRight'  => 0,
        ]);

        Log::info('MiniOmController: generated mini O&M PDF', [
            'project_id' => $project->id,
            'filename'   => $filename,
        ]);

        $downloadName = sprintf(
            '%s - %s - Mini O&M.pdf',
            $project->ref ?: ('PROJ-' . $project->id),
            $project->client_name ?: 'Mini O&M',
        );

        return response()
            ->download($absPath, $downloadName, [
                'Content-Type' => 'application/pdf',
            ]);
    }
}
```
