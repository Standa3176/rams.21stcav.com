<objective>
The on-site engineer-facing tablet view at `/survey/{token}` is the most important data
capture point on the platform — yet today it cannot capture the 17 engineer-feedback
fields that quick task 260503-rgg added to the internal `/site-surveys/{id}/edit` form
and 260503-tfb wired into the RAMS generator. Engineers fill the public wizard on site
and the new fields silently never appear → data captured nowhere → downstream RAMS auto-
classification (Working at Height risk levels, Dust & Debris, Hidden Services,
Manual Handling) all run on null inputs.

This quick task closes that gap by mirroring the engineer-feedback fields into the
public wizard. Critical architectural caveat: **the public wizard is a fundamentally
different beast from the internal form**. The internal form is a classic flat HTML form
with `name="rooms[N][field]"` inputs that POST to validateSurvey() / SurveyService.
The public wizard is a Tailwind-CDN + Alpine.js single-page app that:
  • Persists everything to the SiteSurvey.survey_data JSON column (canonical shape)
  • Uses an 8-step wizard (Room Context, Quick Capture, Photos, Infrastructure,
    Equipment, Access & H&S, Constraints, Sign-off)
  • Auto-saves debounced via `POST /survey/{token}/step-save` (SurveyController::stepSave)
  • DOES NOT write to most SiteSurveyRoom columns directly — it writes to survey_data JSON
  • EXCEPT when the engineer marks a room complete (PublicSurveyController::completeRoom),
    which calls $room->update() with a flat array shaped by roomAttributesFromData()
  • EXCEPT when the engineer hits final submit (PublicSurveyController::submit), which
    calls SurveyService::submitPublic with a flat-form validated payload

So we have to wire the new fields into THREE places at once for the data to actually
land where downstream services expect it (the SiteSurveyRoom + SiteSurvey DB columns
populated in 260503-rgg):

  1. **The Alpine wizard UI** (surveys/show.blade.php) — new "Site Logistics" panel on
     rooms-list screen + 7 new room-level sub-sections inside the per-room flow.
  2. **The canonical survey_data JSON shape** (SurveyController::emptyCanonicalRoom +
     enforceCanonicalShape + normalizeStepContribution + buildStepPayload) — so auto-save
     persists the new fields without losing them on the next normalization pass.
  3. **The DB column mirror** — so the downstream RamsBuilderService extensions from
     260503-tfb actually see the data. Two paths converge here:
       a. Engineer marks room complete via the wizard → completeRoom() copies the
          canonical engineer_feedback block to room columns.
       b. Engineer hits final submit → validatePublicSurvey + SurveyService::submitPublic
          (already accepts flat-form input) writes site-level fields.

Purpose: Close the most important gap — **the engineer's actual data-capture surface**.
Without this, the entire "engineer feedback" pipeline (260503-rgg schema + 260503-tfb
RAMS wiring) is dead-letter for engineers using the public link, which is most of them.

Output: 3 files modified. The on-site tablet captures every engineer-feedback field
exactly once, the field round-trips through reload (saved canonical JSON re-hydrates),
the field reaches the DB columns at room-complete or final-submit time, and the existing
wizard flow is 100% regression-free.

Constraints reminder: 3 files modified. No new partials, no new routes, no new JS files
(extend existing inline Alpine x-data on surveys/show.blade.php). No tests (pure additive
UI + data-flow plumbing; manually verifiable on the tablet). NO changes to:
  - The migration / model fillable / model casts (already shipped in 260503-rgg)
  - The internal form (resources/views/site-survey/_room-form.blade.php — already done)
  - The internal SiteSurveyController::validateSurvey or SurveyService (already done)
  - The RamsBuilderService / RamsDataBuilderService (already done in 260503-tfb)
  - The public wizard's existing 8-step flow (Steps 1–8 stay exactly as today)
  - The Tailwind CDN approach on this view (the rest of the platform uses Vite/utility
    CSS but this view standardizes on the CDN — keep the convention)
</objective>

  private function normalizeMountingHeightOther(mixed $rows): array
  {
      $rows = is_array($rows) ? $rows : [];
      $out = [];
      foreach ($rows as $r) {
          if (! is_array($r)) continue;
          $label  = trim((string) ($r['label']    ?? ''));
          $height = $this->numericOrNull($r['height_m'] ?? null);
          if ($label === '' && $height === null) continue;   // strip empty rows
          $out[] = ['label' => $label, 'height_m' => $height];
      }
      return $out;
  }

  private function normalizeCableRoutes(mixed $rows): array
  {
      $rows = is_array($rows) ? $rows : [];
      $allowedCat = ['ceiling_speakers','desk_cables','mic_cables','booking_panel_cables','screen_cables','rack_to_room','other'];
      $out = [];
      foreach ($rows as $r) {
          if (! is_array($r)) continue;
          $cat = (string) ($r['category'] ?? '');
          $cat = in_array($cat, $allowedCat, true) ? $cat : '';
          $from = trim((string) ($r['from']  ?? ''));
          $to   = trim((string) ($r['to']    ?? ''));
          $len  = $this->numericOrNull($r['length_m'] ?? null);
          $notes = trim((string) ($r['notes'] ?? ''));
          // Strip fully-empty rows
          if ($cat === '' && $from === '' && $to === '' && $len === null && $notes === '') continue;
          $out[] = ['category' => $cat, 'from' => $from, 'to' => $to, 'length_m' => $len, 'notes' => $notes];
      }
      return $out;
  }

  private function normalizeBrackets(mixed $rows): array
  {
      $rows = is_array($rows) ? $rows : [];
      $out = [];
      foreach ($rows as $r) {
          if (! is_array($r)) continue;
          $eq    = trim((string) ($r['equipment'] ?? ''));
          $model = trim((string) ($r['model']     ?? ''));
          $pull  = (bool) ($r['pull_out'] ?? false);
          $notes = trim((string) ($r['notes'] ?? ''));
          if ($eq === '' && $model === '' && $notes === '' && ! $pull) continue;
          $out[] = ['equipment' => $eq, 'model' => $model, 'pull_out' => $pull, 'notes' => $notes];
      }
      return $out;
  }

  private function normalizeStringArray(mixed $vals, array $allowed): array
  {
      if (! is_array($vals)) return [];
      $out = [];
      foreach ($vals as $v) {
          $v = (string) $v;
          if (in_array($v, $allowed, true)) $out[] = $v;
      }
      return array_values(array_unique($out));
  }

  private function numericOrNull(mixed $v): ?float
  {
      if ($v === null || $v === '' || $v === false) return null;
      if (! is_numeric($v)) return null;
      return (float) $v;
  }

  private function intOrNull(mixed $v): ?int
  {
      if ($v === null || $v === '' || $v === false) return null;
      if (! is_numeric($v)) return null;
      return (int) $v;
  }
