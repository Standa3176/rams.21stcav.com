<objective>
Follow-up to 260711-oh4: expose the new Device columns (`is_critical`,
`pse_budget_w`, `pd_load_w`, `signal_role`, `room_name`) through a Tier 4
admin UI, and move the hardcoded 13-branch `inferCableRun()` cascade in
`CableScheduleGeneratorService` into a data-driven `device_cable_rules`
table with its own admin CRUD. Two atomic commits, Task 1 first.

Purpose: 260711-oh4 shipped the DB columns + service consumers (redundant
row emission + PoE budget solver), but the columns are only settable via
seeders / raw SQL / factories. Engineers can't tune the rules or flag a
device as critical without a developer. This task closes the UX gap for
device metadata AND flips the cable-inference cascade from
hardcoded-PHP-if-branches to admin-editable database rows — so future
manufacturer-specific rules (Extron matrix chassis, Crestron NVX, QSC
Q-SYS Core) can be added without a code deploy.

- 2 new admin surfaces: `/admin/devices` + `/admin/device-cable-rules`
- 1 new migration (device_cable_rules, additive, reversible)
- 1 new model + 1 idempotent seeder (13 rules)
