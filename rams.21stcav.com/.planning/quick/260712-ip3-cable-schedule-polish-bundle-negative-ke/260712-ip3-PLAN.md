## Deferred / Next

Follow-ups explicitly OUT OF SCOPE for this bundle — noted here so the next quick task can pick them up:

- **Cross-rule chain intelligence for redundant paths.** The T3-B redundant-row emitter currently pairs a `-R` row when either endpoint is a critical processor, but the preview endpoint's trace makes it visible that redundant paths for critical processors surface differently than the primary — e.g. when the primary is USB 3.0 (priority 141) but the redundant would be Cat6 PoE (priority 70) because the fibre USB extender's back-side is IP. A future task should teach the preview UI to show BOTH primary + redundant matches when the `is_critical` flag is set, so the admin can eyeball whether the paired cable makes sense.
- **Per-row decision log on the cable schedule edit page.** Right now the edit-page rows show the final `cable_type` + `notes` but not WHICH rule + tier fired. A per-row `<details>` disclosure showing "Rule #9 (priority 70) → tier 2 (max_m=300)" would let engineers audit inferred output without re-running the preview endpoint for every line. Requires a schema change (store `inference_rule_id` + `inference_tier_index` on `cable_schedule_items`) so is bigger than a follow-up polish.
- **Preview endpoint rate limiting / audit persistence.** If the preview endpoint is ever exposed for external audit consumption (e.g. project managers reviewing an installer's proposal), it needs per-user throttle + an audit trail of every preview run. For internal-only admin use today, `logging.info()` is fine; extend when the endpoint gets a real customer.
