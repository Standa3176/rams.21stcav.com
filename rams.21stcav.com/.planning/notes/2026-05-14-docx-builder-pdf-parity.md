DOCX renderer (`app/Services/DocxBuilderService.php`, 1433 LOC) had drifted hard from `resources/views/pdf/rams.blade.php` (1976 LOC) — RamsDocument 81 (Light Forms Ltd, package 124) generated DOCX vs PDF on the same `generated_data` payload diverged across 12 axes (D1-D12) discovered during user UAT on the Phase 23 worksheet-classifier-universal branch. Root cause split three ways: (1) DOCX paths (`BuildRamsDocumentJob`, `RamsController::updateAndDownload`, `RamsController::download`) silently bypass `RamsDisplayPatchService::patch($record)` which the PDF download path always applies — so doc_author leaked as the raw client email "Marius@LIGHTFORMS.COM" (D1), site_contact came through empty instead of "TBC at site induction" (D5), and the personnel/scope/rooms resolution chain in the patch service never ran for the DOCX cover; (2) DOCX read `$project['date']` (a render-time `now()->format('F Y')` placeholder written by `RamsDataBuilderService`) instead of `$record->created_at->format('d/m/Y')` (D2), and ignored the PDF's rooms-resolution chain `reviewed_data['rooms']` → `reviewed_data['room_overviews'][n]['room']` → `project['rooms_text']` so ROOMS rendered blank (D3); (3) DOCX `buildMethodStatement()` had a 2-entry `$reqMap` (`'lead engineer'`, `'project manager'`) and a hardcoded "Lead Engineer / 1 / CSCS Card" fallback when `$data['team']` was empty — vs the PDF's full 6-entry map plus the synthesise-team-from-personnel-fields fallback (D4). Plus three self-contained DOCX-only bugs: `riskBadge()` threshold off-by-one (`>= 7` → MED, so RA08/09/11 scores=6 mis-labelled LOW where PDF says MED, D7); `buildMethodStatement()` step-strip regex `/^\d+[\.\-–—\s]+/` didn't strip leading "Step N — " prefix so every step rendered as "Step 1 — Step 1 — Title" (D8); flat 4-col risk legend instead of the PDF's 5×5 likelihood/severity grid + 3-band footer (D6); `buildCdmSection()` invoked between H&S Policy and Scope of Works instead of after Method Statement (D9). Finally DOCX was structurally missing 9 sections all of which had data already present in `$data` post-`RamsComplianceUpgradeService::upgrade()`: §6.7 Material Handling, §6.8 Permit & Isolation, §6.9 Fixings Control, §6.10 Supervision & QA, Permits & Authorisations, COSHH Assessment, Environmental Management (Waste + Noise/Dust), Welfare Arrangements, Appendix A Toolbox Talk Record (D10/D11/D12). Fix shipped as three atomic commits, all targeting `app/Services/DocxBuilderService.php`. Commit 1 (Data parity D1-D5 + D4 expansion): apply `RamsDisplayPatchService::patch($record)` at the top of `build()` (single line — the patch service mutates `$record->generated_data` transiently, identical to PDF behaviour); replace `$project['date']` with `$record->created_at?->format('d/m/Y')` in cover + Document Control (2 sites); port the PDF rooms-resolution chain into `buildCoverPage()` + `buildScopeOfWorks()` reading reviewed_data first; add the empty-team fallback that synthesises Project Manager / Lead Engineer / Engineers / Programmer from `$project` personnel strings; expand `$reqMap` to the full 6-entry version verbatim from rams.blade.php lines 1338-1344; add cover personnel block (PROJECT MANAGER / LEAD ENGINEER / ENGINEERS / PROGRAMMER / VEHICLE REGS) as a third cover table matching the PDF; extend Site Contact resolution chain to fall back to "TBC at site induction". Commit 2 (Structural fixes D6-D9): rewrite `buildRiskAssessment` legend block to emit a 5×5 PhpWord grid (header row Severity 1-5 / row headers Likelihood 1-5 / 25 body cells each L×S with `riskColour()` band) plus a 3-band footer table (LOW 1-4 / MEDIUM 5-9 / HIGH 10+) per user decision to collapse to PDF's 3-band palette (drop `RISK_ORANGE`); fix `riskBadge()` to `>= 5` MED / `>= 10` HIGH threshold; collapse `riskColour()` to 3 bands; extend `buildMethodStatement` step regex to `/^\s*(step\s+\d+[\.\-–—\s]*|phase\s+\d+[\.\-–—\s]*|\d+[\.\-–—\s]+)/i` matching the PDF; move `buildCdmSection()` invocation out of build() at line 90 into a new compliance block after Method Statement. Commit 3 (Missing sections D10-D12): add 9 new private methods rendering the missing sections using PhpWord paragraphs/tables — content/section-order matches PDF; styling can differ (PhpWord can't perfectly mimic dompdf gradients) but content semantics and section-presence parity is the contract under test.
