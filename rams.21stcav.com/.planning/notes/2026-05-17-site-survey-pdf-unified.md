The two Site Survey PDF outputs — the engineer-internal `pdf/site-survey/summary.blade.php` (rendered by `SurveyPdfService::buildSummary()`) and the polished client-facing `pdf/site-survey/client-report.blade.php` (rendered by `SurveyPdfService::buildClientReport()` per quick task 260508-v7g) — shared ~80% of their data axis (project meta, per-room AV requirements, per-room photos) but had drifted into two separate Blade files with two separate CSS chrome systems and two separate render code paths. The duplication was bug-prone (engineer view's photo embed was using a raw `survey-photos/{filename}` string concat + base64_encode, breaking on the post-260508 project-scoped photo path layout; client view used the correct `$photo->storagePath()` + `PdfImageEmbedder::dataUri()` resize-then-embed pattern) and the visual chrome had diverged (engineer = utilitarian `_styles.blade.php` with `#007B8A` teal headings; client = Mini-O&M Tier-1 polish with `#1B7A7A` teal cover bar + `#C07000` orange callouts + variations status pills). The merge consolidates both outputs onto `pdf/site-survey/summary.blade.php` with a single `$internal` boolean toggle (default `true` to preserve back-compat for any caller invoking `buildSummary($survey)` without the flag — `SurveyPdfService::buildSummary()` signature extends to `(SiteSurvey $survey, bool $internal = true)`). The blade branches per-section: engineer-only sections (Site Conditions dimensions/services table, Pre-install Checks Q+A — the row that surfaces engineer free-text like "Pm to work this out" / "wall not built yet I believe you have the designs", Engineer Findings sub-sections including mounting heights / WAH methods / cable routes / wall construction + prep / brackets-to-source / table grommets / floor-box info) are wrapped in `@if ($internal)`; client-only sections (cover accent bar, survey-level `office_review_notes` callout, per-room `office_notes` callout, per-room variations table, survey-wide Variations Summary block + explanatory footer) are wrapped in `@unless ($internal)`; shared sections (project meta header, General Notes, per-room title, AV Requirements with Planned Works + Existing AV Equipment, Photos) render unconditionally. Photo rendering migrates to `$photo->storagePath()` + `PdfImageEmbedder::dataUri()` in both modes (fixes the engineer-view legacy-path-only bug as a side effect of the merge). `SurveyPdfService::buildClientReport()` is now a thin delegate — same H-07 `TYPE_SURVEY` `DocumentArtifactStorage::writePath()` (so `storage/app/documents/site-surveys/client-survey-{id}-{slug}-{ts}.pdf` persistence is unchanged) — but renders `pdf.site-survey.summary` with `internal: false` instead of the deleted `pdf.site-survey.client-report`. `SiteSurveyController::downloadPdf()` extends its signature to accept `Request` and reads `$request->boolean('internal', true)`; the URL surface becomes `/site-surveys/{id}/pdf?internal=0` for client mode (default = engineer for back-compat). Download filename also branches — `site-survey-{id}.pdf` (engineer) vs `site-survey-client-{id}.pdf` (client) so a user saving both modes side-by-side doesn't overwrite one with the other. The legacy `/site-surveys/{id}/client-report` route + `SiteSurveyController::clientReport()` action are preserved unmodified so existing bookmarks / emailed links still resolve. UI buttons on `resources/views/site-survey/show.blade.php:357-362` and `resources/views/projects/show.blade.php:931-940` replace the previous "Download PDF + Client Survey Report" pair with a clearer "Download for Client" (primary, teal, `?internal=0`) + "Download Internal" (outline, `?internal=1`) — both rooted on `route('site-surveys.pdf', $survey)` with the differentiating query string. The 333-line `pdf/site-survey/client-report.blade.php` deletes cleanly in commit 3 of the series — every section it carried lives on in `summary.blade.php` under an `@unless ($internal)` guard. Test coverage in new file `tests/Feature/SiteSurvey/SurveyPdfModesTest.php` (8 cases / 37 assertions): asserts engineer mode renders Site Conditions / Pre-install Checks / Engineer Findings / Installation heights / Brackets-to-source / engineer free-text answers; asserts client mode suppresses all six; asserts BOTH modes render project meta + AV requirements + per-room photos; asserts client mode renders Office review summary + Office notes + per-room variations; asserts engineer mode omits same three; asserts the blade defaults to engineer mode when `$internal` is omitted (back-compat for any caller invoking without the flag); asserts both route names (`site-surveys.pdf` + legacy `site-surveys.client-report`) remain registered. Tests render via `view()->render()` rather than going through `PdfRenderService` / Browsershot so the CI runners don't need Chromium installed. Broader regression suite green: `php artisan test --filter='SiteSurvey|SurveyController|SurveyPdf|SurveyService'` reports 36 cases / 140 assertions / 16.85s all PASS.
